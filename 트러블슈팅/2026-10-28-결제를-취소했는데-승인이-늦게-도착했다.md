# 2026-10-28 결제를 취소했는데, 승인이 늦게 도착했다

> 태그: #트러블슈팅 #결제 #경합 #단말기 #키오스크

## 무엇을 / 왜
사진 키오스크의 카드 결제를 카드 단말기 회사의 결제 프로그램에 바로 연결하면서, 손님이 결제 도중에 '취소'를 누르는 경우를 다시 살펴봤습니다.

- 카드 결제는 단말기에서 결제 프로그램을 거쳐 카드사까지 이어져서, 손님이 취소를 누른 순간에 이미 카드사로 승인 요청이 나가 있을 수 있었습니다.
- 화면만 닫고 끝내면, 늦게 도착한 승인이 그대로 남아 화면은 '취소됨'인데 카드에서는 돈이 나가는 길이 있었습니다.
- 손님은 취소된 줄 알고 떠나고 매장은 받은 줄 모르는 돈이 남는 종류라, 화면만 봐서는 알아채기도 어려운 문제였습니다.

## 어떻게 풀었나
- 취소를 누르면 화면만 닫지 않고 단말기에도 '멈춤'을 보내게 했습니다.
- 멈춤보다 승인이 먼저 끝나 버린 경우를 위해, 취소를 누른 뒤에 도착한 승인에는 바로 '승인 취소'를 보내게 했습니다.
- 승인 취소마저 실패하면 결제 프로그램은 '결제됨'으로 돌려주게 했습니다. 그런데 2026-10-29 교차 검토에서, 화면 쪽이 이 결과를 받고도 매출로 남기지 않아 돈만 나가고 기록이 없는 길이 남아 있던 것을 찾았습니다. 그래서 되돌리지 못한 승인은 '환불 필요' 매출로 남겨 관리자 메뉴에서 되돌릴 수 있게 고쳤습니다.
- 취소가 결제 시작보다 먼저 도착한 경우도 기억해 두었다가, 그 결제는 시작하지 않게 했습니다.
- 결제와 취소가 단말기에 동시에 들어가지 않게, 한 번에 하나씩만 보내도록 순서를 정했습니다.
- 실제 단말기와 카드로 하는 확인은 아직 남아 있습니다.

## 코드로 보기 (개념 재현)
손님이 결제 도중 취소를 눌렀는데, 단말기는 이미 보낸 승인을 늦게 돌려주는 상황을 흉내 냈습니다.

```js
// 결제 중에 손님이 취소를 눌렀는데, 단말기는 이미 보낸 승인을 늦게 돌려준 경우 (개념 재현)
const sleep = ms => new Promise(resolve => setTimeout(resolve, ms))

class FakeTerminal {
  constructor() { this.charged = 0; this.voided = 0; this.stopRequested = false }
  async charge(amount) {
    await sleep(50)                                   // 카드사 응답을 기다리는 동안
    this.charged += amount                            // 멈춤 요청이 늦어 승인은 이미 남
    return { approved: true, approvalNo: 'A0001', amount }
  }
  async stop() { this.stopRequested = true }          // 단말기에 '멈춤' 요청
  async voidApproval(approval) { this.voided += approval.amount }  // 승인 취소 요청
}

async function pay({ fixed }) {
  const terminal = new FakeTerminal()
  let cancelled = false
  const pending = terminal.charge(5000)
  setTimeout(() => {                                  // 20ms 뒤 손님이 '취소'를 누름
    cancelled = true
    if (fixed) terminal.stop()                        // 고친 뒤: 화면만 닫지 않고 단말기도 멈춤
  }, 20)
  const result = await pending
  if (fixed && result.approved && cancelled) {
    await terminal.voidApproval(result)               // 고친 뒤: 취소 뒤 도착한 승인은 바로 승인 취소
  }
  return {
    화면: cancelled ? '취소됨' : '결제 완료',
    나간돈: terminal.charged - terminal.voided,
    멈춤요청: terminal.stopRequested,
  }
}

;(async () => {
  console.log('고치기 전', await pay({ fixed: false }))
  console.log('고친 뒤', await pay({ fixed: true }))
})()
```

실행 결과입니다.

```
고치기 전 { '화면': '취소됨', '나간돈': 5000, '멈춤요청': false }
고친 뒤 { '화면': '취소됨', '나간돈': 0, '멈춤요청': true }
```

고치기 전에는 화면이 '취소됨'인데 돈이 나갔고, 고친 뒤에는 늦게 온 승인을 되돌려 나간 돈이 0 이 됐습니다.

## 💡 배운 것
- 결제에서 '취소'는 화면을 닫는 일이 아니라, 이미 나간 요청까지 되돌리는 일이라는 걸 배웠습니다.
- 늦게 도착한 응답은 지금 기다리는 그 일의 것인지 먼저 확인해야 한다는 걸 다시 배웠습니다(2026-10-26, PIN 확인을 기다리는 사이 손님이 바뀐 글). 이번에는 확인에서 끝나지 않고, 이미 생긴 결과(승인)를 되돌리는 데까지 가야 했습니다.
- 되돌리기도 실패할 수 있다는 것을 처음부터 정해 둬야 했습니다. 실패를 조용히 넘기면 돈만 나가고 기록이 없는 상황이 남았습니다.

## 소감
카드 결제는 화면과 단말기와 카드사가 각자 자기 속도로 움직여서, 누가 먼저 끝나느냐에 따라 결과가 갈렸습니다. 경우를 하나씩 따져 보고 나서야 빈 곳이 보였습니다.
