# 2026-11-02 설치 ID 를 그대로 가져온 새 프로그램이, 예전 시험판을 자기 옛 버전으로 알았다

> 태그: #트러블슈팅 #Windows #설치프로그램 #electron-builder #NSIS #GUID

## 무엇을 / 왜
사진 키오스크 PC 에 까는 관리 프로그램(에이전트)은, 예전에 만들던 시험판 제품의 코드에서 갈라져 나온 것이었습니다. 이름과 설치 화면은 새 제품 것으로 바꿨고, 외주형 고객사에 넘길 설치 파일은 중립 이름으로 따로 만들어 둔 상태였습니다.

- 오픈(2026-11-05)을 앞두고 사내 QA 에서, 새 설치 파일을 실행했더니 그 PC 에 깔려 있던 예전 시험판의 에이전트가 떴다는 피드백이 왔습니다.
- 새 에이전트의 설정 폴더는 제대로 생겨 있었는데, 화면에 뜬 건 예전 시험판이었습니다.
- 매장 PC 에 예전 시험판이 깔려 있으면 같은 일이 생길 수 있어서, 오픈 전에 원인을 알아야 했습니다.

## 어떻게 풀었나
- 먼저 예전 시험판이 뜬 길을 코드로 따라갔습니다. 새 에이전트에는 예전 시험판 설치를 제자리에서 이어받는 코드가 남아 있었습니다. 예전 시험판을 쓰던 PC 를 옮겨 오려고 넣었던 코드였습니다.
  - 이 코드는 PC 에 예전 시험판의 흔적이 있으면, 그 폴더와 키오스크 앱을 자기 것으로 썼습니다.
  - 그래서 새 에이전트가 예전 시험판의 키오스크 앱을 "내 키오스크" 로 알고 띄웠고, 그 키오스크 앱이 자기 짝인 예전 에이전트를 띄웠습니다. 예전 창을 연 것은 예전 키오스크 앱이었고, 방아쇠는 새 에이전트였습니다.
- 두 프로그램이 Windows 에서 어떻게 구분되는지도 봤더니 더 큰 문제가 보였습니다. 두 제품의 설치 ID(electron-builder 의 appId)가 한 글자도 다르지 않았습니다. 코드를 갈라 오면서 이름과 설치 화면은 바꿨지만, 화면에 나오지 않는 이 값은 그대로였습니다.
- 찾아보니 electron-builder 의 NSIS 설치본은 appId 로 GUID 를 만들고(UUID v5), 그 GUID 를 설치 정보와 제거 정보의 레지스트리 키 이름으로 쓴다는 걸 알게 됐습니다. 같은 계산을 직접 해 보니, 이 PC 에 남아 있던 실제 설치 정보 키 이름과 똑같은 값이 나왔습니다. appId 가 같으면 Windows 에게 두 제품은 같은 프로그램의 옛 판과 새 판이었습니다.
- electron-builder 설치본은 시작할 때, 자기 GUID 의 제거 키에 제거 프로그램이 등록돼 있으면 그것을 옛 버전으로 보고 조용히(/S) 실행했습니다. 이때 "업데이트 중" 이라는 표시를 함께 넘겼고, electron-builder 의 기본 제거 단계는 그 표시가 있으면 앱 데이터를 지우지 않게 되어 있었습니다.
- 그런데 예전 시험판에는 직접 넣은 제거 단계가 있었고, 그 단계는 "업데이트 중" 표시를 보지 않았습니다. 지워질 때 키오스크 앱과 데이터 폴더, 출력한 사진을 모아 둔 폴더까지 함께 지우게 되어 있었습니다.
- 정리하면, 예전 시험판이 깔린 PC 에서 새 설치 파일을 실행하면 예전 시험판이 조용히 제거되면서 그 데이터와 사진까지 지워질 수 있는 길이 코드에 있었습니다. 실제 PC 에서 이 길을 타는지까지 확인하지는 않았습니다.
- 오픈 전에 고친 것은 두 가지였습니다.
  - 예전 시험판 이어받기는, 에이전트가 예전 시험판 폴더에서 실행될 때만 하도록 좁혔습니다. 새로 설치한 PC 에서는 예전 폴더와 프로그램을 쓰지 않게 했습니다.
  - 설치 파일은 시작할 때, 같은 GUID 의 제거 키에 다른 제품의 제거 프로그램이 등록돼 있으면 안내를 띄우고 설치를 멈추게 했습니다. 예전 시험판을 지우는 사고부터 막았습니다.
- appId 를 새 값으로 바꾸는 일은 오픈 뒤로 미뤘습니다. 이미 새 제품을 깐 PC 의 설치 정보도 같은 GUID 아래 있어서, 바꾸려면 그 PC 들을 새 GUID 로 옮기는 처리를 같이 만들어야 했기 때문입니다.

## 코드로 보기 (개념 재현)
electron-builder 가 appId 로 GUID 를 만드는 계산(UUID v5, 고정 namespace)을 그대로 옮기고, 설치본이 시작할 때 하는 '옛 버전 지우기'를 흉내 냈습니다. GUID 계산 함수에 실제 제품의 appId 를 넣으면, 이 PC 에 남아 있던 실제 레지스트리 키 이름과 같은 값이 나오는 것을 먼저 확인했습니다. 레지스트리와 제거 스크립트는 흉내이고, 이름은 모두 예시입니다.

```javascript
// 설치 ID(appId)가 같은 두 프로그램을 같은 PC 에 깔면 어떻게 되는지 흉내 낸다.
// GUID 계산은 electron-builder 25 의 NSIS 설치본과 같은 방식(UUID v5)이다. 이름은 모두 예시다.
const crypto = require('crypto');

// electron-builder 가 appId 로 설치본 GUID 를 만들 때 쓰는 고정 namespace
const NS = '50e065bc-3134-11e6-9bab-38c9862bdaf3';

// RFC 4122 UUID v5: namespace 바이트 + 이름 바이트의 SHA-1 에서 앞 16바이트를 쓴다.
function uuidV5(name, ns) {
  const hash = crypto.createHash('sha1')
    .update(Buffer.concat([Buffer.from(ns.replace(/-/g, ''), 'hex'), Buffer.from(name, 'utf8')]))
    .digest();
  const b = Buffer.from(hash.subarray(0, 16));
  b[6] = (b[6] & 0x0f) | 0x50;   // 버전 5
  b[8] = (b[8] & 0x3f) | 0x80;   // RFC 4122 변형
  const h = b.toString('hex');
  return `${h.slice(0, 8)}-${h.slice(8, 12)}-${h.slice(12, 16)}-${h.slice(16, 20)}-${h.slice(20)}`;
}
const uninstallKey = (guid) => `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Uninstall\\${guid}`;

// 갈라져 나오기 전 제품(예전 시험판)과, 그 코드에서 갈라져 나온 새 제품
const oldTrial = { appId: 'com.example.photo.agent', name: 'Trial Agent' };
const newAgent = { appId: 'com.example.photo.agent', name: 'New Agent' };      // appId 를 그대로 가져옴
const renamed  = { appId: 'com.example.newphoto.agent', name: 'New Agent' };   // appId 를 새로 정한 경우

const g1 = uuidV5(oldTrial.appId, NS);
const g2 = uuidV5(newAgent.appId, NS);
const g3 = uuidV5(renamed.appId, NS);
console.log(`예전 시험판 GUID      ${g1}`);
console.log(`새 제품 GUID(같은 ID) ${g2}  같은가: ${g1 === g2}`);
console.log(`새 제품 GUID(새 ID)   ${g3}  같은가: ${g1 === g3}`);

// 이 PC 에는 예전 시험판이 깔려 있다: 제거 키에 그 제거 프로그램이 등록돼 있다.
const registry = new Map([[uninstallKey(g1), {
  DisplayName: oldTrial.name,
  UninstallString: '"C:\\Users\\me\\AppData\\Local\\Programs\\Trial Agent\\Uninstall Trial Agent.exe"',
}]]);

// 예전 시험판의 제거 스크립트: '업데이트 중' 인지 보지 않고 지운다.
function oldTrialUninstall(args) {
  const removed = ['Programs\\Trial Kiosk', 'AppData\\Roaming\\Trial Kiosk', 'Pictures\\Trial'];
  return `인자 "${args}" 를 받았지만 그대로 지움: ${removed.join(', ')}`;
}

// 설치본이 시작할 때 하는 '옛 버전 지우기'. 자기 GUID 의 제거 키에 제거 프로그램이 있으면 조용히 실행한다.
function install(product, { guard }) {
  const key = uninstallKey(uuidV5(product.appId, NS));
  const found = registry.get(key);
  if (!found) return `${product.name}: 옛 버전 없음 → 그냥 설치`;
  if (guard && found.DisplayName !== product.name) {
    // 고친 뒤: 같은 GUID 에 다른 제품의 제거 프로그램이 있으면 설치를 멈춘다.
    return `${product.name}: 같은 GUID 에 '${found.DisplayName}' 가 등록돼 있음 → 설치를 멈춤`;
  }
  return `${product.name}: '${found.DisplayName}' 를 옛 버전으로 보고 조용히 제거 → ${oldTrialUninstall('/S --updated')}`;
}

console.log(install(newAgent, { guard: false }));
console.log(install(newAgent, { guard: true }));
console.log(install(renamed, { guard: false }));
```

Node v22.11.0 에서 돌린 결과입니다.

```
예전 시험판 GUID      6128a9e9-19be-5338-ab80-ebe55c0c92f3
새 제품 GUID(같은 ID) 6128a9e9-19be-5338-ab80-ebe55c0c92f3  같은가: true
새 제품 GUID(새 ID)   fecb7faa-73c1-5bd0-a6f5-17a89f560067  같은가: false
New Agent: 'Trial Agent' 를 옛 버전으로 보고 조용히 제거 → 인자 "/S --updated" 를 받았지만 그대로 지움: Programs\Trial Kiosk, AppData\Roaming\Trial Kiosk, Pictures\Trial
New Agent: 같은 GUID 에 'Trial Agent' 가 등록돼 있음 → 설치를 멈춤
New Agent: 옛 버전 없음 → 그냥 설치
```

- appId 를 그대로 가져온 새 제품은 예전 시험판과 GUID 가 같았고, appId 를 새로 정하면 GUID 도 달라졌습니다.
- 막기가 없을 때 새 제품 설치본은 예전 시험판을 자기 옛 버전으로 보고 조용히 제거했고, 예전 제거 스크립트는 "업데이트 중" 표시를 받고도 데이터와 사진 폴더까지 지웠습니다.
- 막기를 넣자 같은 GUID 에 다른 제품이 등록돼 있는 것을 보고 설치를 멈췄습니다. appId 를 새로 정한 제품은 처음부터 옛 버전을 찾지 않았습니다.

## 💡 배운 것
- 설치 ID(appId)는 화면에 나오는 이름과 달리, Windows 가 설치된 프로그램을 알아보는 신원이라는 걸 배웠습니다. electron-builder 는 이 값으로 GUID 를 만들어 레지스트리 키 이름으로 썼고, 같은 값을 쓴 두 제품은 같은 프로그램의 옛 판과 새 판이 됐습니다.
- 다른 제품에서 갈라져 나올 때는 이름과 아이콘보다, 설치 ID 처럼 화면에 나오지 않는 이름부터 새로 정해야 한다는 걸 배웠습니다. 나중에 바꾸려면 이미 깔린 PC 를 옮기는 일까지 따라왔습니다.
- 예전 설치를 옮겨 오는 코드는 언제 멈출지도 함께 정해 둬야 한다는 걸 배웠습니다. 옮길 PC 를 위해 넣은 코드가, 옮길 필요가 없는 PC 에서 예전 프로그램을 자기 것으로 썼습니다.
- 이름은 화면 밖에도 있다는 걸 다시 배웠습니다([2026-10-30, 손님 페이지에서 플랫폼 이름을 지웠더니, 배포 확인이 배포를 되돌렸다](../트러블슈팅/2026-10-30-손님-페이지에서-플랫폼-이름을-지웠더니-배포-확인이-배포를-되돌렸다.md)). 그때는 화면 글자에 기대던 배포 확인이었고, 이번에는 화면에 나오지 않는 설치 ID 였습니다.

## 소감
QA 피드백은 예전 창이 떴다는 한 줄이었는데, 따라가 보니 그 뒤에 예전 프로그램이 조용히 지워질 수 있는 더 큰 길이 있었습니다. 보이는 이름을 바꾸는 데 신경 쓰는 동안, 보이지 않는 이름은 예전 제품 것 그대로 남아 있었습니다.
