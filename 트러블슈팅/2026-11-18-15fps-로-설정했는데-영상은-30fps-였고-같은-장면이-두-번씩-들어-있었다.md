# 2026-11-18 15fps 로 설정했는데 영상은 30fps 였고, 같은 장면이 두 번씩 들어 있었다

> 태그: #트러블슈팅 #동영상 #프레임레이트 #원본비교 #키오스크

## 무엇을 / 왜

사진 키오스크가 손님에게 주는 짧은 동영상(촬영 장면을 프레임 칸에 넣어 만든 몇 초짜리 영상)과 긴 타임랩스에는 '초당 장면 수(FPS) 상한' 설정이 있었습니다. 고객사 QA 에서 세 가지가 들어왔습니다.

1. 15fps 로 설정했는데 만들어진 영상은 30fps 였습니다.
2. 재생 중간에 잔상이 길게 남는 구간이 있었습니다.
3. 영상이 12초였는데, fps 가 맞으면 8초쯤이 되지 않느냐는 물음이었습니다.

## 어떻게 풀었나

손님 QR 의 동영상을 직접 받아 장면을 세어 봤습니다. 파일은 30fps 였지만 서로 다른 장면은 초당 약 14장이었고, 같은 장면이 두 번씩 들어 있었습니다.

원인은 세 가지였습니다.

- **30fps:** 영상을 만드는 도구가 그림 한 장을 k 칸씩 늘여 파일을 30fps 근처로 맞추고 있었습니다. 초당 15장이면 한 장을 두 칸씩 써서 30fps 가 됐습니다. 움직임은 15장/초 그대로인데 숫자만 30이었습니다. 타임랩스도 설정과 상관없이 30 근처로 나왔습니다.
- **잔상:** 이틀 전 제가 영상을 '부드럽게' 하려고 넣은 처리 때문이었습니다. 자동 초점을 맞추는 동안의 장면을 빼고, 빈자리를 앞뒤 그림을 반투명하게 섞은 그림 약 15장으로 채웠습니다. 컷마다 두 번씩, 1초쯤 두 장면이 겹쳐 보였습니다.
- **12초:** 그 키오스크의 촬영 타이머가 10초였고, 끝에 고정 정지 2초를 붙여 12초가 됐습니다.

예전 프로그램이 같은 영상을 어떻게 만들었는지 코드를 찾아 읽었습니다. 영상 FPS 는 설정값이었고, 저장한 그림 한 장이 영상 한 칸이었고, 맨 앞 3장은 빼고 마지막 그림만 20칸 이어 붙였습니다. 섞은 그림은 없었고, 자동 초점을 맞추는 동안에도 장면 저장을 멈추지 않았습니다.

그 규칙대로 맞췄습니다. 저장된 장면을 차례로 잇고(앞 3장만 뺌), 섞기를 없앴습니다. 영상 FPS 는 설정값으로 고정하고 마지막 그림은 20칸으로 했습니다. 길이는 (장면 수 + 20) ÷ fps 가 되어, 실제 영상 도구로 만들어 보니 촬영 타이머 8초면 약 8.6초, 10초면 약 10.6초였습니다. 고객사가 예상한 "약 8초" 는 촬영 타이머 8초일 때와 가까웠습니다. 타임랩스도 FPS 상한을 정해 두면 그 값으로 만들게 했습니다.

## 코드로 보기 (개념 재현)

이름은 바꾼 더미입니다.

```js
// 고치기 전: 장면 15장/초를 30fps 파일에 맞추려고 한 장을 두 칸씩 늘였다
function planBefore(shots, capturedPerSec = 15, fileFps = 30) {
  const k = Math.round(fileFps / capturedPerSec); // 2
  return { fps: fileFps, frames: shots.flatMap((s) => Array(k).fill(s)) };
}

// 고치기 전(이틀 전 넣은 처리): 빠진 자리를 앞뒤 장면을 섞은 그림으로 채웠다 -> 잔상
function fillGapBefore(prev, next, count) {
  return Array.from({ length: count }, (_, i) => mixImages(prev, next, (i + 1) / (count + 1)));
}

// 고친 뒤: 장면 한 장 = 영상 한 칸, fps = 설정값, 마지막 장면만 20칸
function planAfter(shots, fpsSetting = 15, holdLast = 20) {
  const kept = shots.slice(3); // 맨 앞 3장은 뺀다
  const frames = [...kept, ...Array(holdLast).fill(kept[kept.length - 1])];
  return { fps: fpsSetting, frames, seconds: frames.length / fpsSetting };
}

const shots = Array.from({ length: 103 }, (_, i) => `shot${i}`);
planBefore(shots).frames.length; // 206 칸, 30fps - 같은 장면이 두 번씩
planAfter(shots).seconds;        // (100 + 20) / 15 = 8
```

## 💡 배운 것

- 영상 파일의 fps 와 실제로 움직이는 장면 수는 다를 수 있다는 걸 배웠습니다. 같은 그림을 두 칸에 넣으면 파일은 30fps 가 되지만 움직임은 그대로였고, 설정한 숫자와도 맞지 않았습니다.
- 빈자리를 앞뒤 그림을 섞어 채우면 부드러워지는 게 아니라 잔상이 된다는 걸 배웠습니다. 또렷해야 하는 장면에서는 섞기보다 저장된 장면을 그대로 잇는 편이 나았습니다.
- 예전 프로그램과 같게 해 달라는 요청은 짐작보다 원래 코드를 읽는 쪽이 빨랐습니다. "한 장 = 한 칸, 마지막 20칸" 이라는 규칙을 찾자 길이까지 한 번에 맞았습니다.

## 소감

잔상은 이틀 전에 제가 넣은 '부드럽게' 처리가 만든 것이었습니다. 고친 것이 다음 문제를 만들 수 있다는 걸 다시 느꼈고, 이번에는 실제 영상 도구로 만들어 장면 수와 길이를 세어 본 뒤에 내보냈습니다.
