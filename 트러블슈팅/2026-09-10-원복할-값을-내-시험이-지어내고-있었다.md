# 2026-09-10 원복할 값을 내 시험이 지어내고 있었다

> 태그: #트러블슈팅 #테스트격리 #부수효과 #마스킹

## 무엇을 / 왜

"이용시간이 왜 25분이지?" 로 시작했습니다. 30분으로 바꿔 뒀는데 돌아와 있었어요.

조금 뒤에는 관리자가 넣어 둔 외부 서비스 키가 통째로 사라졌습니다. 그리고 문자 발송 대행사 쪽에는 실패 로그가 산더미로 쌓여 있었습니다.

셋 다 **제가 만든 검증 스크립트가 원인**이었습니다.

## 어떻게 풀었나

### 원복이 관측이 아니라 기억에서 나오고 있었다

설정을 바꿔 보고 끝나면 "원복" 하는 코드가 있었습니다. 그 원복이 이렇게 생겼어요.

```
1) 설정을 30분으로 바꾼다
2) 시험한다
3) 설정을 25분으로 되돌린다   ← 25는 어디서 나온 값인가?
```

**25는 제가 스크립트를 쓸 때 적어 넣은 값**이었습니다. 그때 마침 25였던 것뿐이에요. 외부 서비스 키도 같았습니다. 원래 비어 있었으니 빈 값으로 되돌리게 적어 뒀는데, 그 사이에 누군가 실제 키를 넣어 뒀습니다.

시험이 끝날 때마다 **매장이 실제로 넣어 둔 값이 제 기억으로 덮이고** 있었습니다.

시험 시작 때 **지금 값을 떠 두고** 끝나면 그 값으로 되돌리는 공용 도구를 만들었습니다. 같은 병을 앓던 네 스크립트가 그걸 같이 쓰게 했어요.

### 가려진 값은 되돌릴 수 없다

여기서 걸린 게 하나 있었습니다.

서버는 비밀값을 조회할 때 **별표로 가려서** 줍니다. 그 값을 그대로 떠 두었다가 되돌리면 **별표 여덟 개가 저장됩니다.** 원본을 덮어 버리는 건 매한가지고, 이번엔 알아채기까지 더 어려워집니다.

가려지지 않은 원본을 보려고, 뜨는 경로만 데이터베이스에서 직접 읽게 했습니다.

### 시험이 바깥 시스템으로 새어 나가고 있었다

문자 실패 로그는 다른 문제였습니다. 검증이 표를 수백 장 발권하는데, 그 번호들이 실제 사람 번호가 아니어서 발송이 전부 실패로 쌓였습니다.

**시험이 진짜 발송을 시도하고 있었던 겁니다.** 발신 계정 평판에도 좋지 않고, 진짜 문제를 찾을 때 그 더미에 묻힙니다.

**발송 제외 번호** 설정을 만들어 그 앞자리로는 아예 보내지 않게 했습니다. 대신 보내지 않을 때는 **템플릿에 채워질 값을 그대로 로그에 남기게** 했어요. 발신번호 승인이 안 끝나 진짜 발송을 못 하는 동안에도, 문구와 변수가 원고와 맞는지는 확인할 수 있어야 하니까요.

## 코드로 보기 (개념 재현)

문제가 됐던 원복입니다.

```js
// 시험 전
await api.updateSetting("ride_minutes", 30);

await runScenario();

// 시험 후 "원복"
await api.updateSetting("ride_minutes", 25);   // ★ 25는 스크립트가 지어낸 값
```

관측해서 되돌리게 바꿨습니다.

```js
/**
 * 시험이 건드릴 설정을 미리 떠 두고, 끝나면 그대로 되돌린다.
 * 핵심: 되돌릴 값은 "지금 실제로 무엇인가" 에서만 나온다.
 */
async function withSettings(keys, body) {
  // ★ API 가 아니라 저장소에서 읽는다.
  //    API 는 비밀값을 별표로 가려서 주기 때문에, 그 값을 되돌리면 별표가 저장된다.
  const snapshot = await db.readSettings(keys);

  try {
    return await body();
  } finally {
    // 시험이 실패해 던져도 되돌아가야 하므로 finally 에 둔다.
    await db.writeSettings(snapshot);
  }
}

await withSettings(["ride_minutes", "notify_api_key"], async () => {
  await api.updateSetting("ride_minutes", 30);
  await runScenario();
});
```

발송이 바깥으로 새는 것을 막은 부분입니다.

```js
// 보내지 않되, 무엇을 보내려 했는지는 남긴다.
async function sendNotification(phone, templateId, vars) {
  if (isExcluded(phone)) {
    logger.info("가상 발송", { templateId, phone: mask(phone), vars });
    return { virtual: true };
  }
  return provider.send(phone, templateId, vars);
}
```

## 💡 배운 것

**원복할 값은 기억이 아니라 관측에서 나와야 합니다.** 스크립트에 적어 둔 상수는 "그 코드를 쓰던 시점의 값" 입니다. 시간이 지나면 사실이 아니게 되는데, 그 사실이 바뀐 걸 아무도 알려 주지 않습니다.

**가려서 주는 값은 되돌리기에 쓸 수 없습니다.** 마스킹은 보여 줄 때의 안전장치인데, 그 값을 받아 다시 쓰면 원본을 별표로 덮습니다. 읽기 경로가 쓰기 경로에 쓸 수 있는 값인지 확인해야 했습니다.

**같은 병이 여러 곳에 있으면 한 곳씩 고치지 않습니다.** 네 스크립트를 각각 고쳤으면 다섯 번째가 또 같은 실수를 합니다. 공용 도구로 묶으니 새 스크립트도 그걸 쓰게 됩니다.

**시험은 바깥 시스템으로 새어 나가면 안 됩니다.** 발송·과금·외부 API 처럼 진짜로 무언가가 일어나는 곳은 시험 대상에서 빼되, 무엇을 보내려 했는지는 남겨야 확인할 수 있습니다.

## 소감

버그를 찾으려고 만든 도구가 **버그를 만들고 있었다**는 게 당황스러웠습니다. 게다가 증상이 셋으로 흩어져 나타나서, 처음엔 서로 관계없는 문제인 줄 알았어요.

되짚어 보니 세 가지가 다 "시험이 제 흔적을 안 지운다" 하나였습니다. 검증 코드도 운영 코드와 같은 기준으로 봐야 한다는 걸 알았습니다.
