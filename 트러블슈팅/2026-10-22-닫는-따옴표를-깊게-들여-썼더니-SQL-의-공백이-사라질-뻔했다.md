# 2026-10-22 닫는 따옴표를 깊게 들여 썼더니, SQL 의 공백이 사라질 뻔했다

> 태그: #트러블슈팅 #Java #텍스트블록 #컴파일러경고 #SQL

## 무엇을 / 왜

반품 신청을 거절할 수 있게 만들면서, "이 신청이 그 상품에 아직 유효한가"를 따지는 SQL 조건을 여러 쿼리에서 똑같이 써야 했어요. 쿼리마다 같은 줄을 복사하면 언젠가 한 곳만 바뀔 테니, 조건을 문자열로 돌려주는 함수 하나를 만들고 쿼리 중간에 이어 붙였습니다.

쿼리는 자바 텍스트 블록(`"""` 로 감싼 여러 줄 문자열)으로 쓰고 있어서, 이런 모양이 됐어요.

```java
        where r.store_id = :store
          and """ + notRejectedAfter("r", "i.id") + """
        order by r.created_at desc
```

그런데 빌드가 실패했습니다. 이 프로젝트는 컴파일러 경고를 모두 오류로 다뤄요(`-Xlint:all -Werror`). 나온 경고는 이거였어요.

```text
warning: [text-blocks] trailing white space will be removed
error: warnings found and -Werror specified
```

## 어떻게 풀었나

### 1. 닫는 따옴표 앞도 "줄 끝"이다

텍스트 블록은 두 가지 공백을 지웁니다. 줄마다 공통으로 들여 쓴 만큼(우연한 들여쓰기)과 **줄 끝 공백**이에요. 닫는 따옴표가 내용과 같은 줄에 있으면 그 줄의 끝은 따옴표 바로 앞이라, `and ` 의 공백이 지워집니다.

경고만 내는 빌드였다면 문자열은 `... and` 로 끝나고, 거기에 `not exists (...)` 가 바로 붙어 `andnot exists (...)` 가 됐을 거예요. 컴파일은 되고, 그 쿼리를 실제로 실행할 때에야 SQL 문법 오류가 납니다.

### 2. 따로 줄에 두었더니 같은 경고가 또

닫는 따옴표를 다음 줄로 내리면 `and` 뒤에 줄바꿈이 들어가니 SQL 로는 문제가 없어요. 그래서 이렇게 바꿨는데 같은 경고가 다시 났습니다.

```java
        where r.store_id = :store
          and
          """ + notRejectedAfter("r", "i.id") + """
```

이번엔 닫는 따옴표 줄의 들여쓰기가 문제였어요. 컴파일러는 닫는 따옴표 줄도 들여쓰기 계산에 넣는데, 그 줄(10칸)이 본문의 가장 얕은 줄(8칸)보다 깊으면, 공통 들여쓰기를 빼고 남는 2칸이 "마지막 줄의 끝 공백"이 됩니다. 이번에 지워지는 건 줄바꿈 뒤의 공백 두 칸이라 SQL 에는 해가 없었지만, 경고는 똑같이 납니다.

### 3. 닫는 줄을 본문 들여쓰기에 맞춘다

닫는 따옴표 줄을 본문의 가장 얕은 들여쓰기 이하로 두니 경고가 사라졌어요. 같은 모양으로 이어 붙인 다섯 군데를 모두 이렇게 맞췄습니다.

## 코드로 보기 (개념 재현)

```java
// 여러 쿼리가 같은 기준을 쓰도록 조건을 한 곳에서 만든다.
// 끝이 ')' 라서 바로 뒤에 'order by' 가 붙어도 SQL 로는 괜찮다.
static String notRejectedAfter(String request, String itemId) {
    return "not exists (select 1 from item_events e"
        + " where e.item_id = " + itemId
        + " and e.state = 'REJECTED' and e.created_at >= " + request + ".created_at)";
}

// (1) 경고: "and " 의 끝 공백이 지워져, 경고만 내는 빌드라면 "andnot exists" 가 된다
String broken = """
        select r.id from return_requests r
        join request_items i on i.request_id = r.id
        where r.store_id = :store
          and """ + notRejectedAfter("r", "i.id") + """
        order by r.created_at desc
        """;

// (2) 경고: 닫는 줄(10칸)이 본문(8칸)보다 깊어, 남는 2칸이 끝 공백으로 지워진다
String stillWarned = """
        select r.id from return_requests r
        join request_items i on i.request_id = r.id
        where r.store_id = :store
          and
          """ + notRejectedAfter("r", "i.id") + """
        order by r.created_at desc
        """;

// (3) 깨끗함: 닫는 줄을 본문 들여쓰기(8칸)에 맞춘다
String ok = """
        select r.id from return_requests r
        join request_items i on i.request_id = r.id
        where r.store_id = :store
          and
        """ + notRejectedAfter("r", "i.id") + """
        order by r.created_at desc
        """;

// 경고만 내는 빌드에서 확인해 보면
assert broken.contains("andnot exists");   // 공백이 사라졌다
assert ok.contains("and\nnot exists");      // 줄바꿈이 공백 노릇을 한다
```

공백이 꼭 필요한 자리라면 `\s`(지워지지 않는 공백 한 칸) 이스케이프를 쓰는 방법도 있어요. 이번엔 줄바꿈으로 끊는 쪽이 읽기 쉬워서 그렇게 했습니다.

## 💡 배운 것

**텍스트 블록은 줄 끝 공백을 지우고, 닫는 따옴표 바로 앞도 줄 끝입니다.** 문자열을 이어 붙이는 자리의 공백에 기대면 안 돼요. 이어 붙일 자리는 줄바꿈으로 끊거나, 꼭 공백이 필요하면 지워지지 않는 표기를 씁니다.

**닫는 따옴표 줄의 들여쓰기도 계산에 들어갑니다.** 본문보다 깊으면 남는 만큼이 끝 공백이 돼요. 이번엔 해가 없었지만, 경고가 났다는 건 무언가가 지워진다는 뜻이라 그냥 넘기지 않았습니다.

**경고를 오류로 다루는 설정이, 실행해야 드러날 실수를 빌드에서 잡았습니다.** 이 쿼리들은 반품 목록·할 일 숫자·반품비 계산에 쓰여서, 놓쳤다면 그 화면을 열 때마다 오류가 났을 거예요.

## 소감

처음엔 "경고 하나 때문에 빌드가 막히다니" 싶었는데, 경고 문장을 그대로 읽어 보니 정확히 제 실수를 가리키고 있었어요. 두 번째 경고에서 "따로 줄에 뒀는데 왜?" 하고 한 번 더 헤맸는데, 닫는 줄도 들여쓰기 계산에 들어간다는 걸 알고 나니 규칙이 깔끔하게 이해됐습니다.
