# 2026-10-28 100% 할인 코드를 넣으면, 0원 청구서가 결제를 깨뜨렸다

> 태그: #트러블슈팅 #결제 #정기결제 #할인코드 #경계값

## 무엇을 / 왜

구독형 서비스에서 1개월·3개월·6개월 동안 요금제를 무료로 쓰게 하는 코드를 만들려고 했습니다. 할인 코드는 이미 있었고 정률 할인과 적용 횟수도 정할 수 있었기 때문에, 할인을 100%로 하고 횟수를 1·3·6으로 두면 될 거라고 생각했습니다.

그런데 100% 코드를 넣으니 청구서는 0원으로 잘 만들어졌는데, 그 뒤 결제 단계에서 오류가 났습니다. 청구서는 결제를 기다리는 채로 멈췄고 구독도 시작되지 않았습니다.

## 어떻게 풀었나

### 0원을 받지 않는 곳이 두 군데 있었습니다

결제 흐름을 따라가 보니, 청구서를 만들면 금액과 상관없이 결제 기록을 하나 만들고 결제사에 결제를 요청하고 있었습니다. 그런데 결제 기록에는 "금액은 0보다 커야 한다"는 규칙이 코드와 데이터베이스 양쪽에 걸려 있었습니다. 실수로 0원이나 음수 결제가 생기지 않게 하려고 넣어 둔 규칙이었는데, 할인으로 0원 청구서가 생길 수 있다는 건 생각하지 못했던 것이었습니다. 결제사도 0원 결제는 받지 않았습니다.

청구서는 0원을 허용하고 결제 기록은 0원을 허용하지 않았으니, 그 사이에서 흐름이 깨진 것이었습니다.

### 0원 청구서는 결제사로 보내지 않고 결제 완료로 닫았습니다

0원 결제 기록을 허용하는 방법도 생각해 봤지만, 그러면 "결제 기록이 있으면 실제로 돈이 움직였다"는 뜻이 흐려질 것 같았습니다. 그래서 규칙은 그대로 두고, 구독 청구서가 할인으로 0원이 되면 결제사로 보내지 않고 청구서를 바로 결제 완료로 닫게 했습니다. 이용 기간은 결제에 성공했을 때와 똑같이 늘렸습니다.

등록한 카드는 그대로 두었습니다. 할인이 끝난 다음 주기에는 청구서가 다시 정가로 만들어지고, 그때는 평소처럼 카드로 결제되게 했습니다.

### 결제 기록이 없는 결제 완료를 다른 곳도 알아봐야 했습니다

결제 기록 없이 결제 완료가 생기자, "결제 기록이 있어야 결제된 것"으로 보던 곳들이 걸렸습니다.

- 지금 결제하기 화면은 결제 기록이 없으면 실패로 보여 주고 있었습니다. 청구서가 결제 완료면 성공으로 보이게 했습니다.
- 바로 해지할 때 돌려줄 돈을 계산하는 곳은 결제 기록이 없으면 "결제를 확인할 수 없다"며 해지를 막고 있었습니다. 0원이던 기간은 돌려줄 돈이 없으니 건너뛰게 했습니다.

## 코드로 보기 (개념 재현)

```java
// 청구서를 결제하는 곳 (개념 재현 - 실제 이름과 다름)
public Payment payInvoice(Invoice invoice) {
    // 할인으로 0원이 된 구독 청구서는 결제사로 보내지 않는다.
    //  - 결제사는 0원 결제를 받지 않고
    //  - 결제 기록에는 "금액 > 0" 규칙이 있다 (실수로 생긴 0원·음수 결제를 막는 규칙이라 그대로 둔다)
    if (invoice.total().signum() == 0 && invoice.isSubscription()) {
        invoices.closeAsPaid(invoice.id(), now()); // 청구서만 결제 완료로 닫는다
        subscriptions.extendPeriod(invoice);       // 결제에 성공했을 때와 똑같이 이용 기간을 늘린다
        return null;                               // 결제 기록이 없다는 뜻 - 부르는 쪽은 이것도 성공으로 본다
    }
    Payment payment = payments.create(invoice);    // 여기부터는 평소 결제 (금액 > 0)
    return gateway.charge(payment, invoice.card()); // 카드는 그대로라, 할인이 끝난 주기부터 정가로 결제된다
}

// "결제됐는가"를 결제 기록만 보고 판단하면 0원 기간이 실패로 보인다.
boolean paid = payment != null
    ? payment.succeeded()
    : invoice.isPaid();                            // 결제 기록이 없으면 청구서 상태를 본다
```

## 💡 배운 것

**실수를 막으려고 넣은 규칙이, 나중에 생긴 정상적인 경우를 막을 수 있다는 걸 알게 됐습니다.** "금액은 0보다 크다"는 규칙은 맞는 규칙이었지만, 100% 할인이라는 정상적인 경우를 처음부터 생각하지 않고 만든 규칙이었습니다.

**규칙을 풀기보다, 0원일 때는 그 규칙이 걸린 곳을 지나가지 않는 길을 따로 두는 쪽이 뜻을 덜 흐렸습니다.** 결제 기록은 계속 "실제로 돈이 움직인 기록"으로 남았습니다.

**"결제됐는가"를 한 곳만 보고 판단하던 곳들은 모두 다시 봐야 했습니다.** 결제 없는 결제 완료가 생기자, 결제 기록만 보던 화면과 계산이 차례로 걸렸습니다.

## 소감

100%라는 숫자 하나만 바꾸면 될 줄 알았는데, 0이라는 값이 결제 기록 규칙, 결제사, 해지 계산까지 건드렸습니다. 끝에 있는 값을 넣어 보는 시험을 처음부터 했다면 더 일찍 알았을 것 같습니다.
