# 2026-10-14 테스트 도중에, 자바가 사라졌다

> 태그: #트러블슈팅 #Java #Gradle #Windows #환경변수

## 무엇을 / 왜

푸시하기 전에 백엔드 전체 테스트(약 30분)를 돌리고 있었습니다. 바로 전까지 관련 테스트는 모두 통과하던 코드였는데, **749개째에서 284개가 실패**하고 멈췄어요.

실패 메시지는 거의 같았습니다.

```
Error creating bean with name 'flywayInitializer' ...
Caused by: java.lang.SecurityException: Can't read cryptographic policy directory: unlimited
```

테스트용 스프링이 DB 마이그레이션 단계에서 뜨지 못하고 있었고, 그 뒤 테스트 클래스들은 `initializationError` 로 줄줄이 실패했습니다.

## 어떻게 풀었나

1. **코드보다 환경을 먼저 의심했습니다.** 바꾼 코드와 상관없는 테스트까지 같은 이유로 실패했고, 메시지는 "자바의 암호화 정책 폴더를 못 읽는다"였으니까요.
2. **테스트가 쓰던 자바를 확인했습니다.** 시스템 `JAVA_HOME` 이 IDE(Android Studio)에 딸려 온 자바를 가리키고 있었는데, 그 폴더에 `conf/security/policy` 가 없고 `bin`·`lib` 일부만 남아 있었어요. 테스트가 도는 사이에 그 IDE를 지운 거였습니다. 실행 중인 JVM 이 열고 있던 파일은 남고, 필요할 때 읽는 설정 파일(암호화 정책)은 지워진 것으로 보였어요.
3. **따로 설치된 JDK 로 다시 돌렸습니다.** 시스템 설정은 건드리지 않고, 그 명령에만 `JAVA_HOME` 을 지정했어요. 1,861개가 실패 없이 통과했습니다.
4. **시스템 설정을 고쳤습니다.** 처음에는 Path 에도 IDE 경로가 들어 있는 줄 알았는데, 실제 Path 에는 `%JAVA_HOME%\bin` 이 들어 있었어요. 값을 읽은 방법이 변수를 풀어서 돌려주는 방식이라 IDE 경로로 보였던 겁니다. 레지스트리의 원래 값을 읽어 확인하니 `JAVA_HOME` 하나만 바꾸면 됐어요.

## 코드로 보기 (개념 재현)

```bash
# 시스템 설정은 그대로 두고, 이 명령에만 다른 JDK 를 쓴다
JAVA_HOME="C:\\Program Files\\Java\\jdk-21" ./gradlew test --no-daemon
```

```powershell
# 1) 이렇게 읽으면 %JAVA_HOME% 이 풀린 값이 나온다
#    (Path 안에 "지금 JAVA_HOME 이 가리키는 경로"가 그대로 보인다)
[Environment]::GetEnvironmentVariable("Path", "Machine")

# 2) 레지스트리에 저장된 원래 값은, 풀지 말라고 따로 알려 줘야 보인다
$key = Get-Item 'HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Environment'
$key.GetValue('Path', $null, 'DoNotExpandEnvironmentNames') -split ';' |
  Where-Object { $_ -match '%' }
# → %JAVA_HOME%\bin, %SystemRoot%\system32 ...

# 3) 그래서 바꿀 것은 JAVA_HOME 하나뿐이다 (관리자 권한)
[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Java\jdk-21", "Machine")
# 열려 있던 터미널·편집기는 다시 열어야 새 값을 읽는다
```

## 💡 배운 것

**같은 이유로 수백 개가 한꺼번에 실패하면, 코드보다 환경을 먼저 봅니다.** 이번에는 메시지가 바로 "자바 폴더"를 가리키고 있었어요.

**이미 떠 있는 프로그램도 안전하지 않습니다.** 열려 있던 파일은 남았지만, 나중에 읽는 설정 파일은 사라져 있었어요. 실행 중에 런타임을 지우면 언제 깨질지 알 수 없습니다.

**환경 변수는 저장된 값과 보이는 값이 다를 수 있습니다.** `%JAVA_HOME%` 처럼 다른 변수를 쓰는 값은, 읽는 방법에 따라 풀린 경로로 보여요. 무엇을 바꿀지 정하기 전에 원래 값을 확인해야 했습니다.

**IDE 에 딸린 JDK 를 시스템 기본으로 두면, IDE 를 지울 때 함께 사라집니다.** 따로 설치한 JDK 를 기본으로 두는 편이 안전해요.

## 소감

코드를 한 줄도 바꾸지 않았는데 테스트가 수백 개 깨진 건 처음이었습니다. 실패를 보면 코드부터 의심하던 습관 대신, 메시지가 가리키는 곳부터 확인하는 게 빠르다는 걸 배웠어요.
