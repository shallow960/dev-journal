# 2026-11-16 저장해 둔 손님 사진을, 그림 동기화가 30분 안에 지우게 되어 있었다

> 태그: #트러블슈팅 #동기화 #파일삭제 #키오스크 #Electron

## 무엇을 / 왜

사진 키오스크는 화면에 쓰는 그림(배경, 버튼 등)을 서버에서 '리소스 묶음' 으로 받아 PC 의 사진 폴더 아래에 풀어 두었습니다. 서버에서 그림이 바뀌면 키오스크가 30분마다, 그리고 로그인할 때 서버 목록과 디스크를 맞췄습니다. 이때 "서버 목록에 없는 파일은 지운다" 는 규칙이 있었습니다. 서버에서 뺀 그림이 키오스크에 남아 계속 쓰이지 않게 하려는 규칙이었습니다.

며칠 전 고객사 요청으로 '원본 사진 저장' 과 '완성 저장' 설정을 넣었습니다. 켜면 손님이 찍은 원본 사진과 완성된 사진·영상을 PC 에도 날짜별로 남기는 기능이었고, 설정 설명에는 "자동으로 지우지 않습니다" 라고 적어 두었습니다.

## 어떻게 풀었나

다른 요청(화면 그림 폴더 이름 바꾸기)을 조사하며 폴더 구조를 따라가다가 이상한 점을 찾았습니다. 외주형 브랜드용 설치에서는 사진 저장 폴더가 리소스 묶음 폴더 **안**에 있었습니다(폴더 이름은 바꿨습니다).

```text
사진\(앱 폴더)\                  <- 리소스 묶음을 푸는 곳 (동기화가 관리)
  ├ (화면 그림 폴더들)
  ├ originals\2026-11-16\...     <- 원본 사진 저장
  └ finished\2026-11-16\...      <- 완성 사진·영상 저장
```

동기화는 이 폴더 아래를 모두 훑어서 서버 목록에 없는 파일을 지웠습니다. 손님 사진은 당연히 서버 목록에 없으니, 저장한 사진과 영상은 다음 동기화(30분 안, 로그인, 묶음 다시 받기) 때 지워지게 되어 있었습니다. 설정 설명과 정반대로 동작하는 구조였습니다. 저장 기능을 넣을 때는 저장 폴더 경로만 봤고, 그 위 폴더를 동기화가 통째로 관리한다는 것은 보지 않았습니다.

고친 내용은 세 가지였습니다.

1. 키오스크가 직접 쓰는 저장 폴더(맨 위의 두 폴더)는 지울 후보에서 처음부터 뺐습니다. 대소문자는 가리지 않게 했습니다.
2. 디스크 목록을 만들 때와 빈 폴더를 정리할 때도 그 두 폴더 안으로는 들어가지 않게 했습니다.
3. 서버 목록이 비어서 오면 "전부 지운다" 고 판단하는 곳에서도 그 두 폴더의 파일은 세지 않게 했습니다.

같은 이름의 저장 폴더를 만들어 두고 동기화를 돌리는 시험을 넣어, 고치기 전에는 사진이 지워지고 고친 뒤에는 남는 것을 재현했습니다. 코드를 읽다 찾은 문제라 매장에서 실제로 지워진 사례는 아직 확인하지 못했고, 저장 기능을 쓰는 매장이 있을 수 있어 고친 판을 서둘러 내기로 했습니다.

## 코드로 보기 (개념 재현)

이름은 바꾼 더미입니다.

```js
// 키오스크가 직접 쓰는 맨 위 폴더: 동기화가 절대 지우지 않는다
const KEEP_FOLDERS = ['originals', 'finished'];

function isProtected(relPath) {
  const top = relPath.split(/[\\/]/)[0].toLowerCase(); // 맨 위 폴더만, 대소문자 무시
  return KEEP_FOLDERS.includes(top);
}

// 서버 목록과 디스크를 비교해 받을 것·지울 것을 정한다
function planMirror(serverFiles, diskFiles) {
  const wanted = new Set(serverFiles.map((f) => f.toLowerCase()));
  const onDisk = new Set(diskFiles.map((f) => f.toLowerCase()));
  const toDownload = serverFiles.filter((f) => !onDisk.has(f.toLowerCase()));

  // 고치기 전: 서버 목록에 없으면 모두 지운다 -> 손님 사진도 지운다
  // const toDelete = diskFiles.filter((d) => !wanted.has(d.toLowerCase()));

  // 고친 뒤: 키오스크가 쓰는 폴더는 처음부터 후보에서 뺀다
  const toDelete = diskFiles.filter((d) => !isProtected(d) && !wanted.has(d.toLowerCase()));
  return { toDownload, toDelete };
}

planMirror(
  ['home/bg.png', 'pay/button.png'],
  ['home/bg.png', 'home/old.png', 'originals/2026-11-16/0001.jpg', 'finished/2026-11-16/0001.mp4'],
);
// toDownload: ['pay/button.png']
// 고치기 전 toDelete: ['home/old.png', 'originals/2026-11-16/0001.jpg', 'finished/2026-11-16/0001.mp4']
// 고친 뒤  toDelete: ['home/old.png']
```

## 💡 배운 것

- "서버 목록에 없는 파일은 지운다" 는 동기화는, 그 폴더 안의 모든 파일을 자기 것이라고 가정한다는 걸 배웠습니다. 다른 기능이 같은 폴더에 파일을 두는 순간, 그 파일도 지울 대상이 됐습니다.
- 지우는 규칙에는 "무엇을 지우나" 보다 "무엇은 절대 안 지우나" 를 먼저 적어 두는 편이 안전했습니다.
- 다른 무언가가 정리하는 곳에 지켜야 할 파일을 두면 언젠가 지워진다는 걸 [2026-10-22 글](2026-10-22-임시-폴더에-둔-작업-폴더를-디스크-정리가-골라서-지웠다.md)에 이어 다시 배웠습니다. 그때는 Windows 디스크 정리였고, 이번에는 우리 프로그램의 동기화였습니다.

## 소감

저장 기능을 넣을 때 저장 폴더만 봤고, 그 폴더를 누가 또 관리하는지는 보지 않았습니다. 설정 설명에 "자동으로 지우지 않습니다" 라고 적어 둔 것이 오히려 마음에 걸렸습니다. 앞으로 새 폴더 위치를 정할 때는 그 위의 폴더를 누가 정리하는지부터 확인하려고 합니다.
