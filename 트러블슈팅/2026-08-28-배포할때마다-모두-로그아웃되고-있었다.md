# 2026-08-28 배포할 때마다, 로그인한 사람이 전부 튕기고 있었다

> 태그: #트러블슈팅 #배포 #컨테이너 #인증

## 무엇을 / 왜

배포하고 나면 로그인해 있던 사람들이 전부 튕겨서 다시 로그인해야 하는 문제가 있었습니다. 기능을 하나 고쳐서 배포할 때마다, 아무 상관 없는 로그인 세션까지 다 끊기는 거예요.

## 어떻게 풀었나

### 토큰에 서명하는 "열쇠" 가 어디 있나 봤다

로그인 상태는 토큰으로 증명합니다. 그 토큰은 서버가 가진 열쇠로 서명되고, 요청이 올 때마다 같은 열쇠로 "이거 우리가 서명한 게 맞나" 를 확인합니다. 열쇠가 바뀌면, 예전 열쇠로 서명된 토큰은 전부 "우리가 만든 게 아님" 으로 판정돼 무효가 됩니다.

그 열쇠가 어디 저장되나 봤더니 - **컨테이너 안 임시 폴더** 였습니다.

### 임시 폴더는 배포 때마다 비워진다

배포는 컨테이너를 새로 만드는 일입니다. 컨테이너의 임시 폴더는 컨테이너와 함께 사라지고요. 그러니 배포할 때마다:

```
새 컨테이너 → 임시 폴더 비어 있음 → 열쇠 없네? → 새로 만든다
           → 예전 열쇠로 서명된 토큰 전부 무효 → 전원 로그아웃
```

열쇠를, 배포와 무관하게 살아남는 저장소(볼륨)에 두면 됩니다. 한 번 만든 열쇠가 재배포 후에도 그대로 있으면, 토큰도 계속 유효하니까요.

### 함정: 권한

볼륨을 붙였더니 이번엔 서버가 열쇠를 못 만들어서 아예 시작을 못 할 뻔했습니다. 보안상 서버는 관리자 권한 없이 도는데, 새로 붙인 볼륨은 관리자 소유라 쓰기가 막힌 거였어요.

그래서 이미지를 만드는 단계에서 그 폴더를 **미리 만들어 서버 계정 소유로** 넘겼습니다. 그러면 빈 볼륨이 처음 붙을 때 그 소유권이 따라와서, 서버가 열쇠를 쓸 수 있게 됩니다.

## 코드로 보기 (개념 재현)

```
# 전: 임시 폴더 - 배포마다 사라짐
env:
  KEY_DIR: /tmp/keys           # 컨테이너와 함께 소멸

# 후: 영구 볼륨 - 재배포 간 유지
env:
  KEY_DIR: /app/keys
volumes:
  - keys:/app/keys             # 이름 붙은 볼륨, 배포와 무관하게 남는다

# 이미지(빌드 단계): 비-root 서버가 쓸 수 있게 미리 소유권을 넘긴다
RUN mkdir -p /app/keys && chown 서버계정 /app/keys
USER 서버계정
```

## 💡 배운 것

- **컨테이너의 /tmp 는 "임시" 가 맞다.** 유지돼야 하는 건 볼륨에. 배포 = 컨테이너 재생성이라, 컨테이너 안에 둔 상태는 배포와 함께 사라진다.
- **서명 열쇠는 상태다.** 매번 새로 만들면 "모두 로그아웃" 버튼을 배포마다 누르는 셈이다.
- **비-root 컨테이너 + 볼륨 = 권한을 챙겨야 한다.** 이미지에서 미리 폴더를 만들어 소유권을 넘기면, 빈 볼륨이 그 소유권을 물려받는다.

## 소감

"배포하면 로그아웃되는 거 원래 그런가보다" 하고 넘어갈 뻔했는데, 열쇠가 임시 폴더에 있는 걸 보고서야 원인이 잡혔습니다. 첫 배포 한 번은 여전히 로그아웃되지만(새 열쇠가 볼륨에 처음 생기니까), 그다음부터는 안 끊깁니다.
