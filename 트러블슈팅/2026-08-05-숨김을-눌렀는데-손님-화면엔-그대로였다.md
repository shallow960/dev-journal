# 2026-08-05 "숨김"을 눌렀는데 손님 화면엔 그대로였다

> 태그: #트러블슈팅 #커머스 #쿼리 #데이터모델

## 오늘 한 일 (요약)
- 주인이 상품을 "숨김"(검수요청) 처리했는데도 손님몰 목록에 그대로 떠 있었다.
- 상세 페이지는 숨긴 상품을 잘 막는데 목록만 안 막혔다 - 목록 쿼리가 "판매중" 상태만 걸러내고 "노출 여부"는 안 보고 있었다.
- 목록 검색조건에 "공개 목록은 노출된 것만" 스위치를 넣고, 같은 부류(마켓 상세)까지 전수로 닫았다.

## 무엇을 / 왜 (증상)
주인이 문제가 있는 상품을 "검수요청"하면 그 상품을 손님에게 숨긴다. 그런데 실제로 눌러 보니, 손님몰 상품 목록에서 그 상품이 안 사라졌다.

DB를 확인하니 숨김 표시(`is_displayed = false`)는 제대로 찍혀 있었다. 값은 맞는데 화면엔 그대로였다.

## 어떻게 풀었나 - 상세는 막혔는데 목록은 뚫렸다
어디서 새는지부터 좁혔다.
- 상품 상세 페이지 = 숨긴 상품을 잘 막았다(없는 것처럼 404).
- 상품 목록 = 그대로 떴다.

목록 쿼리를 열어 보니, 손님에게 보일 상품을 고르는 조건이 "판매중(status = ACTIVE)"만 보고 있었다. "노출 여부(is_displayed)"는 아예 조건에 없었다.

여기서 데이터 모델의 두 축이 보였다. "판매중이냐"(상태)와 "화면에 노출하냐"(노출)는 별개의 축이다. 검수요청은 상품을 판매중인 채로 두고 노출만 끈다. 그러니 상태만 보던 목록엔 "판매중이니까 통과"로 걸러지지 않았던 것이다.

목록 검색조건에 "손님 공개 목록은 노출된 것만" 스위치를 추가했다. 중요한 건 이 스위치를 어디에 켜고 끄느냐였다.
- 손님용 목록·브랜드 스토어 = 켠다(숨긴 건 안 보여야 하니까).
- 셀러 본인 관리목록·주인 관리화면 = 끈다(숨긴 것도 관리해야 하니까).

같은 조회를 한쪽엔 켜고 한쪽엔 꺼서, 하나의 쿼리를 "공개용"과 "관리용" 두 목적에 안전하게 재사용했다.

그리고 여기서 멈추지 않고 같은 부류를 훑었다. 입점몰(마켓) 공개 상세도 추천 상품을 노출 여부 안 보고 그대로 내리고 있어서, 거기도 "노출 + 판매중 + 미삭제"만 통과하게 막았다. 홈 화면 섹션은 이미 노출 필터가 있어 안전한 것도 확인했다.

## 코드로 보기 (개념 재현)
```
// (버그) 공개 목록이 "판매중"만 본다 - 숨김을 놓친다
select * from products
where status = 'ACTIVE';           // is_displayed 는 안 봄 -> 숨긴 것도 나옴

// 상태와 노출은 다른 축
//   status       = 판매중/중지/품절 ...   (파느냐)
//   is_displayed = 노출/숨김              (보여주느냐)
// 검수요청 = status는 ACTIVE 그대로, is_displayed만 false

// (수정) 공개/관리 겸용 스위치를 검색조건에 추가
function listProducts({ publicOnly }) {
  let sql = "select * from products where status = 'ACTIVE' and deleted_at is null";
  if (publicOnly) sql += " and is_displayed = true";   // 손님 목록에서만 켠다
  return query(sql);
}

listProducts({ publicOnly: true  });  // 손님 목록/브랜드 스토어 -> 숨김 제외
listProducts({ publicOnly: false });  // 셀러/주인 관리 화면   -> 숨김 포함
```
핵심은 "판매중"과 "노출"을 다른 조건으로 나눠 본 것, 그리고 그 필터를 공개일 때만 켜서 한 쿼리를 두 용도로 안전하게 쓴 것이다.

## 💡 배운 것
- **"숨김이 안 먹는다"를 상세는 막혔는데 목록은 뚫렸다로 좁히니 원인이 바로 나왔다.** 어디는 되고 어디는 안 되는지를 가르면 범위가 확 준다.
- **상태(판매중)와 노출(숨김)은 다른 축이다.** 하나로 뭉뚱그리면 "판매중이지만 숨김" 같은 조합에서 반드시 샌다.
- **공개용과 관리용은 같은 데이터라도 필터가 다르다.** 스위치 하나로 한 쿼리를 두 목적에 재사용하되, 기본은 "덜 보여주는" 쪽(공개)이 안전하다.
- **하나를 고치면 같은 부류를 전수로 훑어라.** 목록을 고친 김에 마켓 상세도 같은 구멍이 있어 함께 닫았다.

## 소감
값(is_displayed=false)은 분명히 맞는데 화면엔 나오는 상황이 처음엔 당황스러웠다. 그런데 "상세는 막히는데 목록만 뚫린다"를 보고, DB 값이 아니라 목록 쿼리가 그 값을 안 보고 있다는 쪽으로 방향이 잡혔다. 결국 "판매중"과 "노출"을 같은 것으로 착각한 조건 하나가 원인이었다. 버그 하나를 고치면서 같은 실수가 있을 다른 화면(마켓 상세)까지 닫은 게, 오늘 제일 잘한 일 같다.
