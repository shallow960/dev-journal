# 2026-10-22 임시 폴더에 둔 작업 폴더를, 디스크 정리가 골라서 지웠다

> 태그: #트러블슈팅 #Windows #임시폴더 #개발환경 #git

## 무엇을 / 왜

여러 브랜치를 동시에 보려고 git 작업 폴더(worktree)를 Windows 임시 폴더(`%TEMP%`) 아래에 여러 개 만들어 쓰고 있었습니다. C 드라이브 여유가 4GB 남짓이라 PC 주인이 디스크 정리를 돌렸습니다.

그다음 키오스크 앱을 켜자 이런 일이 한꺼번에 생겼습니다.

- 카메라를 다루는 서비스가 "필요한 라이브러리(DLL)가 없다" 며 켜지자마자 꺼짐
- 영상 합성에 쓰는 실행 파일이 사라짐
- 다른 폴더의 의존성 폴더를 가리키게 만들어 둔 연결(junction)이 사라짐

이상한 점은 **전부 지워진 게 아니라 일부만** 지워졌다는 것이었습니다. 방금 빌드한 파일은 그대로였습니다.

## 어떻게 풀었나

지워진 파일들의 공통점을 찾았습니다. 모두 **수정 시각이 오래된 파일**이었습니다.

- 빌드 결과 폴더에 복사해 둔 DLL 은 원본의 수정 시각(몇 달 전)을 그대로 갖고 있었습니다.
- 받아 둔 실행 파일도 배포된 날짜가 수정 시각이었습니다.
- 반대로 이번 주에 빌드한 파일은 수정 시각이 새것이라 남아 있었습니다.

디스크 정리의 "임시 파일" 항목은 임시 폴더에서 한동안 쓰지 않은 파일을 지웁니다. 복사한 파일은 "방금 복사" 했어도 수정 시각이 원본과 같아서 "오래된 파일" 로 보였던 것입니다.

해결은 단순했습니다. 지워진 것을 다시 빌드하고 다시 받은 뒤, 작업 폴더를 **D 드라이브의 일반 폴더로 옮겼습니다.** 이후로 작업 폴더는 임시 폴더에 만들지 않습니다.

## 코드로 보기 (개념 재현)

```powershell
# 1) 복사한 파일은 수정 시각이 원본 그대로다 (만든 시각만 지금이 된다)
$dir = Join-Path $env:TEMP 'copytime-demo'
New-Item -ItemType Directory -Force -Path $dir | Out-Null
Set-Content "$dir\old.dll" 'x'
(Get-Item "$dir\old.dll").LastWriteTime = Get-Date '2024-10-12 09:00'   # 원본을 오래된 파일로 만든다
Copy-Item "$dir\old.dll" "$dir\copied.dll"                              # 지금 복사한다

Get-Item "$dir\old.dll", "$dir\copied.dll" |
  Select-Object Name,
    @{ n = 'LastWriteTime'; e = { $_.LastWriteTime.ToString('yyyy-MM-dd') } },
    @{ n = 'CreationTime';  e = { $_.CreationTime.ToString('yyyy-MM-dd') } }
# 실제 출력 (2026-10-23 에 실행):
# Name       LastWriteTime CreationTime
# old.dll    2024-10-12    2026-10-23
# copied.dll 2024-10-12    2026-10-23    <- 방금 복사했는데 수정 시각은 2년 전
```

```powershell
# 2) 작업 폴더에서 '오래돼 보이는' 파일이 얼마나 되는지 미리 본다 (예: 7일)
$root = 'C:\path\to\worktree'
Get-ChildItem $root -Recurse -File -ErrorAction SilentlyContinue |
  Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-7) } |
  Group-Object Extension |
  Sort-Object Count -Descending |
  Select-Object -First 5 Count, Name     # .dll .exe 가 위에 나오면 정리에 취약한 폴더다
```

## 💡 배운 것

- 임시 폴더는 언젠가 비워지는 곳이라는 걸 **다시 배웠습니다**. 2026-08-28 "배포할 때마다 모두 로그아웃되고 있었다" 에서 컨테이너의 임시 폴더로 한 번 배웠고, 이번에는 내 PC 의 임시 폴더였습니다.
- 파일을 복사하면 수정 시각은 원본 것을 그대로 가진다는 걸 배웠습니다. 그래서 "오래된 파일을 지우는" 정리 도구에는 방금 복사한 파일도 지울 대상으로 보일 수 있습니다.
- 일부만 사라지는 이상한 증상은, 사라진 것들의 공통점(이번엔 수정 시각)을 찾는 게 가장 빨랐습니다.

## 소감

처음엔 "누가 파일을 지웠지?" 하고 한참 헤맸는데, 범인은 내가 고른 폴더 위치였습니다. 편하다고 임시 폴더에 작업 공간을 만든 게 문제의 시작이었습니다.
