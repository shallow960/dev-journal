# 2026-11-19 화면 흐름을 고칠 수 있게 열자, 결제 화면을 빼고 인쇄하는 흐름도 발행할 수 있었다

> 태그: #트러블슈팅 #결제 #그래프검사 #다층방어 #웹빌더

## 무엇을 / 왜

사진 키오스크의 화면 순서는 관리 웹의 '웹빌더' 에서 그래프로 고쳐 발행할 수 있었습니다. 보통 흐름은 첫 화면 → 프레임 고르기 → 수량 → 결제 → 촬영 → 사진 고르기 → 인쇄였고, 화면을 끼우거나 빼거나 연결을 바꿀 수 있었습니다. 원래는 본사만 쓰던 기능을 하루 전에 총판·대리점·매장 점주에게도 열었습니다.

밤새 웹빌더의 다음 단계들을 이어 만들면서, 단계가 끝날 때마다 돈·보안만 보는 검토를 다른 AI 코딩 에이전트에 따로 맡겼습니다. 그 검토에서 곧 내보낼 판에도 해당하는 구멍을 잡았습니다.

## 어떻게 풀었나

나온 것은 두 가지였습니다.

1. **결제 화면이 없는 흐름:** 프레임 고르기 → 촬영 → 인쇄처럼 결제 화면을 뺀 흐름을 발행해 자기 키오스크에 걸면, 결제 없이 인쇄되고 매출·로열티·정산이 하나도 남지 않았습니다. 서버는 흐름에 결제 단계가 있는지 보지 않았고, 키오스크는 결제 기록이 없어도 인쇄했습니다.
2. **결제 뒤에 돈을 바꾸는 화면:** 결제 뒤에 수량 화면을 두면 2장 값을 내고 8장으로 바꿔 인쇄할 수 있었습니다. 결제 뒤에 결제 화면을 한 번 더 두면 카드는 두 번 결제되는데 매출은 1건만 남았습니다.

두 곳에서 막았습니다.

- **서버(발행할 때):** "시작에서 촬영·인쇄 화면으로 가는 모든 길은 결제 화면을 지나야 한다", "결제가 끝난 자리에서 수량·쿠폰·결제·프레임 고르기 화면으로 가는 길이 없어야 한다" 를 검사했습니다. 어기면 누가 발행하든 거절하고, 문제가 되는 길을 화면 이름으로 적어 보여 주게 했습니다(예: '처음' → '프레임 고르기' → '촬영'). 결제 화면을 건너뛰고 결제 완료로 가는 길, 인쇄 뒤 다시 촬영·인쇄로 가는 길도 같이 막았습니다.
- **키오스크(인쇄할 때):** 그 손님의 매출 기록이나 승인된 결제가 없으면 인쇄하지 않고 "결제가 확인되지 않아 인쇄하지 않았습니다" 를 보이게 했습니다. 결제가 끝난 주문은 장수·프레임·쿠폰 변경을 무시하고 새 결제를 사유와 함께 거절하게 했고, 같은 주문을 두 번 인쇄하지 않게 했습니다.

규칙이 생기기 전에 발행된 옛 버전은 총판·점주가 배포할 수 없게 하고, 본사에는 경고를 보이게 했습니다. 0원 상품, 100% 쿠폰, 매니저 입금처럼 카드·현금을 받지 않는 길도 모두 결제 화면을 지나며 매출을 남기고 있어서 예외를 두지 않았습니다.

마지막으로, 밤사이 만든 웹빌더 단계들을 이 수정 위로 합치다가 '여러 대상에 한 번에 배포' 하는 새 경로에는 이 검사가 빠져 있는 것을 찾아 같이 막았습니다.

## 코드로 보기 (개념 재현)

이름은 바꾼 더미입니다.

```js
// 화면 흐름: 화면 -> 다음 화면들 (결제 화면을 빼 버린 흐름)
const flow = { start: ['frame'], frame: ['shoot'], shoot: ['pick'], pick: ['print'], print: [] };
const kind = { start: 'start', frame: 'choose', shoot: 'camera', pick: 'choose', print: 'print' };

// 결제 화면을 '지나갈 수 없는 벽' 으로 보고, 벽을 넘지 않고 촬영·인쇄에 닿는 길을 찾는다
function unpaidPath(flow, kind) {
  const queue = [['start']];
  const seen = new Set(['start']);
  while (queue.length) {
    const path = queue.shift();
    const at = path[path.length - 1];
    if (kind[at] === 'camera' || kind[at] === 'print') return path; // 결제 없이 도착했다
    for (const next of flow[at] ?? []) {
      if (kind[next] === 'payment' || seen.has(next)) continue;
      seen.add(next);
      queue.push([...path, next]);
    }
  }
  return null; // 모든 길이 결제 화면을 지난다
}

unpaidPath(flow, kind);
// ['start', 'frame', 'shoot'] -> 발행 거절, 이 길을 화면 이름으로 보여 준다

// 키오스크 쪽 마지막 관문: 흐름이 어떻든 돈 기록이 없으면 인쇄하지 않는다
function mayPrint(order) {
  return Boolean(order.salesRecordNo || order.approvedPaymentId);
}
mayPrint({}); // false -> "결제가 확인되지 않아 인쇄하지 않았습니다"
```

## 💡 배운 것

- 화면 흐름을 여러 계정이 직접 고칠 수 있게 열면 "결제 다음에 촬영" 같은 돈 규칙은 더 이상 흐름 모양이 지켜 주지 않는다는 걸 배웠습니다. 발행하는 서버와 실제로 인쇄하는 기기, 두 곳에서 따로 지켜야 했습니다.
- 그래프에서 "모든 길이 결제를 지나는가" 는 결제 화면을 벽으로 두고도 촬영·인쇄에 닿는지로 보면 간단했습니다. 닿는 길이 있으면 그 길을 그대로 보여 주는 것이 고치는 사람에게 가장 쓸모 있었습니다.
- 같은 결과를 낼 수 있는 모든 경로에 같은 검사를 걸어야 한다는 걸 [2026-07-03 글](2026-07-03-정책은-모든-문에-걸어야.md)에 이어 다시 배웠습니다. 이번에도 마지막에 새로 생긴 '여러 대상 한 번 배포' 경로에 같은 검사가 빠져 있었습니다.
