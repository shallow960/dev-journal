# 2026-08-04 승인 버튼은 눌리는데, 승인해도 판매자가 안 됐다

> 태그: #트러블슈팅 #이벤트 #워크플로 #권한

## 오늘 한 일 (요약)
- 손님이 **입점을 스스로 신청 → 운영자가 승인**하면 그 회원이 판매자가 되는 흐름을 만들려 했다.
- 그런데 기존에 승인/거절 버튼은 있었는데, 눌러도 그 회원이 **판매자로 실제 전환되지 않았다.**
- 원인은 승인 코드가 "승인됨" 상태만 바꾸고 **"승인됐다"는 신호(이벤트)만 쏘고 있었는데, 그 신호를 받아 권한을 부여하는 쪽이 아무 데도 없어서**였다. 승인 시 판매자 권한을 직접 부여하도록 했다.

## 무엇을 / 왜 (증상)
운영자 화면에서 입점 신청을 "승인"으로 눌렀다. 목록에서는 상태가 "승인됨"으로 바뀐다. 그런데 그 회원으로 로그인해 판매자 센터에 가면 **여전히 권한이 없다.** 승인은 됐다는데 판매자가 아닌 문제였다 .

## 어떻게 풀었나 - 기억에 남는 구멍 하나
승인 코드를 따라가 봤다. 하는 일이 딱 두 가지였다.
1. 신청 상태를 "승인됨"으로 바꾼다.
2. **"승인됐다"는 이벤트를 발행한다.**

보통 이런 구조는 어딘가에서 그 이벤트를 **구독** 해서 후속 작업(권한 부여, 알림 발송 등)을 한다. 그래서 "그 이벤트를 받는 쪽"을 찾았는데 - **아무 데도 없었다.** 이벤트는 허공에 쏘아지고 아무도 안 받고 있었다. 즉 "승인"이라는 행위에 **실제 효과를 내는 지점**이 통째로 비어 있던 것이다.

겉보기엔 완성된 워크플로였다. 신청서도 있고, 승인 버튼도 있고, 상태도 바뀌고, 이벤트도 난다. 그런데 정작 "그래서 판매자가 된다"를 하는 코드가 없었다.

고친 건 단순했다. 승인 처리 안에서 그 회원에게 **판매자 권한을 직접 부여**하게 했다(정지·반려하면 회수). 그리고 손님이 스스로 입점을 신청하는 페이지와 접수 경로도 새로 만들어, "회원가입 → 입점 신청 → 승인 → 판매자 권한 → 판매자 센터"가 실제로 끝까지 이어지게 했다.

## 코드로 보기 (개념 재현)
```
// (기존) 승인은 상태만 바꾸고 이벤트만 쏜다 - 받는 쪽이 없다
function approve(applicationId) {
  const app = find(applicationId);
  app.status = 'APPROVED';
  save(app);
  publish(new SellerApproved(app.userId)); // 아무도 구독 안 함 => 효과 없음
}

// (개선) 승인 시 판매자 권한을 직접 부여한다
function approve(applicationId) {
  const app = find(applicationId);
  app.status = 'APPROVED';
  save(app);

  grantRole(app.userId, 'SELLER');         // 실효 지점: 실제로 판매자가 되는 곳
  publish(new SellerApproved(app.userId)); // 이벤트는 부가 알림용으로 유지
}

// 반대 방향도 짝지어 - 정지/반려면 권한 회수
function suspend(applicationId) {
  const app = find(applicationId);
  app.status = 'SUSPENDED';
  save(app);
  revokeRole(app.userId, 'SELLER');
}
```

## 💡 배운 것
- **이벤트만 쏘고 처리기가 없으면 아무 일도 안 일어난다.** 이벤트 기반 구조는 "발행"과 "구독"이 짝을 이뤄야 동작한다. 발행만 있고 구독이 없으면, 코드는 그럴듯해 보여도 실제 효과는 0이다.
- **워크플로에서 "상태가 바뀌는 지점"과 "실제 효과가 나는 지점"은 다르다.** 상태를 APPROVED로 바꾸는 것과, 그래서 권한이 생기는 것은 별개다. 겉보기 완성도에 속지 말고 "그래서 실제로 뭐가 바뀌나"를 확인해야 한다.
- **상태 전이에는 반대 방향을 짝지어라.** 승인이 권한을 주면, 정지·반려는 권한을 회수해야 한다. 한쪽만 있으면 정지해도 판매 권한이 남는 구멍이 생긴다.
- **"운영자가 계정을 찍어준다" vs "손님이 스스로 신청한다"는 모델 자체가 다른 결정이다.** 어느 쪽이냐에 따라 만들 화면과 흐름이 통째로 달라진다. 코드를 짜기 전에 이 모델부터 정해야 했다.

## 소감
승인 버튼이 멀쩡히 눌리고 상태까지 바뀌니, 처음엔 "권한 부여가 어디서 실패했나"를 한참 뒤졌다. 그런데 진실은 "실패한 게 아니라 애초에 부여하는 코드가 없었다"였다. 이벤트가 나길래 당연히 누가 받는 줄 알았는데, 받는 쪽이 비어 있던 거다. 완성돼 보이는 흐름일수록 "진짜 효과가 나는 그 한 줄"이 있는지 의심해야 한다는 걸 배웠다.
