# 2026-11-06 로그인 성공이라고 떴는데, 설치는 로그인을 기다리다 멈췄다

> 태그: #트러블슈팅 #상태표시 #설치 #재시도 #키오스크

## 무엇을 / 왜

새 키오스크 PC 에는 관리 프로그램(에이전트)을 먼저 깔았습니다. 에이전트가 키오스크 계정으로 로그인하면, 그 인증으로 메인 촬영 앱을 내려받아 설치하는 구조였습니다.

2026-11-06 에 새 PC 에서 메인 앱이 설치되지 않는다는 연락이 왔습니다. 받은 화면에는 위쪽에 "로그인 성공" 이 떠 있었고, 아래쪽에는 "메인 프로그램 미설치" 와 함께 "로그인을 10분 기다리다 시간이 지났다" 는 오류가 같이 떠 있었습니다. 로그인을 했다는 말과 로그인을 기다렸다는 말이 한 화면에 함께 있었습니다.

## 어떻게 풀었나

코드를 따라가 보니 "로그인했는가" 를 판단하는 곳이 두 군데였고, 기준이 서로 달랐습니다.

- 화면은 인증 파일이 **있기만 하면** "로그인 성공" 으로 보였습니다.
- 설치는 인증 파일을 **열어서 내용을 읽을 수 있어야** 진행했습니다.

그래서 예전 버전이 남긴 형식의 파일이나 쓰다 만 파일이 있으면, 화면은 로그인됐다고 하고 설치는 인증을 계속 기다리다 시간 초과로 멈췄습니다. 손상된 인증 파일로 이 상태를 실제로 재현할 수 있었습니다.

시간 초과 뒤에도 빠져나갈 길이 없었습니다.

- 그 뒤에 다시 로그인해도, 접힌 첫 설치는 다시 시작되지 않았습니다. 로그인은 화면만 바꿨습니다.
- 화면의 "재시도" 버튼은 첫 설치가 아니라 "업데이트 확인" 을 부르고 있었습니다. 설치된 메인 앱이 아직 없으니 확인할 업데이트도 없었습니다.

한 번 시간 초과가 나면, 현장에서 누를 수 있는 버튼으로는 설치를 다시 시작할 수 없는 상태였습니다. 이렇게 고쳤습니다.

- 화면도 설치와 **같은 함수**로 로그인 여부를 판단하게 했습니다. 파일을 읽을 수 없으면 화면도 "로그인 필요" 로 보이게 됐습니다.
- 시간 초과로 접힌 첫 설치는, 다시 로그인하면 이어서 시작하게 했습니다.
- "재시도" 는 메인 앱이 아직 없으면 첫 설치를 다시 시작하게 했습니다.
- 같은 화면의 "다른 키오스크 프로그램 실행 중" 안내는 장치 통신 포트를 다른 프로그램이 잡고 있을 때도 같은 문구로 떠서, 그 경우를 따로 알리게 나눴습니다.

## 코드로 보기 (개념 재현)

판단 기준이 둘이던 상태와, 시간 초과 뒤 다시 로그인했을 때를 작게 흉내 냈습니다. 실제 대기 시간은 10분이었지만 여기서는 0.2초로 줄였습니다.

```js
// login-state-demo.js - node login-state-demo.js <데모 폴더>
const fs = require('fs');
const path = require('path');
const { EventEmitter } = require('events');

const authFile = path.join(process.argv[2], 'auth.json');

// 고치기 전: 화면과 설치가 서로 다른 기준으로 "로그인" 을 판단했다
const screenSaysLoggedIn = () => fs.existsSync(authFile);      // 파일이 있기만 하면 로그인
function readAuth() {                                           // 설치는 내용을 읽어 토큰이 있어야 진행
  try {
    const a = JSON.parse(fs.readFileSync(authFile, 'utf8'));
    return a.token ? a : null;
  } catch {
    return null;
  }
}

function show(label) {
  console.log(`${label} | 화면(전): ${screenSaysLoggedIn() ? '로그인 성공' : '로그인 필요'}`
    + ` | 설치: ${readAuth() ? '진행' : '인증 대기'}`
    + ` | 화면(후): ${readAuth() ? '로그인 성공' : '로그인 필요'}`);   // 고친 뒤: 같은 함수로 판단
}

// 1) 예전 형식(토큰 칸 없음)과 쓰다 만 파일
fs.writeFileSync(authFile, JSON.stringify({ kiosk: 'kiosk-01', savedBy: 'old-version' }));
show('예전 형식 파일');
fs.writeFileSync(authFile, '{"token": "abc');
show('쓰다 만 파일  ');

// 2) 인증을 기다리다 시간이 지나면 첫 설치를 접는다 (실제 10분, 여기서는 0.2초)
function waitForAuth(timeoutMs) {
  return new Promise((resolve, reject) => {
    const start = Date.now();
    const timer = setInterval(() => {
      if (readAuth()) { clearInterval(timer); resolve(); }
      else if (Date.now() - start > timeoutMs) { clearInterval(timer); reject(new Error('login wait timeout')); }
    }, 20);
  });
}

function makeAgent(fixed) {
  const ev = new EventEmitter();
  const st = { installed: false, waitingFirstInstall: false, log: [] };
  async function firstInstall() {
    st.waitingFirstInstall = true;
    try {
      await waitForAuth(200);
      st.installed = true;
      st.waitingFirstInstall = false;
      st.log.push('첫 설치 완료');
    } catch (e) {
      st.log.push('첫 설치 멈춤: ' + e.message);   // 고치기 전에는 여기서 끝
    }
  }
  const checkUpdate = () => st.log.push(st.installed ? '업데이트 확인' : '업데이트 확인: 설치된 메인 없음');
  ev.on('login', () => {
    st.log.push('다시 로그인');
    if (fixed && st.waitingFirstInstall) firstInstall();   // 고친 뒤: 기다리던 첫 설치를 이어 감
  });
  ev.on('retry', () => (fixed ? firstInstall() : checkUpdate()));   // 고치기 전: 재시도가 업데이트 확인을 불렀다
  return { ev, st, firstInstall };
}

const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
(async () => {
  for (const fixed of [false, true]) {
    fs.writeFileSync(authFile, '{"token": "abc');          // 읽을 수 없는 인증 파일로 시작
    const agent = makeAgent(fixed);
    await agent.firstInstall();                              // 0.2초 뒤 시간 초과
    fs.writeFileSync(authFile, JSON.stringify({ token: 'new-token' }));   // 다시 로그인해 새 파일이 생김
    agent.ev.emit('login');
    await sleep(100);
    if (!agent.st.installed) { agent.ev.emit('retry'); await sleep(100); }
    console.log(`${fixed ? '고친 뒤' : '고치기 전'}: ${agent.st.log.join(' -> ')} | 설치됨=${agent.st.installed}`);
  }
})();
```

돌린 결과입니다.

```text
예전 형식 파일 | 화면(전): 로그인 성공 | 설치: 인증 대기 | 화면(후): 로그인 필요
쓰다 만 파일   | 화면(전): 로그인 성공 | 설치: 인증 대기 | 화면(후): 로그인 필요
고치기 전: 첫 설치 멈춤: login wait timeout -> 다시 로그인 -> 업데이트 확인: 설치된 메인 없음 | 설치됨=false
고친 뒤: 첫 설치 멈춤: login wait timeout -> 다시 로그인 -> 첫 설치 완료 | 설치됨=true
```

고치기 전에는 다시 로그인하고 재시도까지 눌러도 설치되지 않았고, 고친 뒤에는 다시 로그인하자 기다리던 첫 설치가 이어서 끝났습니다.

## 💡 배운 것

- 같은 질문("로그인했나?")에 답하는 곳이 두 군데면 언젠가 서로 다른 답을 한다는 걸 다시 배웠습니다([2026-10-20, 화면의 결제 금액을 청구서와 같은 계산에서 가져오게 했다](../개선/2026-10-20-화면의-결제-금액을-청구서와-같은-계산에서-가져오게-했다.md)). 그때는 화면의 결제 금액이었고, 이번에는 로그인 상태였습니다. 화면에 보이는 상태는 실제 동작이 쓰는 판단을 그대로 빌려 와야 했습니다.
- 시간 초과로 멈추는 코드를 넣을 때는, 멈춘 뒤 무엇이 그 일을 다시 시작시키는지까지 같이 만들어야 한다는 걸 배웠습니다. 다시 시작할 길이 없으면 시간 초과는 "실패 한 번" 이 아니라 "계속 멈춤" 이 됐습니다.
- 버튼 이름("재시도")과 그 버튼이 실제로 부르는 일(업데이트 확인)이 다를 수 있었습니다. 버튼은 상태마다 무엇을 부르는지 따라가 봐야 했습니다.

## 소감

"로그인 성공" 과 "로그인 대기 시간 초과" 가 한 화면에 같이 떠 있는 걸 처음 봤을 때는 둘 중 하나가 틀렸다고 생각했습니다. 따라가 보니 둘 다 자기 기준으로는 맞는 말이었고, 기준이 둘이었다는 게 문제였습니다.
