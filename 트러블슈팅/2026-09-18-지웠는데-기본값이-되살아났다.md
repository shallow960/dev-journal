# 2026-09-18 지웠는데, 기본값이 되살아났다

> 태그: #트러블슈팅 #프레임워크 #배포 #모바일

## 무엇을 / 왜

관리 화면 위주로 만든 서비스라 소개 페이지도 PC 기준으로 짜여 있었습니다. 폰으로 열면 레이아웃이 깨져서, **PC 화면을 그대로 그리고 화면 폭에 맞게 줄여 보여 주기로** 했습니다.

브라우저에 그렇게 시키는 방법이 화면 크기 설정(viewport)입니다.

```html
<meta name="viewport" content="width=1200">
```

폭만 주면 브라우저가 1200 을 화면에 맞춰 줄여서 **전체를 보여 줍니다.** 그런데 여기에 배율까지 같이 주면 얘기가 달라집니다.

```html
<meta name="viewport" content="width=1200, initial-scale=1">
```

배율 1 은 "1:1 로 보여라" 라서, 390px 폰이면 1200 중 **왼쪽 390px 만** 보이고 나머지는 옆으로 밀어야 합니다. 처음 배포한 게 이 상태였습니다.

그래서 배율만 빼고 다시 올렸습니다. **그런데 다음 날 화면이 그대로였습니다.**

## 어떻게 풀었나

### 배포 문제인지 코드 문제인지부터 가른다

"고쳤는데 그대로" 일 때 제일 먼저 할 일은 **내가 고친 코드가 정말 돌고 있는지** 확인하는 것입니다. 전에 한 번 데인 적이 있어서 이번엔 순서대로 봤습니다.

```bash
# 1. 이미지가 최신인가
docker images --format '{{.Repository}}:{{.Tag}}  {{.CreatedSince}}'
#    → 39분 전. 오늘 것이 맞다

# 2. 컨테이너가 그 이미지로 돌고 있나
docker inspect <컨테이너> --format '{{.Image}}'
docker images --no-trunc --format '{{.Repository}}:{{.Tag}} {{.ID}}'
#    → 해시 동일. 최신 이미지로 돌고 있다

# 3. 웹서버를 건너뛰고 컨테이너에 직접 물어본다
docker compose exec 프론트 node -e "fetch('http://localhost:3000/').then(r=>r.text()).then(t=>console.log(t.match(/<meta name=\"viewport\"[^>]*>/)[0]))"
#    → initial-scale=1 이 그대로 있다
```

3번이 결정적이었습니다. **배포는 정상이고, 빌드된 결과물 자체에 그 값이 들어 있었습니다.** 즉 코드가 원인입니다.

### 프레임워크 소스를 열어 봤다

코드에는 배율을 적지 않았는데 결과물에는 있었습니다. 프레임워크가 넣은 것이라고 보고 설치된 소스를 뒤졌습니다.

```js
// 프레임워크의 기본 화면 설정
function 기본값() {
    return {
        width: 'device-width',
        initialScale: 1,      // ★ 여기
        ...
    };
}
```

**기본값이 있고, 우리가 적은 항목만 덮어씁니다.** 그러니 배율을 "지우면" 사라지는 게 아니라 **기본값이 그 자리를 다시 채웁니다.** 제가 한 건 지운 게 아니라 아무것도 안 한 것과 같았습니다.

같은 파일에서 태그를 만드는 부분도 찾았습니다.

```js
if (viewportKey in viewport) {
    let value = viewport[viewportKey];
    if (typeof value === 'boolean') value = value ? 'yes' : 'no';
    else if (!value && viewportKey === 'initialScale') value = undefined;  // ★
    if (value) { /* 태그에 넣는다 */ }
}
```

배율이 **거짓값(0 등)이면 아예 내보내지 않습니다.** 그러니 `0` 을 주면 원하는 결과가 나옵니다.

### 고치기 전에 재현해 확인했다

프레임워크 소스를 읽은 해석이 맞는지, 같은 규칙을 그대로 돌려 봤습니다.

```js
console.log(만들기({width:1200, initialScale:1, userScalable:true}));
// → width=1200, initial-scale=1, user-scalable=yes   (지금 상태)

console.log(만들기({width:1200, initialScale:0, userScalable:true}));
// → width=1200, user-scalable=yes                     (원하는 결과)
```

## 코드로 보기 (개념 재현)

```ts
export const viewport = {
  width: 1200,
  // ★0 = "배율을 아예 내보내지 마라".
  //   그냥 빼면 프레임워크 기본값(1)이 다시 들어가 폰이 1:1 로 열리고
  //   1200 중 화면 폭만큼(왼쪽 일부)만 보인다.
  //   항목이 없어야 브라우저가 1200 을 화면에 맞춰 줄여 전체를 보여 준다.
  initialScale: 0,
  userScalable: true   // 확대·스크롤은 그대로 허용
};
```

배포 후 확인은 태그 한 줄이면 됩니다.

```bash
curl -s https://<주소>/ | grep -o '<meta name="viewport"[^>]*>'
# → <meta name="viewport" content="width=1200, user-scalable=yes"/>
```

## 💡 배운 것

**"지우는 것" 과 "덮어쓰는 것" 은 다릅니다.** 기본값이 있는 설정에서 항목을 빼면 기본값으로 돌아갈 뿐입니다. 없애려면 **없애라는 값을 명시적으로 줘야** 합니다.

**"고쳤는데 그대로" 는 배포부터 가릅니다.** 이미지 → 컨테이너 → 중간 서버를 건너뛴 직접 확인, 이 순서로 보면 코드 문제인지 배포 문제인지 몇 분 만에 갈립니다.

**문서보다 설치된 소스가 빠를 때가 있습니다.** "기본값이 있다" 는 사실도, "0 이면 안 내보낸다" 는 규칙도 소스에 한 줄로 있었습니다.

**해석은 재현해서 확인합니다.** 소스를 읽고 "이럴 것이다" 로 고쳐 올렸으면 또 한 번 틀렸을 수 있습니다. 같은 규칙을 돌려 결과를 눈으로 본 뒤 고쳤습니다.

**배율을 명시하는 것과 생략하는 것의 차이는 사용자 경험에서 큽니다.** 명시하면 잘린 화면으로 시작하고, 생략하면 전체가 보이는 화면으로 시작합니다.

## 소감

전날 "고쳤다" 고 보고했는데 안 고쳐져 있었던 게 제일 걸렸습니다. 배포까지 확인했으면 됐다고 생각했는데, **실제로 나가는 결과물을 확인하지 않았던** 거죠.

다음부터는 화면에 나가는 값을 바꿨으면 배포 후 그 값을 직접 긁어서 보려고 합니다. `curl` 한 줄이면 되는 일이었습니다.
