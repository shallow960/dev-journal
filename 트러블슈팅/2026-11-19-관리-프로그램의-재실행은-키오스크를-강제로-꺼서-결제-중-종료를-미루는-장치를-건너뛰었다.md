# 2026-11-19 관리 프로그램의 재실행은 키오스크를 강제로 꺼서, 결제 중 종료를 미루는 장치를 건너뛰었다

> 태그: #트러블슈팅 #프로세스종료 #Electron #시간제한 #키오스크

## 무엇을 / 왜

하루 전 키오스크에 '종료 미루기' 를 넣었습니다. 손님이 결제하거나 인쇄하는 중에 프로그램이 꺼지면 돈 기록이 사라질 수 있어서, 창 닫기·재시작·원격 재실행·업데이트 같은 종료 요청이 오면 그 일이 끝날 때까지 기다렸다가 끄게 한 장치였습니다.

키오스크 PC 에는 키오스크 앱과 별도로, 앱을 켜고 끄고 업데이트하는 관리 프로그램이 같이 돌았습니다. 다음 날 확인 목록을 쓰다가, 관리 웹의 키오스크 상세 화면에 있는 '관리 프로그램을 통한 제어' 의 [재실행]·[종료] 는 이 장치를 거치지 않는다는 것을 찾았습니다. 이 버튼은 관리 프로그램이 키오스크 프로세스를 바로 강제 종료(taskkill /F)하는 방식이었습니다. 밖에서 프로세스를 죽이면 앱 안의 종료 처리는 돌 기회가 없어서, 미루기 장치가 있어도 소용이 없었습니다.

## 어떻게 풀었나

**1. 강제로 끄기 전에 먼저 부탁하기.** 키오스크 앱은 한 PC 에 하나만 뜨게(단일 인스턴스) 되어 있었습니다. Electron 에서는 같은 실행 파일을 한 번 더 띄우면, 새 프로세스는 바로 끝나고 이미 떠 있는 앱이 그 실행 인자를 이벤트로 받는다는 걸 이용했습니다. 관리 프로그램이 키오스크 실행 파일을 "종료를 부탁한다" 는 인자와 요청 번호를 붙여 한 번 더 띄우면, 떠 있는 앱은 "받았다" 는 확인 파일을 쓰고 정상 종료 절차를 밟게 했습니다. 그래서 미루기 장치를 그대로 지났습니다. 8초 안에 확인 파일이 오지 않으면 이 부탁을 모르는 옛 판이라고 보고 예전처럼 강제로 끄게 했습니다.

**2. 결제·인쇄만이 아니라 손님 이용이 끝날 때까지.** 첫 고침은 결제·인쇄 중일 때만 기다렸습니다. 그런데 결제를 마치고 촬영 중인 손님이 있으면 바로 꺼져, 돈만 내고 사진을 못 받을 수 있었습니다. 이 경우는 출시 전 검토에서 잡았습니다. 원격 재실행과 같은 규칙으로 맞춰, 손님이 첫 화면으로 돌아올 때까지(최대 25분) 미루고 그동안 새 손님 시작을 막았습니다. 첫 화면에서 끌 때는 3초 동안 "잠시 후 다시 시작합니다"(종료면 "잠시 후 프로그램을 종료합니다")를 먼저 보이게 했습니다.

**3. 기다리는 동안의 상태를 위층에도 알리기.** 다음 판 확인 목록을 쓰다가 하나를 더 찾았습니다. 관리 웹 서버는 관리 프로그램에 보낸 명령의 결과가 10분 안에 오지 않으면 "PC 가 꺼져 있거나 연결이 끊겼을 수 있습니다" 라는 사유로 만료시키고, 그 뒤에 온 결과는 버렸습니다. 키오스크는 최대 25분까지 기다리니, 제대로 기다리는 명령이 엉뚱한 사유로 닫혔습니다. 관리 프로그램이 키오스크가 부탁을 받은 뒤 "손님 이용 중이라 기다리는 중" 이라는 진행 상태를 서버에 먼저 보내게 했고, 서버는 진행 상태인 명령을 10분 만료에서 빼고 마지막 진행 알림부터 따로 시간을 재게 했습니다. 시간으로 닫은 명령에 늦게라도 실제 결과가 오면 그 결과로 바꾸게 했습니다.

## 코드로 보기 (개념 재현)

이름은 바꾼 더미입니다.

```js
// 키오스크 앱 (Electron main)
const { app } = require('electron');

if (!app.requestSingleInstanceLock()) app.quit(); // 두 번째로 뜬 프로세스는 바로 끝난다

app.on('second-instance', (_event, argv) => {
  const ask = argv.find((a) => a.startsWith('--polite-exit='));
  if (!ask) return;             // 보통 실행이면 창만 앞으로 가져온다 (생략)
  writeAck(ask.split('=')[1]);  // "받았다" 는 확인 파일
  app.quit();                   // before-quit 의 미루기(손님 이용·결제·인쇄)를 그대로 지난다
});

// 관리 프로그램
async function restartKiosk(exePath, requestId) {
  spawn(exePath, [`--polite-exit=${requestId}`]);  // 같은 실행 파일을 한 번 더 띄워 부탁을 전한다
  if (!(await waitForAck(requestId, 8_000))) {
    return forceKill(exePath);                     // 부탁을 모르는 옛 판: 예전처럼 강제 종료
  }
  await sendProgress('손님 이용이 끝나기를 기다리는 중'); // 서버가 10분 만료로 닫지 않게
  await waitForExit(exePath);
}
```

## 💡 배운 것

- 프로세스를 밖에서 강제로 끝내면 앱 안의 종료 처리는 한 줄도 돌지 않는다는 걸 배웠습니다. 앱 안에 안전장치를 넣는 것만으로는, 앱 밖에서 끄는 쪽을 막지 못했습니다.
- 단일 인스턴스 앱에는 "같은 실행 파일을 인자와 함께 한 번 더 띄우는" 방법으로 말을 걸 수 있었습니다. 따로 통신 통로를 만들지 않아도 됐고, 답이 없으면 옛 판으로 보고 예전 방식으로 돌아가게 해 두니 판이 섞인 매장에서도 안전했습니다.
- 기다리는 시간을 늘리면 그 위층의 시간 제한도 같이 봐야 한다는 걸 배웠습니다. 키오스크는 25분까지 기다리는데 서버는 10분 만에 만료로 닫아서, 맞게 동작한 명령이 실패처럼 보였습니다.

## 소감

종료 미루기를 만든 다음 날, 그 장치를 비켜 가는 버튼을 우리 관리 화면에서 찾았습니다. 프로그램을 끄는 길이 몇 개인지 먼저 세어 봤다면 하루 일찍 막았을 것 같습니다. 새 안전장치를 넣을 때는 그 장치를 거치지 않는 길부터 찾아보려고 합니다.
