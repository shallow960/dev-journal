# 2026-09-08 이름이 같다고 같은 자리가 아니었다

> 태그: #트러블슈팅 #카테고리 #UI #오해를부르는화면

## 무엇을 / 왜

상품 카테고리를 붙이는 기능을 만들고 나서, 실제로 상품을 하나 등록해 봤습니다.

그런데 이런 말이 나왔습니다.

> 패션/잡화 카테고리에 상품을 넣었는데 실제 손님몰 검색화면에서는 패션의류잡화에 없고 식품에 있는거임

패션에 넣었는데 식품에서 나온다니, 저장이 잘못됐거나 필터가 잘못됐거나 둘 중 하나겠다 싶었습니다.

## 어떻게 풀었나

### 먼저 어디가 틀렸는지 좁혔다

세 군데를 의심할 수 있었습니다. 저장할 때, 거를 때, 보여 줄 때.

라이브 서버에 직접 물어봤습니다.

```
category=04    → 4개
category=04-08 → 1개
category=01    → 3개
```

거르는 건 정확했습니다. 상위 코드를 주면 그 아래가 전부 걸립니다.

화면도 열어 봤습니다. "식품 4개 상품" 이 제대로 나옵니다.

그러면 남은 건 **저장된 값 자체**입니다. 상품 목록을 받아 코드를 봤습니다.

```
테스트          04-10-005
긁적이는 예티    13-04-004
```

`13`. 패션은 `01` 인데요.

### 그 코드가 뭔지 풀어 봤더니

카테고리는 계층 구조라 코드로 이름을 되짚을 수 있었습니다.

```
13-04-004 = 음반/DVD > 아티스트 굿즈 > 의류·잡화 굿즈
```

**"의류·잡화 굿즈".**

아이돌 굿즈 티셔츠 같은 걸 파는 자리입니다. 패션의류잡화(`01`)와는 전혀 다른 가지인데, **이름이 거의 같습니다.**

### 진짜 원인은 화면이었다

카테고리를 고르는 화면이 이렇게 생겼습니다.

```
의류·잡화 굿즈
13-04-004
```

잎 이름과 코드만 보여 줍니다. 이걸 보고 패션이 아니라고 알아챌 방법이 없습니다. 코드가 `13-` 으로 시작한다는 걸 눈치채려면 카테고리 체계를 외우고 있어야 하고요.

**잘못 고른 게 아니라 잘못 고를 수밖에 없는 화면이었습니다.**

상위 경로를 함께 보여 주기로 했습니다.

```
의류·잡화 굿즈
음반/DVD > 아티스트 굿즈     ← 이걸 추가
13-04-004
```

이제 고르기 전에 어느 가지인지 보입니다.

### 경로는 서버가 만든다

코드가 `13-04-004` 면 조상은 `13`, `13-04` 입니다. 코드 자체가 계층이라 문자열로 찾을 수 있었습니다.

한 가지 조심할 게 있었습니다.

```sql
-- 위험: "01" 이 "010..." 까지 조상으로 잡힌다
where c.code like p.code || '%'

-- 안전: 경계를 "-" 로 본다
where c.code like p.code || '-%'
```

지금 코드 체계에서는 `01` 다음에 항상 `-` 가 오지만, 나중에 두 자리를 넘어가면 문제가 생깁니다. 경계를 명시해 두는 편이 낫다고 봤습니다.

### 목록에서도 알아챌 수 있어야 한다

여기까지 하고 나니 한 가지가 더 걸렸습니다. **고를 때는 경로가 보이는데 목록에서는 안 보입니다.**

이미 잘못 붙은 상품이 있는데, 목록에서 "의류·잡화 굿즈" 만 보이면 여전히 패션인 줄 압니다.

그런데 목록에 전체 경로를 다 넣으면 길어집니다. 그래서 **최상위와 잎만** 쓰기로 했습니다.

```
음반/DVD … 의류·잡화 굿즈
식품 … 다이어트 식품
```

고를 때는 자세히, 목록에서는 짧게. 셀러 상품 목록·수정 화면·관리자 목록·손님 상품 상세에 같은 표기를 넣었습니다.

### 덤으로 나온 것 두 개

**목록에 코드가 그대로 뜨고 있었습니다.** `01-01-001-001` 이 그대로요. 서버가 이름을 안 내려주고 있었는데, 관리자 목록은 조인해서 주면서 판매자가 쓰는 API 만 코드뿐이었습니다. 판매자 이름을 붙이는 방식이 이미 있어서 그대로 따라 했습니다.

**손님몰 필터가 12개로 잘려 있었습니다.** 대분류는 16개인데 `.slice(0, 12)` 가 있었어요. 잘린 게 하필 음반/DVD·취미·반려용품·상품권이라, **그 카테고리 상품은 필터로 찾을 방법이 아예 없었습니다.** 지금 문제가 된 상품이 딱 그 음반/DVD 였고요.

## 배운 것

**"사용자가 잘못 골랐다" 는 결론이 나오면 대개 화면이 잘못된 겁니다.** 처음엔 저장이나 필터를 의심했는데 둘 다 멀쩡했습니다. 남은 건 "왜 저걸 골랐지" 인데, 화면을 보니 그렇게 고를 수밖에 없었습니다. 사람을 탓하기 전에 그 사람이 본 화면을 봐야 했습니다.

**이름이 같아도 자리가 다르면 다른 것입니다.** "의류·잡화 굿즈" 와 "패션의류잡화" 는 사람 눈에 비슷해 보이지만 트리에서는 완전히 다른 가지입니다. 계층 데이터를 잎 이름만으로 보여 주면 이런 일이 반드시 생깁니다. **어디에 속하는지가 이름만큼 중요한 정보**였는데 그걸 빼고 보여 주고 있었습니다.

**한 곳을 고치면 같은 자리를 다 찾아봐야 합니다.** 고르는 화면을 고쳤더니 목록에서는 여전히 안 보였습니다. "이 정보가 필요한 자리가 또 어디지" 를 따라가니 네 군데가 나왔어요. 하나만 고치고 끝냈으면 반쪽이었습니다.

**목록이 잘려 있는 건 눈에 안 띕니다.** 12개까지만 보여 주는 코드는 화면상 아무 문제 없어 보입니다. 13번째가 있다는 걸 모르니까요. 개수를 자르는 코드를 쓸 때는 "잘리는 게 뭔지" 를 한 번은 세어 봐야겠습니다.
