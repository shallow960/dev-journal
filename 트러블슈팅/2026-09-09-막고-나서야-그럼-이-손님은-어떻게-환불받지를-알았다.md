# 2026-09-09 막고 나서야 "그럼 이 손님은 어떻게 환불받지" 를 알았다

> 태그: #트러블슈팅 #안전장치의역설 #유일경로 #안내문구

## 무엇을 / 왜

결제 취소에서 순서를 잘못 잡아 "돈은 나갔는데 장부는 그대로" 인 사고가 있었습니다. 그걸 고치면서 안전장치를 하나 더 넣었습니다.

**이미 이용을 시작했거나 끝난 건은 키오스크에서 아예 취소하지 못하게** 막았어요. 돈이 먼저 나가는 사고를 막는 게 맞다고 봤고, 화면에는 "관리 웹에서 환불해 주세요" 라고 안내했습니다.

막는 쪽이 보수적이고 안전하다고 생각했습니다.

## 어떻게 풀었나

### 그 안내가 맞는지 확인해 봤다

막아 놓고 나서, 실제 키오스크로 이용이 시작된 건을 취소해 보다가 문득 걸렸습니다.

> 관리 웹에서 환불을 누르면 진짜 환불이 되나?

당연히 된다고 생각했는데 확인은 안 해 봤다는 걸 그때 알았습니다. 서버 코드를 열었습니다.

**아니었습니다.**

관리 웹의 "환불" 은 장부에 환불됨 표시만 남길 뿐, 카드 단말과 대화하지 않았습니다. 서버 어디에도 카드사를 부르는 코드가 없었어요.

### 내가 유일한 길을 막았다

정리하면 이런 상태였습니다.

```
카드에 실제로 돈을 돌려주는 길
  └ 키오스크 [카드 취소]  ← 유일

관리 웹 [환불]
  └ 장부에 표시만 남김 (카드 안 건드림)
```

제가 그 유일한 길을 막은 겁니다. **오픈하면 이용을 마친 손님은 환불받을 방법이 없는 상태**였습니다. 제 카드로 결제한 건을 취소해 보려다 막혀서 알았습니다.

안내 문구는 "관리 웹으로 가세요" 라고 하는데, 그 관리 웹은 그 일을 못 합니다. 문구가 가리키는 곳이 실제로 그 일을 하는지 확인하지 않은 것이었습니다.

### 다시 열되, 그냥 되돌리지 않았다

막은 걸 풀었습니다. 대신 원래대로 돌려놓지 않고 세 가지를 더 했습니다.

**취소 전에 알립니다.** "카드는 취소되지만 매출에서는 자동으로 빠지지 않습니다" 를 확인창으로 띄웁니다.

**취소 후에 한 번 더 알립니다.** 사람은 확인창을 잘 안 읽습니다. 끝난 뒤에 "이제 관리 웹에서 매출 제외를 해 주세요" 를 다시 보여 줍니다.

**완료 문구에서 "실패" 를 뺐습니다.** 이게 중요했는데, 그 건은 매출 제외가 안 되는 게 **정상**입니다. 그런데 "매출 제외 실패" 라고 적으면 직원이 **카드 취소까지 안 된 줄 알고** 한 번 더 누릅니다. 두 번 취소하면 또 다른 사고가 납니다.

### 남는 위험은 적어 뒀다

직원이 "관리 웹에서 장부 맞추기" 를 잊으면 매출이 부풀어 있게 됩니다. 지금은 그걸 찾아낼 화면이 없습니다.

고치지 못한 채로 두되, 그 사실과 함께 작업일지에 남겼습니다.

## 코드로 보기 (개념 재현)

막기 전에 확인했어야 할 것은 "이 길 말고 다른 길이 있나" 였습니다.

```js
// 내가 넣은 안전장치
if (reservation.status === "IN_USE" || reservation.status === "DONE") {
  showError("이용이 시작된 건은 관리 웹에서 환불해 주세요.");
  return;   // ← 여기서 막았는데, 그 관리 웹이 카드를 못 건드린다
}
```

관리 웹의 환불이 실제로 하던 일입니다.

```js
// 장부에만 적는다. 카드 단말과 대화하지 않는다.
async function refund(reservationId, reason) {
  await db.payment.update({
    where: { reservationId },
    data: { refundedAt: new Date(), refundReason: reason }
  });
  // 카드사를 부르는 코드가 없다.
}
```

다시 열면서, 정상 동작을 실패로 적지 않게 결과를 세 갈래로 나눴습니다.

```js
const result = await cancelCard(approvalNo);

if (!result.cardCancelled) {
  // 진짜 실패: 카드가 취소되지 않았다.
  show("카드 취소에 실패했습니다. 다시 시도해 주세요.", "error");
} else if (!result.salesExcluded) {
  // 정상: 이용이 시작된 건이라 매출 제외가 자동으로 안 되는 경우.
  // ★ 여기에 "실패" 라고 적으면 카드 취소까지 안 된 줄 알고 또 누른다.
  show("카드 취소가 완료됐습니다. 매출 제외는 관리 웹에서 처리해 주세요.", "warn");
} else {
  show("취소가 완료됐습니다.", "success");
}
```

## 💡 배운 것

**"막는 것" 이 항상 안전한 선택은 아닙니다.** 위험해 보이는 경로를 막았더니 그게 유일한 경로였습니다. 막기 전에 **그 길 말고 다른 길이 있는지** 확인했어야 했습니다.

**안내 문구가 가리키는 곳이 실제로 그 일을 하는지 코드로 확인해야 합니다.** "관리 웹에서 하세요" 라고 적을 때 관리 웹이 그 일을 한다고 **가정**했습니다. 확인은 안 했고요.

**정상 동작을 "실패" 로 적으면 안 됩니다.** 문구 하나가 직원의 다음 행동을 바꿉니다. "실패" 라고 적으면 한 번 더 누르고, 그게 또 사고가 됩니다.

**못 고친 것은 못 고쳤다고 남겨야 합니다.** 매출이 부풀어 있는 걸 찾아낼 화면이 없다는 사실을 감추면, 나중에 그 숫자를 믿고 쓰게 됩니다.

## 소감

안전장치를 넣는 게 늘 옳다고 생각했는데, **막는 행위 자체가 새로운 구멍을 만들 수 있다**는 걸 처음 겪었습니다.

특히 "관리 웹에서 하세요" 라고 적으면서 관리 웹을 열어 보지 않은 게 뼈아팠습니다. 실제 기기로 취소를 눌러 보지 않았으면 한동안 몰랐을 거예요. 안내 문구도 코드처럼 검증 대상이라는 걸 배웠습니다.
