# 2026-10-20 쓰지 않는 메시지 큐를, 30초마다 두드리고 있었다

> 태그: #트러블슈팅 #상태점검 #로그 #설정값 #메시지큐

## 무엇을 / 왜

서버에는 30초마다 DB·캐시·메시지 큐 같은 구성요소가 살아 있는지 확인하는 상태 점검이 돕니다. 결과는 관리자 화면에 나오고, 실패하면 경보도 띄워요.

운영 서버 로그에서 오류 한 줄을 찾으려고 검색했더니, 결과가 **메시지 큐(Kafka) 설정 수십 줄** 로 뒤덮여 있었습니다. `sasl.*`, `ssl.*` 같은 설정 이름과 값이 30초마다 통째로 찍히고 있었어요.

운영에서는 메시지 큐를 쓰지 않습니다. 접속 주소도 비워 뒀어요. 그런데 상태 점검은 매번 **관리용 클라이언트를 새로 만들어** 연결을 시도했고,

1. 클라이언트를 만들 때마다 라이브러리가 설정 전체를 로그에 찍었고,
2. 주소가 없으니 연결은 당연히 실패해서, 점검 결과는 늘 "실패" 였고 경보도 그대로 떠 있었습니다.

## 어떻게 풀었나

**쓰지 않는 기능은 점검도 하지 않게** 했습니다.

- 점검 전에 접속 주소 설정을 먼저 봅니다. 비어 있으면 클라이언트를 만들지 않고, "설정 안 됨" 을 **정상** 으로 남겨요. 쓰지 않는 게 문제는 아니니까요.
- 비워 둔 값이 생각보다 여러 모양으로 넘어왔습니다. 설정 파일에서 빈 문자열로 두면 프레임워크가 `""` 로, `[]` 로, `[""]` 로 넘기기도 해요. 그래서 "하나라도 진짜 주소가 있나" 를 보는 작은 함수를 두고, 모양별로 시험을 붙였습니다.
- 다른 점검 화면(의존성 점검)은 이미 같은 방식으로 건너뛰고 있었어요. 문구를 똑같이 맞춰서 화면이 같은 안내를 쓰게 했습니다.

## 코드로 보기 (개념 재현)

```java
// 전: 30초마다 관리용 클라이언트를 만들어 본다(설정이 비어 있어도)
Probe probeQueue() {
    try (var admin = QueueAdmin.create(config)) {   // 만들 때마다 설정 전체가 로그에 찍힌다
        admin.describeCluster().get(2, SECONDS);
        return Probe.ok("reachable");
    } catch (Exception e) {
        return Probe.fail(e.getMessage());           // 주소가 없으니 늘 실패 -> 경보
    }
}

// 후: 접속 주소가 없으면 쓰지 않는 것으로 보고 붙지 않는다
Probe probeQueue() {
    if (!hasServers(config.get("bootstrap.servers"))) {
        return Probe.ok("bootstrap servers are not configured");
    }
    try (var admin = QueueAdmin.create(config)) {
        admin.describeCluster().get(2, SECONDS);
        return Probe.ok("reachable");
    } catch (Exception e) {
        return Probe.fail(e.getMessage());
    }
}

// 비워 두면 "", [], [""] 처럼 여러 모양으로 넘어온다. 진짜 주소가 하나라도 있나만 본다.
static boolean hasServers(Object value) {
    if (value instanceof Collection<?> list) {
        return list.stream().anyMatch(v -> v != null && !v.toString().isBlank());
    }
    return value != null
        && Arrays.stream(value.toString().split(",")).anyMatch(s -> !s.isBlank());
}
```

```java
@Test
void 비워_두면_쓰지_않는_것으로_본다() {
    assertThat(hasServers(null)).isFalse();
    assertThat(hasServers("")).isFalse();
    assertThat(hasServers(" , ")).isFalse();
    assertThat(hasServers(List.of())).isFalse();
    assertThat(hasServers(List.of(""))).isFalse();
    assertThat(hasServers("queue:9092")).isTrue();
}
```

## 💡 배운 것

**점검도 설정을 따라야 합니다.** 기능은 꺼 뒀는데 점검만 켜져 있으면, 점검이 실패와 소음을 만들어요. "쓰지 않음" 은 실패가 아니라 정상 상태 중 하나로 다뤄야 했습니다.

**로그가 읽혀야 장애도 보입니다.** 30초마다 수십 줄씩 쌓이는 줄은 그 자체로는 해가 없어 보여도, 정작 필요한 한 줄을 찾을 때 방해가 됐어요.

**"비어 있음" 은 한 가지 모양이 아닙니다.** 빈 문자열, 빈 목록, 빈 문자열 하나짜리 목록이 모두 "없음" 이에요. 이런 값은 작은 함수로 모아 두고 모양별로 시험해 두면 마음이 편합니다.

**같은 걸 확인하는 두 곳은 같은 규칙을 씁니다.** 한쪽 점검 화면은 이미 건너뛰고 있었고 다른 쪽만 빠져 있었어요. 비슷한 코드를 고칠 때는 짝이 되는 곳이 있는지 같이 찾아봐야 했습니다.

## 소감

처음에는 로그 검색에 걸리는 줄을 빼는 필터부터 만들었어요. 당장은 그걸로 찾고 싶은 줄을 찾았지만, 필터를 매번 기억해야 하는 건 근본 해결이 아니었습니다. 왜 그 줄이 생기는지 따라가 보니 "쓰지 않는 걸 계속 확인하는" 코드가 있었고, 그 한 곳을 고치니 로그와 경보가 같이 조용해졌어요. 배포는 끝났고, 실제로 그 줄이 사라졌는지는 서버 로그로 한 번 더 확인할 예정입니다.
