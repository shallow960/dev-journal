# 2026-11-17 설정 칸에는 0과 1이 보였는데, 실제로는 비어 있어서 두 화면이 한 모니터에 겹쳤다

> 태그: #트러블슈팅 #설정 #기본값 #듀얼모니터 #Electron

## 무엇을 / 왜

사진 키오스크에는 모니터 두 대를 쓰는 촬영 방식이 있었습니다. 손님이 결제하는 앞 화면(메인)과, 떨어진 촬영 부스 쪽에서 보는 화면(서브)을 각각 다른 모니터에 띄우는 방식이었습니다. 어느 모니터에 띄울지는 설정의 '메인 화면 위치'·'서브 화면 위치' 두 칸으로 정했고, 값은 0부터 세는 모니터 번호였습니다.

모니터 두 대가 달린 PC 에서 이 방식을 시험하다가, 창 두 개가 한 모니터에 겹쳐 떠서 프로그램이 두 개 켜진 것처럼 보이는 일이 있었습니다. 그런데 설정창을 열어 보니 메인 0, 서브 1 로 제대로 나뉘어 있는 것처럼 보였습니다.

## 어떻게 풀었나

로그와 설정 파일을 보니 두 칸 모두 실제로는 값이 **비어 있었습니다**. 설정창은 값이 비어 있으면 설정 표에 적힌 기본값(메인 0, 서브 1)을 숫자로 채워 보여 줬습니다. 그래서 확인하는 사람은 0·1 이 저장된 줄 알았습니다.

키오스크 쪽 동작은 달랐습니다. 번호가 비어 있거나 범위를 벗어나면 창을 '주 모니터' 로 보냈습니다. 이 PC 는 주 모니터가 1번이어서 메인과 서브가 둘 다 1번 모니터에 떴습니다. "메인과 서브가 같은 번호면 서브를 띄우지 않는다" 는 검사도 있었지만, 두 값이 모두 숫자일 때만 비교했기 때문에 빈 값끼리는 그 검사를 빠져나갔습니다.

고친 것은 두 가지였습니다.

1. 키오스크: 서브 번호가 비어 있으면 '메인이 뜬 모니터가 아닌 첫 모니터' 로 보내게 했습니다. 그렇게 골라도 메인과 같은 모니터라면 겹쳐 띄우지 않고 사유를 로그에 남기게 했습니다.
2. 설정창·관리자 화면: 비어 있는 칸은 숫자 대신 "자동 (주 모니터)", "자동 (메인 화면이 없는 모니터)" 로 보이게 했습니다. 고르는 상자에는 [자동, 0~4] 를 두었고, '자동' 을 고르면 저장된 번호를 지우게 했습니다. 칸을 건드리지 않고 저장하면 기본값 0·1 이 몰래 저장되지 않게도 했습니다.

이미 번호를 정해 둔 키오스크의 화면 위치는 바뀌지 않게 했습니다.

## 코드로 보기 (개념 재현)

이름은 바꾼 더미입니다.

```ts
type Monitor = { id: string };
type Setting = { mainNo?: number; subNo?: number }; // 비어 있으면 undefined

// 번호가 비었거나 범위 밖이면 주 모니터
function chooseScreen(no: number | undefined, monitors: Monitor[], primaryMon: Monitor): Monitor {
  return no !== undefined && no >= 0 && no < monitors.length ? monitors[no] : primaryMon;
}

// 고치기 전: 같은 번호 검사는 둘 다 숫자일 때만 돌았다
function arrangeOld(s: Setting, monitors: Monitor[], primaryMon: Monitor) {
  if (s.mainNo !== undefined && s.subNo !== undefined && s.mainNo === s.subNo) {
    return { main: chooseScreen(s.mainNo, monitors, primaryMon).id, sub: null };
  }
  return {
    main: chooseScreen(s.mainNo, monitors, primaryMon).id,
    sub: chooseScreen(s.subNo, monitors, primaryMon).id, // 둘 다 비면 둘 다 주 모니터
  };
}

// 고친 뒤: 서브가 비면 메인이 없는 모니터로, 그래도 같으면 띄우지 않는다
function arrangeNew(s: Setting, monitors: Monitor[], primaryMon: Monitor) {
  const main = chooseScreen(s.mainNo, monitors, primaryMon);
  const subNo = s.subNo ?? monitors.findIndex((m) => m.id !== main.id);
  const sub = chooseScreen(subNo, monitors, primaryMon);
  return sub.id === main.id ? { main: main.id, sub: null } : { main: main.id, sub: sub.id };
}

// 화면 표시: 빈 값을 기본값 숫자로 채우지 않는다
function showValue(value: number | undefined, autoLabel: string): string {
  return value === undefined ? autoLabel : String(value); // 고치기 전: String(value ?? 기본값)
}

const monitors = [{ id: 'A' }, { id: 'B' }]; // 0번 A, 1번 B
const primaryMon = monitors[1];             // 주 모니터가 1번(B)인 PC

arrangeOld({}, monitors, primaryMon); // { main: 'B', sub: 'B' } -> 한 모니터에 겹침
arrangeNew({}, monitors, primaryMon); // { main: 'B', sub: 'A' }
showValue(undefined, '자동 (주 모니터)'); // '자동 (주 모니터)'
```

## 💡 배운 것

- 화면에 보이는 값과 저장된 값이 다르면, 확인하는 사람은 화면을 믿는다는 걸 배웠습니다. 빈 값을 기본값 숫자로 채워 보여 준 탓에 "설정은 맞는데 동작이 이상하다" 로 보였습니다.
- 같은 빈 값을 두 곳이 다르게 읽고 있었습니다. 키오스크는 빈 값을 '주 모니터' 로 읽었고, 설정창은 '0·1' 로 보여 줬습니다.
- 모르는 값은 그럴듯한 값으로 채우지 말고 비어 있다고 보여 줘야 한다는 걸 [2026-07-20 글](../개선/2026-07-20-모르는-값은-비워두기.md)에 이어 다시 배웠습니다. 이번에는 "자동" 이라는 이름을 붙여, 비어 있다는 것과 그때 어떻게 동작하는지를 함께 보여 줬습니다.
- 두 값을 비교하는 검사는 값이 비어 있는 경우도 따져야 했습니다. 둘 다 숫자일 때만 비교하니, 가장 흔한 상태(아무것도 정하지 않음)가 검사를 빠져나갔습니다.
