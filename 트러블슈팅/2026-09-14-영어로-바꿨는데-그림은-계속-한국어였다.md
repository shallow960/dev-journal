# 2026-09-14 영어로 바꿨는데, 그림은 계속 한국어였다

> 태그: #트러블슈팅 #다국어 #리소스로딩 #WPF

## 무엇을 / 왜

디자이너가 새 화면 그림을 줘서 키오스크에 넣고 있었습니다. 그러다 제보를 받았습니다.

**영어를 고르면 글자는 영어로 바뀌는데, 상품 카드 그림은 한국어 그대로**라는 것이었습니다.

키오스크는 한국어 폴더와 영어 폴더에 같은 이름의 그림을 따로 두고, 고른 언어의 폴더에서 읽게 되어 있었습니다. 적어도 그렇게 되어 있는 줄 알았습니다.

## 어떻게 풀었나

### 그림 폴더가 언제 정해지는지를 따라갔다

"글자는 되는데 그림만 안 된다" 는 건 둘이 서로 다른 길로 바뀐다는 뜻입니다. 그림을 읽는 경로가 **언제 정해지는지**를 봤습니다.

- 프로그램이 켜질 때 그림 폴더를 **한국어 폴더로 한 번** 정합니다
- 그 뒤로 폴더를 바꾸는 곳이 **어디에도 없었습니다**
- 언어 버튼은 화면 글자만 다시 그리고 있었습니다

영어 폴더는 프로그램이 도는 내내 **한 번도 읽히지 않고** 있었습니다.

### 왜 지금까지 아무도 몰랐나

한국어 폴더와 영어 폴더에 **같은 그림인 파일이 많았습니다.** 배경이나 버튼처럼 글자가 없는 그림은 두 폴더에 똑같은 파일이 들어 있었어요.

그래서 한국어 폴더만 읽어도 화면이 멀쩡해 보였고, 이번에 상품 카드가 언어별로 달라지면서 처음 드러났습니다.

### 언어를 바꾸면 폴더도 옮기고 다시 읽는다

- 언어를 고르면 그림 폴더를 그 언어로 옮기고 그림을 다시 읽습니다
- 같은 언어를 다시 고르면 아무것도 하지 않습니다. 손님마다 도는 자리라 그림 서른 장을 괜히 다시 읽지 않게요
- 그림은 화면 스레드에서 만들어야 해서 화면 스레드로 넘겨 읽습니다

### 돌아오는 길도 같은 병이었다

결제를 마치고 첫 화면으로 돌아오면 다음 손님을 위해 한국어로 되돌립니다. 그런데 거기서는 **언어 값만 바꾸고** 있었습니다. 글자는 한국어로 돌아오는데 그림은 영어로 남았습니다.

되돌리는 곳도 언어 버튼과 **같은 함수**를 부르게 했습니다.

### 파일 하나가 없어서 멈추면 안 된다

그림 읽기는 파일 하나만 없어도 예외를 던지는 구조였습니다. 그대로 두면 손님이 언어 버튼을 누른 순간 프로그램이 멈출 수 있습니다.

손님 앞에서 멈추는 것보다 **이전 언어 그림이 잠깐 남는 편이 낫다**고 보고, 실패하면 기록만 남기고 계속 돌게 감쌌습니다.

## 코드로 보기 (개념 재현)

문제가 됐던 구조입니다.

```csharp
// 프로그램 시작
void OnStartup()
{
    Paths.Initialize();
    // ★ 그림 폴더를 여기서 한 번 정하고 끝이다.
    Paths.SetResourceFolder(Language.Ko);   // ".../Resource/ko"
    Images.LoadAll();
}

// 언어 버튼
void OnLanguageButton(Language want)
{
    CurrentLanguage = want;
    Screens.RefreshTexts();   // 글자만 다시 그린다. 그림 폴더는 그대로 ko.
}

// 결제가 끝나고 첫 화면으로 돌아올 때
void ResetSession()
{
    CurrentLanguage = Language.Ko;   // 값만 바꾼다
}
```

고친 구조입니다. 언어가 바뀌는 길은 모두 이 함수 하나를 지납니다.

```csharp
public void ChangeLanguage(Language want)
{
    // 같은 언어면 할 일이 없다. 손님마다 도는 자리라 불필요한 읽기를 막는다.
    if (CurrentLanguage == want) return;

    CurrentLanguage = want;

    try
    {
        Paths.SetResourceFolder(want);   // ".../Resource/en"

        // 그림(BitmapImage)은 화면 스레드에서 만들어야 화면에 붙일 수 있다.
        Application.Current.Dispatcher.Invoke(Images.LoadAll);
    }
    catch (Exception ex)
    {
        // 파일 하나가 없다고 손님 앞에서 멈추지 않는다.
        // 이전 언어 그림이 잠깐 남는 편이 낫다.
        Log.Warn($"언어 전환 중 그림 다시 읽기 실패({want}) : {ex.Message}");
    }
}

void OnLanguageButton(Language want)
{
    ChangeLanguage(want);
    Screens.RefreshTexts();
}

void ResetSession()
{
    // 되돌리는 곳도 같은 함수를 지난다. 값만 바꾸면 그림이 남는다.
    ChangeLanguage(Language.Ko);
}
```

그림 하나를 읽는 쪽도 없으면 그 자리만 비우게 했습니다.

```csharp
BitmapImage LoadOrNull(string fileName)
{
    try
    {
        var img = new BitmapImage();
        img.BeginInit();
        img.CacheOption = BitmapCacheOption.OnLoad;   // 파일을 잡고 있지 않게
        img.UriSource = new Uri(Path.Combine(Paths.ResourceFolder, fileName));
        img.EndInit();
        return img;
    }
    catch (Exception ex)
    {
        Log.Warn($"리소스 없음 : {fileName} ({ex.Message})");
        return null;   // 화면 하나가 비는 것과 프로그램이 멈추는 것은 다르다
    }
}
```

## 💡 배운 것

**"A 는 되는데 B 만 안 된다" 는 둘이 다른 길로 바뀐다는 뜻입니다.** 글자와 그림이 같은 언어 버튼을 지나가는 줄 알았는데, 실제로는 글자만 지나가고 있었습니다. 그림 경로가 **언제 정해지는지**를 따라가니 바로 보였습니다.

**두 쪽이 같은 값이면 버그가 가려집니다.** 한국어와 영어 폴더에 같은 파일이 많아서, 잘못된 폴더를 읽어도 화면이 맞아 보였습니다. 언어별로 확실히 다른 그림 하나를 두고 시험했으면 처음부터 드러났을 겁니다.

**상태를 바꾸는 길이 여러 개면 모두 같은 함수를 지나야 합니다.** 언어 버튼은 고쳤는데 세션을 되돌리는 곳은 값만 바꾸고 있었습니다. "들어가는 길" 을 고치면 "돌아오는 길" 도 같이 봐야 했습니다.

**손님 앞에서 도는 프로그램은 실패의 크기를 골라야 합니다.** 그림 한 장이 옛것으로 남는 것과 프로그램이 멈추는 것 중에서 앞쪽을 골랐습니다.

## 소감

새 그림을 넣는 작업이 **원래 있던 결함을 드러내는** 계기가 됐습니다. 그림이 언어별로 달라지기 전까지는 버그가 있어도 결과가 맞아 보였으니까요.

"잘 되고 있다" 는 게 코드가 맞아서인지, 우연히 같은 값이라서인지를 구분하는 게 중요하다는 걸 다시 느꼈습니다.
