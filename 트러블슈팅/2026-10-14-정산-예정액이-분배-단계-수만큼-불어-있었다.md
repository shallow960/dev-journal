# 2026-10-14 정산 예정액이, 분배 단계 수만큼 불어 있었다

> 태그: #트러블슈팅 #SQL #조인 #집계 #React

## 무엇을 / 왜

판매자 화면의 **"정산 예정액"이 실제보다 크게** 나오는 상점이 있었습니다. 공통점은 판매 금액 일부를 여러 단계로 나눠 주는 **분배 기능**을 쓰는 상점이라는 것이었어요.

정산 건 하나에는 분배 행이 단계마다 하나씩, 최대 5개까지 붙습니다. 합계 쿼리는 정산 건과 분배 행을 그대로 조인한 뒤 `SUM` 을 하고 있었어요. 조인하면 정산 건이 분배 행 수만큼 **반복**되니, 금액도 그만큼 여러 번 더해진 거였습니다.

같은 화면에는 문제가 하나 더 있었어요. 요약·명세·내역 세 가지를 한꺼번에 기다려서, 하나만 실패해도 화면 전체가 '불러오는 중'에 멈췄습니다.

## 어떻게 풀었나

- 분배 행을 **정산 건마다 먼저 묶은 뒤** 조인했습니다. 그러면 조인 결과에서 정산 건은 한 줄이에요.
- 테스트에 분배 3단계가 붙은 정산 건을 넣고, 예정액에 한 번만 들어가는지 확인했습니다. 지급이 끝난 건이 빠지는지도 같이 봤어요.
- 화면은 세 가지를 따로 받아서, 실패한 부분만 "불러오지 못했어요"와 다시 시도를 보여 주게 했습니다. 요약 카드 이름도 무엇을 세는지 드러나게 '정산 건수'에서 '정산 예정 건수'로 바꿨어요.

## 코드로 보기 (개념 재현)

```sql
-- 문제: 1:N 을 그대로 조인한 뒤 합치면, 1 쪽 금액이 N 번 더해진다
SELECT SUM(s.amount)  AS expected,   -- 분배가 3단계면 3배가 된다
       SUM(sh.amount) AS shared
FROM settlement s
LEFT JOIN settlement_share sh ON sh.settlement_id = s.id
WHERE s.seller_id = :sellerId
  AND s.status = 'PENDING';
```

```sql
-- 고침: N 쪽을 정산 건마다 먼저 묶어 한 줄로 만든 뒤 조인한다
SELECT SUM(s.amount)              AS expected,   -- 정산 건마다 한 번만 더해진다
       SUM(COALESCE(sh.total, 0)) AS shared
FROM settlement s
LEFT JOIN (
    SELECT settlement_id, SUM(amount) AS total
    FROM settlement_share
    GROUP BY settlement_id                       -- 정산 건마다 한 줄
) sh ON sh.settlement_id = s.id
WHERE s.seller_id = :sellerId
  AND s.status = 'PENDING';
```

```ts
// 예전: 하나가 실패하면 Promise.all 전체가 실패한다.
// 실패했을 때 채우는 값이 없어, 세 영역 모두 '불러오는 중'에 남았다
async function loadBefore() {
  const [summary, statements, history] = await Promise.all([
    api.summary(),
    api.statements(),
    api.history(),
  ]);
  return { summary, statements, history };
}

// 고침: 각자의 결과를 받아, 실패한 영역만 실패로 보여 준다
async function loadAfter() {
  const results = await Promise.allSettled([
    api.summary(),
    api.statements(),
    api.history(),
  ]);
  // 영역마다 { status: "ready", data } 또는 { status: "error" } (그 영역에만 다시 시도 버튼)
  const [summary, statements, history] = results.map((r) =>
    r.status === "fulfilled" ? { status: "ready", data: r.value } : { status: "error" },
  );
  return { summary, statements, history };
}
```

## 💡 배운 것

**조인은 행을 늘릴 수 있습니다.** 1:N 관계를 조인하면 1 쪽 행이 N 번 나와요. 그 상태에서 1 쪽 값을 `SUM` 하면 N 배가 됩니다. 합계를 내기 전에 "조인한 뒤 이 행이 몇 번 나오나"를 먼저 따져야 했어요.

**N 쪽은 먼저 묶어서 붙입니다.** 서브쿼리(또는 CTE)로 정산 건마다 한 줄을 만든 뒤 조인하면, 조인 결과의 행 수가 정산 건 수와 같아집니다.

**테스트 데이터가 1:1 이면 이 버그는 보이지 않습니다.** 분배가 없거나 한 단계뿐인 데이터로는 결과가 맞게 나와요. 한 건에 여러 단계가 붙은 데이터를 일부러 넣어야 드러났습니다.

**여러 요청을 한꺼번에 기다리면, 하나의 실패가 전체를 멈춥니다.** 서로 상관없는 영역은 결과도 따로 다뤄야 했어요.

## 소감

코드만 볼 때는 자연스러운 쿼리였는데, 분배를 쓰는 상점에서만 숫자가 틀어졌습니다. 테스트 데이터가 실제 모양(한 건에 여러 단계)을 닮아야 버그가 보인다는 걸 배웠어요.
