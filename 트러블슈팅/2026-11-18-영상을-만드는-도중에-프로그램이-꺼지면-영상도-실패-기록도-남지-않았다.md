# 2026-11-18 영상을 만드는 도중에 프로그램이 꺼지면, 영상도 실패 기록도 남지 않았다

> 태그: #트러블슈팅 #장애복구 #작업기록 #결제 #키오스크

## 무엇을 / 왜

사진 키오스크는 촬영이 끝나면 손님에게 QR 을 주고, 휴대폰으로 사진과 짧은 동영상을 받게 했습니다. 동영상은 촬영하면서 남긴 장면으로 키오스크가 직접 만들어(보통 30초쯤 걸림) 서버에 올렸습니다.

운영에 붙은 시험 키오스크의 QR 하나에서 동영상이 빠졌다는 연락을 받았습니다. 서버에는 '실패' 기록도 없이 동영상 칸이 비어 있었고, 찍은 PC 의 로그는 볼 수 없는 상황이었습니다.

## 어떻게 풀었나

운영 DB 를 읽기만 해서 그 키오스크의 기록을 시간 순서로 맞춰 봤습니다.

| 시각 | 일 |
|---|---|
| 21:33:50 | QR 발급 |
| 21:33:52 | 사진 업로드 끝 |
| 21:34:14 | 키오스크 프로그램 종료 |
| 21:37:34 | 다시 켜짐 |

같은 키오스크의 최근 QR 가운데 이 한 건만 동영상이 없었고, 나머지는 QR 발급 뒤 17~40초 안에 동영상이 올라왔습니다. 이 건은 사진을 올린 22초 뒤, 동영상을 만드는 도중에 프로그램이 꺼진 것이었습니다.

코드를 보니 이유가 분명했습니다. 업로드 대기열은 디스크에 있어서 일단 들어간 뒤에는 꺼져도 다음 실행에서 이어 보냈습니다. 하지만 동영상을 만들고 → 대기열에 넣고 → 실패하면 서버에 알리는 일이 모두 화면 쪽 프로그램의 메모리 안에서만 이어졌습니다. 그래서 만드는 도중에 끄면 만들던 영상, 대기열 등록, 실패 보고가 한꺼번에 사라졌고, 다시 켜도 이어서 만들지 않았습니다. 서버에 "실패" 조차 남지 않은 이유였습니다.

고친 내용은 세 가지였습니다.

1. 동영상 작업을 **시작할 때** 무엇을 만들 것인지(손님 촬영 폴더, 종류, 프레임, QR)를 디스크에 먼저 적게 했습니다. 대기열에 넣거나 실패를 알리면 그 기록을 지웠습니다.
2. 다시 켜지면(로그인 15초 뒤, 인터넷이 돌아올 때, 5분마다) 남은 기록을 보고 촬영 장면으로 다시 만들어 대기열에 넣게 했습니다. 대기열에 같은 QR 이 이미 있으면 다시 만들지 않았습니다. 촬영 장면이 없거나, 24시간이 지났거나, 다시 만들기도 실패하면 "영상을 만들기 전에 프로그램이 종료되었습니다" 와 그 사유를 서버에 알리게 했습니다.
3. 창 닫기·재시작·원격 재실행·업데이트로 끌 때 동영상을 만드는 중이면 최대 60초 기다리게 했습니다. Windows 종료는 막지 않았습니다.

같은 구조가 다른 곳에도 있을 것 같아, 읽기 전용 점검을 AI 코딩 에이전트에 따로 맡겨 코드 위치까지 받았습니다. 카드 승인부터 매출 기록 전, 현금을 넣는 중, 인쇄 뒤 정산(크레딧·유료 프레임·출력 장수)이 같은 위험에 있었습니다. 돈이 걸린 이 부분도 같은 방식으로 고쳤습니다. 결제를 시작하기 **전에** '진행 중 결제' 를 먼저 적고, 다시 켜졌을 때 끝나지 않은 결제는 직원 화면에 '확인이 필요한 결제' 로 보이게 했습니다. 인쇄 뒤 정산은 인쇄가 성공한 직후 한 번에 디스크에 적게 했습니다.

## 코드로 보기 (개념 재현)

이름은 바꾼 더미입니다.

```js
// 고치기 전: 만들고 -> 넣고 -> 실패면 알리는 일이 메모리 흐름 안에만 있었다
async function makeClipOld(qr) {
  const file = await buildClip(qr); // 약 30초. 이 사이에 꺼지면 아래 줄은 영영 돌지 않는다
  await clipQueue.add(qr, file);  // 디스크 대기열: 여기 들어간 뒤로는 안전
}

// 고친 뒤: 시작할 때 먼저 적고, 대기열에 넣은 뒤 지운다
async function makeClipNew(qr) {
  jobNotes.write(qr, { startedAt: Date.now() }); // 디스크에 먼저 (fsync 까지)
  const file = await buildClip(qr);
  await clipQueue.add(qr, file);
  jobNotes.remove(qr);
}

// 다시 켜졌을 때: 남은 기록으로 이어 간다
async function pickUpLeftovers(now) {
  for (const [qr, job] of jobNotes.entries()) {
    if (clipQueue.has(qr)) { jobNotes.remove(qr); continue; } // 이미 들어가 있으면 다시 만들지 않는다
    if (!shotsExist(qr) || now - job.startedAt > 24 * 3600_000) {
      await sendFailure(qr, '영상을 만들기 전에 프로그램이 종료되었습니다'); // 빈칸 대신 실패라도 남긴다
      jobNotes.remove(qr);
      continue;
    }
    await makeClipNew(qr);
  }
}
```

## 💡 배운 것

- 대기열을 디스크에 두는 것만으로는 부족했습니다. "대기열에 들어가기 전" 구간이 메모리뿐이면, 그 사이에 꺼질 때 일이 통째로 사라졌습니다. 오래 걸리는 일은 **시작할 때** 먼저 적어 둬야 다시 켜졌을 때 이어 갈 수 있다는 걸 배웠습니다.
- 끝내 못 한 일은 실패라도 남겨야 했습니다. 서버의 빈칸은 "아직" 인지 "실패" 인지 알 수 없어서, 원인을 찾으려면 운영 기록을 거꾸로 맞춰야 했습니다.
- 복구를 만들 때는 다시 켜진 뒤 무엇이 사라지거나 처음으로 돌아가는지를 봐야 한다는 걸 [2026-10-27 글](2026-10-27-카메라-프로그램을-다시-켰더니-사진-이름이-처음부터-시작해-앞-사진을-덮어썼다.md)에 이어 다시 배웠습니다. 그때는 사진 번호가 처음으로 돌아갔고, 이번에는 만들던 영상과 진행 중이던 결제가 사라졌습니다.

## 소감

동영상 한 건의 원인을 찾다가 같은 틈이 결제 기록에도 있다는 걸 알게 됐습니다. 매장이 열리기 전에 찾아서 다행이었습니다. 실제 카드 단말과 지폐기로 껐다 켜는 확인은 시험 매장에서 이어서 하려고 합니다.
