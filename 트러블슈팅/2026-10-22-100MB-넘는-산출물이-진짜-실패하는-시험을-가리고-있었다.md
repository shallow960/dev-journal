# 2026-10-22 100MB 넘는 산출물이, 진짜 실패하는 시험을 가리고 있었다

> 태그: #트러블슈팅 #CI #GitLab #아티팩트 #파이프라인

## 무엇을 / 왜

새로 맡은 저장소에서 기능 브랜치를 main 으로 합치려고 병합 요청을 열었습니다. 파이프라인의 백엔드 빌드 단계가 빨간색이었습니다.

로그를 끝까지 보니 빌드 자체는 성공했습니다. 실패한 곳은 맨 마지막, 빌드 결과물(jar 파일, 116.6MB)을 다음 단계에 넘기려고 서버에 올리는 순간이었습니다. 응답은 `413 Request Entity Too Large` 였습니다. 이 GitLab 의 아티팩트 한도는 100MB 였습니다.

그런데 이 jar 를 받아 쓰는 단계가 있었나 찾아보니, 예전에 고객사 서버로 배포하던 단계였고 그 단계는 이미 지운 뒤였습니다. 아무도 쓰지 않는 파일을 올리다가 실패하고 있었던 것입니다.

## 어떻게 풀었나

1. 한도를 올리는 대신, 받는 쪽이 없으니 **아티팩트를 올리지 않게** 했습니다. 빌드 단계는 "빌드가 되는지" 만 확인합니다.
2. 고치자 그동안 한 번도 시작되지 않던 다음 단계(백엔드 시험)가 처음으로 돌았습니다.
3. 그리고 숨어 있던 실패가 하나 드러났습니다. 시험용 데이터베이스를 컨테이너로 띄우는 시험이 Docker 를 찾지 못했습니다. CI 러너가 "컨테이너 안에서 Docker 를 띄우는 권한(privileged)" 없이 설정되어 있었기 때문입니다. 이건 러너 서버의 설정 파일을 바꿔야 해서 관리자 작업으로 넘겼습니다.

정리하면, 413 이 "빌드 실패" 로 보이면서 그 뒤의 진짜 시험 실패를 가리고 있었습니다. 시험 단계는 앞 단계가 실패하면 아예 시작하지 않게(needs) 되어 있었으니까요.

## 코드로 보기 (개념 재현)

```yaml
# ---- 고치기 전 ----
build-backend:
  stage: build
  script:
    - ./gradlew build -x test        # 결과물 jar 가 약 116MB
  artifacts:
    paths:
      - build/libs/*.jar             # 업로드가 한도(100MB)를 넘으면 413 -> 이 job 이 실패로 끝난다

test-backend:
  stage: test
  needs: [build-backend]             # 앞 job 이 실패하면 이 job 은 시작조차 하지 않는다
  script:
    - ./gradlew test                 # 그래서 여기서 나던 실패는 아무도 보지 못했다

# ---- 고친 뒤 ----
build-backend:
  stage: build
  script:
    - ./gradlew build -x test        # 빌드가 되는지만 본다. 받는 job 이 없으니 artifacts 를 두지 않는다

test-backend:
  stage: test
  needs: [build-backend]
  script:
    - ./gradlew test                 # 이제 실행된다 -> 숨어 있던 실패(러너 권한)가 드러남
```

```text
# 로그에서 본 순서 (요약)
build-backend : BUILD SUCCESSFUL
build-backend : Uploading artifacts ... 116.6 MB
build-backend : ERROR: Uploading artifacts ... 413 Request Entity Too Large
test-backend  : (시작 안 함)
```

## 💡 배운 것

- 앞 단계의 실패가 뒤 단계를 "실행 안 됨" 으로 만들어, 뒤에 있는 진짜 실패를 숨길 수 있다는 걸 배웠습니다. 하나를 고치면 그다음 실패가 나타날 수 있으니, 고친 뒤에는 파이프라인을 끝까지 다시 봅니다.
- 아티팩트는 받아 쓰는 단계가 있을 때만 올립니다. 쓰는 곳이 없는 큰 파일은 시간과 저장 공간만 쓰고, 한도에 걸리면 이렇게 실패가 됩니다.
- 413 같은 업로드 오류는 "빌드가 깨졌다" 와 다른 문제라서, 실패한 단계의 로그를 마지막 줄까지 읽어야 구분할 수 있었습니다.

## 소감

빨간 표시 하나를 지웠더니 다른 빨간 표시가 나와서 처음엔 당황했습니다. 그런데 생각해 보면 그 시험은 원래부터 실패하고 있었고, 그동안 보이지 않았을 뿐이었습니다. 숨어 있던 걸 찾았다는 쪽이 맞는 것 같습니다.
