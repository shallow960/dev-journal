# 2026-11-03 조회 전용에게 안 보인다는 시험이, 숨길 자료가 없어서 통과하고 있었다

> 태그: #트러블슈팅 #시험 #권한 #역할 #Spring

## 무엇을 / 왜

운영 화면을 쓰는 운영자는 모두 최고 관리자였습니다. 고객 문의에 답하거나 숫자만 확인할 사람에게도 대리 접속, 환불, 스토어 정지 권한까지 함께 줘야 했습니다. 그래서 운영자 역할을 최고 관리자, 고객지원, 조회 전용 셋으로 나눴습니다.

조회 전용은 스토어 상세 화면을 열 수 있게 하되, 그 스토어의 팀원과 운영 기록은 응답에서 빼기로 했습니다. 팀원 목록에는 이름과 이메일이 들어 있었고, 숫자만 볼 사람에게 보여 줄 이유가 없었습니다.

이 규칙을 확인하는 시험을 만들었고, 통과했습니다. 그런데 작업을 마무리하면서 시험을 다시 읽어 보니 이상한 점이 있었습니다. 시험이 쓰는 스토어는 시험 안에서 방금 만든 빈 스토어였고, 팀원도 운영 기록도 처음부터 없었습니다. 응답이 0건인 것은 코드가 숨겨서가 아니라 원래 없어서였습니다. 숨기는 코드를 빼먹었더라도 이 시험은 똑같이 통과했을 것입니다.

## 어떻게 풀었나

### 막는 시험과 가리는 시험이 다르다는 걸 알았습니다

역할 시험에는 "이 역할로 이 요청을 보내면 403 이다" 를 보는 것이 많았습니다. 이런 시험은 자료가 있든 없든 문이 닫혀 있는지를 봤기 때문에 빈 스토어로도 뜻이 있었습니다.

문제의 시험은 달랐습니다. 요청은 200 으로 성공하고, 응답 안에서 일부만 빠져야 했습니다. 이런 시험은 빠질 자료가 있어야 확인이 됐습니다.

### 같은 자료를 두고 역할별로 비교했습니다

시험 앞부분에서 팀원 1명과 운영 기록 1건을 넣었습니다. 그리고 같은 스토어를 세 역할로 열어 봤습니다.

- 최고 관리자와 고객지원에게는 팀원 1명, 운영 기록 1건이 보여야 한다고 적었습니다. 자료가 실제로 들어갔고 응답까지 나온다는 확인이었습니다.
- 조회 전용에게는 같은 자료가 0건이어야 한다고 적었습니다.

볼 수 있는 역할의 1건이 함께 있어야, 조회 전용의 0건을 "숨겨서 0건" 이라고 말할 수 있었습니다.

고친 시험을 돌려 보니 조회 전용에게는 실제로 0건이었습니다. 숨기는 코드는 제대로 동작하고 있었지만, 그 전까지는 그걸 증명하는 시험이 없었던 셈입니다.

### 대시보드도 같은 식으로 고쳤습니다

모든 스토어의 최근 운영 기록은 최고 관리자만 보게 했는데, 이 시험도 자료 없이 0건만 보고 있었습니다. 여기도 최고 관리자에게 1건 이상 보이는 것을 먼저 확인하고, 나머지 두 역할에게 0건인지 보게 했습니다.

## 코드로 보기 (개념 재현)

```java
// 예전 시험 (개념 재현 - 실제 이름과 다름)
@Test
void 조회_전용에게는_팀원과_운영_기록이_보이지_않는다() throws Exception {
    UUID store = newStore();   // 방금 만든 빈 스토어 - 팀원도 운영 기록도 없다

    mockMvc.perform(get("/stores/{id}", store).header(AUTHORIZATION, tokenOf("VIEWER")))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$.members.length()").value(0))   // 원래 없어서 0건
        .andExpect(jsonPath("$.history.length()").value(0));  // 숨기는 코드가 없어도 통과한다
}
```

```java
// 고친 시험 (개념 재현)
@Test
void 같은_자료를_역할에_따라_다르게_보여_준다() throws Exception {
    UUID store = newStore();
    addMemberAndHistory(store);   // 숨길 자료부터 넣는다

    // 볼 수 있는 역할: 자료가 들어갔고 응답까지 나온다는 증거
    for (String role : List.of("ADMIN", "SUPPORT")) {
        mockMvc.perform(get("/stores/{id}", store).header(AUTHORIZATION, tokenOf(role)))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.members.length()").value(1))
            .andExpect(jsonPath("$.history.length()").value(1));
    }

    // 조회 전용: 같은 자료인데 0건이면, 코드가 가린 것이다
    mockMvc.perform(get("/stores/{id}", store).header(AUTHORIZATION, tokenOf("VIEWER")))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$.members.length()").value(0))
        .andExpect(jsonPath("$.history.length()").value(0));
}
```

## 💡 배운 것

- "안 보인다", "없다", "0건" 을 확인하는 시험은 자료가 없어도 통과했습니다. 이런 시험은 먼저 자료가 있다는 것부터 보여 줘야 뜻이 있었습니다.
- 볼 수 있는 쪽의 확인을 같은 시험에 함께 두니, 시험 준비가 잘못돼 자료가 들어가지 않은 경우도 바로 드러나게 됐습니다.
- 403 으로 막는 권한과 응답 일부를 가리는 권한은 시험 준비가 달랐습니다. 권한 시험을 쓸 때 어느 쪽인지 먼저 따져 보게 됐습니다.

## 소감

시험이 통과한다고 규칙이 지켜진다는 뜻은 아니었습니다. 특히 권한은 너무 열려 있어도 오류가 나지 않아서, 시험이 못 잡으면 아무도 모른 채 넘어갈 수 있었습니다. 이번에는 코드가 아니라 시험이 무엇을 증명하는지를 고쳤습니다. 앞으로 "없다" 를 확인하는 시험을 쓸 때는 "있다" 부터 넣으려고 합니다.
