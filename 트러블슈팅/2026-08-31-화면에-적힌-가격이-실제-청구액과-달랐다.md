# 2026-08-31 화면에 적힌 가격이, 실제 청구액과 달랐다

> 태그: #트러블슈팅 #결제 #요금제 #단일출처

## 무엇을 / 왜

요금제 화면을 열어봤더니 이런 게 적혀 있었습니다.

```
starter     KRW 99,000
standard    KRW 299,000
enterprise  KRW 1,490,000
```

그런데 실제 요금제는 이렇습니다.

```
Start     19,000
Growth    49,000
Business  99,000
```

숫자가 5배씩 틀린 것도 문제인데, `standard` 는 **이미 없어진 요금제**였습니다. 한참 전에 `business` 로 합쳐졌는데 화면에만 남아 있던 거예요.

## 어떻게 풀었나

### 왜 아무도 몰랐나

제일 먼저 든 생각이 이거였습니다. 이 정도로 틀렸으면 진작 터졌어야 하는데.

결제 요청을 보니 이렇게 생겼더군요.

```
{ planCode: "starter", ... }
```

**금액을 안 보냅니다.** 요금제 코드만 보내고, 얼마를 청구할지는 서버가 자기 테이블에서 찾아 정합니다. 보안상 당연한 설계예요 - 금액을 브라우저가 정하게 두면 1원짜리 결제가 가능해지니까요.

그래서 화면에 99,000원이라고 적혀 있어도, 결제를 누르면 19,000원이 청구되고 **아무 오류도 안 납니다.** 시스템 입장에서는 완벽하게 정상 동작이에요. 틀린 걸 아는 건 사람뿐입니다.

### 같은 값이 몇 군데에 있는지 세어봤다

고치려고 보니 요금 정보가 여기저기 흩어져 있었습니다.

- 콘솔 결제 화면에 하드코딩된 배열
- 가입 결제 화면이 쓰는 별도 상수 파일
- 운영 콘솔의 코드→이름 표
- 해지 화면의 코드→이름 표
- 마케팅 요금표의 한도 문구

다섯 군데가 서로를 모른 채 각자 값을 들고 있었습니다. 요금이 바뀔 때 다섯 군데를 다 고쳐야 하는데, 그럴 리가 없죠. 실제로 하나씩 뒤처져 있었고요.

그래서 **금액은 백엔드에서만 온다**로 정리했습니다. 화면은 조회해서 그리기만 하고, 파일에 적지 않습니다.

```
전: 화면마다 금액을 적어 둠 → 요금 바뀌면 다섯 군데를 고쳐야 함 → 하나씩 뒤처짐
후: 화면은 /plans 를 조회 → 요금은 한 곳에서만 바뀜
```

코드→이름 표도 파일 하나로 모았습니다. 이건 조회로 못 없애는 값이라(코드만 있고 이름이 없는 자리가 있어서) 대신 한 군데에만 두기로 했어요.

### 이름과 코드가 어긋나 있었다

정리하다 또 하나 나왔습니다. 콘솔에 요금제가 **"Starter"** 라고 떠 있는데, 실제 이름은 `Start` 입니다.

코드를 보니 이렇게 돼 있었어요.

```
코드 그대로 대문자로 만들어서 보여주기  →  starter → "Starter"
```

한참 전에 이름만 Start·Growth·Platform 으로 바꾸고 코드는 starter·pro·enterprise 로 뒀던 거였습니다. 그러니 코드를 그대로 이름처럼 쓰면 **어디에도 없는 이름**이 화면에 뜹니다. 오너가 보는 이름과 운영자가 보는 이름이 다른 상태였어요.

### 팔면 안 되는 페이지가 열려 있었다

찾다 보니 영구 라이선스 판매 페이지도 나왔습니다. 990,000 ~ 5,990,000원짜리로요.

기획 문서에는 이렇게 적혀 있습니다. **"SaaS 구독제 전용 → 영구 라이선스 없음."** 링크가 걸린 데는 없었지만 주소를 직접 치면 열리는 공개 페이지였습니다. 지웠습니다.

### 파는 것과 실제 한도가 달랐다

요금표의 한도 문구도 실제와 달랐습니다.

| | 화면에 적힌 것 | 실제 |
|---|---|---|
| Start | 라이브 월 5회 | 라이브가 **꺼진** 요금제 |
| Growth | 라이브 **무제한** · 입점 브랜드 **10팀** | 월 265분 · **2곳** |
| Business | 입점 브랜드 **10팀** | **5곳** |

"라이브 무제한"으로 팔고 265분을 주면 그냥 문제가 됩니다. 이건 오류가 아니라 약속이 달라지는 일이에요.

## 코드로 보기 (개념 재현)

```
// 전: 화면이 금액을 알고 있다
const 요금제들 = [
  ["starter", "99,000원"],     // 실제 19,000원
  ["standard", "299,000원"],   // 없어진 요금제
];
요금제들.map(그리기)

// 후: 화면은 조회만 한다
const 요금제들 = await 요금제_조회()   // 금액의 단일 출처
요금제들.map(요금제 => 그리기(요금제.이름, 요금제.월요금))
```

## 💡 배운 것

- **오류가 안 난다고 맞는 게 아니다.** 결제가 코드만 보내는 구조라, 화면 금액이 틀려도 시스템은 아무 불평을 안 했다. 자동으로 안 잡히는 종류의 버그가 있다는 걸 알았다.
- **같은 값이 두 군데 있으면 언젠가 갈라진다.** 다섯 군데에 흩어져 있었고 실제로 전부 다른 값이었다. "지금은 같으니까 괜찮다"가 통하지 않는다.
- **코드와 이름은 다른 것이다.** 코드를 대문자로 만들어 이름처럼 쓰면, 이름이 바뀌는 순간 존재하지 않는 이름이 화면에 뜬다.
- **파는 화면은 기획서와 대조해야 한다.** 없애기로 한 상품이 페이지째 살아 있었다. 코드가 도는 것과 팔아도 되는 것은 별개다.

## 소감

숫자 몇 개 고치는 일인 줄 알고 시작했는데, "왜 아무도 이걸 몰랐나"를 따라가다 보니 결제 구조까지 보게 됐습니다.

제일 무서웠던 건 이게 **조용한 버그**라는 점이었어요. 서버가 틀렸다고 말해주지 않고, 테스트도 통과하고, 로그도 깨끗합니다. 사람이 화면을 열어서 "어? 이 숫자 이상한데" 하고 알아채는 수밖에 없었어요.

그래서 값을 한 곳에만 두는 게 왜 중요한지 좀 알 것 같습니다. 흩어져 있으면 "지금 맞는지" 를 확인할 방법 자체가 없더라고요.
