# 2026-09-15 재시도 예약을 닫지 않아, 같은 달을 두 번 긁고 있었다

> 태그: #트러블슈팅 #결제 #재시도 #멱등성

## 무엇을 / 왜

정기결제에는 실패했을 때의 정책이 있습니다.

```
결제 실패 → 연체 표시 → 3일 뒤 1차 재시도 → 4일 뒤 2차 재시도 → 그 뒤로는 자동 재시도 없음
```

문서에는 그렇게 적혀 있었습니다. 그런데 오픈 전 점검으로 코드를 읽어 보니 **실제 동작이 셋 다 달랐습니다.** 평소에는 드러나지 않습니다. 카드가 한 번 실패해야 지나가는 길이라서요.

## 어떻게 풀었나

### 재시도 날에는 청구가 두 번 일어난다

배치는 두 가지 일을 순서대로 합니다.

1. **결제일이 지난 구독**을 모아 새 청구서를 만들고 결제한다
2. **재시도 시각이 된 결제 기록**을 모아 그 청구서를 다시 결제한다

결제가 실패하면 구독의 다음 결제일이 **재시도 시각으로 설정**됩니다. 그래서 재시도 날이 되면 **1번에도 잡히고 2번에도 잡힙니다.**

```
9/1  결제 실패 → 다음 결제일 = 9/4, 재시도 예약 = 9/4
9/4  1번: "결제일 지났네" → 새 청구서 → 결제   ← 한 번
     2번: "재시도 시각 됐네" → 9/1 청구서 → 결제  ← 또 한 번
```

카드가 그 사이 정상으로 돌아왔다면 **같은 달 요금이 두 번 빠집니다.**

### 재시도 예약이 닫히지 않는다

2번에서 다시 결제할 때, 새 시도는 **새 기록**으로 남습니다. 그런데 원래의 "재시도 대기" 기록은 그대로 남아 있었습니다.

```
9/4  재시도 성공 → 새 기록(성공) 저장. 옛 기록은 여전히 "재시도 대기, 시각 9/4"
9/5  배치: "재시도 시각이 지난 기록이 있네" → 이미 결제된 청구서를 또 결제
9/6  같은 일 반복
```

성공한 뒤에도 **매일 같은 청구서를 다시 긁는** 구조였습니다.

### 재시도 횟수가 늘지 않는다

다음 재시도 간격은 "이번이 몇 번째 실패인가" 로 정합니다. 그런데 새 시도 기록을 만들 때 직전 기록의 횟수를 **그대로 복사**하고 있었습니다. 항상 0이니 항상 "첫 실패" 로 계산됩니다.

```
실패(0회차) → 3일 뒤 → 실패(0회차) → 3일 뒤 → 실패(0회차) → ...
```

"2차까지만 재시도" 가 실제로는 **3일마다 무한 재시도**였습니다. 실패를 계속 반복하면 결제사 쪽에서 막힐 수도 있습니다.

### 세 가지를 함께 고쳤다

- **재시도 대기 중인 구독은 1번에서 건너뛴다.** 그 구독은 재시도 경로가 책임진다
- **재시도 예약은 꺼내 쓸 때 닫는다.** 새 시도는 새 기록으로 남고, 또 실패하면 그 기록이 다음 재시도를 잡는다
- **새 시도의 횟수는 직전 시도 + 1.** 단, 직전이 성공이면 그대로 둔다

여기에 마지막 안전장치를 하나 더 뒀습니다. **이미 결제됐거나 무효가 된 청구서는 어느 경로로 오든 결제하지 않습니다.** 위 셋을 다 고쳐도, 앞으로 생길 새 경로가 같은 실수를 하면 이 한 줄이 막습니다.

## 코드로 보기 (개념 재현)

```java
// 1. 결제일이 지난 구독
for (구독 구독 : 결제일이_지난_구독들(지금)) {
    // 재시도가 잡혀 있으면 그 경로가 같은 청구서로 다시 긁는다. 여기서 새 청구서를 또 만들면 두 번 결제된다.
    if (재시도_대기중(구독.id())) continue;
    결제하기(청구서만들기(구독));
}

// 2. 재시도 대기 기록
for (결제기록 기록 : 재시도_시각이_지난_기록들(지금)) {
    // ★ 예약은 여기서 닫는다. 닫지 않으면 성공한 뒤에도 매일 다시 잡힌다.
    저장(기록.재시도_종료());

    var 청구서 = 청구서조회(기록.청구서id());
    if (청구서 == null || 청구서.결제됨() || 청구서.무효()) continue;
    if (청구서.구독id() != null && 구독상태(청구서.구독id()) != 연체) continue;  // 그 사이 회복·해지됨

    결제하기(청구서.id());
}
```

검증은 **같은 배치를 두 번 돌려** 확인해야 의미가 있습니다.

```java
@Test
void 재시도_날에는_같은_청구서로_한_번만_결제한다() {
    var 구독 = 구독시작(가게, 시작일: 지금.minusDays(35));
    var 청구서 = 청구서만들기(구독, 55_000);
    저장(실패기록(청구서, 사유: "카드 한도 초과", 재시도시각: 지금.minusMinutes(5)));
    구독.연체로(지금.minusMinutes(5));
    저장(구독);

    정기결제배치.실행();
    정기결제배치.실행();          // 다음 날도 돈다

    assertThat(청구서수(구독.id())).isEqualTo(1);        // 새 청구서를 만들지 않았다
    assertThat(결제건수(구독.id(), "성공")).isEqualTo(1); // 결제는 한 번뿐
    assertThat(결제건수(구독.id(), "재시도대기")).isZero(); // 예약이 닫혔다
}

@Test
void 이미_결제된_청구서의_재시도_예약은_결제하지_않고_닫는다() {
    var 청구서 = 청구서만들기(구독, 55_000);
    저장(실패기록(청구서, 재시도시각: 지금.minusMinutes(5)));
    결제완료로_표시(청구서, 지금.minusDays(1));   // 그 사이 다른 경로로 결제됐다

    정기결제배치.실행();

    assertThat(결제건수(구독.id(), "성공")).isZero();
    assertThat(결제건수(구독.id(), "요청")).isZero();     // 시도조차 하지 않았다
}
```

## 💡 배운 것

**같은 대상에 이르는 경로가 둘이면, 한쪽만 봐서는 안 됩니다.** "결제일이 지난 구독" 과 "재시도 시각이 된 기록" 은 각각 보면 멀쩡한데, 재시도 날에는 같은 구독을 동시에 가리켰습니다.

**예약·큐는 꺼내 쓰는 시점에 닫아야 합니다.** 닫지 않으면 "처리했다" 는 사실이 어디에도 남지 않아서, 다음 실행이 같은 일을 또 합니다.

**재시도 횟수는 시도 기록을 이어야 의미가 있습니다.** 매번 새 기록을 만들면서 횟수를 복사하면, 정책에 적힌 "2차까지" 가 코드에서는 "무한" 이 됩니다.

**배치는 두 번 돌려도 결과가 같아야 하고, 테스트도 두 번 돌려서 확인해야 합니다.** 한 번만 실행하는 테스트는 이 결함을 전부 통과시킵니다.

**정책 문서와 코드가 어긋날 수 있습니다.** 표에 적힌 일정이 맞는지는 코드로 확인해야 했습니다.

## 소감

실패 경로는 평소에 지나갈 일이 없습니다. 카드가 실패해야 처음 실행되는 코드라, 결함이 있어도 오래 살아 있습니다. 그런데 그 경로는 **하필 돈이 걸린 쪽**입니다.

정상 경로 테스트는 촘촘했는데 실패 이후의 흐름은 시험이 거의 없었습니다. 만들 때 "실패하면 재시도" 까지는 생각했지만 "재시도가 성공한 다음" 과 "재시도를 몇 번까지" 는 끝까지 따라가지 않았던 것 같습니다.
