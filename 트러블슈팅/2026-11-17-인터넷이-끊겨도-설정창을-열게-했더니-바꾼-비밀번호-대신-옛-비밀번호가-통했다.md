## 무엇을 / 왜

사진 키오스크의 설정창(매장 직원이 키보드로 여는 관리 화면)은 매니저 비밀번호를 서버에 물어 확인한 뒤에야 열렸습니다. 그래서 인터넷이 끊기면 설정창을 열 수 없었고, 매장에서 인터넷이 안 될 때 직원이 설정을 볼 수조차 없는 문제가 있었습니다. 인터넷이 없어도 설정창을 열 수 있게 하기로 했습니다.

처음 만든 방식은 이랬습니다.

- 서버가 "맞다" 고 답한 비밀번호의 확인 값만 PC 에 남겼습니다. 원문은 두지 않고, 느린 해시(scrypt)에 저장할 때마다 새로 만든 소금과 그 키오스크·서버 정보를 섞어 만들었습니다. 파일은 Windows 계정 암호화(DPAPI)로 한 번 더 감쌌습니다.
- 서버에 닿지 못할 때만 그 값과 비교해 설정창을 열었습니다. 오프라인에서는 설정 저장을 막고, 결제·매니저 입금 확인은 예전처럼 서버에서만 하게 했습니다. 5번 틀리면 5분 동안 막았습니다.

## 어떻게 풀었나

돈이나 보안이 걸린 변경은 출시 전에 다른 AI 코딩 에이전트에 따로 검토를 맡기고 있었는데, 이 기능의 검토에서 두 가지 빈틈을 잡았습니다.

1. 관리자 화면에서 매니저 비밀번호를 바꿔도 키오스크에 저장된 확인 값은 그대로였습니다. 그래서 인터넷이 끊기면 **옛 비밀번호로** 설정창이 열렸습니다. 확인 값은 "다음에 서버가 맞다고 할 때" 에만 새로 쓰였기 때문이었습니다.
2. 오프라인으로 연 설정창은 인터넷이 돌아와도 다시 확인하지 않고 그대로 열려 있었고, 그 창에서 직전 카드 결제 취소처럼 돈이 움직이는 버튼도 누를 수 있었습니다.

고친 내용은 이랬습니다.

- 서버의 키오스크 정보에 '비밀번호 판 번호' 를 두고, 비밀번호를 바꿀 때마다 1씩 올렸습니다. 이 번호를 비밀번호 확인 응답과 30초마다 오가는 하트비트 응답에 실었습니다.
- 키오스크는 확인 값을 저장할 때 그 번호를 함께 적고, 하트비트에서 번호가 달라지면 확인 값을 지우게 했습니다. 다음에 서버가 새 비밀번호를 맞다고 할 때 다시 남겼습니다.
- 오프라인으로 연 창은 인터넷이 닿는 순간 비밀번호 창을 다시 띄워 서버에 확인하게 했습니다.
- 오프라인으로 연 창에서는 카드 결제 취소를 막고 그 사유를 보이게 했습니다.

원리상 남는 한계도 적어 두었습니다. 키오스크가 꺼져 있거나 인터넷이 끊긴 동안 비밀번호를 바꾸면, 다시 연결될 때까지는 옛 비밀번호로 열렸습니다. 또 그 PC 의 관리자 권한이 있는 사람은 저장된 확인 값으로 짧은 비밀번호를 하나씩 대입해 볼 수 있어서, 느린 해시로 늦출 수는 있어도 완전히 막을 수는 없었습니다.

## 코드로 보기 (개념 재현)

이름은 바꾼 더미입니다.

```js
const crypto = require('node:crypto');

// 느린 해시 (개념용, 실제로는 반복 강도를 더 높게 잡는다)
const hashPw = (pw, salt) => crypto.scryptSync(pw, salt, 32);

const cache = { check: null }; // { hash, salt, rev } - 원문은 두지 않는다

// 서버가 "맞다" 고 할 때만 남긴다
function rememberOnServerOk(pw, rev) {
  const salt = crypto.randomBytes(16);
  cache.check = { hash: hashPw(pw, salt), salt, rev };
}

// 인터넷이 없을 때만 쓴다
function openOffline(pw) {
  if (!cache.check) return { ok: false, reason: '이 PC 에 저장된 확인 값이 없습니다' };
  const same = crypto.timingSafeEqual(hashPw(pw, cache.check.salt), cache.check.hash);
  return same ? { ok: true, viaCache: true } : { ok: false, reason: '비밀번호가 다릅니다' };
}

// 고친 뒤: 하트비트로 서버의 비밀번호 판 번호를 받아, 다르면 지운다
function onHeartbeat({ pwRev }) {
  if (cache.check && cache.check.rev !== pwRev) cache.check = null;
}

// 고친 뒤: 오프라인으로 연 창에서는 돈이 움직이는 일을 막는다
function cancelLastCard(session) {
  if (session.viaCache) {
    return { ok: false, reason: '인터넷 없이 연 설정창에서는 카드 결제를 취소할 수 없습니다' };
  }
  return { ok: true };
}

rememberOnServerOk('1234', 1); // 서버에서 확인된 비밀번호, 판 번호 1
// 관리자 화면에서 비밀번호를 '5678' 로 바꿈 -> 서버의 판 번호 2

// 고치기 전(판 번호를 보지 않음): 인터넷이 끊기면
openOffline('1234'); // { ok: true, viaCache: true } - 옛 비밀번호가 통했다

// 고친 뒤: 바꾼 뒤 첫 하트비트에서 지워진다
onHeartbeat({ pwRev: 2 });
openOffline('1234'); // { ok: false, reason: '이 PC 에 저장된 확인 값이 없습니다' }
```

## 💡 배운 것

- 오프라인에서 쓰려고 남긴 확인 값도 결국 캐시라는 걸 배웠습니다. 캐시를 만들 때 "언제 이 값이 틀려지는지" 와 "그때 누가 지우는지" 를 함께 정하지 않으면, 바뀐 비밀번호 대신 옛 비밀번호가 통했습니다.
- 기록이 실제와 달라지는 순간 그 기록은 그럴듯한 답을 계속 내놓는다는 걸 [2026-10-19 글](2026-10-19-되돌린-비밀번호가-계속-통하고-있었다.md)에 이어 다시 배웠습니다. 그때는 메시지 브로커 비밀번호 파일의 기록이었고, 이번에는 키오스크의 비밀번호 확인 값이었습니다.
- 오프라인으로 열어 준 권한은 범위를 좁혀야 했습니다. 설정을 보고 고치는 일과 돈을 움직이는 일은 같은 문으로 들어오더라도 따로 막아야 했습니다.
