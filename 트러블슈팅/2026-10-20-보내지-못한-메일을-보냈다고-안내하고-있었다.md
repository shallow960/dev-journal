# 2026-10-20 보내지 못한 메일을, 보냈다고 안내하고 있었다

> 태그: #트러블슈팅 #메일 #예외처리 #트랜잭션 #개인정보

## 무엇을 / 왜

회원가입을 마친 사람이 '확인 메일 보내기' 를 누르면, 화면은 "확인 메일을 보냈어요" 라고 알려 줍니다. 서버를 새로 옮긴 날 직접 가입해 보니, 화면은 보냈다고 하는데 메일이 오지 않았어요.

이유는 두 겹이었습니다.

1. 새 계정의 메일 발송 서비스가 아직 **연습 모드** 였습니다. 연습 모드에서는 미리 확인한 주소로만 보낼 수 있어서, 처음 보는 주소는 발송 서비스가 거절합니다(554).
2. 그런데 우리 코드의 메일 발송 함수가 그 실패를 **잡아서 로그만 남기고 끝냈습니다.** 함수를 부른 쪽은 실패를 알 길이 없으니 늘 "보냈어요" 라고 답했어요.

로그를 보다가 하나가 더 보였습니다. 발송 서비스가 돌려준 오류 문장에 **받는 사람 주소가 그대로** 들어 있었고, 우리 코드는 그 문장을 통째로 로그에 남기고 있었어요.

## 어떻게 풀었나

세 가지를 고쳤습니다.

- **성공 여부를 돌려준다.** 발송 함수가 예외를 삼키는 건 그대로 두되(다른 메일은 실패해도 흐름을 막지 않는 게 맞아서), 이 함수는 보냈는지 못 보냈는지를 `true/false` 로 돌려줍니다.
- **못 보냈으면 요청 전체를 실패시킨다.** 확인 메일 요청은 한 트랜잭션 안에서 "확인 토큰 만들기 + 보낸 횟수 남기기 + 메일 보내기" 를 합니다. 메일이 실패하면 503 과 "보내지 못했어요" 를 돌려주며 예외를 던져서, 토큰과 횟수 기록까지 함께 되돌립니다. 그래서 실패한 시도가 "하루 몇 번까지" 제한에 세지지 않아요.
- **로그에 남기기 전에 주소를 가린다.** 오류 문장 안의 이메일 모양을 찾아 앞부분만 남기고 가립니다.

## 코드로 보기 (개념 재현)

```java
// 전: 실패를 삼켜서 부른 쪽은 늘 성공으로 안다
void sendVerification(String to, String link) {
    try {
        mail.send(to, "이메일 확인", link);
    } catch (MailException e) {
        log.warn("verification mail failed: {}", e.toString()); // 받는 주소가 그대로 남는다
    }
}

// 후: 성공 여부를 돌려주고, 로그에는 주소를 가려서 남긴다
boolean sendVerification(String to, String link) {
    try {
        mail.send(to, "이메일 확인", link);
        return true;
    } catch (MailException e) {
        log.warn("verification mail failed: {}", maskEmails(e.toString()));
        return false;
    }
}

private static final Pattern EMAIL =
    Pattern.compile("[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}");

static String maskEmails(String text) {
    if (text == null) return null;
    // someone.test@example.com -> so***@example.com 처럼 바꾼다
    return EMAIL.matcher(text).replaceAll(m -> Matcher.quoteReplacement(mask(m.group())));
}

// 요청을 받는 쪽: 메일이 실패하면 토큰과 횟수 기록까지 되돌린다
@Transactional
void requestVerification(Account account) {
    limiter.assertAllowed(account);          // 하루 몇 번까지
    Token token = tokens.issue(account);     // 보낸 횟수도 이 기록으로 센다
    if (!mailer.sendVerification(account.email(), linkFor(token))) {
        // 예외를 던지면 트랜잭션이 되돌아가 토큰도 횟수도 없던 일이 된다
        throw new ServiceUnavailable("확인 메일을 보내지 못했어요. 잠시 뒤 다시 시도해 주세요.");
    }
}
```

시험은 두 갈래로 남겼습니다. 가짜 발송기가 실패하게 만든 뒤 "503 이 오고, 보낸 횟수가 늘지 않는다" 를 보고, 오류 문장 속 주소가 모두 가려지는지(주소가 없으면 그대로인지)도 봅니다.

## 💡 배운 것

**실패를 삼키는 함수는 부른 쪽에 거짓말을 합니다.** 로그를 남겼으니 처리했다고 생각하기 쉬운데, 부른 쪽 입장에서는 성공과 구별이 안 돼요. 화면에 결과를 알려 주는 흐름이라면 실패도 돌려줘야 했습니다.

**횟수 제한 기록은 실패와 함께 되돌아가야 합니다.** 실패한 시도까지 세면, 메일을 한 통도 못 받은 사람이 "너무 많이 보냈어요" 를 보게 돼요. 기록을 같은 트랜잭션에 두면 예외 하나로 함께 정리됩니다.

**외부 서비스의 오류 문장에도 개인정보가 들어 있습니다.** 우리가 만든 문장만 가리면 된다고 생각했는데, 받아 온 문장을 그대로 찍는 곳이 더 위험했어요.

## 소감

"보냈어요" 라는 한 줄을 믿고 넘어갈 뻔했습니다. 연습 모드 덕분에 실패가 확실하게 드러나서 오히려 다행이었어요. 이제 외부로 무언가를 보내는 함수를 보면, 실패했을 때 부른 쪽이 그걸 알 수 있는지부터 확인하게 됐습니다.
