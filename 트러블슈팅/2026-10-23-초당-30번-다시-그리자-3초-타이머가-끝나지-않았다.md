# 2026-10-23 초당 30번 다시 그리자, 3초 타이머가 끝나지 않았다

> 태그: #트러블슈팅 #React #useEffect #객체동일성 #WeakMap

## 무엇을 / 왜

사진 키오스크에서 결제가 끝나면 "결제 완료" 화면을 보여 주고, 3초 뒤 촬영 화면으로 넘어가야 합니다. 시험해 보니 이 화면에서 멈춰 버렸습니다.

로그를 보니 이 화면의 "진입" 기록이 39초 동안 1,354번 찍혀 있었습니다. 초당 약 35번입니다. 화면에 한 번 들어왔는데, 들어올 때 하는 일(타이머 걸기)이 계속 처음부터 다시 실행되고 있었습니다.

## 어떻게 풀었나

이 화면은 다음 화면을 빨리 띄우려고 미리 카메라 미리보기(라이브뷰)를 켭니다. 미리보기 영상이 바뀔 때마다 화면이 다시 그려지니, 초당 약 30번 다시 그려집니다. 여기까지는 정상입니다.

문제는 타이머를 거는 effect 의 의존값 목록에 "프레임 목록" 객체가 들어 있었다는 점입니다. 이 목록을 주는 훅은 서버에서 받은 원본을 정리(정규화)해서 돌려주는데, **부를 때마다 새 객체를 만들어** 돌려줬습니다.

React 는 의존값이 바뀌었는지를 내용이 아니라 **같은 객체인지**(`Object.is`)로 봅니다. 새 객체는 내용이 같아도 "바뀐 값" 입니다. 그래서 다시 그릴 때마다 effect 가 정리(타이머 취소)되고 다시 실행(타이머 새로 걸기)됐습니다. 3초가 찰 틈이 없었습니다.

예전 경로(서버 목록을 캐시해 같은 객체를 돌려주는 곳)에서는 문제가 없었고, 새로 만든 배포 경로에서만 드러났습니다.

고친 방법은 정규화 함수가 **같은 원본에는 같은 결과 객체**를 돌려주게 한 것입니다. `WeakMap` 에 "원본 → 정규화 결과" 를 기억해 둡니다. 원본이 새로 오면(새 배포) 새로 만들고, 옛 원본은 다른 곳에서 안 쓰면 함께 정리됩니다.

고친 코드가 실행 중인 앱에 바로 반영되자, 멈춰 있던 화면이 약 4초 뒤 촬영 화면으로 넘어갔습니다.

## 코드로 보기 (개념 재현)

```js
// identity-demo.mjs - 다시 그릴 때마다 정규화 결과가 같은 객체인지에 따라
// 3초 타이머가 끝나는지 흉내 낸다.

function normalize(source) {
  // 부를 때마다 새 객체를 만든다(내용은 매번 같다)
  return { ...source, items: source.items.map((item) => ({ ...item })) };
}

const cache = new WeakMap();
function normalizeCached(source) {
  // 같은 원본이면 처음 만든 결과를 그대로 돌려준다
  let cached = cache.get(source);
  if (!cached) {
    cached = normalize(source);
    cache.set(source, cached);
  }
  return cached;
}

// 초당 30번 다시 그린다. 의존값이 바뀌면(Object.is 가 false) 타이머를 처음부터 다시 건다.
function simulate(fn, seconds = 10) {
  const source = { items: [{ id: 1 }] };
  let prev;
  let restarts = 0;
  let startedAt = 0;
  for (let frame = 0; frame < seconds * 30; frame++) {
    const now = frame / 30;
    const value = fn(source);                 // 렌더할 때마다 훅이 돌려주는 값
    if (!Object.is(value, prev)) {            // React 가 의존값을 비교하는 방식
      restarts++;
      startedAt = now;                        // effect 다시 실행 = 타이머 새로 걸기
      prev = value;
    }
    if (now - startedAt >= 3) return `타이머 다시 건 횟수 ${restarts}, ${now.toFixed(2)}초에 넘어감`;
  }
  return `타이머 다시 건 횟수 ${restarts}, ${seconds}초 동안 넘어가지 못함`;
}

console.log('렌더마다 새 객체 :', simulate(normalize));
console.log('같은 객체(WeakMap):', simulate(normalizeCached));
```

```text
# 실제 출력 (node identity-demo.mjs)
렌더마다 새 객체 : 타이머 다시 건 횟수 300, 10초 동안 넘어가지 못함
같은 객체(WeakMap): 타이머 다시 건 횟수 1, 3.00초에 넘어감
```

## 💡 배운 것

- effect 의존값은 "내용이 같은가" 가 아니라 "같은 객체인가" 로 비교된다는 걸 배웠습니다. 부를 때마다 새 객체를 돌려주는 훅을 의존값에 넣으면, 다시 그리는 횟수만큼 effect 가 다시 실행됩니다.
- 평소에는 드물게 다시 그려져서 안 보이다가, 라이브뷰처럼 초당 수십 번 다시 그리는 화면에서만 드러났습니다. 시험할 때 "자주 다시 그려지는 화면" 을 따로 봐야겠다고 생각했습니다.
- 로그에서 "한 번만 일어나야 하는 일" 의 횟수를 세어 보는 것이 원인을 찾는 가장 빠른 길이었습니다.

## 소감

화면은 멀쩡해 보이는데 넘어가지만 않아서, 처음엔 타이머 시간이 잘못 설정된 줄 알았습니다. 로그의 숫자 1,354 를 보고 나서야 "타이머가 한 번 걸리는 게 아니구나" 를 알았습니다.
