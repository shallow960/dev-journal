# 2026-10-27 청구서 PDF 가 한 번도 만들어지지 않았던 건, 소문자 doctype 때문이었다

> 태그: #트러블슈팅 #PDF #XML #HTML #시험

## 무엇을 / 왜

관리 화면의 청구서 표에 "청구서 PDF" 버튼을 달기로 했습니다. 청구서를 PDF 로 내려 주는 기능은 예전부터 있었으니 버튼만 이으면 될 줄 알았습니다.

그런데 새 버튼이 부를 주소의 시험을 쓰다 보니 PDF 가 나오지 않고 오류가 났습니다. 예전부터 있던 주소도 같았습니다. 이 기능은 만든 뒤로 PDF 를 한 번도 만들지 못하고 있었고, 화면에 버튼이 없어서 누른 사람이 없으니 아무도 몰랐던 것이었습니다.

## 어떻게 풀었나

### 1. 오류가 난 자리를 찾았습니다

PDF 는 HTML 템플릿에 청구서 값을 채운 뒤, 그 HTML 을 PDF 로 바꾸는 오픈소스 라이브러리(openhtmltopdf)에 넘겨 만들고 있었습니다. 오류는 라이브러리가 문서를 읽는 첫 단계에서 났습니다.

### 2. 라이브러리가 HTML 을 무엇으로 읽는지 확인했습니다

찾아보니 이 라이브러리는 입력을 HTML 이 아니라 XML(XHTML)로 읽는다는 걸 알게 됐습니다. 브라우저는 문법이 조금 틀려도 알아서 고쳐 읽지만, XML 은 문법이 엄격하고 대소문자도 가린다는 것도 그때 알게 됐습니다.

템플릿 첫 줄은 `<!doctype html>` 이었습니다. HTML5 에서는 소문자도 맞는 표기라 브라우저로 열면 아무 문제가 없었습니다. 하지만 XML 에서 문서형 선언은 `<!DOCTYPE` 이어야 해서, 소문자 선언을 만나자 문서를 읽지 못하고 멈췄던 것이었습니다.

### 3. 한 줄을 고치고, "정말 PDF 가 나오는지"를 시험으로 남겼습니다

선언을 `<!DOCTYPE html>` 로 바꾸니 PDF 가 나왔습니다. 다시는 조용히 깨지지 않게, 시험에서 응답 내용의 첫 바이트가 PDF 파일의 시작 표시(`%PDF-`)인지 확인했습니다. 응답 코드만 보면 오류 내용을 200 으로 돌려줘도 통과할 수 있어서, 내용 자체를 봤습니다.

## 코드로 보기 (개념 재현)

```java
// HTML 을 XML 로 읽는 PDF 변환기에 넘기는 템플릿.
// 브라우저는 <!doctype html> 도 받지만, XML 파서는 대문자 선언만 받는다.
String template = """
    <!DOCTYPE html>
    <html xmlns="http://www.w3.org/1999/xhtml">
      <head><meta charset="UTF-8"/></head>   <!-- XML 이라 빈 태그도 닫는다 -->
      <body>
        <h1>청구서 {{number}}</h1>
        <p>합계 {{total}}원</p>
      </body>
    </html>
    """;

byte[] pdf = renderer.render(fill(template, invoice));
```

```java
@Test
void 청구서_PDF_가_실제로_만들어진다() {
    byte[] body = download("/invoices/" + invoiceId + "/pdf");

    // 응답 코드가 아니라 내용을 본다 - PDF 파일은 늘 "%PDF-" 로 시작한다.
    assertThat(new String(body, 0, 5, StandardCharsets.US_ASCII)).isEqualTo("%PDF-");
}
```

## 💡 배운 것

**"HTML 을 받는다"는 라이브러리라도 실제로는 XML 로 읽을 수 있다는 걸 알게 됐습니다.** 그러면 대소문자, 닫지 않은 태그, `&` 같은 기호가 모두 문제가 될 수 있었습니다. 입력을 어떤 문법으로 읽는지부터 확인해야 했습니다.

**누르는 사람이 없는 기능은 깨져 있어도 알려 주지 않았습니다.** 버튼이 없던 동안 이 기능은 한 번도 성공하지 못했지만 오류를 본 사람이 없었습니다. 결과물을 만드는 기능에는 "결과물이 실제로 나오는지"를 보는 시험이 하나는 있어야 했습니다.

## 소감

한 글자의 대소문자 때문에 기능 하나가 처음부터 동작하지 않았다는 게 허탈했습니다. 그래도 버튼을 달기 전에 시험부터 써 본 덕분에, 손님이 처음 누르는 순간 오류를 보는 일은 피할 수 있었습니다.
