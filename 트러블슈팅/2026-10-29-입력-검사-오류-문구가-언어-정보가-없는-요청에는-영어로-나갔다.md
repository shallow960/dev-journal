# 2026-10-29 입력 검사 오류 문구가, 언어 정보가 없는 요청에는 영어로 나갔다

> 태그: #트러블슈팅 #Spring #BeanValidation #다국어 #오류문구

## 무엇을 / 왜

서버는 요청 값을 `@NotBlank`, `@Email`, `@Size` 같은 검사 표시로 확인하고, 맞지 않으면 400 과 함께 오류 문구를 돌려주고 있었습니다. 화면은 이 문구를 손님에게 그대로 보여 줬습니다.

그런데 이 문구에 문제가 두 가지 있었습니다.

1. 문구 앞에 코드의 칸 이름이 영어로 붙어 있었습니다. "email: 올바른 형식의 이메일 주소여야 합니다"처럼 나와서, 손님은 어느 칸을 고쳐야 하는지 알기 어려웠습니다.
2. 서버 시험에서 문구를 확인해 봤더니, "newPassword: must not be blank"처럼 문구까지 영어로 나왔습니다.

검사 라이브러리에는 한국어 문구도 들어 있는데, 어떤 요청에는 영어가 나간 것이었습니다.

## 어떻게 풀었나

### 문구의 언어는 요청이 정하고 있었습니다

찾아보니 검사 라이브러리에는 기본 문구가 언어별 파일로 들어 있었고, 한국어 파일에는 "공백일 수 없습니다", "올바른 형식의 이메일 주소여야 합니다" 같은 문구가 있었습니다. 스프링은 그 가운데 지금 요청의 언어에 맞는 파일을 골랐고, 요청의 언어는 요청 머리글 `Accept-Language` 를 보고 정한다는 걸 알게 됐습니다. 브라우저는 이 머리글에 쓰는 언어를 붙여 보내니, 한국어 브라우저에서 온 요청에는 한국어 문구가 골라졌습니다.

문제는 머리글이 없을 때였습니다.

- 시험에서 쓰는 가짜 요청은 머리글이 없으면 영어를 기본 언어로 갖고 있었습니다. 시험에서 영어가 나온 까닭이 이것이었습니다.
- 실제 서버는 머리글이 없으면 서버가 도는 환경의 기본 언어를 쓴다는 것도 알게 됐습니다. 컨테이너 이미지는 기본 언어가 영어로 잡혀 있는 경우가 많아서, 머리글 없이 들어오는 요청에는 운영에서도 영어 문구가 나갈 수 있었습니다.

스프링 부트에는 머리글이 없을 때 쓸 언어를 정하는 설정이 있었습니다. 이 값을 한국어로 정했습니다. 머리글이 있으면 그 언어를 따르고, 없을 때만 한국어를 쓰게 했습니다.

### 칸 이름은 사람이 읽는 이름으로 바꿨습니다

오류 문구는 "칸 이름: 문구" 모양으로 이어 붙이고 있었고, 칸 이름은 코드의 필드 이름이었습니다. 손님과 쇼핑몰 주인이 실제로 넣는 칸 70여 개에 한국어 이름표를 붙였습니다. 이메일, 새 비밀번호, 제목, 사유, 수량, 운송장 번호 같은 칸들이었습니다.

- 목록 안의 칸은 `items[0].quantity` 처럼 번호와 점이 붙어 와서, 번호를 떼고 마지막 이름으로 찾았습니다.
- 이름표가 없는 칸은 원래 이름을 따옴표로 감싸 보였습니다. 같은 오류 처리기의 다른 문구가 쓰던 모양과 맞췄습니다.
- 여러 검사가 똑같은 문구를 내면 한 번만 보이게 했습니다.

### 칸이 없는 오류도 따로 봤습니다

칸 하나가 아니라 객체 전체를 검사하는 규칙(예를 들어 "시작일이 종료일보다 앞이어야 한다")에는 칸 이름이 없었습니다. 이럴 때는 이어 붙일 문구가 비어서, 스프링 예외의 영어 설명이 통째로 나가고 있었습니다. 그 규칙의 문구를 쓰고, 그마저 없으면 "요청 값이 올바르지 않습니다."를 보이게 했습니다.

## 코드로 보기 (개념 재현)

```yaml
# application.yml - 요청에 Accept-Language 가 없을 때 쓸 언어
spring:
  web:
    locale: ko_KR   # 없으면 서버가 도는 환경의 기본 언어를 쓴다
```

```java
// 칸 이름표 (개념 재현 - 실제 이름과 다름)
final class FieldNames {

    private static final Map<String, String> LABELS = Map.of(
        "email", "이메일",
        "newPassword", "새 비밀번호",
        "title", "제목",
        "quantity", "수량",
        "trackingNumber", "운송장 번호");

    static String label(String field) {
        if (field == null || field.isBlank()) {
            return "입력값";
        }
        // items[0].quantity -> items.quantity -> quantity
        String plain = field.replaceAll("\\[\\d+]", "");
        String last = plain.substring(plain.lastIndexOf('.') + 1);
        String label = LABELS.get(last);
        return label != null ? label : "'" + field + "'";   // 모르는 칸은 원래 이름을 따옴표로
    }
}
```

```java
@ExceptionHandler(MethodArgumentNotValidException.class)
ResponseEntity<ErrorBody> onInvalidBody(MethodArgumentNotValidException ex) {
    BindingResult result = ex.getBindingResult();

    // 1) 칸 오류: "이메일: 올바른 형식의 이메일 주소여야 합니다"
    String detail = result.getFieldErrors().stream()
        .map(e -> FieldNames.label(e.getField()) + ": " + e.getDefaultMessage())
        .distinct()                                   // 같은 문구는 한 번만
        .collect(Collectors.joining(", "));

    // 2) 칸이 없는 오류(객체 전체 검사)는 그 규칙의 문구
    if (detail.isBlank()) {
        detail = result.getGlobalErrors().stream()
            .map(ObjectError::getDefaultMessage)
            .filter(m -> m != null && !m.isBlank())
            .distinct()
            .collect(Collectors.joining(", "));
    }

    // 3) 그래도 없으면 예외의 영어 설명 대신 정해 둔 한국어 문구
    if (detail.isBlank()) {
        detail = "요청 값이 올바르지 않습니다.";
    }
    return ResponseEntity.badRequest().body(new ErrorBody("VALIDATION_FAILED", detail));
}
```

시험은 머리글 없이 보낸 요청의 문구에 "새 비밀번호: "가 들어 있고, "newPassword" 나 "must" 같은 영어는 없는지 확인했습니다.

## 💡 배운 것

**검사 문구의 언어는 요청이 정했습니다.** 같은 코드라도 요청에 어떤 머리글이 붙어 오느냐에 따라 문구가 달라졌습니다. 브라우저로만 확인하면 머리글이 없는 경우를 놓치기 쉬웠습니다.

**머리글이 없을 때의 기본값은 돌고 있는 환경을 따랐습니다.** 시험의 가짜 요청, 내 컴퓨터, 컨테이너가 저마다 다른 기본 언어를 가질 수 있어서, 기본 언어는 설정으로 정해 두는 편이 안전했습니다.

**오류 문구 앞의 칸 이름도 손님이 읽는 글이었습니다.** 코드의 이름을 그대로 보이면 개발자에게만 뜻이 통했습니다.

## 소감

한국어 서비스라서 문구도 당연히 한국어로 나올 거라고 생각했는데, 그 "당연히"는 브라우저가 붙여 보내는 머리글 덕분이었다는 걸 알게 됐습니다. 이제 오류 문구를 시험할 때는 머리글이 없는 요청도 한 번 보내 보게 됐습니다.
