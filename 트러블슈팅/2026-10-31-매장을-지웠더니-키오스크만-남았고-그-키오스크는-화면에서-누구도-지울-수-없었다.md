# 2026-10-31 매장을 지웠더니 키오스크만 남았고, 그 키오스크는 화면에서 누구도 지울 수 없었다

> 태그: #트러블슈팅 #소프트삭제 #권한 #Hibernate #데이터정합성

## 무엇을 / 왜
사진 키오스크 관리 서버는 본사 아래에 매장, 매장 아래에 키오스크를 두는 구조였습니다. 매장과 키오스크는 지워도 행을 남기고 지운 시각만 적는 소프트 삭제(지운 표시)를 쓰고 있었습니다.

- 2026-10-31 밤, 외주형 고객 브랜드에 관리자 계정을 넘기기 전에 그 브랜드 안을 정리했습니다. 예전에 시험으로 만든 키오스크 하나가 그 브랜드 아래에 남아 있었습니다.
- 플랫폼 최고 관리자 계정으로 그 키오스크를 지우려 하자 "권한 범위 밖의 요청입니다" 가 떴습니다. 가장 넓은 권한을 가진 계정이 권한 밖이라는 답을 받은 것이라 이상했습니다.

## 어떻게 풀었나
- DB 를 읽어 보니, 그 키오스크가 속한 매장은 일주일 전인 2026-10-25 에 이미 지워져 있었습니다. 키오스크만 지운 표시 없이 남아 있었습니다.
- 매장 삭제 코드를 따라가 봤습니다. 매장에 따로 만든 계정이 남아 있으면 삭제를 막았고, 그 매장 키오스크에 걸려 있던 원격 명령도 정리하고 있었습니다. 그런데 키오스크 자체는 보지 않았습니다. 그래서 매장만 지워지고 키오스크는 부모 없이 남았습니다.
- 키오스크 삭제 코드는 지우기 전에 이 키오스크를 관리할 수 있는지를 매장으로 확인했습니다. 키오스크의 매장을 먼저 찾고, 그 매장이 관리 범위 안인지 봤습니다. 최고 관리자인지는 매장을 찾은 다음에 봤습니다.
- 이 서버는 ORM(Hibernate)이 매장과 키오스크의 모든 조회에 "지운 표시가 없는 행만" 이라는 조건을 붙이고 있었습니다. 권한을 확인하는 조회도 예외가 아니어서 지운 매장을 찾지 못했고, 매장을 못 찾으면 "범위 밖" 으로 처리됐습니다. 최고 관리자도 그 앞에서 막혔습니다.
- 정리하면 두 가지가 겹쳤습니다. 매장 삭제가 남은 키오스크를 챙기지 않아 부모 없는 키오스크가 생겼고, 권한 확인이 부모를 거쳐 가서 그 키오스크는 화면에서 누구도 지울 수 없었습니다.
- 당장 고칠 일은 아니었습니다. 그 키오스크에는 매출·QR·사진 기록이 하나도 없었고, 매장이 지워져 있어 브랜드 쪽 매장·매출 화면에도 나오지 않았습니다. 보이는 곳은 플랫폼의 키오스크 목록뿐이었습니다. 그래서 그대로 두기로 했고, 필요해지면 DB 에서 그 키오스크 한 줄에만 지운 표시를 하기로 했습니다.
- 고치는 일은 오픈 뒤 할 일로 적어 두었습니다. 매장 삭제가 남은 키오스크를 매장 계정처럼 막거나, 함께 지우게 하는 방향입니다.

## 코드로 보기 (개념 재현)
Node 에 들어 있는 SQLite 로 매장, 매장 계정, 키오스크 표를 만들고, 고치기 전의 매장 삭제와 키오스크 삭제 순서를 그대로 옮겼습니다. 조회 함수에는 ORM 이 붙이던 "지운 표시가 없는 행만" 조건을 직접 넣었습니다. 고치는 방향(남은 키오스크가 있으면 매장 삭제를 막기)도 함께 돌려 봤습니다. 이름은 모두 예시입니다.

```javascript
// 매장을 '지운 표시'로 지운 뒤 남은 키오스크를, 키오스크 삭제가 왜 막는지 재현한다. 이름은 모두 예시다.
// 실행: node --experimental-sqlite orphan-kiosk.cjs
const { DatabaseSync } = require('node:sqlite');

function freshDb() {
  const db = new DatabaseSync(':memory:');
  db.exec(`
    create table store_record (id integer primary key, name text, removed_at text);
    create table store_member (id integer primary key, store_ref int, name text);
    create table kiosk_record (id integer primary key, store_ref int, code text, removed_at text);
    insert into store_record values (1, '시험 매장', null);
    insert into kiosk_record values (1, 1, 'K-001', null);
  `);
  return db;
}

// ORM 이 모든 조회에 덧붙이는 조건: 지운 표시가 없는 행만 보인다.
const findStore = (db, id) => db.prepare('select * from store_record where id = ? and removed_at is null').get(id);
const findKiosk = (db, id) => db.prepare('select * from kiosk_record where id = ? and removed_at is null').get(id);
const liveKiosks = (db) => db.prepare(
  'select k.code, s.name store, s.removed_at is not null store_removed from kiosk_record k join store_record s on s.id = k.store_ref where k.removed_at is null').all();

// 매장 삭제(고치기 전): 매장 계정은 확인하지만, 남은 키오스크는 보지 않고 지운 표시만 한다.
function deleteStoreBefore(db, id) {
  const users = db.prepare('select count(*) n from store_member where store_ref = ?').get(id).n;
  if (users > 0) return '409 매장 계정이 남아 있어 지울 수 없음';
  db.prepare("update store_record set removed_at = '2026-10-25' where id = ?").run(id);
  return '매장 지움';
}

// 매장 삭제(고치는 방향): 남은 키오스크도 매장 계정처럼 막는다.
function deleteStoreAfter(db, id) {
  const kiosks = db.prepare('select count(*) n from kiosk_record where store_ref = ? and removed_at is null').get(id).n;
  if (kiosks > 0) return `409 남은 키오스크 ${kiosks}대가 있어 지울 수 없음`;
  return deleteStoreBefore(db, id);
}

// 키오스크 삭제: 관리 범위를 매장으로 확인한다. 매장을 먼저 찾고, 그다음에 최고 관리자인지 본다.
function deleteKiosk(db, kioskId, caller) {
  const k = findKiosk(db, kioskId);
  if (!k) return '404 키오스크를 찾을 수 없음';
  const s = findStore(db, k.store_ref);          // 지운 매장은 여기서 보이지 않는다
  if (!s) return '403 권한 범위 밖';
  if (!caller.topAdmin && caller.storeId !== s.id) return '403 권한 범위 밖';
  db.prepare("update kiosk_record set removed_at = '2026-10-31' where id = ?").run(kioskId);
  return '키오스크 지움';
}

const admin = { topAdmin: true };

console.log('[고치기 전]');
let db = freshDb();
console.log('매장 삭제:', deleteStoreBefore(db, 1));
console.log('키오스크 목록:', JSON.stringify(liveKiosks(db)));
console.log('최고 관리자가 키오스크 삭제:', deleteKiosk(db, 1, admin));

console.log('[고치는 방향]');
db = freshDb();
console.log('매장 삭제:', deleteStoreAfter(db, 1));
console.log('최고 관리자가 키오스크 삭제:', deleteKiosk(db, 1, admin));
console.log('그다음 매장 삭제:', deleteStoreAfter(db, 1));
console.log('키오스크 목록:', JSON.stringify(liveKiosks(db)));
```

Node v22.11.0 에서 `node --experimental-sqlite` 로 돌린 결과입니다(실험 기능이라는 경고 줄은 뺐습니다).

```
[고치기 전]
매장 삭제: 매장 지움
키오스크 목록: [{"code":"K-001","store":"시험 매장","store_removed":1}]
최고 관리자가 키오스크 삭제: 403 권한 범위 밖
[고치는 방향]
매장 삭제: 409 남은 키오스크 1대가 있어 지울 수 없음
최고 관리자가 키오스크 삭제: 키오스크 지움
그다음 매장 삭제: 매장 지움
키오스크 목록: []
```

- 고치기 전에는 매장이 지워져도 키오스크가 목록에 남았고, 그 키오스크의 매장은 지운 상태였습니다.
- 최고 관리자가 지우려 해도 403 이 나왔습니다. 매장을 찾는 조회가 지운 매장을 걸러 냈기 때문입니다.
- 고치는 방향에서는 키오스크가 남아 있으면 매장 삭제가 409 로 멈췄고, 키오스크를 먼저 지운 뒤에야 매장이 지워졌습니다. 부모 없는 키오스크가 생기지 않았습니다.

## 💡 배운 것
- 부모를 지운 표시로 지울 때는 남은 자식을 어떻게 할지(막을지, 함께 지울지)를 같이 정해야 한다는 걸 배웠습니다. 매장 삭제는 매장 계정과 원격 명령은 챙겼지만, 정작 키오스크는 빠져 있었습니다.
- 권한을 부모를 거쳐 확인하면, 부모가 사라진 자식은 가장 높은 관리자도 손댈 수 없게 된다는 걸 배웠습니다. 화면에 뜬 "권한 범위 밖" 은 권한 문제가 아니라 데이터가 어긋났다는 신호였습니다.
- 지운 표시는 모든 조회에 걸린다는 걸 다시 배웠습니다([2026-10-02, 이력에 묶인 카드는, 지우지 않고 지운 표시로](../개선/2026-10-02-이력에-묶인-카드는-지우지-않고-지운-표시로.md)). 그때는 결제할 때 지운 카드를 다시 집어 오면 안 됐고, 이번에는 권한을 확인하는 조회가 지운 매장을 찾지 못했습니다.

## 소감
"권한 범위 밖" 이라는 문구만 봤다면 권한 설정부터 의심했을 것 같습니다. 코드를 따라가 보니 권한은 멀쩡했고, 일주일 전에 지운 매장이 남긴 빈자리가 문제였습니다. 지우는 기능을 만들 때는 지워진 다음의 모습까지 그려 봐야 한다는 걸 느꼈습니다.
