# 2026-11-24 ETag 를 설정 버전으로 썼더니, 압축이 붙인 꼬리 때문에 30초마다 새 설정으로 보였다

> 태그: #트러블슈팅 #HTTP #ETag #프록시 #키오스크

## 무엇을 / 왜

운영 매장의 사진 키오스크 첫 화면에 '설정 업데이트 중' 이 30초마다 떴다가 사라졌습니다. 손님이 보는 첫 화면이라 그냥 둘 수 없었습니다.

키오스크는 30초마다 서버에 매장 설정을 물었습니다. 응답의 ETag 를 '지금 적용한 설정 버전' 으로 저장해 두고, 서버가 알려 주는 목표 버전과 다르면 설정을 다시 받아 적용하면서 첫 화면에 안내를 띄웠습니다.

매장 로그를 받아 보니 "받은 설정 버전이 서버 목표와 다름" 이 하루 356번 찍혀 있었습니다. 두 값을 나란히 놓고 보니 받은 쪽 끝에만 `-gzip` 이 붙어 있었습니다.

## 어떻게 풀었나

### 원인: 압축하면서 ETag 가 바뀌었다

서버 앞에 둔 프록시(Caddy)가 응답을 gzip 으로 압축하면서, ETag 끝에 `-gzip` 을 붙이고 있었습니다. 압축한 응답은 원래 응답과 바이트가 다르니, 같은 ETag 를 그대로 두면 캐시가 둘을 같은 것으로 착각할 수 있습니다. 그래서 ETag 를 바꾸는 것은 프록시 입장에서는 맞는 동작이었습니다.

문제는 키오스크가 이 값을 캐시용이 아니라 '우리 설정 버전 번호' 로 쓰고 있었다는 데 있었습니다. 서버가 알려 주는 목표 버전에는 꼬리가 없었고, 받은 ETag 에는 늘 꼬리가 있었습니다. 둘은 영원히 같아질 수 없었고, 키오스크는 30초마다 새 설정을 받았다고 보고 다시 적용했습니다.

### 고친 것

1. **프록시:** 설정 응답은 압축하지 않게 했습니다. 크기가 작은 응답이라 압축할 이유도 거의 없었습니다. 서버 쪽만 바꾸면 되니, 이미 매장에 깔린 키오스크도 프로그램을 바꾸지 않고 바로 고쳐졌습니다.
2. **키오스크:** ETag 를 버전으로 읽을 때 `-gzip`·`-zstd`·`-br`·`-deflate` 꼬리를 떼고 비교하게 했습니다. 나중에 누가 프록시 설정을 다시 바꿔도 같은 일이 생기지 않게 하기 위해서였습니다.

고친 뒤 현장 키오스크에서 몇 분을 지켜보며 깜박임이 다시 나오지 않는 것을 확인했습니다.

## 코드로 보기 (개념 재현)

이름은 바꾼 더미입니다.

```js
// 서버가 만든 ETag:          "s12-r262"
// 프록시가 압축하며 바꾼 ETag: "s12-r262-gzip"

function toSettingVersion(etag) {
  if (!etag) return null;
  const v = etag.replace(/^W\//, '').replace(/^"|"$/g, ''); // 약한 표시와 따옴표 떼기
  return v.replace(/-(gzip|zstd|br|deflate)$/, '');        // 압축이 붙인 꼬리 떼기
}

toSettingVersion('"s12-r262-gzip"'); // 's12-r262'
toSettingVersion('"s12-r262"');      // 's12-r262'

// 고치기 전: 받은 값 그대로 비교 → 늘 다름 → 30초마다 다시 적용
// 's12-r262-gzip' !== 's12-r262'
```

```
# 프록시: 설정 응답만 빼고 압축 (개념)
@compressible not path /api/device/settings
encode @compressible gzip zstd
```

## 💡 배운 것

- ETag 는 캐시가 "같은 응답인가" 를 가리려고 쓰는 값이라, 압축처럼 응답 바이트를 바꾸는 중간 단계는 ETag 도 바꿀 수 있다는 걸 배웠습니다. 우리 쪽 버전 번호로 쓰려면 꼬리를 정리하거나, 아예 응답 본문에 버전을 따로 실어야 했습니다.
- 서버 쪽 고침과 키오스크 쪽 고침을 같이 두는 게 좋았습니다. 서버 쪽은 이미 깔린 키오스크를 바로 고쳤고, 키오스크 쪽은 앞으로 프록시가 바뀌어도 버티게 했습니다.

## 소감

로그 한 줄에 두 값이 나란히 찍혀 있어서 원인을 빨리 찾을 수 있었습니다. 비교에 실패했을 때 두 값을 모두 남기게 해 둔 것이 도움이 됐습니다. 앞으로 다른 계층이 만든 값을 우리 쪽 의미로 쓸 때는, 중간에서 바뀔 수 있는 값인지 먼저 보려고 합니다.
