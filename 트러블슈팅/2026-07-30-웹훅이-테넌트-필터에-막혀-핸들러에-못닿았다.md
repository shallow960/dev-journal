# 2026-07-30 배포하고 찔러보니 웹훅이 테넌트 필터에 막혀 있었다

> 태그: #트러블슈팅 #멀티테넌트 #웹훅 #배포

## 무엇을 / 왜
외부 영상 서비스가 "녹화가 끝났어"라고 알려주는 **웹훅**을 새로 만들어 배포했다. 컴파일도 타입 검사도 다 통과했다. 그런데 배포하고 나서 **그 주소를 실제로 한 번 찔러봤더니 400(잘못된 요청)** 이 왔다.

이상했다. 내 코드는 "서명이 없으면 401(인증 실패)"을 내게 짜여 있었다. 그런데 401이 아니라 400이 왔다는 건, **요청이 내 코드에 닿기도 전에 다른 곳에서 막혔다**는 뜻이었다. 기대한 에러와 다른 에러가 오는 것 자체가 결정적 단서였다.

## 원인을 따라가기
응답 본문을 열어보니 이렇게 적혀 있었다.

```json
{ "error": { "code": "TENANT_NOT_FOUND", "message": "No tenant is mapped for host molida.co" } }
```

"molida.co 라는 호스트에 연결된 가게(테넌트)가 없다"는 것이다. 여기서 감이 왔다.

우리 시스템은 멀티테넌트라, 손님 요청이 들어오면 **"이 주소(호스트)가 어느 가게냐"를 먼저 해석하는 필터**가 `/api/v1/**` 전체에 걸려 있다. 예를 들어 `가게이름.molida.co` 로 들어오면 그 가게로 해석한다.

그런데 **웹훅은 중앙 도메인 `molida.co` 로 들어온다.** 그건 특정 가게가 아니라 플랫폼 전체의 주소다. 필터 입장에선 "molida.co? 이건 어느 가게도 아닌데?" 하고 400으로 막아버린 것이다. 즉 웹훅은 **가게와 무관한 플랫폼 콜백**인데, 가게 해석 필터를 통과하려다 걸린 거였다.

## 어떻게 풀었나
다행히 우리 코드엔 이미 **"가게 해석에서 제외할 플랫폼 레벨 경로 목록"** 이 있었다. 자사 운영 API, 계정 API, 공개 자산, 중앙 소셜로그인 콜백 같은 것들 - 전부 특정 가게가 아니라 플랫폼 전체로 오는 요청이라 이미 빼두고 있었다. 웹훅도 정확히 그 부류라, **그 제외 목록에 웹훅 경로 한 줄을 추가**하는 것으로 끝났다.

그럼 "이 웹훅은 어느 가게 거냐"는 어떻게 아냐고? 그건 필터가 주소로 추측하는 게 아니라, **서비스가 안에서 직접** 푼다. 방송을 만들 때 "이 방송 = 이 가게"라는 매핑을 저장해뒀으니, 웹훅이 오면 그 매핑을 찾아 어느 가게인지 안전하게 해석한다. 주소로 넘겨짚는 게 아니라 저장해둔 사실로 잇는 것이다.

## 💡 배운 것
- **배포해서 실제로 찔러보기 전엔 안 보이는 버그가 있다.** 컴파일·타입 검사가 다 통과해도, "요청이 내 코드에 닿기 전에 앞단의 다른 계층이 막는" 문제는 실제 요청을 보내봐야만 드러난다. 이번엔 배포하고 딱 한 번 찔러본 덕에 잡았다.
- **기대한 에러 코드와 다른 에러가 오면, 내 코드보다 앞단을 의심하자.** 401을 기대했는데 400이 온 게 "내 핸들러에 닿지도 못했구나"의 신호였다. 에러 코드는 "어디까지 갔는지"를 알려주는 지도다.
- **외부에서 오는 콜백은 "어느 가게"가 아니라 "플랫폼 전체"로 온다.** 멀티테넌트에서 가게 해석은 손님 요청에나 맞는 규칙이고, 플랫폼 레벨 경로(운영·계정·웹훅 등)는 그 해석에서 빼야 한다. "모든 /api 요청은 가게에 속한다"는 가정을 깔면 안 된다.

## 코드로 보기 (개념 재현)
가게 해석 필터를 `/api/v1/**` 에 걸되, 플랫폼 레벨 경로는 제외 목록으로 빼는 구조다. 이번에 마지막 줄(웹훅)을 추가한 것이 전부다.

```java
// 이 경로들은 특정 가게가 아니라 "플랫폼 전체"로 오는 요청 -> 가게 해석에서 제외한다.
private static final String[] TENANT_EXCLUDES = {
    "/api/v1/ops/**",              // 자사 운영 콘솔
    "/api/v1/account/**",          // 계정 (어느 가게인지와 무관)
    "/api/v1/public/**",           // 공개 자산
    "/api/v1/auth/oauth/central-callback/**", // 중앙 소셜로그인 콜백
    "/api/v1/live/webhooks/**"     // 외부 영상 서비스 웹훅  <- 이번에 추가
};

// molida.co(중앙 도메인)로 오는 웹훅이, 위 목록에 없으면
// "이 호스트는 어느 가게?" 해석 단계에서 TENANT_NOT_FOUND(400)로 막힌다.
```

## 소감
"컴파일 됐고 배포도 성공했으니 되겠지"가 아니라, **배포하고 실제로 한 번 눌러본** 게 이번 버그를 잡았다. 안 찔러봤으면 나중에 진짜 녹화 웹훅이 왔을 때 조용히 다 막혀서, "다시보기가 왜 안 붙지?"를 한참 헤맸을 거다. 그리고 멀티테넌트에서는 "모든 요청이 어느 가게에 속한다"는 게 기본값처럼 느껴지지만, 밖에서 들어오는 콜백은 그 바깥에 있다는 걸 다시 새겼다. 앞으로 외부 서비스 콜백을 붙일 땐 "이건 가게 요청이 아니다"부터 떠올려야겠다.
