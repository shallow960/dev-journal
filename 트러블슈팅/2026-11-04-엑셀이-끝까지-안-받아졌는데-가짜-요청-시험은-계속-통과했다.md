# 2026-11-04 엑셀이 끝까지 안 받아졌는데, 가짜 요청 시험은 계속 통과했다

> 태그: #트러블슈팅 #Spring #SpringSecurity #StreamingResponseBody #MockMvc #비동기

## 무엇을 / 왜
관리 화면을 역할별로 열어 주기 전에, 진짜 서버와 DB, 브라우저로 모든 화면을 돌려 보는 점검을 했습니다. 그러다 통계 엑셀 내려받기가 모든 역할에서 끝나지 않는 것을 찾았습니다.

- 권한 문제처럼 처음부터 막히지 않았습니다. 요청은 200 으로 시작했습니다.
- 그런데 파일이 끝까지 오지 않아 브라우저의 내려받기가 실패로 끝났습니다.
- 같은 기능의 기존 시험은 모두 통과하고 있었습니다.

## 어떻게 풀었나
- 내려받기는 파일이 커도 메모리에 다 올리지 않으려고 `StreamingResponseBody` 로 만들어져 있었습니다.
- 찾아보니 이 방식은 응답을 다른 스레드에서 쓰고, 다 쓰고 나면 서블릿 컨테이너가 같은 요청을 **ASYNC 디스패치로 한 번 더** 돌린다는 걸 알게 됐습니다.
- Spring Security 는 이 ASYNC 디스패치에도 권한 검사를 했습니다. 그런데 로그인 토큰을 읽는 필터는 요청당 한 번만 도는 필터라 이때는 건너뛰었습니다. 그래서 응답을 다 쓴 뒤의 두 번째 통과에서 로그인하지 않은 요청처럼 보였습니다.
- 이미 파일을 보내고 있는 중이라 상태 코드는 200 이었고, 끝맺음만 실패했습니다. 그래서 처음부터 막히는 권한 오류와 모양이 달랐습니다.
- 시험이 통과한 이유도 찾았습니다. 기존 시험은 가짜 요청을 쓰는 MockMvc 였고, 그 안에서는 이 디스패치가 진짜 컨테이너처럼 필터를 다시 지나지 않았습니다.
- 이렇게 고쳤습니다.
  - 처음 요청에서 이미 권한 검사를 통과한 것이므로, ASYNC 디스패치는 보안 규칙에서 허용했습니다.
  - 진짜 포트로 서버를 띄우는 시험을 새로 만들어, 받은 내용이 온전한 엑셀 파일로 열리는지까지 봤습니다.

## 코드로 보기 (개념 재현)
```java
@Bean
SecurityFilterChain api(HttpSecurity http) throws Exception {
    return http
        .authorizeHttpRequests(auth -> auth
            // 스트리밍 응답이 끝날 때 같은 요청이 다시 들어온다. 처음 들어올 때 이미 검사를 끝냈다.
            // 토큰 필터는 이 두 번째 통과를 건너뛰므로, 여기서 막으면 로그인 안 한 요청으로 보인다.
            .dispatcherTypeMatchers(DispatcherType.ASYNC).permitAll()
            .anyRequest().authenticated())
        .build();
}

@GetMapping("/reports/export")
ResponseEntity<StreamingResponseBody> export() {
    // 이 람다는 요청 스레드가 아닌 곳에서 돈다. 끝나면 컨테이너가 ASYNC 디스패치를 건다.
    StreamingResponseBody body = out -> reportWriter.writeTo(out);
    return ResponseEntity.ok().body(body);
}
```

## 💡 배운 것
- `StreamingResponseBody` 같은 비동기 응답은 보안 필터를 두 번 지날 수 있고, 두 번째에는 로그인 정보가 없을 수 있다는 걸 배웠습니다.
- 응답이 200 으로 시작했다고 끝까지 성공한 것은 아니었습니다. 내려받기 시험은 상태 코드가 아니라 받은 파일을 열어 봐야 했습니다.
- 흉내 낸 시험은 흉내 낸 곳까지만 알려 준다는 걸 다시 배웠습니다([2026-11-03, 표 하나에 글자 비교 규칙을 적지 않아, 모든 계정의 현금 화면이 500 이었다](../트러블슈팅/2026-11-03-표-하나에-글자-비교-규칙을-적지-않아-모든-계정의-현금-화면이-500-이었다.md)). 그때는 저장소를 가짜로 바꿔 SQL 이 안 돌았고, 이번에는 요청을 가짜로 만들어 디스패치가 안 돌았습니다.

## 소감
시험이 다 통과하는 기능이 진짜 서버에서는 끝까지 돌지 않았다는 사실이 가장 놀라웠습니다. 진짜 서버로 한 번 돌려 보는 일이 왜 필요한지 몸으로 알게 된 결함이었습니다.
