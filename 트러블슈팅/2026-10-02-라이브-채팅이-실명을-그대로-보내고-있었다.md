# 2026-10-02 라이브 채팅이, 실명을 그대로 보내고 있었다

> 태그: #트러블슈팅 #개인정보 #마스킹 #WebSocket #라이브커머스 #Java

## 무엇을 / 왜

라이브 방송 화면에는 시청자 채팅이 있습니다. 손님이 채팅을 남기면 보낸 사람 이름이 함께 표시되는데, 이 이름이 **회원 가입 때 적은 실명** 이었고, 그대로 방송을 보는 모든 사람에게 전달되고 있었습니다. 같은 서비스의 상품 후기는 이미 "김*수" 처럼 가려서 보여 주고 있었는데, 채팅만 빠져 있었어요.

같이 찾은 문제가 하나 더 있었습니다. 방송 중간에 들어온 손님은 지난 채팅을 서버에서 불러오지 못해, 늘 빈 채팅창으로 시작했습니다.

## 어떻게 풀었나

### 화면이 아니라 서버에서 가린다

가장 쉬운 방법은 화면에서 이름을 가리는 것입니다. 하지만 그러면 **네트워크 응답에는 실명이 그대로** 남아서, 개발자 도구만 열어도 보입니다. 그래서 서버가 보낼 때부터 가리기로 했습니다.

채팅이 시청자에게 가는 길은 세 가지였습니다.

1. 실시간 채팅(웹소켓으로 모두에게 뿌림)
2. 지난 채팅 목록(새로 들어온 사람이 불러옴)
3. 채팅을 보낸 사람에게 돌아가는 응답

세 곳이 모두 같은 "시청자용 변환" 을 거치게 했습니다. 한 곳이라도 원본을 보내면 의미가 없기 때문입니다.

### 누구에게는 실명이 필요하다

운영자 관리 화면은 악성 채팅을 처리해야 해서 실명을 그대로 받습니다. 그래서 변환을 "항상" 이 아니라 **받는 사람에 따라** 하도록, 같은 메시지에서 시청자용과 관리자용 응답을 따로 만들었습니다.

채팅 차단이 이름에 기대고 있지 않은지도 확인했습니다. 차단은 회원 ID로 하고 있어서, 이름을 가려도 그대로 동작했습니다.

### 가리는 규칙

후기와 같은 규칙을 썼습니다.

| 이름 | 가린 결과 |
|---|---|
| 김민수 | 김*수 |
| 남궁민수 | 남**수 |
| 이준 | 이* |
| 한 글자 | 한 글자 + * |
| 비어 있음 | 비어 있음(화면이 기본 이름으로 표시) |

### 지난 채팅

지난 채팅은 공개 API(최근 100개, 최근 것부터)로 열었습니다. 다만 손님 화면에서 숨긴 방송의 채팅은 내주지 않게 해서, 숨긴 방송이 이 API로 드러나지 않게 했습니다.

## 코드로 보기 (개념 재현)

이름은 예시입니다.

```java
// 가리는 규칙: 첫 글자와 마지막 글자만 남긴다(두 글자면 첫 글자만)
static String maskName(String name) {
    if (name == null || name.isBlank()) return null;
    String n = name.trim();
    if (n.length() <= 1) return n + "*";
    if (n.length() == 2) return n.charAt(0) + "*";
    return n.charAt(0) + "*".repeat(n.length() - 2) + n.charAt(n.length() - 1);
}

// 같은 메시지라도 받는 사람에 따라 다른 응답
record ChatView(long id, String author, String message, Instant at) {
    static ChatView forViewers(ChatMessage m) {   // 시청자: 가린 이름
        return new ChatView(m.id(), maskName(m.authorName()), m.text(), m.createdAt());
    }
    static ChatView forOperators(ChatMessage m) { // 운영자: 실명(관리용)
        return new ChatView(m.id(), m.authorName(), m.text(), m.createdAt());
    }
}

// 실시간 방송, 지난 채팅, 보낸 응답이 모두 forViewers 를 거친다
void broadcast(ChatMessage m) { sessions.sendAll(json(ChatView.forViewers(m))); }
List<ChatView> recent(long streamId) {
    return chats.recent(streamId, 100).stream().map(ChatView::forViewers).toList();
}
```

지금은 자바의 `char` 단위로 세고 있어서, 이모지처럼 `char` 두 개를 차지하는 글자가 이름 끝에 오면 반쪽만 남을 수 있습니다. 실명 칸이라 드문 경우지만, `codePoint` 단위로 세도록 바꿀지 확인할 점으로 남겨 두었습니다.

## 💡 배운 것

**개인정보는 보내는 쪽에서 가립니다.** 화면에서 가리면 눈에는 안 보여도 응답에는 남습니다.

**출구를 전부 셉니다.** 실시간·지난 목록·보낸 응답 중 하나만 빠져도 실명이 나갑니다. 같은 변환을 한곳에 두고 모든 출구가 그걸 지나게 했습니다.

**받는 사람에 따라 응답을 나눕니다.** 운영자에게는 실명이 필요하고 시청자에게는 필요 없습니다. "항상 가림" 이 아니라 "누구에게 보내나" 로 정했습니다.

**식별은 이름이 아니라 ID로.** 차단이 ID 기준이라 이름을 가려도 기능이 깨지지 않았습니다.

## 소감

후기는 가리고 있었는데 같은 회원의 이름이 채팅으로는 그대로 나가고 있었다는 게, 기능을 따로 만들 때 생기기 쉬운 구멍이라는 걸 느꼈습니다. 시청자에게 가는 메시지에 실명이 없는지, 지난 채팅이 최근 것부터 오고 숨긴 방송은 막히는지를 테스트로 확인했습니다.
