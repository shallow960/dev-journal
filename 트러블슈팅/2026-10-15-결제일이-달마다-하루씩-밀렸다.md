# 2026-10-15 결제일이, 달마다 하루씩 밀렸다

> 태그: #트러블슈팅 #배치 #정기결제 #시간경계 #Java

## 무엇을 / 왜

정기결제는 매일 02:15 에 도는 배치가 **"결제 예정 시각 <= 지금"** 인 구독을 골라 결제합니다. 결제가 성공하면 다음 기간을 계산하는데, 새 기간의 시작을 **결제가 끝난 시각**(예: 02:15:03)으로 잡고 있었어요.

한 달 뒤 결제 예정 시각은 02:15:03 인데, 배치는 02:15:00 에 돕니다. 3초 차이로 그날은 대상이 아니고 다음 날 결제돼요. 그렇게 달마다 하루씩 밀렸습니다.

- 10/1 결제 → 다음 예정 11/1 02:15:03 → 11/1 배치는 지나침 → 11/2 결제
- 11/2 결제 → 다음 예정 12/2 02:15:0x → 12/3 결제

실패한 결제를 "정확히 3일 뒤" 다시 시도하게 했을 때도 같은 일이 생겼습니다.

## 어떻게 풀었나

- 정상 갱신은 새 기간을 **직전 기간이 끝나는 시각에 이어 붙였습니다.** 결제가 몇 초 늦게 끝나도 다음 결제 예정 시각은 그대로예요.
- 체험 뒤 첫 결제나 연체 뒤 회복처럼 **기간이 끊겼다가 다시 시작하는 경우만** 결제 시각부터 시작합니다.
- 31일에 시작한 구독은 **원래 날짜를 기억해** 둡니다. 짧은 달엔 말일에, 다음 달엔 다시 31일에 결제돼요.
- 재시도 시각은 **그 날짜의 0시(영업 시간대)** 로 잡아, 그날 배치에 반드시 들어가게 했습니다.

## 코드로 보기 (개념 재현)

```java
// 문제: 새 기간을 결제가 끝난 시각부터 시작한다
Period nextPeriod(Period current, ZonedDateTime paidAt) {
    ZonedDateTime start = paidAt;                 // 예: 10/01 02:15:03
    ZonedDateTime end = start.plusMonths(1);      // 11/01 02:15:03
    return new Period(start, end);
}
// 배치: 매일 02:15:00 에 nextBillingAt <= now 인 구독만 결제
// 11/01 02:15:00 에는 02:15:03 이 아직 '미래'라 빠지고, 11/02 에 결제된다
```

```java
// 고침: 정상 갱신은 직전 기간 끝에 이어 붙이고, 원래 날짜를 기억한다
Period nextPeriod(Period current, ZonedDateTime paidAt, boolean continuous, int anchorDay) {
    ZonedDateTime start = continuous ? current.end() : paidAt;  // 끊긴 경우만 결제 시각부터

    YearMonth next = YearMonth.from(start).plusMonths(1);
    int day = Math.min(anchorDay, next.lengthOfMonth());        // 31일 시작 → 짧은 달은 말일
    ZonedDateTime end = start
            .withDayOfMonth(1)
            .plusMonths(1)
            .withDayOfMonth(day);                               // 시각은 start 와 같다
    return new Period(start, end);
}

// 재시도도 "정확히 3일 뒤" 대신 그 날짜의 0시로
ZonedDateTime retryAt = failedAt.plusDays(3)
        .toLocalDate()
        .atStartOfDay(BUSINESS_ZONE);   // 그날 02:15 배치에 반드시 들어간다
```

## 💡 배운 것

**정해진 시각에 도는 배치와 '지금 시각'을 섞으면, 몇 초가 하루가 됩니다.** 배치는 하루에 한 번이라 몇 초 늦은 대상은 다음 날까지 기다려요.

**기간은 이어 붙여야 밀리지 않습니다.** 끝나는 시각을 다음 시작으로 쓰면, 처리에 시간이 얼마나 걸리든 일정이 그대로입니다.

**같은 실수는 같은 모양으로 또 나옵니다.** 재시도를 "정확히 3일 뒤"로 잡자 같은 이유로 밀렸어요. 배치 대상이 되는 시각은 날짜 경계(0시)에 맞추는 게 안전했습니다.

## 소감

결제 흐름을 날짜를 넘겨 가며 따라가다 찾았습니다. 결제 한 번만 보면 맞는데, 두세 달을 이어서 보니 틀어졌어요. 시간이 들어가는 코드는 한 주기가 아니라 여러 주기를 이어서 따라가 봐야 한다는 걸 배웠습니다.
