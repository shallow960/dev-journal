# 2026-11-12 작업 관리자에서 끈 시작 프로그램을, 앱이 켜질 때마다 다시 켜고 있었다

> 태그: #트러블슈팅 #Electron #Windows #레지스트리 #자동시작

## 무엇을 / 왜

매장 PC 는 켜지면 촬영 앱(Electron)이 저절로 시작되게 해 두었습니다. 그런데 고객사에서 이런 요청이 왔습니다. 작업 관리자의 '시작 앱' 에서 촬영 앱을 '사용 안 함' 으로 바꿔도, 얼마 뒤 다시 '사용' 으로 돌아간다는 것이었습니다. 예전에 쓰던 프로그램에서도 같은 증상이 있었다고 했습니다. 점검하거나 다른 프로그램을 띄워야 하는 날에는 매장에서 자동 시작을 끌 수 있어야 했습니다.

## 어떻게 풀었나

앱이 켜질 때 하는 일을 따라가 보니, 시작할 때마다 자동 시작을 다시 등록하고 있었습니다.

```js
app.setLoginItemSettings({ openAtLogin: true, openAsHidden: false });
```

업데이트로 설치 위치가 바뀌어도 자동 시작이 맞는 실행 파일을 가리키게 하려고 넣은 줄이었습니다. 문제는 여기에 빠진 옵션이었습니다. Electron 문서를 찾아보니 Windows 에는 `enabled` 라는 옵션이 있고, `true` 면 "시작 승인(startup approved)" 레지스트리 값을 바꿔 작업 관리자와 Windows 설정에서 앱을 켜고 끈다고 되어 있었습니다. 그리고 기본값이 `true` 였습니다. 옵션을 빼고 부르면 "켜라" 로 부른 것과 같았습니다.

작업 관리자의 '사용 안 함' 이 어디에 적히는지도 확인했습니다. 찾아보니 자동 시작 목록(`HKCU\...\CurrentVersion\Run`)은 그대로 두고, 따로 `HKCU\...\Explorer\StartupApproved\Run` 아래 같은 이름의 값(REG_BINARY)으로 켬/끔을 적는다는 걸 알게 됐습니다. 첫 바이트가 짝수(02, 06)면 사용, 홀수(03, 07)면 사용 안 함으로 보고, 작업 관리자는 끌 때 03 과 끈 시각을 함께 적었습니다.

그래서 일은 이런 순서로 벌어지고 있었습니다.

1. 매장에서 작업 관리자로 '사용 안 함' 을 골랐습니다. 시작 승인 값의 첫 바이트가 03 이 됐습니다.
2. 다음에 촬영 앱이 켜졌습니다(손으로 켜거나 관리 프로그램이 띄움).
3. 앱이 `enabled` 없이 자동 시작을 다시 등록했고, Electron 이 시작 승인 값을 '사용' 으로 되돌렸습니다.

고친 방법은 등록하기 전에 지금 상태를 읽어 그대로 넘기는 것이었습니다.

- 시작 승인 값을 읽어 '사용 안 함' 이면 `enabled: false`, '사용' 이거나 값이 없으면(끈 적이 없음) `enabled: true` 로 등록하게 했습니다.
- 값을 읽지 못했는데 자동 시작 등록이 이미 있으면 아무것도 건드리지 않게 했습니다. 끈 상태인지 모르고 되돌리는 것보다 그대로 두는 쪽이 안전했습니다.
- 앞으로 같은 실수가 다시 들어오지 않게, 이 등록을 부르는 코드에 `enabled` 가 빠져 있으면 실패하는 시험을 넣었습니다.

값을 읽는 데는 Windows 에 들어 있는 `reg.exe` 를 썼습니다. 값 이름은 실행 파일 경로가 아니라 앱마다 정해 둔 ID 라서, 업데이트로 설치 위치가 바뀌어도 같은 항목을 볼 수 있었습니다.

## 코드로 보기 (개념 재현)

이름은 바꾼 더미입니다.

```js
const { execFile } = require('node:child_process');

const APPROVED_KEY = 'HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Explorer\\StartupApproved\\Run';

// 시작 승인 값 읽기: true = 사용 안 함, false = 사용(또는 끈 적 없음), null = 모름
function readDisabled(valueName) {
  return new Promise((resolve) => {
    execFile('reg.exe', ['query', APPROVED_KEY, '/v', valueName], { windowsHide: true }, (err, stdout) => {
      if (err) return resolve(err.code === 1 ? false : null); // 끝 코드 1 = 값 없음 -> 끈 적이 없다
      // 출력 예: "    my.photo.app    REG_BINARY    0300000066A1B2C3D4E5F601"
      const line = stdout.split(/\r?\n/).map((l) => l.trim()).find((l) => l.startsWith(valueName + ' '));
      const hex = line ? line.split(/\s+/).pop() : '';
      if (hex.length < 2) return resolve(null);
      resolve((parseInt(hex.slice(0, 2), 16) & 1) === 1); // 첫 바이트가 홀수면 '사용 안 함'
    });
  });
}

async function registerAutostart(app, valueName, alreadyRegistered) {
  const disabled = await readDisabled(valueName);
  if (disabled === null && alreadyRegistered) return; // 모르면 건드리지 않는다

  // enabled 를 빼면 기본값 true 가 쓰여 '사용 안 함' 이 풀린다. 그래서 늘 직접 넘긴다
  app.setLoginItemSettings({ openAtLogin: true, openAsHidden: false, enabled: disabled !== true });
}
```

```text
작업 관리자로 끈 뒤 앱이 다시 켜졌을 때 (예)
- 고치기 전: 시작 승인 값 03.. -> enabled 없이 등록 -> '사용' 으로 바뀜
- 고친 뒤  : 시작 승인 값 03.. -> enabled: false 로 등록 -> '사용 안 함' 그대로
```

## 💡 배운 것

- Electron 의 자동 시작 등록은 Windows 에서 켬/끔(`enabled`)까지 함께 정하고, 빼면 기본값이 "켬" 이라는 걸 배웠습니다. 옵션을 빼는 것은 "건드리지 않음" 이 아니라 "기본값으로 덮음" 이었습니다. 설정에서 항목을 빼면 기본값이 되살아난다는 걸 [2026-09-18 글](2026-09-18-지웠는데-기본값이-되살아났다.md)에 이어 다시 배웠습니다.
- 작업 관리자의 '사용 안 함' 은 자동 시작 목록을 지우는 게 아니라, 따로 적어 두는 시작 승인 값이라는 걸 알게 됐습니다. 프로그램이 자동 시작을 다시 등록할 때는 그 값을 먼저 읽어야 했습니다.
- 사람이 고른 설정을 프로그램이 매번 다시 쓰는 코드는, 지금 값을 모를 때 손대지 않는 쪽으로 만들어야 한다는 걸 배웠습니다.

## 소감

"켜질 때마다 다시 등록" 은 업데이트 뒤에도 자동 시작이 맞게 걸리도록 넣은 친절한 코드였는데, 그 친절이 매장의 선택을 매번 덮고 있었습니다. 고친 판은 매장 PC 에서 한 번 더 확인하려고 합니다. 앞으로 "매번 다시 쓰는" 코드를 보면, 그 값을 사람이 바꿀 수 있는 값인지부터 따져 보려고 합니다.
