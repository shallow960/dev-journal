# 2026-10-27 카메라 프로그램을 다시 켰더니, 사진 이름이 처음부터 시작해 앞 사진을 덮어썼다

> 태그: #트러블슈팅 #카메라 #파일이름 #복구 #키오스크

## 무엇을 / 왜
사진 키오스크는 손님이 셔터를 누를 때마다 카메라 제어 프로그램이 카메라에서 사진 파일을 받아 그 손님의 폴더에 저장했습니다. 카메라 연결이 끊길 때를 대비해 카메라 제어 프로그램을 다시 켜는 복구 기능을 점검하다가, 다시 켠 뒤에 찍은 사진이 앞 사진을 덮어쓰는 문제가 있었다는 걸 알게 됐습니다.

- 카메라에서 받아 오는 파일 이름은 `IMG_0001`, `IMG_0002`처럼 번호가 붙었는데, 카메라 제어 프로그램을 다시 켜면 번호가 처음부터 다시 시작했습니다.
- 저장할 때 이 이름을 그대로 썼기 때문에, 한 손님이 찍는 도중에 프로그램을 다시 켜면 다음 사진이 앞 사진과 같은 이름으로 저장됐습니다.
- 같은 이름이면 앞 파일을 덮어써서, 손님이 고를 수 있는 사진 가운데 한 장이 아무 표시 없이 사라지는 길이었습니다.

## 어떻게 풀었나
- 저장 이름 앞에 찍은 시각을 밀리초까지 붙였습니다. 카메라 번호가 처음으로 돌아가도 시각이 달라서 이름이 겹치지 않게 했습니다.
- 이름에 시각이 붙으면 지난 촬영본이 계속 쌓이므로, 며칠 지난 촬영본은 정리하게 했습니다.
- 고친 카메라 제어 프로그램을 시험 키오스크에 넣었습니다.

## 코드로 보기 (개념 재현)
카메라 번호가 다시 켜질 때 처음으로 돌아가는 모습과, 저장 이름에 시각을 붙인 뒤를 흉내 냈습니다.

```js
// 카메라가 붙이는 파일 이름은, 카메라 프로그램이 켜질 때마다 처음부터 다시 센다 (개념 재현)
class FakeCamera {
  constructor() { this.counter = 0 }                 // 프로그램을 다시 켜면 0부터 다시 셈
  shoot() {
    this.counter += 1
    return `IMG_${String(this.counter).padStart(4, '0')}.JPG`
  }
}

// 고치기 전: 카메라가 준 이름 그대로 손님 폴더에 저장 (같은 이름이면 덮어씀)
const before = new Map()
let camera = new FakeCamera()
before.set(camera.shoot(), '1번째 사진')
before.set(camera.shoot(), '2번째 사진')
camera = new FakeCamera()                             // 촬영 도중 카메라 프로그램을 다시 켬
before.set(camera.shoot(), '3번째 사진')               // 다시 IMG_0001 -> 1번째 사진 자리를 덮어씀
console.log('고치기 전', [...before])

// 고친 뒤: 저장 이름 앞에 찍은 시각을 붙여, 다시 켜도 이름이 겹치지 않게
const after = new Map()
const times = ['101500123', '101507456', '101533789'] // 찍은 시각(시분초+밀리초)
camera = new FakeCamera()
after.set(`${times[0]}_${camera.shoot()}`, '1번째 사진')
after.set(`${times[1]}_${camera.shoot()}`, '2번째 사진')
camera = new FakeCamera()
after.set(`${times[2]}_${camera.shoot()}`, '3번째 사진')
console.log('고친 뒤', [...after])
```

실행 결과입니다.

```
고치기 전 [ [ 'IMG_0001.JPG', '3번째 사진' ], [ 'IMG_0002.JPG', '2번째 사진' ] ]
고친 뒤 [
  [ '101500123_IMG_0001.JPG', '1번째 사진' ],
  [ '101507456_IMG_0002.JPG', '2번째 사진' ],
  [ '101533789_IMG_0001.JPG', '3번째 사진' ]
]
```

고치기 전에는 세 장을 찍었는데 두 장만 남았고, 1번째 사진 자리에 3번째 사진이 들어가 있었습니다.

## 💡 배운 것
- 장치가 붙이는 번호는 그 프로그램이 켜져 있는 동안에만 겹치지 않는다는 걸 배웠습니다. 다시 켜지는 순간 번호는 처음으로 돌아갔습니다.
- 그래서 저장하는 쪽의 이름은 장치 번호에만 기대지 않고, 우리 쪽에서 겹치지 않는 값(찍은 시각 같은)을 섞어 만들어야 했습니다.
- 복구 기능을 만들 때는 "다시 켜진 뒤 무엇이 처음 값으로 돌아가는지"를 함께 봐야 한다는 걸 배웠습니다.

## 소감
끊김을 고치려고 넣은 다시 켜기 기능이, 다른 곳에서는 사진을 지우는 길을 열 뻔했습니다. 복구 기능은 복구된 뒤의 상태까지 확인해야 한다는 걸 느꼈습니다.
