# 2026-08-20 타입이 거짓말을 해서 화면이 통째로 죽었다

> 태그: #트러블슈팅 #타입 #프론트엔드 #방어적코딩

## 무엇을 / 왜

방송하는 사람이 쓰는 화면(라이브 스튜디오)에 들어갔더니 이것만 떴습니다.

```
화면을 불러오지 못했습니다
일시적인 오류가 발생했습니다.
[다시 시도]
```

다시 시도를 눌러도 같았습니다. 서버 응답은 200이고, 실패한 요청도 없었어요. 그런데 화면은
통째로 비어 있었습니다.

방송 중에 상품을 강조하고 스트림 키를 받는 화면이라, 이게 안 열리면 방송 준비를 아예 못 합니다.

## 어떻게 풀었나

### 서버는 멀쩡했다

먼저 서버를 의심했습니다. 그런데 요청 기록을 보니 실패가 하나도 없었어요.

```
GET /shopos/seller/live/{id}/studio   200
```

화면 파일 자체는 잘 내려오고 있었습니다. 그러면 브라우저 안에서 죽은 겁니다.

### 브라우저 콘솔을 봤다

화면 오류는 화면 안에서 잡아 버리기 때문에 겉으로는 "일시적인 오류" 로만 보입니다. 그래서
브라우저가 남기는 메시지를 직접 받아 봤습니다.

```
TypeError: Cannot read properties of undefined (reading 'toLocaleString')
    at LiveProductLineup ...
```

상품 목록을 그리는 곳에서 `undefined` 에 대고 숫자 서식을 부르고 있었습니다.

### 서버가 주는 것과 화면이 믿는 것

방송에 걸린 상품을 가져오는 응답을 열어 봤습니다.

```json
{
  "streamId": "...",
  "goodsId": "...",
  "displayOrder": 0,
  "highlightedAt": null,
  "soldCount": 0
}
```

**이름도, 가격도, 이미지도 없습니다.** 이 응답은 "어떤 상품을 걸었는지" 만 담고 있어요.
표시에 필요한 값은 상품 쪽에서 따로 가져와야 합니다.

그런데 화면 쪽 타입에는 이렇게 적혀 있었습니다.

```
type 방송상품 = {
  goodsId: string
  name: string      // 필수
  image: string     // 필수
  price: number     // 필수
  soldCount: number
}
```

서버가 주지 않는 값 셋이 **필수**로 적혀 있었습니다. 타입만 보면 언제나 있는 값이니, 화면은
당연히 그대로 씁니다.

```
{product.price.toLocaleString("ko-KR")}원   // price 가 undefined
```

여기서 화면 전체가 멈춘 겁니다.

### 왜 손님 화면은 멀쩡했나

같은 데이터를 손님 화면도 씁니다. 그런데 손님 화면은 살아 있었어요. 코드를 보니 이렇게 돼
있었습니다.

```
{ name: p.name ?? "상품", price: p.price ?? 0, image: p.image }
```

값이 없을 때를 대비해 둔 겁니다. 아마 만들 때 실제로 비어 있는 걸 보고 막아 뒀겠죠.

**같은 데이터를 쓰는데 한쪽만 죽는다면, 그건 그 화면의 문제가 아니라 타입이 잘못된 것**이라는
신호였습니다.

### 고친 것

세 가지를 했습니다.

1. **타입을 실제 응답에 맞췄습니다.** 이름·이미지·가격을 "있을 수도 없을 수도 있는 값" 으로
   바꿨습니다. 그러자 값을 쓰던 곳들이 전부 컴파일 단계에서 잡혔습니다.
2. **스튜디오가 상품 정보를 따로 채워 오게 했습니다.** 그냥 기본값으로 때우면 "상품 / 0원" 이
   줄줄이 뜨는데, 방송하는 사람은 이름을 보고 어느 걸 강조할지 골라야 하니까요.
3. **카드가 값 없이도 죽지 않게** 막았습니다. 카드 한 장 때문에 화면 전체가 사라질 이유는
   없습니다.

## 코드로 보기 (개념 재현)

```
// 이렇게 적어 두면 컴파일은 통과하고 화면이 죽는다
type 상품 = { name: string; price: number }   // 서버는 안 주는 값
<div>{상품.price.toLocaleString()}</div>       // undefined 에서 터짐

// 응답에 맞춘 타입 + 필요한 값은 따로 채워 온다
type 상품 = { goodsId: string; name?: string; price?: number }
const 채운상품 = { ...상품, ...(await 상품조회(상품.goodsId)) }
<div>{(상품.price ?? 0).toLocaleString()}</div>  // 그래도 죽지는 않게
```

## 💡 배운 것

- **서버가 주지 않는 값을 필수라고 적어 두면 컴파일은 통과하고 화면이 죽는다.** 타입은 약속인데,
  그 약속을 지키는 건 서버입니다. 화면이 혼자 "있을 것" 이라고 적어 두면 아무도 지켜 주지 않습니다.
- **같은 데이터로 한쪽만 죽으면 데이터 정의를 의심하자.** 살아 있는 쪽이 방어 코드를 갖고 있다면,
  그건 누군가 이미 "이 값이 비어 있다" 를 경험했다는 뜻입니다.
- **화면 오류는 조용하다.** 서버 응답은 200이고 실패 요청도 없어서, 겉으로는 원인이 전혀 안
  보였습니다. 브라우저가 남기는 메시지를 직접 받아 보고 나서야 한 줄 만에 찾았습니다.
- **기본값으로 때우는 것과 값을 채워 오는 것은 다르다.** 죽지 않게 막는 건 최소한이고, 화면이
  실제로 쓸모 있으려면 필요한 값을 가져와야 합니다.

## 소감

처음엔 배포가 잘못됐거나 서버가 죽은 줄 알았습니다. 200이 오는 걸 보고서야 브라우저 안을
들여다볼 생각을 했어요.

타입을 적을 때 "이 정도는 당연히 오겠지" 하고 필수로 쓴 적이 저도 있습니다. 그게 나중에 이렇게
돌아온다는 걸 눈으로 보니, 응답을 한 번 찍어 보고 타입을 쓰는 습관이 왜 필요한지 알겠더군요.
