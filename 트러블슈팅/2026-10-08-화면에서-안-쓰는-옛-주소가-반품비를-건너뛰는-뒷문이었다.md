# 2026-10-08 화면에서 안 쓰는 옛 주소가, 반품비를 건너뛰는 뒷문이었다

> 태그: #트러블슈팅 #API #반품 #공격면 #테스트 #Spring

## 무엇을 / 왜

손님 반품·교환은 주문 상세의 '반품 요청'·'교환 요청' 버튼으로 받습니다. 품목·수량·사유·사진을 받고, 사유가 단순 변심이면 반품 배송비를 빼고 환불합니다.

그런데 서버에는 예전에 쓰던 **"주문 단위 반품·교환 신청" 주소 두 개**가 그대로 열려 있었습니다. 화면은 오래전에 새 주소로 바꿨는데 옛 주소를 지우지 않았던 거예요. 로그인한 손님이 그 주소를 직접 부르면 이렇게 됐습니다.

1. **주문 전체로 신청하면** 관리 화면에 옛 처리 버튼(환불승인 → 수거확인 → 환불완료)이 뜨고, 마지막 단계가 **반품비 없이 결제액 전부를 환불**했습니다. 판매자에게 쌓여야 할 반품비 몫도 쌓이지 않았고요.
2. **품목으로 신청하면** 사유 분류를 거치지 않아 반품비가 0원이 되고, 신청 기록 표에 행이 없어서 관리 화면의 신청 목록에도 보이지 않았습니다.

반품비 규칙을 정산에 연결하는 작업을 하다가, 그 규칙을 아예 거치지 않는 길이 있다는 걸 알게 됐습니다.

## 어떻게 풀었나

- **두 주소를 지웠습니다.** 403으로 "막는" 대신 404로 "없앴"어요. 쓰는 화면이 없는 주소라 남겨 둘 이유가 없었습니다.
- **같이 남아 있던 흔적도 정리했습니다.** 휴점 중에도 허용하던 주소 목록, 자동 생성된 API 타입, 화면 쪽에 남아 있던 호출 함수까지요.
- **이미 들어온 신청은 끝낼 수 있게** 관리 화면의 옛 처리 버튼과 서비스 코드는 남겼습니다. 새로 생기지만 않으면 되니까요.
- **지운 주소가 다시 생기지 않게 테스트를 붙였습니다.** 여기서 함정이 있었어요. 없는 주문 번호로 부르면 "주문 없음"도 404라서, 상태 코드만 보면 주소가 살아 있어도 테스트가 통과합니다. 그래서 **실제로 있는 주문**으로 부르고, 응답의 오류 코드가 "경로 없음"인지까지 확인했습니다.

## 코드로 보기 (개념 재현)

```java
// 지운 주소가 '경로 없음'으로 막히는지 지킨다
@Test
void 옛_주문단위_반품_교환_주소는_없다() throws Exception {
    // 실제로 있는 주문으로 부른다.
    // 없는 주문으로 부르면 '주문 없음' 404와 구분이 안 돼서, 주소가 살아 있어도 통과해 버린다
    String orderId = paidOrderOfCustomer();

    for (String path : List.of(
            "/orders/" + orderId + "/legacy-return",
            "/orders/" + orderId + "/legacy-exchange")) {
        mvc.perform(post(path).header("Authorization", customerToken()))
            .andExpect(status().isNotFound())
            // 처리기가 없을 때 공통 오류 처리기가 주는 코드인지 확인 - '주문 없음' 코드가 아니어야 한다
            .andExpect(jsonPath("$.code").value("NOT_FOUND"));
    }
}
```

반대로 새 신청 주소는 반품비가 빠지는지 따로 테스트하고 있어서, "새 길은 규칙을 지킨다"와 "옛 길은 없다"를 둘 다 지키게 됐습니다.

## 💡 배운 것

**화면이 부르지 않는 API도, 열려 있으면 기능입니다.** 화면을 새 주소로 옮길 때 옛 주소를 같이 지우지 않으면, 검증이 빠진 옛 길이 그대로 남습니다. 사용자는 화면이 아니라 서버를 상대로도 요청할 수 있으니까요.

**"없어야 한다"는 테스트는, 무엇 때문에 없는지까지 확인해야 합니다.** 404 하나에 여러 이유가 섞여 있으면 테스트가 엉뚱한 이유로 통과합니다.

**지울 때는 남길 것도 같이 정합니다.** 이미 들어온 신청을 끝낼 길은 남겨야 운영이 멈추지 않습니다.

## 소감

새 길을 만들 때 옛 길을 닫는 것까지가 한 작업이라는 걸 배웠습니다. 앞으로는 화면을 새 API로 옮기면, 옛 API를 누가 아직 부르는지부터 찾아보려고 합니다.
