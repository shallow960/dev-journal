# 2026-10-26 가려진 창에서 1초 타이머를 이어 붙였더니, 300초 제한이 511초에 끝났다

> 태그: #트러블슈팅 #타이머 #Electron #Chromium #카운트다운

## 무엇을 / 왜
사진 키오스크의 화면에는 제한시간이 있어서, 손님이 아무것도 하지 않으면 정해진 시간 뒤에 처음 화면으로 돌아가야 했습니다. 그런데 300초로 정해 둔 화면이 로그로 재 보니 들어온 지 약 511초 뒤에야 끝나는 문제가 있었습니다. 같은 날 100초짜리 다른 화면은 거의 정확했기 때문에 처음에는 설정값이 잘못 들어갔다고 의심했습니다.

## 어떻게 풀었나
- 같은 시간대의 진단 로그를 뒤져 봤더니, 250ms마다 돌아야 할 다른 타이머가 1.7초, 2.6초, 3.1초 간격으로 돌다가 나중에는 약 60초 간격으로 돈 기록이 있었습니다. 그 시간 동안 키오스크 창은 다른 창에 가려져 있었습니다.
- 찾아보니 Chromium 은 보이지 않는 창이나 탭의 타이머를 늦게 돌린다는 걸 알게 됐습니다. CPU 와 배터리를 아끼려는 동작이었고, Electron 앱도 안은 Chromium 이라 같은 일이 생겼습니다.
- 문제의 카운트다운은 1초 setTimeout 을 이어 붙이면서 남은 초에서 1씩 빼는 방식이었습니다. 이 방식은 틱이 늦게 오면 늦게 온 만큼 마감도 그대로 밀렸습니다. 300번 × 약 1.7초 ≈ 511초로 계산이 맞아떨어졌습니다.
- 그래서 화면에 들어올 때 마감 시각을 정해 두고, 틱이 올 때마다 "지금 시각에서 마감까지 몇 초 남았나"를 다시 계산하게 바꿨습니다. 틱은 숫자를 다시 그리라는 신호로만 쓰고, 남은 시간은 시계로 쟀습니다. 같은 값이면 다시 그리지 않으니 틱을 250ms로 촘촘히 둬도 부담이 없었습니다.

## 코드로 보기 (개념 재현)
틱이 1.7배 늦게 오는 창을 흉내 내고, 1초를 100ms 로 줄여서 두 방식을 비교해 봤습니다.

```js
// 1초 = 100ms 로 줄여서, 타이머가 늦게 오는 창(틱이 1.7배 늦게 옴)을 흉내 낸다.
const SECOND = 100;
const LATE = 1.7; // 가려진 창에서 틱 하나가 늦게 오는 비율(로그에서 본 1.7초 간격)
const lateTimeout = (fn, ms) => setTimeout(fn, ms * LATE);
const lateInterval = (fn, ms) => setInterval(fn, ms * LATE);

function countByTicks(limitSec) {          // 틱마다 1씩 빼기
  return new Promise((done) => {
    const start = Date.now(); let left = limitSec;
    const tick = () => { left -= 1; if (left <= 0) return done(Date.now() - start); lateTimeout(tick, SECOND); };
    lateTimeout(tick, SECOND);
  });
}
function countByClock(limitSec) {          // 마감 시각을 정해 두고 틱마다 남은 시간을 다시 계산
  return new Promise((done) => {
    const start = Date.now(); const deadline = start + limitSec * SECOND;
    const id = lateInterval(() => {
      const left = Math.ceil((deadline - Date.now()) / SECOND);
      if (left <= 0) { clearInterval(id); done(Date.now() - start); }
    }, SECOND / 4);
  });
}
const limit = 30;
const a = await countByTicks(limit), b = await countByClock(limit);
console.log(`제한 ${limit}초 → 틱 세기: ${(a / SECOND).toFixed(1)}초 뒤 끝 / 시계 기준: ${(b / SECOND).toFixed(1)}초 뒤 끝`);
```

실행 결과입니다.

```
제한 30초 → 틱 세기: 52.8초 뒤 끝 / 시계 기준: 30.2초 뒤 끝
```

틱을 세는 쪽은 늦어진 비율만큼 길어졌고, 시계로 재는 쪽은 틱이 늦게 와도 마감 근처에서 끝났습니다.

## 💡 배운 것
- 타이머의 틱은 "이 간격마다 온다"는 약속이 아니라 "적어도 이만큼 지난 뒤에 온다"는 것뿐이라는 걸 배웠습니다. 창이 가려지거나 기기가 바쁘면 얼마든지 늦어질 수 있었습니다.
- 그래서 남은 시간은 틱을 센 횟수가 아니라 마감 시각과 지금 시각의 차이로 재야 했습니다.
- 3초 타이머가 다시 그릴 때마다 처음부터 다시 걸리던 일(2026-10-23)에 이어, 타이머는 "언제 다시 걸리고 언제 늦게 오는지"를 늘 의심해야 한다는 걸 다시 배웠습니다.

## 소감
화면을 계속 보고 있을 때는 멀쩡해서 놓치기 쉬운 문제였습니다. 로그에 남은 시각을 하나씩 빼 보지 않았다면 설정값만 고치다가 끝났을 것 같습니다.
