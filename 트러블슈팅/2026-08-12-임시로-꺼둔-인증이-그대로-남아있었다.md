# 2026-08-12 임시로 꺼둔 인증이 그대로 남아 있었다 - 새 화면을 만들고 옛 화면을 안 지웠더니

> 태그: #트러블슈팅 #보안 #리팩터링 #죽은코드

## 오늘 한 일 (요약)
- 회사 내부용 운영 화면을 정리하다가, **옛 관리자 화면 주소가 아직 살아 있는 것**을 발견했다.
- 그 화면은 로그인 확인이 **"임시로" 꺼진 채** 복구되지 않았다. 주소만 치면 그냥 열렸다.
- 새 운영 화면을 만들면서 옛 화면을 대체했는데, **파일을 지우지 않아서** 생긴 일이었다.
- 막고, 지우고, 지우다가 한 번 크게 헛디뎠다. 그 과정에서 안전하게 지우는 순서를 배웠다.

## 어떻게 발견했나

관리 화면들을 점검하다가 옛 화면의 레이아웃 코드에서 이 주석을 봤다.

```tsx
// ⚠️ 인증 임시 비활성화(추후 재구현) — 로그인 없이 항상 플랫폼 운영자 세션.
const session = getMockAdminSession({
  role: "ADMIN",
  kind: "PLATFORM_OPERATOR",
  twoFactor: "verified"
});
```

"추후 재구현"이라고 적혀 있었다. 그 추후가 오지 않았다.

바로 실제 주소를 확인했다.

```
$ curl -o /dev/null -w "%{http_code}" https://우리도메인/admin
200
```

열려 있었다.

## 무엇이 위험했나

다행히 **실제 정보가 새지는 않았다.** 그 화면은 데이터를 전부 예시로 들고 있어서, 화면에 뜨는 매출이나 고객사 목록이 코드에 적힌 가짜였다. 실제 조회를 부르는 곳이 한 군데도 없었다.

그래도 그대로 둘 수는 없었다.

- 누구나 우리 **"운영자 콘솔처럼 보이는 화면"** 을 열 수 있다.
- 그 화면에는 가짜지만 **매출 숫자와 고객사 이름**이 떠 있다.
- 무엇보다, 나중에 누군가 이 화면에 실제 조회를 붙이는 순간 **인증 없는 관리자 화면**이 된다.

마지막 항목이 제일 무서웠다. 지금은 우연히 안전한 상태다.

## 왜 이렇게 됐나

이력을 따라가 보니 순서가 이랬다.

1. 원래 `/admin`이 회사용 운영 화면이었다.
2. 스토어 사장님용 화면(`/cms`)과 성격이 달라서 둘을 분리했다.
3. 분리 작업 중 두 화면의 로그인 확인을 **잠시 껐다.**
4. 이후 회사용 운영 화면을 `/ops`로 **새로 만들었다.** 인증도 2단계 인증까지 제대로 붙였다.
5. **옛 `/admin`은 아무도 지우지 않았다.** 3번에서 꺼둔 인증도 그대로였다.

새 화면을 잘 만드는 데 집중하느라, **옛 화면을 지우는 일은 아무의 할 일 목록에도 없었다.**

## 두 단계로 처리했다

먼저 **막고**, 그다음 **지웠다.** 순서가 중요했다. 파일을 지우는 건 검토가 필요한 작업이라 시간이 걸리는데, 노출은 지금 당장 닫아야 했다.

막는 건 요청을 가로채는 지점에서 처리했다.

```ts
// /admin 은 /ops 로 대체된 옛 표면인데 인증이 꺼진 채 남아 있었다.
// 라우트 파일을 지우기 전까지 여기서 없는 경로로 취급한다.
if (pathname === "/admin" || pathname.startsWith("/admin/")) {
  const url = request.nextUrl.clone();
  url.pathname = "/_removed-surface";
  return NextResponse.rewrite(url, { status: 404 });
}
```

이 상태로 먼저 배포해서 노출을 닫았다. 그다음 파일 정리에 들어갔다.

## 지우다가 헛디뎠다

지워도 되는지 확인하는 방법은 간단하다고 생각했다. **어디서도 안 쓰이면 지운다.**

그렇게 옛 화면 파일들과, 그 화면만 쓰던 예시 데이터를 지웠다. 여기까지는 문제없었다. 그런데 정리하는 김에 화면 목록에 남아 있던 **옛 화면 이름들**까지 지웠더니 이렇게 됐다.

```
error TS2322: Type '"admin.permissions"' is not assignable to type 'AdminPageCode'.
error TS2305: Module '"../src/lib/api/admin"' has no exported member 'blockedUserSession'.
```

지운 이름들이 **권한 검사 테스트**에서 쓰이고 있었다. 화면은 없어졌지만 "권한이 없는 사용자는 이 화면을 못 본다"를 확인하는 테스트는 그 이름을 기준값으로 삼고 있었다.

되돌렸다.

## 그래서 순서를 바꿨다

그 뒤로는 이렇게 했다.

1. **정의한 파일을 뺀 나머지에서 몇 번 쓰이는지 먼저 센다.**

```bash
grep -rn "\bDashboardOverview\b" --include=*.tsx src tests | grep -v "components/admin/DashboardOverview.tsx"
```

2. 0이면 지운다. **1이라도 나오면 그게 무엇인지 본다** (주석인지 실제 사용인지).
3. **한 단계 지울 때마다** 타입 검사를 돌린다. 여러 개를 한 번에 지우고 나중에 확인하지 않는다.

이렇게 하니 나머지는 사고 없이 정리됐다. 최종적으로 파일 19개, 1,600줄 정도가 없어졌다.

## 배운 것
- **"임시"라고 적어도 그 임시는 스스로 끝나지 않는다.** 껐다면 언제 다시 켤지, 누가 켤지를 같이 정해야 한다. 주석은 알림이 아니다.
- **대체한 화면은 지우는 것까지가 대체다.** 새 화면을 만드는 순간 옛 화면은 "안 쓰는 것"이 아니라 "치워야 할 것"이 된다.
- 지금 안전한 것과 앞으로 안전한 것은 다르다. **가짜 데이터라 괜찮다는 건 우연**이고, 그 우연은 다음 사람이 실제 데이터를 붙이면 깨진다.
- 노출을 막는 일과 코드를 정리하는 일은 **속도가 다르다.** 먼저 막고 나중에 지운다.
- **지우는 일은 만드는 일보다 조심스러워야 한다.** 참조 수를 세고, 한 단계마다 확인한다. 화면이 없어져도 그 이름을 쓰는 테스트가 남아 있을 수 있다.
