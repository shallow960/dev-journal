# 2026-10-19 스냅샷으로 복원한 DB 에, 서버가 접속하지 못했다

> 태그: #트러블슈팅 #AWS #RDS #보안그룹 #서버이전

## 무엇을 / 왜

서버 이전 당일, 옛 DB 의 스냅샷을 새 계정에서 복원했습니다. 리허설 때 만든 DB 는 지우고 같은 이름으로 다시 복원해서, DB 주소(엔드포인트)를 그대로 쓰는 계획이었어요. 그런데 복원이 끝난 DB 에 새 서버가 접속하지 못했습니다. 접속 확인 명령은 아무 말 없이 5초 뒤에 끝났어요.

같은 날 바깥 인터넷도 한 번 막혔습니다. 리허설 때 막아 둔 아웃바운드 규칙을 되돌렸는데, 서버에서 외부 HTTPS(443)로 나가지 못했어요.

## 어떻게 풀었나

**DB 접속 시간 초과**

1. 처음엔 DB 가 아직 "생성 중"이었습니다. 콘솔에서 "사용 가능"이 된 뒤 다시 해 봤는데도 안 됐어요.
2. DB 의 연결 정보를 보니 VPC 보안 그룹이 `default` 로 잡혀 있었습니다. DB 전용 보안 그룹(서버 보안 그룹에서 오는 5432 만 허용)을 따로 만들어 뒀는데, 복원 화면은 보안 그룹 칸을 기본값으로 채워 두고 이번엔 그걸 바꾸지 않았어요.
3. DB 를 수정해 전용 보안 그룹으로 바꾸고 "즉시 적용"을 고르자 바로 연결됐습니다.

**바깥 인터넷**

1. 아웃바운드 규칙을 지웠더니 보안 그룹 자체가 지워진 줄 알고 새로 만들려다 "이미 있다"는 오류를 봤습니다. 그룹은 그대로였고 규칙만 비어 있었어요.
2. 규칙을 다시 넣었는데도 443 이 막혔습니다. 대상은 `0.0.0.0/0` 이었지만 규칙 유형이 "모든 트래픽"이 아니었어요. "모든 트래픽" 으로 바꾸자 열렸습니다.

그다음부터는 콘솔에서 무엇을 바꿀 때마다 서버 안에서 바로 한 줄로 확인했습니다.

## 코드로 보기 (개념 재현)

```bash
# DB 포트가 열렸는지: 성공과 실패를 둘 다 찍는다 (조용히 끝나면 실패인지 모른다)
timeout 5 bash -c "</dev/tcp/db.example.internal/5432" \
  && echo "DB 연결 OK" || echo "DB 연결 안 됨 (DB 상태·보안 그룹 확인)"

# 바깥 HTTPS 가 나가는지
curl -sS -m 5 -o /dev/null https://www.example.com && echo "443 열림" || echo "443 막힘"
```

```bash
# 콘솔 대신 CLI 로 보면: 복원한 DB 가 어떤 보안 그룹을 달고 있는지
aws rds describe-db-instances --db-instance-identifier my-db \
  --query 'DBInstances[0].VpcSecurityGroups[].VpcSecurityGroupId'

# 원하는 보안 그룹으로 바꾸고 바로 적용
aws rds modify-db-instance --db-instance-identifier my-db \
  --vpc-security-group-ids sg-0123456789abcdef0 --apply-immediately

# 처음부터 피하려면: 복원할 때 보안 그룹을 같이 지정한다
aws rds restore-db-instance-from-db-snapshot --db-instance-identifier my-db \
  --db-snapshot-identifier my-snapshot \
  --vpc-security-group-ids sg-0123456789abcdef0
```

## 💡 배운 것

**스냅샷은 데이터를 기억하지, 네트워크 설정을 기억하지 않습니다.** 복원하면 보안 그룹 같은 주변 설정은 새로 고르거나 기본값이 들어가요. 같은 이름으로 복원해 주소가 같아도, 문은 새로 달아야 했습니다.

**조용한 실패는 출력을 붙여 둬야 보입니다.** 처음 쓴 확인 명령은 실패하면 아무것도 찍지 않아서 성공인지 실패인지 알 수 없었어요. 확인 명령에는 성공과 실패 문구를 둘 다 넣게 됐습니다.

**규칙은 대상만이 아니라 유형까지 봅니다.** 대상(0.0.0.0/0)이 맞아도 유형이 다르면 필요한 포트가 막혀요.

**바꾸고 나면 그 자리에서 확인합니다.** 콘솔 변경과 서버 안 한 줄 확인을 한 묶음으로 했더니, 그 뒤 단계에서는 막힌 곳이 없었습니다.

## 소감

리허설에서 다 해 본 일이라 같은 순서면 같은 결과가 나올 거라고 생각했는데, 복원 화면의 기본값 하나가 결과를 바꿨습니다. 복원 순서에는 "보안 그룹 고르기"를 꼭 한 줄로 넣어야 한다는 걸 알게 됐어요.
