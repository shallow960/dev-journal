# 2026-10-20 한 키오스크에만 다른 화면을 배정했더니, 나머지가 흰 화면이 될 뻔했다

> 태그: #트러블슈팅 #릴리스 #스냅샷 #통합테스트 #키오스크

## 무엇을 / 왜

매장 키오스크는 서버에서 "릴리스" 를 받아 화면을 그립니다. 관리 웹에서 만든 손님 화면 묶음도 릴리스에 실려 내려가요. 관리자는 이 화면을 브랜드 전체, 국가, 매장, 키오스크 한 대 단위로 배정할 수 있고, 좁은 범위가 이깁니다(키오스크 > 매장 > 국가 > 브랜드 기본).

출시 전에 코드를 읽다가 이상한 점을 봤어요.

- 릴리스에는 화면 버전이 **하나만** 적혀 있었습니다. 마지막으로 배포한 버전이에요.
- 키오스크에 보낼 때는 **지금의** 배정표에서 "그 버전과 같은 배정" 만 골랐습니다.
- 맞는 배정이 없으면 오류가 아니라, **화면이 빠진 릴리스를 정상으로 서명해서** 보냈어요.

그렇다면 이런 일이 생깁니다.

1. 브랜드 기본 = 화면 A. 모든 키오스크가 A 를 씁니다.
2. 키오스크 2번에만 화면 B 를 시범으로 배정합니다. 새 릴리스에는 B 만 적혀요.
3. 키오스크 1번의 배정(A)은 릴리스의 버전(B)과 다릅니다. 그래서 화면이 빠진 릴리스를 받아요.

## 어떻게 풀었나

추측으로 끝내지 않고 재현부터 했습니다.

- 서버 구성요소를 실제 그대로 띄우고(DB 는 시험용 컨테이너), 관리자 동작을 순서대로 부르는 통합 시험 5개를 만들었어요. 이 시험들은 일부러 **"결함이 있다" 고 단언하게** 짰습니다. 통과하면 "재현됨" 이라는 뜻이에요.
- 5개 모두 통과했습니다. 키오스크 1번이 받은 릴리스에는 화면이 없었고, 키오스크는 이것을 "적용 완료" 로 보고했어요. 관리 화면이 읽는 배포 상태도 "적용 완료" 였습니다(관리 화면을 직접 열어 보지는 않았어요).
- 반대 방향도 있었어요. 브랜드 기본을 다시 배포하자, 이번에는 키오스크 2번의 개별 배정이 경고 없이 무시됐습니다.
- 서버가 실제로 서명해 보낸 응답을 키오스크 코드에 그대로 넣어 보니, 서명이 맞으니 받아들이고 화면 데이터가 비었습니다. 다음에 앱이 다시 뜨면 흰 화면이 돼요. (실제 기기 화면을 찍지는 않았습니다. 키오스크의 화면 상태 코드를 실행하고 그리는 코드를 읽어 확인했어요.)
- 같은 원인에서 두 가지가 더 나왔습니다. 롤백은 릴리스 내용만 되돌리고 배정표는 그대로라 같은 결과가 났고, 시즌 묶음을 **만들기만 해도**(아직 켜기 전) 지금의 배정표가 바뀌었어요.

고친 방향은 하나입니다(아직 커밋 전이에요). **릴리스를 만들 때, 그 시점의 배정표 전체를 릴리스에 함께 저장합니다.** 보낼 때는 지금의 배정표가 아니라 저장해 둔 배정표에서 고릅니다.

- 키오스크마다 다른 화면이 함께 살 수 있어요.
- 롤백하면 옛 배정표까지 그대로 돌아옵니다.
- 만들기만 한 묶음은 지금 화면에 영향을 주지 않아요. 배정은 묶음을 켤 때 반영합니다.
- 저장본이 없는 옛 릴리스는 예전 방식으로 읽습니다.

그리고 화면이 있어야 하는 릴리스에서 키오스크 몫을 못 찾으면, **빈 릴리스를 보내지 않고 거절(409)** 합니다. 키오스크는 거절을 받으면 마지막 정상 화면을 지켜요.

재현 시험 5개는 버리지 않았어요. 단언만 "기대하는 동작" 으로 뒤집고, 고칠 동작마다 시험을 더해 14개로 만들어 완료 기준으로 썼습니다. 고치기 전 코드에서 돌리니 14개 중 13개가 실패했어요. 남은 하나는 고친 뒤의 예약 실행 경로를 지키려고 넣은 시험이라, 고치기 전에도 통과하는 게 맞았습니다. 고친 뒤에는 시험을 하나 더해 15개 모두 통과했고, 고친 곳을 하나씩 되돌려 보면 그때마다 해당 시험이 실패했어요.

고친 코드는 따로 적대적 검토를 받았는데, "오래전에 만들어 둔 묶음을 나중에 켜면 그 사이의 배포가 되돌아간다" 같은 지적이 나와 다시 고치는 중입니다.

## 코드로 보기 (개념 재현)

```ts
// 개념 재현: 이름은 모두 더미다.
type Scope = 'KIOSK' | 'STORE' | 'COUNTRY' | 'BRAND';
interface Assignment { scope: Scope; target: string; screenVersion: string }
interface Kiosk { id: string; storeId: string; country: string }
interface Release { id: number; screenVersion: string; pinned?: Assignment[] }

// 좁은 범위가 이긴다: 키오스크 > 매장 > 국가 > 브랜드 기본
const NARROW_FIRST: Scope[] = ['KIOSK', 'STORE', 'COUNTRY', 'BRAND'];

function appliesTo(a: Assignment, k: Kiosk): boolean {
  if (a.scope === 'KIOSK') return a.target === k.id;
  if (a.scope === 'STORE') return a.target === k.storeId;
  if (a.scope === 'COUNTRY') return a.target === k.country;
  return true; // 브랜드 기본은 모든 키오스크에 해당한다
}

function narrowest(list: Assignment[]): Assignment | undefined {
  return [...list].sort((x, y) => NARROW_FIRST.indexOf(x.scope) - NARROW_FIRST.indexOf(y.scope))[0];
}

// 고치기 전: "지금의" 배정표에서, 릴리스에 적힌 버전 하나와 같은 배정만 본다.
function screenBefore(r: Release, liveTable: Assignment[], k: Kiosk): string | null {
  const mine = liveTable.filter(a => a.screenVersion === r.screenVersion && appliesTo(a, k));
  // 못 찾으면 null. 오류가 아니라 "화면 없는 릴리스" 가 정상 서명되어 나간다.
  return narrowest(mine)?.screenVersion ?? null;
}

// 고친 뒤: 릴리스를 만들 때 배정표 전체를 함께 저장하고, 보낼 때는 그것만 본다.
function screenAfter(r: Release, liveTable: Assignment[], k: Kiosk): string {
  // 저장본이 없는 옛 릴리스는 예전 방식으로 읽는다.
  const table = r.pinned ?? liveTable.filter(a => a.screenVersion === r.screenVersion);
  const picked = narrowest(table.filter(a => appliesTo(a, k)));
  if (!picked) {
    // 화면이 있어야 하는 릴리스인데 이 키오스크 몫을 못 찾았다.
    // 빈 릴리스를 서명해 보내지 않고 거절(409)한다. 키오스크는 마지막 정상 화면을 지킨다.
    throw new Error('409: no screen for this kiosk');
  }
  return picked.screenVersion;
}

const k1: Kiosk = { id: 'k1', storeId: 's1', country: 'KR' };
const live: Assignment[] = [
  { scope: 'BRAND', target: '*', screenVersion: 'A' },  // 브랜드 기본 = A
  { scope: 'KIOSK', target: 'k2', screenVersion: 'B' }, // 키오스크 2번만 B 로 시범 배정
];
const latest: Release = { id: 12, screenVersion: 'B' };  // 마지막 배포가 B 라 버전도 B 하나

console.log(screenBefore(latest, live, k1));                    // null -> k1 은 화면 없는 릴리스를 받는다
console.log(screenAfter({ ...latest, pinned: live }, live, k1)); // A    -> k1 은 자기 배정대로
```

## 💡 배운 것

**릴리스는 보낼 때 필요한 것을 전부 담고 있어야 바뀌지 않는다는 걸 다시 배웠습니다.** 버전 하나만 적어 두고 나머지를 보낼 때 지금의 표에서 읽으면, 표가 바뀌는 순간 지난 릴리스의 결과도 바뀌어요. 2026-10-07 에 "바뀔 수 있는 조건은 거래 시점에 고정한다" 를 수수료율에서 배웠는데, 이번엔 화면 배정이었습니다.

**"못 찾음" 을 "없음" 으로 바꿔 정상 처리하면 안 된다는 걸 다시 배웠습니다.** 오류가 아니라 서명까지 된 빈 릴리스가 나가니, 키오스크도 관리 화면이 읽는 배포 상태도 성공이었어요. 2026-09-15 에 "권한 정보를 못 찾았을 때의 기본값이 제일 위험하다" 를 배웠는데, 이번엔 화면 배정이었습니다. 찾아야 할 것을 못 찾으면 거절해야 받는 쪽이 지킬 수 있습니다.

**결함을 단언하는 시험으로 먼저 재현하고, 고칠 때 그 단언을 뒤집어 쓰는 방법을 배웠습니다.** "통과 = 재현" 이라 코드를 읽고 내린 판단이 맞는지 바로 알 수 있어요. 뒤집은 시험은 고치기 전 코드에서 실패한다는 게 이미 확인된 시험이 됩니다. 2026-08-13 에 "새 시험은 한 번 깨뜨려 보고 믿는다" 를 배웠는데, 같은 이야기를 반대 순서로 다시 배웠습니다.

**같은 원인은 여러 증상으로 나온다는 걸 다시 배웠습니다.** 개별 배정, 롤백, 시즌 묶음 만들기가 모두 "보낼 때 지금의 표를 본다" 하나에서 나왔어요. 2026-09-01 에 "증상만 고치면 원인은 남는다" 를 배웠는데, 이번에도 증상마다 따로 막았다면 세 곳을 고치고도 원인은 남았을 겁니다.
