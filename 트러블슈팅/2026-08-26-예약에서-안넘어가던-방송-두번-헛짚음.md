# 2026-08-26 예약에서 안 넘어가던 방송, 원인 두 번 헛짚음

> 태그: #트러블슈팅 #라이브 #오진 #상태기계

## 무엇을 / 왜

만들어 둔 라이브 방송이 전부 "예약" 에 멈춰 있었다. "방송 중" 으로 안 넘어감. 6개 다 그대로.

영상 서비스(Cloudflare)는 이미 붙어 있고 실제로 스트림도 만들어지는데, 상태만 안 바뀐다.
이걸 왜 이렇게 오래 헛짚었나 싶어서 기록해 둔다.

## 첫 번째 확신 - 웹훅

처음엔 바로 답이 보인다고 생각했다. 서버 환경설정에 웹훅 검증 키가 비어 있었으니까.

가설: 영상 서비스가 "방송 시작됨/종료됨" 알림(웹훅)을 보내는데, 우리가 검증 키가 없어서
전부 거부한다. 그래서 상태가 안 바뀐다. 딱 맞는 것 같았다.

그런데 코드를 끝까지 따라가 보니 아니었다. 그 웹훅 핸들러는 상태를 바꾸는 일을 아예 안 한다.
녹화본(다시보기)을 연결하는 용도였다. 상태 전이는 어디에도 없었음.

```
// 웹훅이 하는 일 전부
if (녹화준비됨) 녹화_video를_스트림에_연결();
// live/ended 로 바꾸는 코드? 없음
```

상태를 올리는 건 웹훅이 아니라 셀러가 "시작" 을 누르는 것 하나뿐이었다. 웹훅 키는 이 증상과
관계가 없었다. (다시보기 연결이 안 되는 별개 문제이긴 했지만 지금 증상은 아님.)

## 진짜 원인 - 크레딧 게이트

"시작" 을 누르면 실행되는 코드를 봤다.

```
start() {
  requireOwned(...);   // 내 방송 맞나
  requireCredit(...);  // <- 여기
  ...
}
```

`requireCredit` 이 잔액 0이면 402를 던진다. 미터링(과금)을 켰든 껐든 무조건 건다. 정책상
"잔액이 있어야 방송을 연다" 니까.

그 테넌트를 보니 크레딧 계정 자체가 없었다. 잔액 0. 그래서 시작할 때마다 402로 막히고,
계속 예약에 남아 있던 거였다. 코드 버그가 아니라 의도된 게이트인데, 테스트 크레딧이 없어서
막힌 것. 테스트 크레딧 넣으니 통과.

## 두 번째 헛짚음 - 토큰이 "무효"

웹훅을 마저 붙이려고 영상 서비스 API를 호출했는데 이번엔 토큰이 "Invalid" 로 나왔다.

```
/user/tokens/verify -> "Invalid API Token"
```

앱은 스트림을 잘 만드는데 토큰이 무효? 앞뒤가 안 맞았다. 값이 잘못 들어갔나, 회전됐나
한참 의심했다.

알고 보니 이 토큰은 "계정 소유 토큰" 이라 검증 주소가 달랐다. `/user/...` 가 아니라
`/accounts/{id}/tokens/verify` 로 물어봐야 했음. 내가 엉뚱한 창구에 물어보고 "무효" 라는
답을 받은 거였다. 제대로 물어보니 멀쩡한(active) 토큰이었다.

## 💡 배운 것

- 그럴듯한 가설로 바로 손대지 말자. "웹훅 키가 없으니 상태가 안 바뀐다" 는 말이 되지만,
  정작 상태를 바꾸는 코드는 웹훅이 아니었다. **증상과 원인을 잇기 전에, 그 상태를 실제로
  바꾸는 코드가 어디인지부터 찾아야 했다.**
- "무효" 라는 응답을 그대로 믿지 말자. 키가 잘못된 게 아니라 내 확인 방법이 틀린 거였다.
  외부 API는 토큰 종류마다 확인 창구가 다를 수 있다.
- 하나의 증상(예약에 멈춤)에 원인 후보가 여럿(웹훅/크레딧/토큰)이었는데, 앞 둘은 관계없고
  진짜는 세 번째였다. **후보를 하나 배제할 때마다 코드로 확인**하고 넘어갔어야 빨랐다.

## 소감

두 번 연달아 확신하고 두 번 틀렸다. 웹훅이라고 확신할 때 코드부터 봤으면 5분이었을 것을,
"딱 맞는 것 같다" 로 시작해서 돌아왔다. 맞는 것 같은 느낌이 제일 위험하다는 걸 또 겪었다.
