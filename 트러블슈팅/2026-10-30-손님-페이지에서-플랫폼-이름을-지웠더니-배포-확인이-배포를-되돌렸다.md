# 2026-10-30 손님 페이지에서 플랫폼 이름을 지웠더니, 배포 확인이 배포를 되돌렸다

> 태그: #트러블슈팅 #배포 #배포확인 #화이트라벨 #재발방지

## 무엇을 / 왜
사진 키오스크 손님은 인화한 사진의 QR 을 찍어, 휴대폰으로 사진을 받는 페이지에 들어왔습니다. 화이트라벨 고객사(자기 브랜드로만 보여야 하는 고객사)의 손님에게는 이 페이지에 플랫폼 이름이 보이면 안 됐습니다.

- 그래서 손님 사진 페이지가 처음 내려주는 HTML 의 제목을 "플랫폼 이름 + Photos" 에서 중립인 "Photos" 로 바꿨습니다.
- 서버, 손님 페이지, 키오스크 시험은 모두 통과했습니다.
- 그런데 합친 뒤 개발 서버 배포가 마지막 단계에서 실패했고, 서버는 이전 판으로 되돌아갔습니다.

## 어떻게 풀었나
- 배포 기록을 보니 DB 변경 확인을 지났고 컨테이너도 모두 정상으로 떴습니다. 실패한 곳은 그다음인 배포 스크립트의 마지막 확인이었습니다.
- 배포 스크립트는 새 판을 띄운 뒤 서버가 응답하는지, 새 버전이 맞는지, 손님 사진 페이지가 제대로 나오는지를 확인하고, 하나라도 실패하면 이전 판으로 되돌리게 되어 있었습니다.
- 세 번째 확인은 손님 사진 페이지를 받아 그 안에 "플랫폼 이름 Photos" 라는 글자가 있는지를 grep 으로 보고 있었습니다. 바로 제가 지운 글자였습니다.
- 페이지는 멀쩡했는데 확인은 페이지가 고장 났다고 판단했고, 되돌리기 장치는 맡은 일을 했습니다. 서버는 이전 판으로 계속 돌아서 손님 쪽에는 영향이 없었습니다.
- 시험에서 잡지 못한 이유도 보였습니다. 이 확인은 실제 서버에 배포할 때만 도는 스크립트 안에 있었고, 페이지 제목을 바꿀 때 그 스크립트가 제목 글자에 기대는지는 보지 않았습니다.
- 제목을 되돌릴 수는 없었습니다. 화이트라벨 손님에게 플랫폼 이름이 보이면 안 됐기 때문입니다. 그래서 페이지에 화면 글과 상관없는 표시 한 줄(`<meta name="…" content="…">`)을 넣고, 확인이 그 표시를 보게 했습니다.
- 그런데 새 표시만 보게 하면 되돌리기가 막힌다는 걸 알게 됐습니다. 같은 확인이 예전 판을 다시 적용하는 길에도 있었는데, 예전 판 페이지에는 새 표시가 없었습니다. 그래서 확인은 옛 제목이나 새 표시 둘 중 하나가 있으면 통과하게 했습니다.
- 같은 엇갈림이 다시 생기지 않게, 배포 스크립트에서 확인 패턴을 뽑아 손님 사진 페이지에 실제로 맞는지 보는 시험을 더했습니다. 고치기 전 스크립트에서는 이 시험이 실패했습니다.
- 배포 스크립트의 다른 확인 가운데 상표 글자에 기대는 곳이 없는지도 훑어봤고, 없었습니다. 다시 합치자 배포가 끝까지 갔습니다.
- 2026-10-29 에도 합친 뒤 배포가 실패했던 터라(빌드 재료 목록에 새 파일이 빠졌던 일), 합치기 전에 잡을 방법도 만들었습니다. 실제 배포와 같은 묶음으로 내 PC 에서 서버 이미지를 만들고 이 마지막 확인까지 돌려 보는 배포 리허설을 만들었습니다. 2026-10-29 에 실패한 판과 이번에 실패한 판을 넣어 보니 둘 다 실패로 잡혔고, 고친 판은 통과했습니다.

## 코드로 보기 (개념 재현)
옛 판과 새 판 페이지를 만들어 두고, 확인 후보 세 가지를 실제 확인처럼 `grep -q -E` 로 돌려 봤습니다. 마지막에는 배포 스크립트에서 확인 패턴을 뽑아 지금 페이지와 대조했습니다. 이름은 모두 예시입니다.

```bash
#!/usr/bin/env bash
# 손님 사진 페이지의 옛 판과 새 판에 배포 확인 세 가지를 돌려 보고,
# 배포 스크립트의 확인 패턴이 지금 페이지에 맞는지 대조한다. 이름은 모두 예시다.
set -u
rm -rf demo && mkdir demo && cd demo

# 옛 판: 첫 제목에 플랫폼 이름이 들어 있다.
cat > page-old.html <<'EOF'
<!doctype html>
<html><head>
  <meta charset="utf-8" />
  <title>Platform Photos</title>
</head><body><div id="app"></div></body></html>
EOF

# 새 판: 화이트라벨 손님에게 플랫폼 이름이 보이지 않게 제목을 중립으로 바꿨다.
#        그리고 화면 글과 상관없는 표시 한 줄을 넣었다.
cat > page-new.html <<'EOF'
<!doctype html>
<html><head>
  <meta charset="utf-8" />
  <meta name="page-kind" content="guest-photos" />
  <title>Photos</title>
</head><body><div id="app"></div></body></html>
EOF

# 배포 확인 후보 세 가지. 배포 스크립트는 페이지를 받아 grep 으로 본다.
title='Platform Photos'                                   # 고치기 전: 화면 글자를 찾는다
marker='name="page-kind" content="guest-photos"'          # 새 표시만 찾는다
both='Platform Photos|name="page-kind" content="guest-photos"'   # 고친 뒤: 둘 중 하나면 통과

for name in title marker both; do
  pattern=${!name}
  line="확인($name):"
  for page in page-old.html page-new.html; do
    # 실제로는 curl 로 받은 페이지를 grep 에 넘긴다. 여기서는 파일을 그대로 넘긴다.
    if grep -q -E "$pattern" "$page"; then result=통과; else result=실패; fi
    line="$line ${page%.html}=$result"
  done
  echo "$line"
done

# 같은 실수를 막는 대조: 배포 스크립트에서 확인 패턴을 뽑아, 지금 페이지에 실제로 맞는지 본다.
cat > deploy-before.sh <<'EOF'
curl --fail --silent http://localhost:9000/guest-check | grep -q 'Platform Photos'
EOF
cat > deploy-after.sh <<'EOF'
curl --fail --silent http://localhost:9000/guest-check | grep -q -E 'Platform Photos|name="page-kind" content="guest-photos"'
EOF
for script in deploy-before.sh deploy-after.sh; do
  # grep -q 뒤 작은따옴표 안의 패턴을 뽑는다(-E 는 있어도 없어도 된다).
  pattern=$(sed -n "s/.*grep -q \(-E \)\{0,1\}'\([^']*\)'.*/\2/p" "$script")
  if grep -q -E "$pattern" page-new.html; then result=맞음; else result=안맞음; fi
  echo "대조 $script: 지금 페이지와 $result"
done
```

Git Bash(GNU grep 3.0)에서 돌린 결과입니다.

```
확인(title): page-old=통과 page-new=실패
확인(marker): page-old=실패 page-new=통과
확인(both): page-old=통과 page-new=통과
대조 deploy-before.sh: 지금 페이지와 안맞음
대조 deploy-after.sh: 지금 페이지와 맞음
```

- 제목 글자만 보는 확인은 새 판에서 실패했습니다. 이번에 배포를 되돌린 경우였습니다.
- 새 표시만 보는 확인은 옛 판에서 실패했습니다. 옛 판을 다시 적용하거나 되돌릴 때 확인이 그 길을 막는 경우였습니다.
- 둘 중 하나를 보는 확인만 두 판 모두 통과했습니다.
- 배포 스크립트의 확인 패턴을 지금 페이지와 대조하자, 고치기 전 스크립트는 맞지 않는다고 나왔습니다. 합치기 전 시험에서 이렇게 걸렸다면 배포까지 가지 않았을 것입니다.

## 💡 배운 것
- 배포 확인은 화면에 보이는 글자가 아니라, 화면 글이 바뀌어도 그대로 남는 표시로 해야 한다는 걸 배웠습니다. 보이는 글자는 이번처럼 제품 요구에 따라 언제든 바뀌었습니다.
- 확인 조건을 바꿀 때는 새 판만이 아니라 되돌아갈 옛 판에서도 통과하는지 봐야 한다는 걸 배웠습니다. 새 판에만 맞춘 확인은 되돌리기를 막을 수 있었습니다.
- 서로 맞아야 하는 두 곳은 사람이 기억하기보다 시험이 대조하게 해야 한다는 걸 다시 배웠습니다([2026-10-29, 빌드 설정에 복사 줄을 넣었는데도, 서버에서는 그 파일이 없었다](../트러블슈팅/2026-10-29-빌드-설정에-복사-줄을-넣었는데도-서버에서는-그-파일이-없었다.md)). 그때는 빌드 재료 목록이었고, 이번에는 배포 확인 글자와 페이지였습니다.
