# 2026-09-28 본인확인 버튼이, 가입 폼을 제출했다

> 태그: #트러블슈팅 #HTML #폼 #React #소셜로그인

## 무엇을 / 왜

소셜 로그인으로 처음 가입하는 사람은 약관 동의 화면을 한 번 거칩니다. 이때 소셜 쪽에서 실명과 휴대폰 번호를 받지 못하면, 같은 화면 안에 **휴대폰 본인확인** 단계가 하나 더 붙어요.

그런데 구글로 가입할 때만 "휴대폰 본인확인" 을 누르면 인증창이 뜨지 않고 이런 문구가 나왔습니다.

```
로그인 정보가 올바르지 않아요. 다시 시도해 주세요.
```

- 네이버·카카오 가입은 멀쩡했습니다.
- 일반(이메일) 가입의 본인확인도 멀쩡했습니다.
- 브라우저 콘솔에는 에러가 하나도 없었습니다.

## 어떻게 풀었나

### 구글만 다른 점부터 찾았다

세 소셜의 차이를 비교해 보니, 네이버·카카오는 가입할 때 실명과 휴대폰을 넘겨 줘서 본인확인 단계가 **아예 나오지 않았습니다.** 구글은 이메일만 주기 때문에 본인확인 단계가 붙는, 유일한 경우였어요. 그러니까 "구글이 이상하다" 가 아니라 "본인확인 단계가 붙은 소셜 가입 화면이 이상하다" 였습니다.

### 주소창이 힌트였다

버튼을 누른 직후 주소창을 보니 콜백 주소는 그대로인데 **뒤에 붙어 있던 `?code=...` 가 사라져 있었습니다.** 콜백 화면은 이 코드로 로그인을 이어 가는데, 코드 없이 다시 열리니 "로그인 정보가 올바르지 않아요" 가 뜬 거였어요.

페이지가 **다시 불려 왔다** 는 뜻입니다. 자바스크립트가 인증창을 여는 게 아니라, 브라우저가 무언가를 제출하면서 페이지를 새로 연 거죠.

### 폼 속의 폼

화면 구조를 보니 이랬습니다.

```tsx
<form onSubmit={handleSignup}>          {/* 가입 폼 */}
  <PhoneVerification />              {/* 본인확인 - 안에 자기 <form> 이 있다 */}
  <Agreements />
  <button type="submit">가입하기</button>
</form>
```

본인확인 컴포넌트는 따로 쓸 때를 위해 **자기 `<form>` 을 갖고** 있었습니다. 일반 가입 화면에서는 가입 폼 **밖에** 놓여 있어서 문제가 없었는데, 소셜 가입 화면에서는 가입 폼 **안에** 넣으면서 폼 속의 폼이 됐어요.

HTML 은 폼 안에 폼을 허용하지 않습니다. 이 상태에서 본인확인 버튼을 누르면 본인확인 폼의 처리(인증창 열기)가 아니라 바깥 가입 폼이 **브라우저 기본 방식으로** 제출됐습니다. `action` 이 없는 폼은 지금 주소로 제출되는데, 이때 주소의 쿼리가 폼 값으로 바뀌면서 `?code=...` 가 사라졌던 거예요.

### 재현하고 나서 고쳤다

고치기 전 코드로 로컬 브라우저에서 같은 순서를 밟아, 주소에서 코드가 사라지는 것까지 똑같이 재현했습니다. 원인이 맞다는 걸 확인한 뒤, 일반 가입 화면과 같은 배치로 본인확인을 가입 폼 **밖으로** 뺐어요.

## 코드로 보기 (개념 재현)

고치기 전입니다.

```tsx
export function SocialSignup() {
  return (
    <form onSubmit={handleSignup}>
      {needsVerification && <PhoneVerification />}  {/* 폼 속의 폼 */}
      <Agreements />
      <button type="submit">가입하기</button>
    </form>
  );
}
```

고친 뒤입니다.

```tsx
export function SocialSignup() {
  return (
    <>
      {/* 본인확인은 자기 <form> 을 가진다. 가입 폼 안에 넣으면 폼 속의 폼이 되어
          버튼이 바깥 가입 폼을 제출해 버린다. 그래서 가입 폼 밖에 둔다. */}
      <div>{needsVerification && <PhoneVerification />}</div>

      <form onSubmit={handleSignup}>
        <Agreements />
        <button type="submit">가입하기</button>
      </form>
    </>
  );
}
```

## 💡 배운 것

**"한 곳에서만 난다" 면 그곳만의 차이를 먼저 찾습니다.** 구글을 의심하기 전에 구글에서만 붙는 화면 조각이 있다는 걸 찾은 게 결정적이었어요.

**주소창도 로그입니다.** 콘솔이 조용해도 주소가 바뀌었다는 건 페이지가 새로 불려 왔다는 뜻이고, 그러면 자바스크립트 오류가 아니라 브라우저 기본 동작을 의심해야 합니다.

**컴포넌트를 다른 곳에 넣을 때는 그 안의 태그도 같이 옮겨집니다.** 컴포넌트 이름만 보면 안에 `<form>` 이 있는지 모릅니다. 폼·버튼처럼 **바깥에 영향을 주는 태그**가 들어 있는 컴포넌트는 어디에 놓이는지 확인해야 합니다.

**원인을 안다고 생각해도 재현부터 합니다.** 고치기 전 코드로 같은 증상을 만들어 보니 "혹시 콜백 문제?" 같은 다른 의심을 깔끔하게 지울 수 있었어요.

## 소감

처음에는 콜백 설정이나 구글 쪽 문제일 거라고 생각했습니다. 막상 원인은 HTML 기초 규칙 하나였어요. 오래 쓴 컴포넌트를 새 화면에 끼워 넣을 때, 그 컴포넌트가 원래 어디에 놓이도록 만들어졌는지를 같이 봐야 한다는 걸 배웠습니다.
