# 2026-08-28 외부에 "발행" 하는 API는, 두 번 부르면 두 번 신고된다

> 태그: #트러블슈팅 #멱등성 #외부연동 #세무

## 무엇을 / 왜

그동안 "세금계산서 발행" 기능은 껍데기만 있었습니다. 요청이 오면 "발행 접수됨" 이라고 응답만 하고, 실제로는 어디에도 보내지 않는 임시 코드였어요. 발행을 대행해 주는 외부 서비스의 테스트 환경을 받으면서, 이 껍데기를 진짜 발행으로 바꾸게 됐습니다.

붙이는 것 자체는 어렵지 않았습니다. 문제는 "붙이고 나면 생기는 위험" 이었어요.

## 어떻게 풀었나

### 스텁일 땐 안전하던 게, 실연동이 되니 위험해졌다

원래 코드는 요청이 올 때마다 새 기록을 하나 남기고 발행기를 불렀습니다. 껍데기(가짜 발행)일 땐 여러 번 불려도 아무 일도 안 일어나니 문제가 없었죠.

그런데 진짜 발행은 다릅니다. 세금계산서는 발행하는 순간 **국세청에 신고** 됩니다. 손님이 버튼을 두 번 누르거나, 네트워크가 끊겨 재요청이 가거나, 새로고침 한 번이면 - 같은 건이 **두 번 신고** 될 수 있습니다. 한 번 신고된 걸 되돌리는 건 훨씬 번거롭고요.

"실제로 바깥에 영향을 주는 호출" 은 같은 요청이 여러 번 와도 **한 번만 일어나게** 만들어야 한다는 걸 여기서 절감했습니다. 흔히 멱등성이라고 부르는 성질입니다.

### 문서번호를 "요청" 이 아니라 "청구 건" 에 묶었다

발행에는 문서번호(사업자별로 겹치면 안 되는 고유번호)가 필요합니다. 처음엔 요청마다 새로 만들려다, 그러면 두 번 요청하면 문서번호도 두 개가 되어 둘 다 발행된다는 걸 깨달았습니다.

그래서 문서번호를 **청구 건에서 결정** 되게 했습니다. 같은 청구 건이면 몇 번을 요청해도 문서번호가 똑같아지도록요. 여기에 더해, 이미 발행됐거나 처리 중인 청구 건이면 아예 발행기를 부르기 전에 막았습니다. 이중 안전장치인 셈입니다 - 우리 쪽에서 먼저 걸러내고, 혹시 동시에 두 요청이 들어와도 외부 서비스가 "같은 문서번호" 를 거부하니까요.

## 코드로 보기 (개념 재현)

```
// 나쁜 예: 요청마다 새 문서번호 → 두 번 부르면 두 번 발행
function 발행요청(청구) {
  const 문서번호 = 랜덤();          // 매번 달라진다
  외부발행(문서번호, 청구.금액);    // 두 번 오면 두 번 신고
}

// 고친 것: 문서번호를 청구 건에 고정 + 이미 처리된 건 차단
function 발행요청(청구) {
  if (이미_발행되었거나_처리중(청구.id)) {
    return 거절("이미 발행된 청구 건입니다");    // ① 우리 쪽 1차 방어
  }
  const 문서번호 = 청구id로_고정(청구.id);       // ② 같은 청구면 늘 같은 값
  외부발행(문서번호, 청구.금액);
  // 동시에 두 요청이 ①을 지나쳐도, 외부가 같은 문서번호를 거부한다(2차 방어)
}
```

## 💡 배운 것

- **스텁이 안전하다고 실연동도 안전한 건 아니다.** 가짜일 땐 여러 번 불려도 무해하던 코드가, 진짜 바깥에 영향을 주기 시작하면 그대로 사고가 된다.
- **멱등키는 "요청" 이 아니라 "대상" 에 묶는다.** 요청마다 새로 만들면 의미가 없다. 같은 대상이면 같은 키가 나와야, 두 번 와도 한 번만 처리된다.
- **방어는 두 겹으로.** 우리 쪽 사전 차단 + 외부의 고유키 거부. 동시성까지 생각하면 한 겹은 뚫린다.

## 소감

"기능을 붙였다" 보다 "붙이고 나서 뭐가 위험해지나" 를 보는 게 더 중요한 일이었습니다. 눈에 보이는 발행은 금방 됐지만, 안 보이는 "두 번 눌렸을 때" 를 막는 데 시간을 더 썼고, 그게 맞는 선택이었다고 생각합니다.
