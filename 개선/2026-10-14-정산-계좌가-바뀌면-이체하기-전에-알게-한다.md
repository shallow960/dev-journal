# 2026-10-14 정산 계좌가 바뀌면, 이체하기 전에 알게 한다

> 태그: #개선 #보안 #암호화 #권한 #데이터모델링

## 무엇을 / 왜

상점 오너는 판매자 정산금을 판매자 계좌로 직접 이체합니다. 그런데 판매자가 계좌를 적어 둘 곳이 없어서, 판매자 화면에 사업자 정보·서류·정산 계좌를 받는 "내 정보"를 만들었어요.

만들면서 가장 신경 쓴 건 **계좌가 바뀌는 순간**이었습니다. 누가 판매자 계정을 가로채 계좌를 자기 것으로 바꾸면, 오너는 평소처럼 이체하고 돈은 엉뚱한 곳으로 갑니다. 계좌를 받는 기능이 오히려 사고의 입구가 될 수 있었어요.

## 어떻게 풀었나

- **바뀌면 "확인 전":** 계좌에 바뀐 시각(`changed_at`)과 오너가 확인한 시각·사람(`confirmed_at`, `confirmed_by`)을 두었습니다. 계좌나 통장 사본이 바뀌면 확인 칸을 비워 "확인 전"이 돼요.
- **같은 값이면 그대로:** 같은 계좌를 다시 저장하면 아무것도 바꾸지 않습니다. 저장할 때마다 경고가 뜨면 오너가 경고에 무뎌지니까요. 계좌번호는 암호문으로 저장하는데, 암호문은 저장할 때마다 달라서 **풀어서** 비교했습니다.
- **돈을 보내는 순간에 보이게:** 관리 화면 판매자 목록에 "계좌 확인 필요"와 메뉴 옆 숫자를 달고, 정산 "지급 완료" 창에 **이체할 계좌와 경고**를 띄웠습니다.
- **확인은 오너·관리자만:** 통장 사본을 보고 "확인했어요"를 누르면 풀리고, 누가 언제 확인했는지 남습니다.
- **보이는 범위는 역할별로:** 판매자 화면에는 끝 4자리만, 스태프에게는 가린 번호와 예금주만, 통장 사본은 오너·관리자만 봅니다. 서류는 비공개 분류로 두어 1시간짜리 서명 주소로만 열리고, 파일 키는 서버가 정해 저장해요. 화면이 키를 보내지 않으니 남의 파일 키를 끼워 넣을 수 없습니다.
- **다른 입구도 같은 규칙:** 예전부터 있던 다른 경로(출금 요청)로 계좌가 바뀌어도 똑같이 "확인 전"이 되게 했습니다.
- **감사 기록에는 값 대신:** 사업자 정보는 바뀐 칸 이름만, 계좌는 가린 값의 전후만 남겼어요.

## 코드로 보기 (개념 재현)

```java
@Transactional
public void savePayoutAccount(long sellerId, AccountInput in, String ip) {
    Optional<StoredAccount> current = accountRepo.find(sellerId); // 읽을 때 계좌번호를 풀어서 준다

    // 같은 계좌면 아무것도 바꾸지 않는다.
    // 암호문은 저장할 때마다 달라서(무작위 IV) 암호문끼리는 비교할 수 없다. 푼 값으로 비교한다
    boolean changed = current.isEmpty()
        || !current.get().bank().equals(in.bank())
        || !current.get().holder().equals(in.holder())
        || !digits(current.get().number()).equals(digits(in.number()));
    if (!changed) {
        return;
    }

    // 바뀌었으면 저장하면서 "오너 확인"을 비운다
    jdbc.sql("""
            INSERT INTO payout_account (seller_id, bank, holder, number_enc, changed_at)
            VALUES (:seller, :bank, :holder, :number, now())
            ON CONFLICT (seller_id) DO UPDATE
            SET bank         = EXCLUDED.bank,
                holder       = EXCLUDED.holder,
                number_enc   = EXCLUDED.number_enc,
                changed_at   = now(),
                confirmed_at = NULL,   -- 오너가 다시 확인해야 한다
                confirmed_by = NULL
            """)
        .param("seller", sellerId)
        .param("bank", in.bank())
        .param("holder", in.holder())
        .param("number", cipher.encrypt(in.number()))
        .update();

    // 감사 기록에는 가린 값만 남긴다
    audit.write("payout_account.update", sellerId, ip,
        current.map(a -> mask(a.number())).orElse(null), mask(in.number()));
}

static String digits(String s) {
    return s.replaceAll("\\D", ""); // 하이픈·공백 차이는 같은 계좌로 본다
}

static String mask(String number) {
    String d = digits(number);
    int keep = Math.min(4, d.length());
    return "*".repeat(d.length() - keep) + d.substring(d.length() - keep); // 끝 4자리만
}
```

```sql
-- 오너 화면의 숫자: 확인을 기다리는 계좌 변경
SELECT COUNT(*)
FROM payout_account
WHERE changed_at IS NOT NULL
  AND confirmed_at IS NULL;
```

테스트는 같은 계좌를 다시 저장하면 상태가 그대로인지, 다른 계좌나 통장 사본을 새로 올리면 다시 "확인 전"이 되는지, 스태프에게는 가린 계좌만 가는지, 다른 경로로 바뀌어도 확인 전이 되는지를 봤습니다.

## 💡 배운 것

**기능을 만들 때 "이걸로 무슨 사고가 날 수 있나"를 먼저 그려 봤습니다.** 계좌를 받는 기능은 계좌를 바꿔치기하는 기능이기도 했어요.

**경고는 행동하는 순간에 보여야 합니다.** 목록의 표시만으로는 놓칠 수 있어서, 실제로 돈을 보내는 "지급 완료" 창에 계좌와 경고를 띄웠습니다.

**변경 감지는 "정말 바뀌었을 때"만.** 같은 값 저장에도 경고가 뜨면 경고가 소음이 됩니다. 암호화한 값은 풀어서 비교해야 했어요.

**입구가 여러 개면 모든 입구에 같은 규칙을 겁니다.** 새 화면만 막으면 옛 경로가 뒷문이 돼요.

## 소감

처음엔 "계좌를 적는 칸"을 만드는 일이라고 생각했는데, 실제로 시간을 쓴 건 계좌가 바뀌는 순간을 어떻게 드러낼지였습니다. 본인 재인증과 알림 메일은 아직 없어서, 이 정도로 충분한지는 따로 확인을 받기로 했어요.
