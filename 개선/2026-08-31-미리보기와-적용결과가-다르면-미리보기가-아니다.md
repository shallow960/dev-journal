# 2026-08-31 미리보기와 적용 결과가 다르면, 그건 미리보기가 아니다

> 태그: #개선 #설계 #템플릿 #단일출처

## 무엇을 / 왜

쇼핑몰 디자인 템플릿을 10종 만들어 뒀습니다. 고르면 그 디자인으로 시작할 수 있게요. 그런데 갤러리에서 **보기만 되고 적용이 안 됐습니다.** 마음에 들어도 거기서 끝이었어요.

"미리보기 → 홈 편집기로 넘겨서 → 배치 고치고 → 적용" 흐름으로 잇기로 했습니다.

## 어떻게 풀었나

### 이어붙일 수 있는 구조인지부터 봤다

두 화면이 다루는 게 뭔지 봤더니 이랬습니다.

```
갤러리 템플릿 = 통짜 React 컴포넌트 (완성된 화면 하나)
홈 편집기     = [{섹션코드, 폭, 설정}, ...] 배열
```

**표현 방식이 아예 달랐습니다.** 통짜로 그려진 화면을 배열로 쪼갤 수는 없어요. 그래서 각 템플릿이 "어떤 섹션을 어떤 순서·폭으로 놓는가"를 데이터로 갖게 만들어야 했습니다.

찾아보니 그 데이터를 담을 자리가 이미 DB에 있었습니다. 그런데 열어보니 이렇더군요.

```
소프트 뉴트럴  : [히어로, 카테고리, 상품목록, 배너, 푸터]
컴팩트 그리드  : [히어로, 카테고리, 상품목록, 배너, 푸터]
프리미엄 부티크: [히어로, 카테고리, 상품목록, 배너, 푸터]
에디토리얼    : [히어로, 카테고리, 상품목록, 배너, 푸터]
```

넷이 완전히 똑같았습니다. 형식만 채워 둔 껍데기였어요. 게다가 이 값을 **읽는 코드가 어디에도 없었습니다.** 그래서 템플릿을 바꿔도 배치가 안 따라왔던 거고요.

### 여기서 갈림길이 있었다

섹션 조합으로는 통짜 디자인을 100% 똑같이 못 그립니다. 그러면 이렇게 됩니다.

```
갤러리에서 본 화면   ≠   적용한 뒤의 화면
```

처음엔 "갤러리는 예쁜 시안으로 두고, 적용은 근사치로" 를 생각했습니다. 만들어 둔 통짜 디자인이 아까웠거든요.

근데 그러면 오너가 **적용해보고 되돌리기를 반복**하게 됩니다. 그럴 거면 미리보기가 왜 있나 싶더라고요. 미리보기의 존재 이유가 "적용하기 전에 결과를 아는 것"인데, 결과가 다르면 오히려 없느니만 못합니다.

그래서 **갤러리 미리보기를 편집기와 같은 렌더러로 다시 그리기로** 했습니다. 통짜 컴포넌트로 그리던 걸 섹션 배열로 그리게요. 보이는 것이 곧 적용 결과가 됩니다.

대신 템플릿의 개성은 다른 데서 냅니다.

- 색·글꼴 (템플릿마다 다른 팔레트)
- 섹션 조합과 순서
- 섹션별 세부 설정 - 같은 "상품 목록"이어도 4열 / 5열, 이미지 1:1 / 3:4, 카드에 테두리 있음 / 없음

### 폭이 두 가지밖에 없었다

프리셋을 채우다 막혔습니다. 아이템 폭이 50% 아니면 100% 뿐이었는데, 템플릿들이 쓰는 건 이랬거든요.

```
2:1   (왼쪽 큰 배너 + 오른쪽 쿠폰 타일)
1.4:1 (영상 + 상품 리스트)
3분할 (프로모 타일 3개)
```

하나도 표현이 안 됩니다. 폭을 늘려야 했는데, 여기서 배운 게 있었습니다.

처음엔 12분할(25·33·50·66·75)을 제안했습니다. 3등분·4등분이 딱 떨어지니까요. 그런데 이런 지적을 받았어요.

> 30 / 30 / 30 이면 그 사이에 5 / 5 만큼 간격을 두는 거지

**맞는 말이었습니다.** 제가 간격을 0으로 놓고 생각했던 거예요. 30 세 개면 90이고, 남은 10이 사이 간격이 됩니다. CSS 로도 딱 떨어집니다 - 컨테이너에 `space-between` 을 주면 남은 몫이 사이로 자동으로 나뉘어 들어가요.

```
50 + 50           → 붙음 (간격 0)
30 + 30 + 30      → 사이 5씩
60 + 30           → 2:1, 사이 10
```

폭만 정하면 간격이 따라옵니다. 간격을 따로 설정할 필요가 없어요.

### 폭을 클래스로 조립하면 안 된다

폭을 적용하면서 두 번 막혔습니다.

**첫 번째** - 클래스 이름을 문자열로 만들었더니 폭이 통째로 안 먹혔습니다.

```
안 됨:  `pc:w-[${폭}%]`     ← 빌드 결과에서 사라진다
```

CSS 도구가 소스에 **그대로 적힌 클래스만** 뽑아 가기 때문이었습니다. 조립한 문자열은 소스에 없는 걸로 칩니다.

**두 번째** - 그러면 인라인 스타일로 주면 되겠다 싶었는데, 이번엔 모바일에서 30% 조각이 그대로 남았습니다. 인라인 스타일은 **화면 크기별 조건을 걸 수 없거든요.**

답은 둘을 섞는 거였습니다. 값은 CSS 변수로 넘기고, 적용은 클래스가 합니다.

```
style = { --아이템폭: "30%" }        ← 값은 변수로
class = "w-full pc:w-[var(--아이템폭)]"  ← 조건은 클래스가 (소스에 그대로 적힘)
```

## 코드로 보기 (개념 재현)

```
// 템플릿이 갖는 것 = 섹션 배열 + 색 + 글꼴
컴팩트그리드 = {
  섹션: [
    { 코드: "헤더",     폭: 100 },
    { 코드: "히어로",   폭: 60 },   ┐ 2:1, 사이 10 간격
    { 코드: "배너",     폭: 30 },   ┘
    { 코드: "상품목록", 폭: 100, 설정: { 열: 5, 이미지비율: "1:1" } },
    { 코드: "푸터",     폭: 100 },
  ],
  팔레트: { 배경: "#fff", 강조: "#3b5bdb" },
}

// 갤러리 미리보기와 편집기가 같은 렌더러를 쓴다
갤러리미리보기 = 렌더러(템플릿.섹션, 템플릿.팔레트)
홈편집기      = 렌더러(내가고친섹션, 템플릿.팔레트)
//              ↑ 같은 함수 = 보이는 게 곧 결과
```

## 💡 배운 것

- **미리보기는 정확하거나 없거나다.** "비슷하게 보여주기"는 오히려 신뢰를 깎는다. 결과와 다르면 결국 적용해보고 되돌리게 되고, 그럴 거면 미리보기가 시간을 뺏는 셈이다.
- **껍데기 데이터는 없는 것보다 나쁠 수 있다.** 자리는 있는데 값이 전부 같고 읽는 코드도 없었다. "구조는 있으니 나중에 채우면 되겠지" 로 남겨두면, 다들 채워져 있는 줄 안다.
- **남는 몫이 간격이다.** 폭과 간격을 따로 설정하게 만들 뻔했는데, 폭 합이 100보다 작으면 남은 게 사이로 들어간다. 설정을 하나 줄이면 사용자가 맞춰야 할 것도 하나 준다.
- **CSS 클래스는 조립하면 안 된다.** 도구가 소스를 훑어 클래스를 뽑는 구조라, 문자열로 만든 클래스는 존재하지 않는 것과 같다. 값은 CSS 변수로, 조건은 소스에 적힌 클래스로.

## 소감

"연결만 하면 되겠지" 하고 시작했는데, 표현 방식이 다르다는 걸 알고 나서 설계를 다시 봐야 했습니다.

제일 고민한 건 만들어 둔 통짜 디자인 10종을 포기하는 부분이었어요. 예쁘게 뽑아 놨는데 섹션 조합으로 다시 그리면 100% 재현이 안 되니까요. 근데 "미리보기와 결과가 다른 게 더 큰 문제"라는 쪽으로 정리했습니다.

그리고 폭 이야기를 하다 "30/30/30이면 사이가 5/5 아니냐"는 말을 듣고, 제가 문제를 더 어렵게 만들고 있었다는 걸 알았습니다. 간격을 따로 다루려던 걸 폭 하나로 풀 수 있었어요. 설정을 늘리기 전에 "이거 이미 다른 값이 정해주고 있는 거 아닌가"를 먼저 봐야겠다 싶었습니다.
