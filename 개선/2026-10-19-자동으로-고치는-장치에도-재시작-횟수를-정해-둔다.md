# 2026-10-19 자동으로 고치는 장치에도, 재시작 횟수를 정해 둔다

> 태그: #개선 #자동복구 #운영 #인증서 #systemd

## 무엇을 / 왜

메시지 브로커의 보안 인증서를 바꾸는 스크립트는 하루 한 번 새벽(03:40)에 돕니다. 인증서를 바꾸려면 브로커를 재시작해야 하고, 재시작하면 매장 키오스크 연결이 모두 한 번 끊기기 때문이에요.

그런데 교체가 중간에 멈추면(파일만 바뀌고 확인은 못 한 상태) "확인 대기" 표시가 남고, 다음 새벽까지 그대로였습니다. 그동안 이런 일이 생길 수 있었어요.

- 다른 스크립트(키오스크 계정 동기화)가 그 인증서를 건드리지 않으려고 5분마다 작업을 미룹니다. 그동안 키오스크 계정 변경이 막혀요.
- 되돌리기까지 실패했다면, 브로커가 꺼진 채 하루를 보낼 수도 있었습니다.

처음 나온 제안은 "인증서 스크립트를 매시간 돌리자" 였어요. 하지만 그러면 새 인증서가 들어온 날, 낮에 그 인증서를 설치하면서 브로커가 재시작됩니다. 새벽에 몰아 둔 이유가 사라지는 거예요.

## 어떻게 풀었나

1. **매시간 실행을 따로 만들되, "멈춘 상태 마무리" 만 하게 했습니다.** 대기 표시가 없으면 아무것도 하지 않고 끝나요. 새 인증서는 설치하지 않습니다. 새 인증서는 계속 새벽에만 들어가요.
2. **다시 검토하니 구멍이 있었습니다.** 대기 표시가 남아 있는데 브로커가 **인증서와 상관없는 이유로** 비정상이면(상태 점검용 계정 비밀번호가 어긋났거나, 접속이 꽉 찬 경우), 매시간 실행이 "인증서 탓" 으로 보고 시간마다 재시작을 두 번(새 인증서로 한 번, 예전 것으로 되돌리며 한 번) 할 수 있었어요. 하루 48번 끊길 수 있는 셈입니다.
3. **그래서 고치기 전에 원인부터 가르게 했습니다.** 실행 중인 브로커는 건드리기 전에, 1회용 브로커에 디스크의 인증서를 넣어 읽히는지 먼저 봐요.
   - 읽히면 인증서 문제가 아닙니다. 재시작하지 않고 "인증서 문제 아님" 으로 실패를 드러내요. 원인을 고치면 다음 실행이 표시를 정리합니다.
   - 읽히지 않을 때만 예전 인증서로 되돌리며 재시작합니다.
4. **재시작은 대기 인증서 하나당 한 번만 합니다.** 재시작하기 **전에** "이 인증서로 한 번 시도함" 을 먼저 적어 둬요. 재시작 직후에 끊겨도 다음 실행은 다시 시도하지 않습니다(틀려도 안전한 쪽으로). 그 뒤는 새벽 실행이나 사람이 맡아요.

실제 브로커로 확인했습니다. 상태 점검용 비밀번호를 일부러 틀리게 한 채 매시간 실행을 세 번 돌려도 브로커의 시작 시각과 재시작 횟수가 그대로였고(재시작 0번), 비밀번호를 되돌리자 다음 실행이 재시작 없이 표시를 정리했어요. 재시작을 반복하던 브로커는 매시간 실행 한 번으로 되살아났습니다.

## 코드로 보기 (개념 재현)

```bash
#!/usr/bin/env bash
# 개념 재현: 매시간 도는 "마무리 전용" 실행. 이름과 경로는 모두 더미다.
set -euo pipefail

pending=state/cert.pending          # "확인 대기" 표시 (대상 인증서 지문이 들어 있다)
tried=state/cert.restart-tried      # "이 인증서로 재시작을 한 번 시도함"

# 표시가 없으면 할 일이 없다. 새 인증서도 여기서는 설치하지 않는다.
[ -f "$pending" ] || exit 0
target=$(cat "$pending")

# 이미 적용돼 있으면 재시작 없이 정리만 한다
if broker_is_healthy && broker_serves "$target"; then   # 더미 함수
  rm -f "$pending" "$tried"
  exit 0
fi

# 고치기 전에 원인부터 가른다: 1회용 브로커로 디스크의 인증서를 먼저 판정
if pair_loads_in_throwaway; then                         # 더미 함수
  echo "인증서 문제 아님: 재시작하지 않음" >&2
  exit 1                                                 # 실패로 드러내고, 원인은 사람이 본다
fi

# 같은 인증서로는 한 번만 재시작한다
if [ "$(cat "$tried" 2>/dev/null)" = "$target" ]; then
  echo "이 인증서로는 이미 한 번 재시작했음: 새벽 실행이나 수동 조치 대기" >&2
  exit 1
fi
echo "$target" > "$tried"             # 재시작 "전에" 먼저 적는다

put_back_old_cert                     # 예전 인증서로 되돌리고 (더미 함수)
restart_and_prove                     # 재시작해서 실제로 서비스되는지 확인 (더미 함수)
rm -f "$pending" "$tried"
```

## 💡 배운 것

**자동으로 고치는 장치도 장애를 만들 수 있다는 걸 배웠습니다.** 고치는 동작(재시작)의 비용이 크면, 장치가 자주 돌수록 잘못 판단했을 때의 피해도 커져요. 그래서 "얼마나 자주" 와 "몇 번까지" 를 같이 정해야 했습니다.

**고치기 전에 원인을 가른다는 걸 다시 배웠습니다.** 2026-09-18 에 쌓인 알림을 끄기 전에 원인부터 갈랐는데, 이번엔 사람이 아니라 스크립트가 가르게 했어요. 가르지 않으면 인증서와 상관없는 문제에도 인증서를 고치려 듭니다.

**반복 실행되는 작업의 "한 번만" 은 기록으로 지킨다는 걸 다시 배웠습니다.** 2026-08-14 자동 결제에서 "조건이 참이면 실행" 은 계속 참일 수 있다는 걸 배웠는데, 재시작도 똑같았어요. 행동하기 전에 기록부터 남기니, 중간에 끊겨도 같은 행동을 반복하지 않았습니다.

**영향이 큰 동작은 시간대를 지킨다는 걸 배웠습니다.** 매시간은 마무리만, 새로 바꾸는 건 새벽에. 빨리 고치는 것과 손님이 있는 시간에 끊지 않는 것을 둘 다 지키는 나눔이었어요.
