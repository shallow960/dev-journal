# 2026-08-28 설정이 없으면, 결제가 조용히 "성공" 하고 있었다

> 태그: #개선 #결제 #안전장치 #실패설계

## 무엇을 / 왜

결제 코드를 살펴보다가 이상한 걸 발견했습니다. 스토어에 실제 결제사 설정이 안 돼 있으면, 결제가 **가짜로 승인** 되고 있었어요. 개발할 때나 데모할 때 편하라고 넣어둔 장치입니다 - 결제사 계약 전에도 화면이 돌아가게요.

문제는, 이게 실서비스에 그대로 나가면 위험하다는 거였습니다.

## 어떻게 풀었나

### "돌아가게 하려던" 편의가, 조용한 사고가 될 수 있었다

상상해 봤습니다. 배포할 때 결제사 자격증명 하나를 실수로 빠뜨립니다. 그러면 손님 화면엔 **"결제 성공"** 이 뜨는데, 실제로는 아무 데도 청구가 안 됩니다. 물건은 나가고 돈은 안 들어오는데, 아무도 오류를 못 봅니다. 로그에도 성공이라고 찍히고요.

가장 무서운 건 "실패" 가 아니라 **"조용한 성공"** 이었습니다. 실패는 눈에 띄지만, 가짜 성공은 한참 뒤 정산이 안 맞을 때에야 발견됩니다.

### 편의를 없애는 대신, 환경에 따라 갈랐다

편의 자체를 없애면 로컬 개발이 불편해집니다. 그래서 **환경에 따라 다르게** 동작하게 했습니다.

- 로컬·테스트: 지금처럼 가짜 승인 허용 (설정 없이도 개발이 돌아가게)
- 운영: 결제 수단이 준비 안 됐으면 **가짜 성공 대신 명시적으로 실패**

기본값은 "운영" 쪽(안전한 쪽)으로 뒀습니다. 아무 설정도 안 하면 자동으로 안전하게 - 실수로 편의 모드가 켜지는 게 아니라, 실수로 꺼지는 방향으로요. 혹시 운영에서 이 편의가 켜지면 서버가 뜰 때 경고 로그를 남기게도 했습니다.

## 코드로 보기 (개념 재현)

```
// 전: 설정이 없으면 조용히 가짜 처리기로 폴백 → 늘 "성공"
function 결제수단_고르기(스토어) {
  const 실결제 = 스토어.활성_결제사();
  return 실결제 ?? 가짜결제기();      // 없으면 가짜, 그리고 가짜는 늘 승인
}

// 후: 환경에 따라 - 운영은 조용한 성공 대신 명시적 실패
function 결제수단_고르기(스토어) {
  const 실결제 = 스토어.활성_결제사();
  if (실결제) return 실결제;
  if (가짜허용) return 가짜결제기();           // 로컬·테스트만
  throw 실패("결제 수단이 설정되지 않았습니다"); // 운영: 조용히 넘어가지 않는다
}
```

## 💡 배운 것

- **조용한 성공은 실패보다 위험하다.** 실패는 바로 보이지만, 가짜 성공은 장부가 안 맞을 때에야 드러난다. 확신이 없으면 성공시키지 말고 실패시키는 게 맞다.
- **기본값은 안전한 쪽으로.** 아무것도 설정 안 했을 때 위험 모드가 아니라 안전 모드가 되게. 편의는 명시적으로 켜야만 켜지도록.
- **개발 편의와 운영 안전은 같이 갈 수 있다.** 없앨 필요 없이, 환경으로 가르면 된다.
