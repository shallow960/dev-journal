# 2026-10-13 '첫 구매'의 뜻을, 세 곳이 따로 정하지 않게 했다

> 태그: #개선 #쿠폰 #도메인규칙 #SQL #테스트 #Spring

## 무엇을 / 왜

쿠폰 종류에 '첫 구매'가 있었는데, 실제로는 **아무도 그 종류를 검사하지 않았습니다.** 누구나 받아서 아무 주문에나 쓸 수 있었어요. 다른 쇼핑몰 빌더의 안내를 참고해서 "이 상점에서 구매 이력이 없는 회원만 받고, 첫 주문에만 쓴다"로 정했습니다.

검사가 필요한 곳은 세 군데였습니다.

1. 쿠폰 받기
2. 결제 금액 계산(쿠폰을 적용한 견적)
3. 이미 만든 주문에 쿠폰 걸기

세 곳이 각자 "구매 이력"을 판단하면, 언젠가 한 곳만 기준이 바뀌어 서로 다른 답을 내게 됩니다.

## 어떻게 풀었나

- **'구매 이력'을 먼저 문장으로 정했습니다:** 결제까지 간 주문 중, 주문 전체가 취소·반품으로 끝나지 않은 것.
  - 결제 전 주문, 결제를 안 해서 자동 취소된 주문: 이력 아님
  - 주문 전체 취소·전체 반품: 이력 아님(첫 주문을 통째로 취소하면 다시 대상이 됨)
  - 일부만 취소·반품한 주문: 이력
- **판정을 클래스 하나에 두고** 세 곳이 그것만 부르게 했습니다.
- **자기 자신을 빼고 봐야 하는 경로:** 3번은 쿠폰을 거는 그 주문이 이미 결제된 상태라 이력으로 잡혀 버립니다. 그래서 "이 주문 말고 이력이 있는지"를 묻는 메서드를 따로 뒀어요.
- 받기 목록에서도 대상이 아니면 빼고, 막힐 때는 이유 코드를 보내 화면이 "첫 주문 전용 쿠폰"이라고 알려 줍니다.

## 코드로 보기 (개념 재현)

```java
@Component
public class FirstOrderRule {

    // 이력으로 보지 않는 주문 상태: 결제 전, 취소, 전체 반품 완료
    private static final String NOT_PURCHASED = "'PENDING', 'CANCELED', 'FULLY_RETURNED'";

    private final JdbcClient jdbc;

    public FirstOrderRule(JdbcClient jdbc) {
        this.jdbc = jdbc;
    }

    public boolean hasPurchased(UUID memberId) {
        return hasPurchasedOtherThan(memberId, null);
    }

    /** 이미 만든 주문에 쿠폰을 걸 때는 그 주문을 빼고 본다. */
    public boolean hasPurchasedOtherThan(UUID memberId, UUID exceptOrderId) {
        return jdbc.sql("""
                select exists (
                    select 1 from shop_orders o
                    where o.member_id = :memberId
                      and (cast(:except as uuid) is null or o.id <> cast(:except as uuid))
                      and o.status not in (%s)
                )
                """.formatted(NOT_PURCHASED))
            .param("memberId", memberId)
            .param("except", exceptOrderId)
            .query(Boolean.class)
            .single();
    }
}
```

```java
// 받기·견적·적용 세 곳이 같은 규칙만 부른다
if (coupon.isFirstOrderOnly() && firstOrderRule.hasPurchased(memberId)) {
    throw new CouponRejected("FIRST_PURCHASE_ONLY"); // 화면은 이 코드로 이유를 보여 준다
}
```

테스트는 경계 사례를 하나씩 확인했습니다. 첫 주문 전에는 받을 수 있는지, 결제한 뒤에는 막히는지, 결제 안 해서 자동 취소된 주문은 이력이 아닌지, 전체 취소하면 다시 대상인지, 일부만 반품하면 여전히 이력인지.

## 💡 배운 것

**정책 이름을 데이터 조건으로 바꾸는 게 일의 절반입니다.** '첫 구매'라는 짧은 말 안에 미결제, 부분 취소, 전체 반품 같은 경계가 숨어 있었어요.

**같은 판정을 여러 곳에서 하면 한 곳에 모읍니다.** 기준이 바뀌어도 한 군데만 고치면 되고, 세 곳이 다른 답을 낼 일이 없습니다.

**자기 자신을 빼고 봐야 하는 경로가 있습니다.** "이력이 있나?"를 묻는 순간 지금 다루는 주문이 그 이력이 될 수 있다는 걸 놓치기 쉬웠습니다.

## 소감

쿠폰 종류에 이름만 있고 규칙이 없었다는 게 조금 무서웠습니다. 이름이 있으면 동작도 있을 거라고 믿지 말고, 그 이름을 검사하는 코드가 실제로 있는지부터 찾아보게 됐습니다.
