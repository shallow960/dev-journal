# 2026-10-15 약관은 고치지 않고, 새 판을 쌓는다

> 태그: #개선 #데이터모델 #감사기록 #PostgreSQL #트리거

## 무엇을 / 왜

"이 손님이 가입할 때 어떤 약관에 동의했나요?"에 답할 수 있어야 했습니다. 그런데 약관은 저장하면 예전 내용 위에 덮어써졌고, 동의 기록에는 "동의함, 언제"만 있었어요. 약관이 바뀐 뒤에는 그때 무엇에 동의했는지 알 길이 없었습니다.

약관이 비어 있어도 가입과 주문이 그대로 되는 것도 문제였어요. 빈 약관에 동의한 기록은 의미가 없으니까요.

## 어떻게 풀었나

- 약관을 저장할 때마다 **새 판(version)** 을 만들고, 만든 판은 **DB 트리거로 고칠 수 없게** 했습니다. 바꾸려면 새 판을 올려야 해요.
- 판마다 원문, 원문의 해시, 시행일을 둡니다. 시행일이 미래인 판은 그날까지 지금 판이 쓰이고, 화면에는 바뀔 내용과 시행일이 함께 보여요.
- 동의 기록에는 **그때 시행 중인 판의 번호** 를 잇습니다. 화면을 보는 사이 판이 바뀌었으면(화면이 보낸 판 번호와 지금 판 번호가 다르면) 다시 보게 했어요.
- 약관이 비어 있으면 가입·주문을 받지 않습니다.

## 코드로 보기 (개념 재현)

```sql
-- 판은 한 번 만들면 고칠 수 없다
CREATE TABLE terms_version (
    id            BIGSERIAL   PRIMARY KEY,
    shop_id       BIGINT      NOT NULL,
    kind          TEXT        NOT NULL,   -- terms / privacy
    body          TEXT        NOT NULL,
    body_sha256   TEXT        NOT NULL,
    effective_at  TIMESTAMPTZ NOT NULL,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE FUNCTION forbid_terms_update() RETURNS trigger AS $$
BEGIN
    RAISE EXCEPTION 'terms versions are immutable';   -- 고치려면 새 판을 넣는다
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER terms_version_immutable
    BEFORE UPDATE ON terms_version
    FOR EACH ROW EXECUTE FUNCTION forbid_terms_update();

-- 동의는 '무엇에' 동의했는지 판을 가리킨다
CREATE TABLE consent (
    id          BIGSERIAL   PRIMARY KEY,
    member_id   BIGINT      NOT NULL,
    version_id  BIGINT      NOT NULL REFERENCES terms_version(id),
    agreed_at   TIMESTAMPTZ NOT NULL,
    ip          INET
);
```

```java
// 가입할 때: 화면이 보여 준 판과 지금 시행 중인 판이 같은지 본다
TermsVersion current = versions.currentFor(shopId, "terms", now);
if (current == null) {
    throw new ConflictException("약관이 비어 있어 가입을 받을 수 없어요");

if (!current.id().equals(request.seenVersionId())) {

consents.save(new Consent(memberId, current.id(), now, clientIp));
```

## 💡 배운 것

**기록을 남긴다는 건 덮어쓰지 않는 데서 시작합니다.** 내용을 고치는 대신 새 판을 쌓으면, 과거 시점의 내용이 저절로 남아요.

**"고칠 수 없음"은 서비스 코드보다 DB 에서 막는 게 확실합니다.** 화면이나 서비스 코드에서 막아도 다른 경로로 UPDATE 하면 그만이에요. 트리거는 어떤 경로로 와도 막습니다.

**동의는 무엇에 동의했는지를 가리켜야 합니다.** 동의 여부만 있으면 내용이 바뀐 뒤에는 증거가 되지 않았어요.

## 소감

처음엔 약관 칸 하나를 저장하는 단순한 기능이었는데, "나중에 증명할 수 있어야 한다"는 요구가 붙으니 구조가 완전히 달라졌습니다. 요구가 '보여 주기'에서 '증명하기'로 바뀌면 데이터 모델부터 다시 봐야 한다는 걸 배웠어요.
