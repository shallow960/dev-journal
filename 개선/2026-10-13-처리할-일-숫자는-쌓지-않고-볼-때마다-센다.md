# 2026-10-13 처리할 일 숫자는, 쌓지 않고 볼 때마다 센다

> 태그: #개선 #React #API설계 #권한 #UX

## 무엇을 / 왜

관리 화면 네 곳(플랫폼 운영 콘솔, 상점 콘솔, 상점 관리 화면, 판매자 센터)의 왼쪽 메뉴 옆에 **처리할 일이 몇 건인지** 숫자를 달기로 했습니다. 방법은 두 가지였어요.

1. 일이 생길 때마다 '알림' 행을 쌓고, 처리하거나 읽으면 지운다.
2. 화면이 물어볼 때 서버가 **지금 상태로** 센다.

1번은 처리했는데 알림이 남거나, 알림을 만들지 않은 경로로 생긴 일이 빠지는 식으로 실제 상태와 어긋나기 쉽습니다. 처리할 일은 이미 상태(답 없음, 발송 전, 신청됨 등)로 DB에 있으니 2번을 골랐습니다.

## 어떻게 풀었나

- **화면마다 건수 API 하나:** 예를 들어 상점 관리 화면은 보낼 주문, 반품·교환 요청, 답 없는 문의, 입점 신청, 재검수 요청, 안 읽은 판매자 메시지, 정산일이 된 명세를 한 번에 셉니다. 메뉴 항목마다 따로 요청하지 않아요.
- **역할별로 서버에서 거르기:** 결제 관련 숫자는 오너만, 정산은 스태프 제외. 화면에서 숨기기만 하면 API 응답에는 숫자가 남으니까요.
- **다시 셀 때를 정하기:** 화면 진입, 메뉴 이동, 창으로 돌아올 때, 무언가 바꾸는 요청이 성공했을 때, 그리고 1분마다. 신호가 한꺼번에 오면 짧게 모아서 한 번만 셉니다. "바꾸는 요청 성공"은 공통 API 클라이언트가 이벤트로 알려 줘서, 화면마다 갱신 코드를 넣지 않았어요.
- **줄어들 수 없는 숫자 찾기:** 세어 보니 영원히 줄지 않는 숫자가 있었습니다. 서비스 문의·체험 신청은 상태를 바꿀 방법이 없어 계속 '신규'였고, 상점 콘솔 1:1 문의는 답을 읽었는지 기록이 없었어요. 상태 바꾸기와 읽음 표시를 붙였습니다.
- 0건이면 아예 그리지 않고, 100건부터는 "99+"로 보여 줍니다.

## 코드로 보기 (개념 재현)

```ts
// 공통 API 클라이언트: 바꾸는 요청이 성공하면 "다시 세라" 신호를 보낸다
export const COUNTS_REFRESH = "app:counts-refresh";

export async function apiFetch(url: string, init: RequestInit = {}) {
  const res = await fetch(url, init);
  const method = (init.method ?? "GET").toUpperCase();
  if (
    res.ok &&
    method !== "GET" &&
    typeof window !== "undefined" &&
    typeof window.dispatchEvent === "function" // 테스트의 가짜 window 에는 없을 수 있다
  ) {
    window.dispatchEvent(new Event(COUNTS_REFRESH));
  }
  return res;
}
```

```ts
// 메뉴 숫자 훅: 진입·이동·복귀·신호·주기마다 다시 센다
export function useMenuCounts<T>(load: () => Promise<T>, everyMs = 60_000) {
  const [counts, setCounts] = useState<T | null>(null);
  const pathname = usePathname();

  useEffect(() => {
    let timer: ReturnType<typeof setTimeout> | undefined;
    const refresh = () => {
      clearTimeout(timer); // 몰려오는 신호는 짧게 모아 한 번만 센다
      timer = setTimeout(() => {
        load().then(setCounts).catch(() => {});
      }, 300);
    };
    const onVisible = () => {
      if (document.visibilityState === "visible") refresh();
    };

    refresh();
    window.addEventListener("focus", refresh);
    window.addEventListener(COUNTS_REFRESH, refresh);
    document.addEventListener("visibilitychange", onVisible);
    const interval = setInterval(refresh, everyMs);

    return () => {
      clearTimeout(timer);
      clearInterval(interval);
      window.removeEventListener("focus", refresh);
      window.removeEventListener(COUNTS_REFRESH, refresh);
      document.removeEventListener("visibilitychange", onVisible);
    };
  }, [load, everyMs, pathname]); // 메뉴를 옮기면 다시 센다

  return counts;
}
```

서버 쪽은 건수 쿼리마다 테스트를 붙였습니다. 역할별로 숫자가 빠지는지, 처리하면 줄어드는지, 다른 상점의 일은 세지 않는지를 봤어요.

## 💡 배운 것

**상태에서 바로 셀 수 있으면, 알림을 따로 쌓지 않는 편이 어긋나지 않습니다.** 일을 처리하면 숫자가 저절로 줄어요.

**계산해서 보여 주는 방식에서는 "언제 다시 셀지"가 설계의 중심이 됩니다.** 갱신 신호를 공통 클라이언트 한 곳에서 보내니 화면 코드가 단순해졌습니다.

**숫자를 달아 보면 줄어들 수 없는 숫자가 드러납니다.** 그건 대개 "처리할 수단이 없는 기능"이라는 신호였습니다.

## 소감

숫자를 다는 작은 일이라고 생각했는데, 처리 상태가 없는 기능을 두 개나 찾게 됐습니다. 배포 뒤 "숫자가 안 보인다"는 말을 들었을 때는, 처리할 일이 0건이면 그리지 않게 만든 것이라는 설명부터 하게 됐어요.
