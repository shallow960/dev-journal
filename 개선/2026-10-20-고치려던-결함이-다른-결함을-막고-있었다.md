# 2026-10-20 고치려던 결함이, 다른 결함을 막고 있었다

> 태그: #개선 #수정순서 #안전장치 #재서명 #키오스크

## 무엇을 / 왜

같은 날 키오스크 화면 배포에서 결함 두 개를 확인했습니다.

- **(가)** 시즌 묶음을 만들기만 해도(아직 켜기 전) 지금 쓰는 릴리스가 "화면 없음" 으로 다시 서명되어 나갔어요.
- **(나)** 키오스크는 같은 릴리스 번호인데 내용(매니페스트 내용의 해시)이 다른 것이 오면 거부하고 "실패" 로 보고합니다. 서버는 발급하고 23시간쯤 지나면 같은 릴리스를 다시 서명해서 보내요. 그러면 키오스크가 거의 다 "실패" 로 굳고, 5분마다 서버 오류(500)가 납니다. 화면은 마지막 정상본으로 계속 돌아요.

(나)는 누가 봐도 고쳐야 할 결함이었습니다. 그런데 (가)를 다시 따라가 보니 이랬어요.

- (가)가 만든 "화면 없는 재서명" 을, (나)가 거부하고 있었습니다.
- 그래서 그 릴리스를 이미 받아 둔 키오스크는 (나) 덕분에 화면을 지키고 있었어요.
- 받아 둔 게 없는 키오스크(새로 설치한 기기, 다시 설치한 기기)만 화면 없는 릴리스를 처음 받아 흰 화면이 됩니다.

**(나)부터 고쳤다면,** 받아 둔 키오스크도 재서명을 받아들여 흰 화면이 됐을 거예요. 결함 하나가 다른 결함의 안전장치 노릇을 하고 있었습니다.

## 어떻게 풀었나

고치는 순서를 먼저 정했어요.

1. **서버가 화면 없는 릴리스를 내지 않게 합니다.** 화면이 있어야 하는 릴리스에서 키오스크 몫을 못 찾으면 거절(409)해요. (가)의 원인 쪽입니다.
2. **키오스크도 스스로 지킵니다.** 지금 화면이 있는데 화면이 빠진 릴리스가 오면 적용하지 않아요. 서버가 실수하거나, 옛 서버가 남아 있어도 키오스크가 버팁니다.
3. **그다음에야 재서명을 받아들입니다.** 같은 릴리스·같은 묶음이고, 발급 시각이 지금 것보다 **더 새로울 때만** 받아요. 옛 발급본을 다시 보내 되돌리는 것(재생)을 막기 위해서입니다.

그리고 1·2·3 을 한 번에 같이 배포하기로 했어요. 3만 먼저 나가는 일이 없게요.

조사 때 서버가 실제로 발급했던 매니페스트를 고친 키오스크 코드에 다시 넣어 확인했습니다. 23시간 뒤 재서명은 "적용" 으로 바뀌었고, 같은 릴리스의 옛 발급본은 거부됐고, 화면이 빠진 릴리스는 "거부" 되고 화면은 그대로였어요. 아직 커밋 전이고, 따로 받은 검토에서 나온 지적(시계가 서버보다 조금 늦은 키오스크가 새 발급본을 "아직 유효하지 않음" 으로 거부하는 경우 등)을 고치는 중입니다.

## 코드로 보기 (개념 재현)

```ts
// 개념 재현: 이름은 모두 더미다.
interface Manifest { releaseNo: number; bundleNo: number; signedAt: string; hasScreen: boolean }
type Decision = 'APPLY' | 'KEEP' | 'REFUSE';

function decide(next: Manifest, current: Manifest | null): Decision {
  if (!current) return 'APPLY';

  // 1) 지금 화면이 있는데 화면이 빠진 릴리스가 오면 적용하지 않는다.
  //    서버가 실수해도 키오스크가 마지막 정상 화면을 지킨다.
  if (current.hasScreen && !next.hasScreen) return 'REFUSE';

  // 2) 더 옛 릴리스는 재생(옛 응답을 다시 보내기)으로 보고 거절한다.
  if (next.releaseNo < current.releaseNo) return 'REFUSE';

  if (next.releaseNo === current.releaseNo) {
    // 3) 같은 릴리스를 다시 서명한 것: 같은 묶음이고, 발급 시각이 "더 새로울 때만" 받는다.
    //    옛 발급본을 다시 보내 되돌리는 것을 막기 위해서다.
    if (next.bundleNo !== current.bundleNo) return 'REFUSE';
    const nextAt = Date.parse(next.signedAt);
    const curAt = Date.parse(current.signedAt);
    if (nextAt === curAt) return 'KEEP';          // 같은 발급본: 할 일 없음
    return nextAt > curAt ? 'APPLY' : 'REFUSE';
  }
  return 'APPLY'; // 새 릴리스
}

const cur: Manifest = { releaseNo: 4, bundleNo: 3, signedAt: '2026-10-20T04:00:00Z', hasScreen: true };
console.log(decide({ ...cur, signedAt: '2026-10-21T03:01:00Z' }, cur)); // APPLY  : 23시간 뒤 재서명
console.log(decide({ ...cur, signedAt: '2026-10-19T04:00:00Z' }, cur)); // REFUSE : 옛 발급본 재전송
console.log(decide({ ...cur, releaseNo: 5, hasScreen: false }, cur));   // REFUSE : 화면이 빠진 릴리스
console.log(decide({ ...cur, releaseNo: 5 }, cur));                     // APPLY  : 새 릴리스
```

## 💡 배운 것

**결함을 고치기 전에, 그 결함이 지금 무엇을 막고 있는지부터 봐야 한다는 걸 다시 배웠습니다.** 겉으로는 "실패로 굳는 문제" 였지만, 그 거부가 다른 결함 앞에서 화면을 지키고 있었어요. 2026-09-18 에 "멈춘 것이 고장인지 안전장치인지부터 가른다" 를 배웠는데, 이번엔 설계한 안전장치가 아니라 결함이 그 노릇을 하고 있었습니다.

**한쪽을 고친 것이 다른 길을 열 수 있다는 걸 다시 배웠습니다.** 2026-10-19 에도 맞는 수정 하나가 기록이 예전 값으로 남는 상태를 만들었어요. 그래서 고치는 순서와 같이 나갈 묶음을 먼저 정했습니다.

**받는 쪽도 스스로 지키게 두 겹으로 만든다는 걸 다시 배웠습니다.** 2026-08-28 에 "방어는 두 겹으로(우리 쪽 사전 차단 + 받는 쪽 거부)" 를 배웠는데, 이번엔 서버와 키오스크였어요. 서버만 고치면 옛 서버나 실수 한 번에 다시 뚫려요. 키오스크에도 "화면이 빠지면 적용하지 않는다" 를 넣으니, 어느 한쪽이 틀려도 화면은 남습니다.

**같은 것을 다시 받을 때는 시각이 앞으로만 가게 한다는 걸 배웠습니다.** 재서명을 받아들이는 순간, 옛 발급본을 다시 보내는 것도 받아들일 수 있게 돼요. "더 새로울 때만" 이라는 한 줄이 그 길을 막습니다.
