# 2026-11-07 늦게 도착한 재부팅 명령을, 옛 키오스크는 모르는 이름으로 보냈다

> 태그: #개선 #원격명령 #하위호환 #멱등 #키오스크

## 무엇을 / 왜

관리 화면에서 매장 키오스크를 원격으로 재부팅하거나 끌 수 있었습니다. 명령은 서버가 메시지로 키오스크에 보내고, 키오스크가 받아서 Windows 재부팅을 불렀습니다. 2026-11-06 에 QA 항목을 정리하다가, 명령에 적어 둔 기한이 서버 기록에만 있고 실제로 보내고 실행하는 길에서는 아무도 보지 않는다는 걸 알게 됐습니다.

그러면 이런 일이 생길 수 있었습니다. 영업이 끝난 뒤에 하려던 재부팅 명령을 보냈는데 키오스크가 꺼져 있었고, 다음 날 손님이 있는 시간에 켜지자마자 그 명령을 받아 재부팅하는 일이었습니다. 재부팅은 "보낸 때" 가 아니라 "실행하는 때" 에 해도 되는지가 정해지는 명령이었습니다.

## 어떻게 풀었나

처음 떠올린 방법은 메시지에 기한 칸을 하나 더 넣는 것이었습니다. 그런데 매장에는 옛 버전 키오스크가 남아 있을 수 있었고, 옛 키오스크는 모르는 칸을 그냥 무시했습니다. 기한 칸을 넣어도 옛 키오스크는 예전처럼 바로 재부팅했을 것입니다.

그래서 2026-11-07 에 네 가지를 바꿨습니다.

- **옛 버전이 모르는 새 명령 종류로만 보냈습니다.** 옛 키오스크는 모르는 종류를 무시했기 때문에, 늦게 받아도 아무것도 하지 않게 됐습니다. 새 종류를 처리할 수 있다고 최근에 알려 온 키오스크에게만 보내고, 옛 종류로 바꿔 다시 보내지는 않게 했습니다.
- **실행 바로 전에 서버에서 한 번만 쓰는 허가를 받게 했습니다.** 키오스크는 Windows 재부팅을 부르기 직전에 서버에 묻고, 서버는 기한과 취소 여부를 본 뒤 허가를 한 번만 내줬습니다. 같은 메시지가 두 번 와도 두 번째는 허가를 받지 못했습니다.
- **결과를 모르는 경우를 실패로 세지 않게 했습니다.** Windows 재부팅 요청이 시간 초과로 끝나면, 실제로는 이미 재부팅이 시작됐을 수도 있었습니다. 이걸 "실행 안 됨" 으로 알리면 서버는 다시 보내도 되는 명령으로 보고, 두 번 재부팅될 수 있었습니다. 결과를 모르면 "확인 대기" 로 남기고 다시 보내기를 막았습니다.
- **허가를 받은 뒤 늦게 온 완료 보고도 받게 했습니다.** 기한 전에 허가를 받아 실행했는데 완료 보고가 기한 뒤에 오면, 예전 코드는 기한이 지났다며 "만료" 로 끝내고 그 보고를 버렸습니다. 허가를 받은 명령은 기한만으로 만료시키지 않고, 늦게 온 완료 보고로 마무리하게 했습니다.

뒤의 두 가지는 올리기 전 교차 검토에서 나온 지적이었습니다.

## 코드로 보기 (개념 재현)

옛 키오스크, 새 키오스크, 허가를 내주는 서버를 아주 작게 흉내 냈습니다.

```js
// power-permit-demo.js - node power-permit-demo.js
const MIN = 60 * 1000;

// 옛 키오스크: 아는 종류만 처리하고, 모르는 칸(expiresAt)은 그냥 무시한다
function oldKiosk(msg) {
  if (msg.type === 'reboot') return '바로 재부팅';
  return `무시 (모르는 종류: ${msg.type})`;
}

// 서버: 명령마다 기한을 두고, 실행 직전에 받는 "한 번만 쓰는 허가" 를 내준다
const server = {
  cmds: new Map(),
  create(id, now, ttlMs) { this.cmds.set(id, { expiresAt: now + ttlMs, permitUsed: false, state: '보냄' }); },
  permit(id, now) {
    const c = this.cmds.get(id);
    if (c.permitUsed) return '거절: 이미 쓴 허가';
    if (now > c.expiresAt) { c.state = '만료'; return '거절: 기한 지남'; }
    c.permitUsed = true;
    c.state = '허가됨';
    return '허가';
  },
  report(id, outcome) {
    const c = this.cmds.get(id);
    if (outcome === 'done') c.state = '완료';
    else if (outcome === 'rejected') c.state = '실행 안 됨 (다시 보내기 가능)';
    else c.state = '확인 대기 (다시 보내기 막음)';      // 결과를 모르면 실패로 치지 않는다
    return c.state;
  },
};

// 새 키오스크: 새 종류만 받고, OS 를 부르기 바로 전에 서버 허가를 받는다
function newKiosk(msg, now, osCall) {
  if (msg.type !== 'reboot-v2') return '무시';
  const p = server.permit(msg.id, now);
  if (p !== '허가') return `실행 안 함 (${p})`;
  return server.report(msg.id, osCall());
}

const t0 = Date.now();
server.create('c1', t0, 30 * MIN);   // 30분 안에만 의미가 있는 재부팅

// 1) 키오스크가 꺼져 있다가 5시간 뒤에 받았다
const late = t0 + 5 * 60 * MIN;
console.log('1) 옛 종류 + 기한 칸 -> 옛 키오스크:', oldKiosk({ type: 'reboot', id: 'c1', expiresAt: t0 + 30 * MIN }));
console.log('1) 새 종류        -> 옛 키오스크:', oldKiosk({ type: 'reboot-v2', id: 'c1' }));
console.log('1) 새 종류        -> 새 키오스크:', newKiosk({ type: 'reboot-v2', id: 'c1' }, late, () => 'done'));

// 2) 기한 안에 받았고, 같은 메시지가 한 번 더 왔다
server.create('c2', t0, 30 * MIN);
console.log('2) 첫 도착 :', newKiosk({ type: 'reboot-v2', id: 'c2' }, t0 + MIN, () => 'done'));
console.log('2) 또 도착 :', newKiosk({ type: 'reboot-v2', id: 'c2' }, t0 + 2 * MIN, () => 'done'));

// 3) OS 재부팅 요청이 시간 초과로 끝나 결과를 모른다
server.create('c3', t0, 30 * MIN);
console.log('3) 결과 모름 :', newKiosk({ type: 'reboot-v2', id: 'c3' }, t0 + MIN, () => 'unknown'));
server.create('c4', t0, 30 * MIN);
console.log('3) 실패로 셈 :', newKiosk({ type: 'reboot-v2', id: 'c4' }, t0 + MIN, () => 'rejected'),
  '<- 이미 재부팅 중이었다면 두 번 재부팅');
```

돌린 결과입니다.

```text
1) 옛 종류 + 기한 칸 -> 옛 키오스크: 바로 재부팅
1) 새 종류        -> 옛 키오스크: 무시 (모르는 종류: reboot-v2)
1) 새 종류        -> 새 키오스크: 실행 안 함 (거절: 기한 지남)
2) 첫 도착 : 완료
2) 또 도착 : 실행 안 함 (거절: 이미 쓴 허가)
3) 결과 모름 : 확인 대기 (다시 보내기 막음)
3) 실패로 셈 : 실행 안 됨 (다시 보내기 가능) <- 이미 재부팅 중이었다면 두 번 재부팅
```

첫 줄이 처음 떠올린 방법의 결과였습니다. 기한 칸을 넣어도 옛 키오스크는 5시간 늦게 받은 명령으로 바로 재부팅했습니다.

## 💡 배운 것

- 받는 쪽이 모르는 칸을 무시한다면, 새 칸으로는 옛 버전을 멈출 수 없다는 걸 배웠습니다. 옛 버전이 하면 안 되는 일을 막으려면, 옛 버전이 아예 알아듣지 못하는 이름으로 보내야 했습니다.
- 늦게 도착한 것은 도착한 때가 아니라 "지금 해도 되는가" 로 다시 확인해야 한다는 걸 다시 배웠습니다([2026-10-28, 결제를 취소했는데, 승인이 늦게 도착했다](../트러블슈팅/2026-10-28-결제를-취소했는데-승인이-늦게-도착했다.md)). 그때는 늦은 결제 승인이었고, 이번에는 늦은 재부팅 명령이었습니다.
- 바깥 호출의 결과는 성공·실패·모름 세 가지이고, 모름을 실패로 치면 다시 시도하게 된다는 걸 다시 배웠습니다([2026-09-15, 결과를 모르는 결제는 멈추는 쪽으로](../개선/2026-09-15-결과를-모르는-결제는-멈추는-쪽으로.md)). 결제에서 배운 것이 재부팅에도 그대로 맞았습니다.

## 소감

"기한 칸 하나만 넣으면 되겠다" 고 생각했던 일이, 옛 버전과 늦은 보고와 결과를 모르는 경우까지 따라가니 네 가지 변경이 됐습니다. 원격으로 기계를 끄는 명령은 한 번 잘못 실행되면 손님 앞에서 화면이 꺼지는 일이라, 애매하면 실행하지 않는 쪽으로 틀리게 정했습니다.
