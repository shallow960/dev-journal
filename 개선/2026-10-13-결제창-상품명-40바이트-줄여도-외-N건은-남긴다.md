# 2026-10-13 결제창 상품명 40바이트, 줄여도 "외 N건"은 남긴다

> 태그: #개선 #결제 #문자열 #UTF-8 #바이트 #Java

## 무엇을 / 왜

모든 상점의 카드 결제창에 상품명이 **고정된 영문 문구**로 떠서, 손님이 결제창에서 무엇을 사는지 알 수 없었습니다. 주문 첫 상품 이름 + "외 N건"으로 바꾸기로 했는데, 결제사 매뉴얼을 보니 상품명 최대 길이가 **40바이트**였어요. 한글은 UTF-8에서 한 글자가 3바이트라, 열서너 글자면 넘칩니다.

## 어떻게 풀었나

- **잘릴 때 남길 순서를 먼저 정했습니다.** "외 N건"은 꼭 남깁니다. 손님에게는 몇 개를 결제하는지가 상품명 뒷부분보다 중요하니까요. 남는 자리만큼만 상품명을 쓰고 말줄임표를 붙입니다.
- **바이트로 세되, 자르는 단위는 글자로.** 바이트 배열을 40에서 그냥 자르면 한글 한 글자가 반으로 갈려 깨집니다. 문자(코드 포인트)를 하나씩 더하면서 바이트를 세고, 넘기 직전에 멈췄어요. 이모지처럼 자바 문자열에서 두 칸(서로게이트 쌍)을 쓰는 문자도 이렇게 하면 쪼개지지 않습니다.
- 결제사가 다른 문자로 바꿔 버리는 큰따옴표·세로선은 미리 '-'로 바꾸고, 연속 공백은 하나로 줄였습니다.
- 상품명을 못 찾으면 "주문 {주문번호}"로 대신합니다.

## 코드로 보기 (개념 재현)

```java
public final class CheckoutTitle {

    static final int MAX_BYTES = 40;
    static final String ELLIPSIS = "…";

    public static String of(String firstGoodsName, int lineCount, String orderNo) {
        String name = clean(firstGoodsName);
        if (name.isEmpty()) {
            return fit(clean("주문 " + orderNo), "");
        }
        return fit(name, lineCount > 1 ? " 외 " + (lineCount - 1) + "건" : "");
    }

    static String fit(String name, String suffix) {
        if (bytes(name + suffix) <= MAX_BYTES) {
            return name + suffix;
        }
        int budget = MAX_BYTES - bytes(suffix) - bytes(ELLIPSIS); // 꼬리말 자리부터 뺀다
        StringBuilder kept = new StringBuilder();
        int used = 0;
        for (int i = 0; i < name.length(); ) {
            int cp = name.codePointAt(i);                          // 글자(코드 포인트) 단위로
            int size = bytes(new String(Character.toChars(cp)));
            if (used + size > budget) {
                break;                                             // 넘기 직전에 멈춘다
            }
            kept.appendCodePoint(cp);
            used += size;
            i += Character.charCount(cp);                          // 서로게이트 쌍이면 두 칸 이동
        }
        return kept.toString().strip() + ELLIPSIS + suffix;
    }

    static int bytes(String s) {
        return s.getBytes(StandardCharsets.UTF_8).length;
    }

    static String clean(String s) {
        return s == null ? "" : s.replace('"', '-').replace('|', '-').strip().replaceAll("\\s+", " ");
    }
}
```

테스트는 이런 것들을 봤습니다. 긴 한글 상품명에 품목이 여럿이면 40바이트 이하이면서 "외 N건"으로 끝나는지, 이모지가 반쪽으로 깨지지 않는지, 짧은 이름은 그대로인지, 상품명이 없으면 주문번호가 나오는지.

## 💡 배운 것

**길이 제한은 "몇"보다 "무엇으로 세는지"를 먼저 봅니다.** 40이 글자 수인지 바이트 수인지에 따라 들어가는 한글이 세 배 차이 납니다.

**바이트로 제한해도, 자르는 단위는 글자여야 합니다.** 그래야 한 글자가 반쪽으로 깨지지 않습니다. 자바에서는 `char`가 아니라 코드 포인트로 돌아야 이모지까지 안전했습니다.

**잘릴 때 남길 정보의 순서를 정해 둡니다.** 여기서는 상품명 끝부분보다 "외 N건"이 먼저였어요.

## 소감

바이트는 UTF-8 기준으로 셌습니다. 한글은 UTF-8이 가장 크게 세는 편이라 넘치지는 않을 거라고 보고 있지만, 결제사가 실제로 어떤 문자셋으로 세는지는 아직 확인하지 못했습니다. 실제 결제창에 어떻게 보이는지는 배포 뒤 눈으로 확인해 볼 생각입니다.
