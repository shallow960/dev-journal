# 2026-10-15 지울 때가 된 정보를 지우되, 법정 기간보다 먼저 지우지 않는다

> 태그: #개선 #개인정보 #배치 #데이터보존 #Java #SQL

## 무엇을 / 왜

처리방침에는 정보마다 보유기간(예: 주문 정보 5년, 문의 3년, 로그 90일)이 적혀 있는데, 기간이 지난 정보를 실제로 지우는 작업이 없었습니다. "내보내기 파일은 7일 뒤 만료"라고 적어 둔 파일도 지우지 않고 있었어요.

## 어떻게 풀었나

- 정보마다 **규칙** 을 하나씩 적었습니다. 어떤 표에서, 어떤 날짜 칸을 기준으로, 며칠이 지나면, 지울지 아니면 사람을 알아볼 수 있는 칸만 가릴지.
- 주문·정산처럼 매출·세무 집계에 남아야 하는 기록은 **지우지 않고 가립니다**(받는 사람·연락처·주소 같은 칸만 비움).
- 기간은 설정 값으로 바꾸지만, **법이 정한 최소 기간보다 짧게 넣으면 그 규칙은 건너뛰고 오류로 기록** 합니다. 설정 실수 하나로 지우면 안 되는 걸 지우지 않게요.
- 진행 중인 주문·반품, 답을 기다리는 문의처럼 **아직 쓰는 행은 조건에서 뺍니다.**
- 한 번에 1,000건씩 나눠 지우고(한 번 실행에 최대 횟수 제한), **끔 / 세기만 / 지움** 세 모드를 뒀습니다. 처음엔 세기만으로 며칠 건수를 본 뒤 지움으로 켭니다.
- 언제, 어떤 규칙으로, 몇 건을 지웠는지 실행 기록을 남깁니다(개인정보는 넣지 않음).

## 코드로 보기 (개념 재현)

```java
enum Mode { OFF, REPORT, DELETE }

record PurgeRule(
        String name,
        int days,             // 설정 값
        int minimumDays,      // 법이 정한 최소 보관 기간
        boolean maskOnly      // true 면 행은 남기고 칸만 가린다
) {}

void runAll(List<PurgeRule> rules, Mode mode) {
    if (mode == Mode.OFF) return;

    for (PurgeRule rule : rules) {
        if (rule.days() < rule.minimumDays()) {
            // 설정이 법정 최소보다 짧으면 지우지 않고 기록만 남긴다
            runs.record(rule, 0, "SKIPPED_BELOW_MINIMUM");
            continue;
        }
        Instant cutoff = clock.instant().minus(Duration.ofDays(rule.days()));

        if (mode == Mode.REPORT) {
            runs.record(rule, countExpired(rule, cutoff), "REPORTED");   // 세기만
            continue;
        }

        long total = 0;
        for (int batch = 0; batch < MAX_BATCHES; batch++) {
            int n = rule.maskOnly()
                    ? maskExpired(rule, cutoff, 1000)     // 칸만 가림
                    : deleteExpired(rule, cutoff, 1000);  // 행을 지움
            total += n;
            if (n < 1000) break;                          // 더 남은 게 없다
        }
        runs.record(rule, total, "DONE");
    }
}
```

```sql
-- 지우는 쿼리의 모양: 기간이 지났고, 아직 쓰는 행이 아닌 것만, 1000건씩
DELETE FROM inquiry
WHERE id IN (
    SELECT id
    FROM inquiry
    WHERE created_at < :cutoff
      AND status <> 'WAITING_ANSWER'   -- 답을 기다리는 문의는 남긴다
    ORDER BY id
    LIMIT 1000
);

-- 가리는 쿼리의 모양: 집계에 쓰는 금액·날짜는 남기고 사람을 알아볼 칸만 비운다
UPDATE order_record
SET recipient_name = NULL, recipient_phone = NULL, recipient_address = NULL,
    masked_at = now()
WHERE id IN (
    SELECT id FROM order_record
    WHERE completed_at < :cutoff
      AND masked_at IS NULL
    ORDER BY id
    LIMIT 1000
);
```

## 💡 배운 것

**지우는 기능은 '안 지울 것'을 먼저 정해야 합니다.** 기간보다 먼저, 진행 중인 것, 집계에 필요한 것, 법으로 남겨야 하는 것을 빼는 조건이 핵심이었어요.

**지우기와 가리기는 다릅니다.** 매출 기록은 남기고 사람을 알아볼 수 있는 칸만 비우면, 집계와 개인정보 보호를 같이 지킬 수 있었습니다.

**설정 값에도 안전장치가 필요합니다.** 기간을 설정으로 바꿀 수 있게 하면, 잘못된 값 하나가 대량 삭제가 돼요. 최소 기간 아래로는 동작하지 않게 막았습니다.

**처음 켤 때는 세기만 합니다.** 지우기 전에 몇 건이 대상인지 며칠 지켜보면, 조건이 틀렸을 때 데이터가 아니라 숫자로 먼저 알 수 있어요.

## 소감

'오래된 데이터 지우기'는 쉬운 배치처럼 보였는데, 실제로는 무엇을 지우면 안 되는지 정하는 일이 대부분이었습니다. 되돌릴 수 없는 작업일수록 켜기 전 단계를 여러 번 두는 게 맞다는 걸 배웠어요.
