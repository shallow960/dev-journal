# 2026-09-08 같은 번호를 세 화면이 각자 만들고 있었다

> 태그: #개선 #단일출처 #키오스크 #중복로직

## 무엇을 / 왜

직원이 손님을 부를 번호가 필요했습니다. 대기 순번 같은 것이죠.

이미 영수증·전광판·관리 화면에 번호가 찍히고 있었는데, 확인해 보니 **세 화면이 각자 휴대폰 뒷자리를 잘라 쓰고** 있었습니다. 규칙이 조금씩 달랐고, 번호 없이 결제한 손님은 부를 번호 자체가 없었습니다.

실제 키오스크로 발권해 보니, 손님이 알림을 보고 전광판에서 자기 번호를 못 찾는 상태였습니다.

## 어떻게 풀었나

### 세 곳이 각자 자르고 있었다

같은 값을 만드는 코드가 세 벌 있으면 규칙이 바뀔 때 한쪽만 고쳐집니다. 실제로 이미 갈라져 있었어요.

- 어떤 화면은 하이픈이 섞인 번호를 그대로 잘라 `4-56` 같은 값이 나왔습니다
- 번호 없이 결제한 손님은 자를 게 없어 빈칸이었습니다

**규칙을 서버 함수 한 곳에 두고** 세 화면이 그 값을 받아 쓰게 했습니다.

- 휴대폰 뒷 4자리
- 번호 없이 결제한 손님은 서버가 붙인 임시 식별번호에서 `T####`
- 자르기 전에 숫자만 뽑아서 하이픈이 섞여도 안전하게

### 나중에 붙는 기능이 같은 실수를 반복한다

여기까지 하고 며칠 뒤, 알림 메시지 원고를 정리하다 같은 문제를 또 만났습니다.

**알림만 자기 자리에서 뒷 4자리를 따로 자르고 있었습니다.**

세 화면은 고쳤는데, 그 뒤에 붙은 기능이 같은 계산을 새로 만든 것이었어요. 그것도 같은 함수를 부르게 고쳤습니다.

한 곳으로 모으는 작업은 **모은 뒤에 붙는 것까지 봐야** 끝난다는 걸 알았습니다.

## 코드로 보기 (개념 재현)

세 화면이 각자 하던 계산입니다.

```js
// 영수증 쪽
const callNo = phone.slice(-4);

// 전광판 쪽
const callNo = phone.substring(phone.length - 4);

// 관리 화면 쪽
const callNo = phone ? phone.slice(-4) : "";
```

같아 보이지만 다릅니다. 하이픈이 섞인 `010-1234-4-56` 같은 입력이나 번호가 없는 경우에서 갈라집니다.

서버 한 곳으로 모았습니다.

```js
/**
 * 손님을 부를 번호를 만든다.
 * 이 규칙은 여기 한 곳에만 둔다 - 영수증·전광판·관리화면·알림이 모두 이 값을 받아 쓴다.
 */
function buildCallNumber({ phone, tempId }) {
  // 하이픈·공백이 섞여 들어와도 숫자만 남긴다.
  const digits = (phone ?? "").replace(/\D/g, "");

  if (digits.length >= 4) {
    return digits.slice(-4);
  }
  // 번호 없이 결제한 손님: 임시 식별번호에서 만든다.
  // 휴대폰 뒷자리와 섞이지 않도록 접두사를 붙인다.
  if (tempId) {
    return "T" + String(tempId).padStart(4, "0").slice(-4);
  }
  return "";
}
```

화면 쪽은 받아 쓰되, 못 받았을 때의 예비 계산도 같은 규칙을 부르게 했습니다.

```js
// 서버가 준 값을 우선 쓴다. 못 받았을 때만 같은 함수로 만든다.
// ★ 여기서 또 slice(-4) 를 쓰면 규칙이 다시 두 벌이 된다.
const callNo = payload.callNumber ?? buildCallNumber(payload);
```

## 💡 배운 것

**같은 값을 여러 곳에서 쓰면 계산은 한 곳에만 둬야 합니다.** 세 화면이 각자 자르고 있으면 "뒷 4자리" 라는 규칙이 바뀔 때 한쪽만 고쳐집니다. 실제로 이미 갈라져 있었고요.

**한 곳으로 모으는 작업은 모은 뒤에 붙는 것까지 봐야 끝납니다.** 세 화면을 고친 뒤 새로 붙은 기능이 같은 계산을 새로 만들었습니다. 모으고 나서 "이 값을 쓰는 데가 또 생겼나" 를 확인하는 습관이 필요했습니다.

**예비 계산도 같은 규칙을 불러야 합니다.** "서버가 못 주면 화면에서 만들자" 는 흔한 폴백인데, 거기서 직접 자르면 규칙이 다시 두 벌이 됩니다.

## 소감

기능을 새로 만드는 일인 줄 알고 시작했는데, 열어 보니 **이미 세 곳에서 각자 만들고 있던 값을 하나로 모으는 일**이었습니다.

눈에 보이는 증상은 "번호가 화면마다 다르다" 하나였지만, 원인은 "같은 계산이 세 벌" 이었고 그 세 벌이 조금씩 다르게 자라 있었습니다. 중복은 처음 만들 때는 편하고 나중에 비싸다는 걸 실제로 봤습니다.
