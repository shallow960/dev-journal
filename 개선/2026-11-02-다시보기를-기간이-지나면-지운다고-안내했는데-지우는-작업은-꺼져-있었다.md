# 2026-11-02 다시보기를 기간이 지나면 지운다고 안내했는데, 지우는 작업은 꺼져 있었다

> 태그: #개선 #라이브 #안내문구 #설정 #약관

## 무엇을 / 왜

라이브 방송이 끝나면 녹화가 다시보기로 남게 돼 있었습니다. 다시보기는 정해진 무료 기간 동안 두고, 그 뒤에도 남기려면 판매자가 '보관' 을 하게 돼 있었습니다. 판매자 화면과 쇼핑몰 관리 화면에는 "보관하지 않으면 무료 기간이 지난 뒤 자동으로 삭제됩니다", "○월 ○일에 삭제됩니다" 라는 안내가 보였습니다.

그런데 기간이 지난 다시보기를 실제로 지우는 정리 작업은 운영에서 꺼져 있었습니다. 화면은 지운다고 알리고 있었고, 시스템은 지우지 않고 있었습니다.

지우지 않으니 잃는 사람은 없다고 볼 수도 있었습니다. 하지만 판매자는 그 날짜를 보고 서둘러 보관하거나 영상을 미리 내려받을 수 있었습니다. 그리고 플랫폼 약관에는 기간이 지나면 자동으로 지우는 방식을 도입할 때, 대상과 기한과 내려받는 방법을 미리 알리겠다고 적어 두었습니다. 하지 않는 삭제를 날짜까지 안내하는 것은 그 약속과도 맞지 않았습니다.

## 어떻게 풀었나

### 작업을 켤지, 안내가 작업을 따르게 할지 정했습니다

길은 두 가지였습니다. 정리 작업을 켜서 안내대로 지우거나, 안내가 정리 작업을 따르게 하는 것입니다. 작업을 켜는 일은 약관대로 미리 알리는 절차가 먼저라 바로 할 일이 아니었습니다. 그래서 화면이 정리 작업 스위치를 따르게 하기로 정했습니다.

### 서버가 스위치 상태를 함께 알려 주게 했습니다

문제의 뿌리는 화면이 안내 문구를 혼자 정하고 있었다는 것이었습니다. 화면에는 정리 작업이 켜져 있는지 알 방법이 없었습니다. 그래서 서버가 다시보기 보관 상태를 보낼 때 "자동 삭제가 켜져 있는가" 를 함께 보내고, 꺼져 있으면 사라질 날짜를 비워 보내게 했습니다.

화면은 이 값만 보고 안내를 정하게 했습니다. 판매자 화면의 다시보기 목록과 머리말, 쇼핑몰 관리 화면의 안내 문구와 보관 해제 확인 창과 보관 알림, 방송 성과 화면의 보관 칸이 모두 같은 값을 따랐습니다. 나중에 스위치를 켜면 안내도 그대로 다시 보이게 했습니다.

## 코드로 보기 (개념 재현)

```java
// 다시보기 보관 상태 응답 (개념 재현 - 실제 이름과 다름)
record ReplayKeep(boolean kept, boolean purgeEnabled, Instant purgeOn) {}

ReplayKeep keepStatus(Replay replay) {
    boolean purgeEnabled = replayPurge.enabled();      // 정리 작업이 실제로 켜져 있는가 (운영 설정)
    Instant purgeOn = (purgeEnabled && !replay.kept())
        ? replay.endedAt().plus(KEEP_FREE_FOR)          // 켜져 있을 때만 사라질 날짜가 있다
        : null;                                         // 꺼져 있으면 지우지 않으니 날짜도 없다
    return new ReplayKeep(replay.kept(), purgeEnabled, purgeOn);
}
```

## 💡 배운 것

- 화면 안내가 실제 동작과 다른 곳을 보고 있으면, 설정 하나만 바뀌어도 둘이 어긋났습니다. 동작을 정하는 스위치에서 안내도 함께 나오게 해야 했습니다.
- 하지 않는 일을 한다고 알리는 것도 결함이었습니다. 특히 지우는 일처럼 되돌릴 수 없는 일을 안내할 때는, 실제로 그 일을 하는지부터 확인해야 했습니다.
- 약관에 적은 약속이 기능을 켜는 순서를 정해 주기도 했습니다. 지우는 작업은 미리 알린 다음에야 켤 수 있었습니다.

## 소감

정리 작업은 만들어 두고 운영에서는 아직 켜지 않은 상태였습니다. 기능을 꺼 둘 때 그 기능을 설명하는 화면까지 함께 따져 보지는 않았다는 걸 알게 됐습니다. 앞으로 스위치를 둘 때는 그 스위치를 따라야 하는 화면이 어디인지도 같이 적어 두려고 합니다.
