# 2026-11-04 표 만드는 시간이 디스크를 기다리는 시간이어서, 시험 이미지에서 동기화를 건너뛰었다

> 태그: #개선 #MariaDB #Docker #테스트속도 #fsync #Testcontainers

## 무엇을 / 왜
서버 시험은 시험 클래스마다 MariaDB 컨테이너를 새로 띄우고 마이그레이션 전부를 처음부터 돌리는 구조였습니다. C 드라이브가 꽉 차서 Docker 디스크를 HDD 인 D 드라이브로 옮겼더니, 전체 시험이 끝나지 않는 문제가 생겼습니다.

- 시험 클래스 하나를 시작하는 데만 수 분이 걸렸습니다.
- 다른 시험이 겹친 탓도 있었지만, 몇 시간이 지나도 진행률이 20% 를 넘지 못했습니다.
- 시험 내용과 데이터를 줄이면 시험의 뜻이 달라져서, 줄이지 않고 빠르게 만들어야 했습니다.

## 어떻게 풀었나
- 처음에는 DB 설정이 답이라고 생각했습니다. 찾아보니 InnoDB 에 디스크 동기화를 줄이는 설정이 여러 개 있어서 모두 넣은 이미지를 만들었습니다.
- 그런데 표를 만드는 SQL 360개를 돌려 재 보니 66초가 60초가 됐을 뿐이었습니다. 표를 만들고 바꾸는 작업은 이 설정과 상관없이 동기화를 하고 있는 것으로 보였습니다.
- 그래서 같은 SQL 을 메모리 디스크(tmpfs)에서도 재 봤습니다. 1.4초였습니다. 원인이 디스크 동기화라는 게 여기서 분명해졌습니다.
- 다만 메모리 디스크는 시험 클래스마다 컨테이너 설정을 고쳐야 했습니다. 찾아보니 `eatmydata` 라는 도구가 프로그램의 `fsync` 호출을 가로채 아무것도 하지 않게 해 준다는 걸 알게 됐습니다. 이미지에 넣어 재 보니 2.0초였습니다.
- 시험 코드를 고치지 않고 켜고 끌 수 있게 했습니다. Testcontainers 는 환경 변수 하나로 이미지 이름 앞에 접두사를 붙일 수 있어서, 접두사가 붙은 이름으로 로컬 이미지를 만들어 뒀습니다.
- 이 이미지는 이 PC 의 시험에만 쓰기로 했습니다. 운영과 CI 이미지는 그대로 두었습니다. 전원이 나가면 데이터가 깨질 수 있는 설정이었기 때문입니다.
- 전체 시험은 2시간 안쪽으로 끝났습니다. 시험 내용은 하나도 줄이지 않았습니다.

## 코드로 보기 (개념 재현)
```dockerfile
# 1단계: DB 설정만 낮춘 이미지. 표를 만드는 시간은 거의 줄지 않았다.
FROM mariadb:10.11
CMD ["mariadbd", "--innodb-flush-log-at-trx-commit=0", "--innodb-flush-method=nosync", "--innodb-doublewrite=0", "--sync-binlog=0"]
```

```dockerfile
# 2단계: 위 이미지에 eatmydata 를 더한다. fsync 호출 자체가 아무 일도 하지 않게 된다.
FROM local-fast/mariadb:10.11
RUN apt-get update -qq && apt-get install -y -qq eatmydata >/dev/null && rm -rf /var/lib/apt/lists/*
ENV LD_PRELOAD=libeatmydata.so
```

```powershell
# 시험 코드는 그대로 두고, 이 값으로 이미지 이름 앞에 접두사만 붙인다.
$env:TESTCONTAINERS_HUB_IMAGE_NAME_PREFIX = 'local-fast/'
```

HDD 에서 표를 만드는 SQL 360개를 돌려 잰 값입니다.

| 조건 | 걸린 시간 |
|---|---|
| 기본 이미지 | 66초 |
| 동기화 설정만 낮춤 | 60초 |
| `eatmydata` 추가 | 2.0초 |
| 메모리 디스크(tmpfs) | 1.4초 |

## 💡 배운 것
- 느린 원인을 짐작으로 고치지 말고, 원인을 없앤 경우를 같이 재 봐야 한다는 걸 배웠습니다. 메모리 디스크 값을 재기 전에는 설정을 더 만지려고 했습니다.
- DB 의 동기화 설정은 데이터 쓰기에 대한 것이고, 표를 만드는 작업까지 줄여 주지는 않았습니다. 마이그레이션이 많은 시험은 이쪽이 병목이 될 수 있다는 걸 배웠습니다.
- 시험에만 쓰는 위험한 설정은 시험 코드 밖에서 켜는 편이 안전했습니다. 환경 변수를 빼면 바로 원래 이미지로 돌아갔습니다.

## 소감
디스크를 옮긴 것은 공간 문제를 푼 일이었는데, 그 일이 다음 날 시험 시간으로 돌아왔습니다. 숫자 네 개를 나란히 놓고 나서야 어디를 고쳐야 할지 보였습니다.
