# 2026-10-20 화면의 결제 금액을, 청구서와 같은 계산에서 가져오게 했다

> 태그: #개선 #결제 #할인 #부가세 #한곳에서계산

## 무엇을 / 왜

정기 구독 결제 화면에는 할인 코드 칸이 있습니다. 코드를 넣고 '적용' 을 누르면 "월 약 98,406원 할인" 처럼 깎이는 금액이 보여요. 그런데 그 아래 결제 버튼은 여전히 **"99,000원 결제하기"** 였습니다. 실제로 결제되는 금액은 할인된 금액이었는데도요.

금액 계산이 생각보다 단순하지 않아서, 화면이 직접 빼서 보여 주기도 애매했습니다.

1. 할인은 **공급가**(부가세를 뺀 금액)에 매깁니다.
2. 깎은 공급가에 **부가세를 다시** 계산합니다(소수 둘째 자리 반올림).
3. 마지막으로 **원 단위로 내립니다.**

정가에서 "할인 금액 × 1.1" 을 빼는 식으로 화면이 따라 하면, 반올림 위치가 달라서 1원씩 어긋날 수 있어요. 결제 화면에서 보이는 금액과 실제 청구 금액이 1원이라도 다르면 안 됩니다.

## 어떻게 풀었나

**계산은 한 곳에만 두고, 화면은 결과만 받게 했습니다.**

- 청구서를 만드는 서버 함수(할인 뒤 총액 계산)를 그대로 써서, 코드 확인 응답에 **"이번에 실제로 결제될 금액"** 을 함께 담았습니다.
- 화면은 그 값이 있으면 '결제 금액' 줄에 "594원 (VAT 포함, 정가 99,000원)" 처럼, 버튼에 "594원 결제하기" 로 보여 줍니다. 값이 없으면 예전처럼 정가를 보여 줘요(배포 순서가 어긋나도 깨지지 않게).
- 무료체험 중에 미리 걸어 둔 코드는 '적용 중' 으로만 보여서, 그때도 같은 금액을 받도록 '적용 중 코드' 응답에 금액을 더했습니다.
- 그리고 **"확인 때 알려 준 금액 = 실제 청구 금액"** 을 시험으로 고정했습니다.

## 코드로 보기 (개념 재현)

```java
// 청구서를 만들 때 쓰는 계산(원래 있던 것). 이 함수 하나만 금액을 정한다.
Money totalAfterDiscount(Money gross, Money supplyDiscount) {
    Money supply = gross.divide("1.10", 2, HALF_UP);          // 1) 공급가
    Money discount = supplyDiscount.min(supply);
    if (discount.isZero()) return gross;
    Money rest = supply.minus(discount);                       // 깎은 공급가
    Money vat = rest.times("0.10").scale(2, HALF_UP);          // 2) 부가세를 다시 매긴다
    return rest.plus(vat).scale(0, DOWN);                      // 3) 원 단위로 내린다
}

// 코드 확인 응답: 같은 함수로 계산한 결제 금액을 함께 준다
QuoteResponse quote(String code, Plan plan) {
    Money gross = plan.monthlyPrice();
    Money discount = promos.discountFor(code, gross.supplyPart());
    return new QuoteResponse(code, discount, totalAfterDiscount(gross, discount));
}
```

// 화면은 계산하지 않는다. 방금 확인한 코드 -> 이미 걸린 코드 -> 정가 순으로 고른다.
const charge = trialMode ? null : quote?.chargeAmount ?? activeCode?.chargeAmount ?? null;

```java
@Test
void 확인_때_알려_준_금액이_실제로_청구된다() {
    var quote = api.quote(code, "standard");                  // 화면이 받는 값
    var invoice = billing.chargeNow(owner, "standard", code); // 실제 청구
    assertThat(invoice.total()).isEqualByComparingTo(quote.chargeAmount());
}
```

같은 계산으로 할인율별 금액도 미리 뽑아 봤어요. 정가 99,000원 요금제에 정률 99.99% 를 걸면 9원, 99.4% 면 594원이 나옵니다. 카드 결제는 최소 금액이 있을 수 있어서, 시험 결제에는 100원이 넘는 쪽을 골랐습니다.

## 💡 배운 것

**같은 숫자를 두 곳에서 계산하면 언젠가 어긋납니다.** 반올림 위치 하나만 달라도 1원 차이가 나요. 금액처럼 틀리면 안 되는 값은 계산을 한 곳에 두고, 나머지는 그 결과를 받아 쓰는 게 안전했습니다.

**"보여 준 금액 = 청구한 금액" 은 시험으로 고정해 둡니다.** 나중에 누가 계산을 바꿔도 이 시험이 바로 알려 줘요.

**값이 없을 때의 모양도 정해 둡니다.** 화면과 서버가 따로 배포되는 동안 새 값이 비어 있을 수 있어서, 그때는 예전처럼 보이게 했습니다.

## 소감

할인 금액은 잘 보이는데 버튼만 정가라서, 처음에는 화면 문제로만 생각했어요. 막상 화면에서 계산하려고 보니 부가세와 반올림 규칙을 그대로 옮겨 와야 해서, "금액은 서버가 정하고 화면은 보여만 준다" 로 방향을 바꿨습니다. 결제처럼 돈이 오가는 곳은 화면이 똑똑할수록 오히려 위험하다는 걸 배웠습니다.
