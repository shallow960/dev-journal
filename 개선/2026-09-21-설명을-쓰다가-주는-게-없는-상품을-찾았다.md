# 2026-09-21 설명을 쓰다가, 주는 게 없는 상품을 찾았다

> 태그: #개선 #결제 #화면 #데이터

## 무엇을 / 왜

관리 화면에서 부가기능(애드온)을 파는 목록이 **이름과 가격뿐**이었습니다. "영상 저장 Lite 월 3만원" 이라고만 있으니, 사면 무엇을 받는지 알 수가 없다는 이야기가 나왔습니다.

그래서 애드온을 누르면 상세 창이 열리게 만들기로 했습니다. 제공 내용, 이런 스토어에 필요해요, 알아두세요.

## 어떻게 풀었나

### 설명은 기획서가 아니라 실제 동작에서

상세 문구를 쓰기 전에 **각 상품이 실제로 무엇을 켜 주는지**를 하나씩 확인했습니다. 기획서에 적힌 대로 쓰면 편하지만, 기획과 구현이 어긋나 있으면 화면이 거짓말을 하게 됩니다.

애드온 한 줄에는 이런 값이 들어 있었습니다.

```
코드 | 이름 | 월 가격 | 켜 주는 기능 목록 | 늘려 주는 한도 | 판매 방식
```

"켜 주는 기능" 과 "늘려 주는 한도" 가 핵심이었습니다. 그리고 그 기능 코드를 **실제로 검사하는 곳이 코드에 있는지**까지 찾아봤습니다. 16개를 훑었습니다.

### 숫자는 화면에 박지 않는다

영상 저장 애드온은 "저장 공간 +N GB" 를 주는데, 이 N 이 예전에 **50GB 에서 17GB 로 바뀐 적**이 있었습니다. 원가를 다시 계산하면서 줄였던 거예요.

화면 문구에 "+50GB" 라고 적어 뒀다면, 한도를 바꿀 때 화면은 그대로 남아 **약속과 실제가 어긋났을** 겁니다. 그래서 숫자는 서버 설정값을 받아서 보여 주게 했습니다. 목록 응답에 "늘려 주는 한도" 를 같이 실었습니다.

### 그러다 두 개가 걸렸다

16개를 훑다 보니 이런 상품이 두 개 있었습니다.

- 판매 방식은 **바로 결제**(버튼 한 번에 월 요금 합산)
- 켜 주는 기능: **없음**
- 늘려 주는 한도: **없음**
- 그 코드를 검사하는 곳: **없음**

즉 **사면 돈만 나가고 아무것도 켜지지 않는** 상품이었습니다. 하나는 사람이 직접 해 주는 관리 서비스였고, 하나는 이미 기본 기능으로 주기로 한 것과 겹쳤습니다.

- 사람이 해 주는 일 → **바로 결제를 막고 상담으로 받게** 바꿨습니다. 결제가 먼저 되면 못 지킬 약속이 되니까요.
- 기본 기능과 겹치는 것 → **판매를 내렸습니다.** 다만 지우지 않고 비활성만 했습니다. 지우면 예전에 산 기록이 이름을 못 찾아 청구서 표시가 깨집니다.

## 코드로 보기 (개념 재현)

목록 응답에 늘려 주는 한도를 싣습니다. 원문은 JSON 이라 맵으로 풀어서 보냅니다.

```java
public record AddonItem(
    String code,
    String name,
    BigDecimal priceMonthly,
    String salesMode,                 // self / consult / coming_soon
    Map<String, Object> grantsLimits, // 예: {"storage.gb": 17}
    String billing                    // recurring / one_time
) { }
```

화면은 그 값으로 문장을 만듭니다. 숫자가 바뀌면 문장도 따라 바뀝니다.

```ts
// 영상 1GB = 720p 약 53분 (서버의 저장 계산과 같은 기준)
const MINUTES_PER_GB = 53;

function storageLine(addon: AddonItem): string | null {
  const gb = Number(addon.grantsLimits?.["storage.gb"] ?? 0);
  if (!gb) return null;
  const hours = Math.floor((gb * MINUTES_PER_GB) / 60);
  return `영상 저장 공간 +${gb}GB (720p 기준 약 ${hours}시간)`;
}
```

판매 중단은 삭제가 아니라 비활성입니다.

```sql
-- 지우지 않는다. 남은 구매 이력이 이름을 찾을 수 있어야 한다.
update 애드온 set 판매중 = false where 코드 = '주는게없는상품';

-- 사람이 해 주는 일은 바로 결제만 막고 문의로 받는다.
update 애드온 set 메타 = 메타 || '{"salesMode": "consult"}' where 코드 = '관리서비스';
```

## 💡 배운 것

**설명 문구는 실제 동작에서 거꾸로 확인합니다.** 기획서는 의도이고, 화면은 약속입니다. 약속은 실제로 되는 것만 해야 합니다.

**바뀔 수 있는 숫자는 한 곳에서만 관리합니다.** 서버 설정과 화면 문구에 같은 숫자가 두 번 있으면, 언젠가 한쪽만 바뀝니다.

**"파는데 주는 게 없는" 상품은 목록만 봐서는 안 보입니다.** 가격도 있고 이름도 그럴듯해서, 켜 주는 것과 그걸 검사하는 코드를 같이 봐야 드러납니다.

**판매 중단은 비활성으로.** 과거 기록이 참조하는 대상은 지우는 순간 다른 화면이 깨집니다.

## 소감

설명 창 하나 만드는 작업이었는데, 문구를 쓰려고 확인하다가 결제 쪽 구멍을 찾았습니다. 무언가를 "설명" 하려면 그게 실제로 어떻게 동작하는지 알아야 하고, 그 과정 자체가 좋은 점검이 된다는 걸 느꼈습니다.
