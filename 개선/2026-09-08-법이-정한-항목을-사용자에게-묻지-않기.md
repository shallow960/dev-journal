# 2026-09-08 법이 정한 항목을 사용자에게 묻지 않기

> 태그: #개선 #전자상거래법 #폼설계 #판단을대신하기

## 무엇을 / 왜

상품정보제공고시라는 게 있습니다. 전자상거래법에서 "이 물건을 팔려면 이런 항목은 반드시 적어야 한다" 고 정해 둔 것입니다. 옷이면 소재·치수·세탁방법, 식품이면 원재료·유통기한·영양성분 같은 것들이죠.

안 적고 팔면 시정조치나 과태료 대상입니다. 그런데 우리 상품에는 **이걸 담을 자리가 아예 없었습니다.**

만들어야 했습니다.

## 어떻게 풀었나

### 품목군마다 항목이 다르다

먼저 막힌 건 "항목이 몇 개냐" 였습니다. 하나가 아니었어요.

법이 품목군을 나눠 놓고 각각 다른 항목을 요구합니다. 의류는 9개, 화장품은 11개, 건강기능식품은 11개인데 내용이 전혀 다릅니다. 건강기능식품에는 **"질병의 예방·치료를 위한 의약품이 아니다"** 라는 문구를 적으라는 항목까지 있습니다.

우리 상품 카테고리에 맞춰 추리니 25개 품목군이 나왔습니다.

### 컬럼으로 만들지 않았다

처음엔 컬럼을 쭉 만들까 했습니다. `material`, `color`, `size`... 그런데 품목군마다 항목이 다르니 전부 합치면 100개가 넘습니다. 대부분은 비어 있고요.

게다가 **법이 바뀌면 항목도 바뀝니다.** 컬럼으로 두면 그때마다 데이터베이스를 고쳐야 합니다.

그래서 항목 정의는 표로, 값은 JSON 한 칸에 담기로 했습니다.

```
품목군 표      의류 / 화장품 / 가공식품 ...
항목 표        의류 → 소재, 색상, 치수, 제조자 ...
상품별 값      {"material": "면 100%", "color": "블랙"}
```

품목군이 하나 바뀌어도 표의 행만 고치면 됩니다.

대신 아무 값이나 들어가지 않게 막았습니다. 저장할 때 **그 품목군에 정의된 항목만** 받습니다. 화면이 잘못 보내거나 옛 폼이 남아 있어도 엉뚱한 키가 쌓이지 않게요.

### 어려운 판단을 사용자에게 넘기지 않기

여기서 한참 고민한 게 있습니다. **"이 상품이 어느 품목군이냐" 를 누가 정하냐** 입니다.

처음엔 판매자가 고르게 하려고 했습니다. 파는 사람이 제일 잘 알 테니까요.

그런데 25개 목록을 놓고 보니 생각이 바뀌었습니다. "영상·음향가전" 과 "가정용 전기제품" 은 뭐가 다른가요? TV 는 앞이고 냉장고는 뒤인데, 파는 사람이 그걸 알아야 할 이유가 없습니다.

그러다 상품 카테고리를 보니 답이 있었습니다. **어차피 카테고리는 고르고 있습니다.** "TV" 를 고르는 건 "영상가전" 을 고르는 것보다 훨씬 쉽습니다.

그래서 카테고리에서 품목군을 추천하게 했습니다.

```
스마트폰  → 휴대폰
쌀        → 농수축산물
이불      → 침구류/커튼
세탁세제  → 기타 재화
```

한 가지 조심할 게 있었습니다. **한 카테고리 안에도 다른 품목이 섞입니다.** 가전 안에 TV 와 냉장고가 같이 있고 법정 항목이 서로 다릅니다. 그래서 추천을 대분류·중분류에 심어 두고 **가장 구체적인 것이 이기게** 했습니다. `08` 가전은 "가정용 전기제품" 이지만 `08-02` 휴대폰은 "휴대폰" 으로 덮입니다.

그리고 추천일 뿐이라 상품마다 바꿀 수 있게 뒀습니다.

### 등록 흐름 안에 넣기

다음 고민은 "어디에 두냐" 였습니다.

별도 화면으로 빼면 깔끔합니다. 상품을 등록하고 나중에 채우는 거죠. 그런데 그러면 **계속 빠뜨립니다.** 법정 의무인데요.

등록 폼의 마지막 단계로 넣었습니다.

```
기본정보 → 옵션 → 이미지 → 배송 → 설명 → 정보고시
```

여기서 순서 문제가 하나 있었습니다. 고시는 상품에 딸린 것이라 **상품이 저장된 뒤에야** 쓸 수 있습니다. 등록할 때는 저장 전까지 상품 번호가 없으니까요.

그래서 상품을 먼저 저장하고 이어서 고시를 저장하는데, **고시 저장이 실패하면** 어떻게 할지 정해야 했습니다. 상품은 이미 저장된 상태입니다.

숨기지 않기로 했습니다.

> 상품은 저장됐지만 정보고시를 저장하지 못했습니다. 다시 시도해 주세요.

"저장됐습니다" 라고만 하면 법정 표기가 빠진 채로 팔립니다.

### 빈 칸은 보여 주지 않는다

손님 상품 페이지에 표로 나갑니다. 여기서 정한 것 하나.

**값이 안 적힌 항목은 아예 빼고 보여 줍니다.** 처음엔 항목을 다 늘어놓고 빈 칸으로 둘까 했는데, 그러면 "다 적었다" 는 착각만 줍니다. 적힌 것만 보여 주는 편이 정직합니다.

대신 관리자에게는 **빠진 상품이 몇 개인지** 보여 주는 화면을 따로 만들었습니다. 쓰는 건 판매자 몫이지만 책임은 스토어가 지니까요.

## 배운 것

**사용자에게 무엇을 물을지 정하는 것도 설계입니다.** "판매자가 제일 잘 안다" 는 처음 생각이 틀렸습니다. 판매자가 아는 건 "이건 TV 다" 이지 "TV 는 영상가전 품목군이다" 가 아니었어요. **이미 알고 있는 것으로 모르는 것을 채울 수 있으면** 굳이 묻지 않는 게 맞습니다.

**법이 정한 것은 "나중에" 로 미룰 수 없습니다.** 별도 화면으로 빼면 코드는 깔끔한데 사람이 안 채웁니다. 흐름 안에 넣으면 등록이 한 단계 길어지지만 빠뜨리지 않아요. 어느 쪽이 깔끔하냐가 아니라 **어느 쪽이 실제로 지켜지냐** 로 골라야 했습니다.

**절반만 성공했을 때 뭐라고 말할지 미리 정해야 합니다.** 상품은 저장됐는데 고시는 실패한 상황을 생각 안 했으면 "저장됐습니다" 라고 했을 겁니다. 거짓말은 아니지만 중요한 걸 빠뜨린 말이죠. 두 단계로 나뉜 저장은 중간에 끊길 수 있다는 걸 전제로 만들어야 했습니다.

**모르는 걸 아는 척하지 않는 게 낫습니다.** 빈 칸을 표에 늘어놓는 것도, 과세 구분을 모르는 매출을 합계에 넣는 것도 화면은 깔끔해지지만 틀린 인상을 줍니다. 비워 두고 "이건 빠졌다" 고 말하는 편이 지저분해도 정확했습니다.
