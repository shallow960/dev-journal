# 2026-10-02 체험 중에 결제하면, 남은 체험이 사라졌다

> 태그: #개선 #구독 #결제 #기간계산 #경계조건 #Java

## 무엇을 / 왜

구독 서비스에 14일 무료 체험이 있습니다. 체험 중에 "지금 결제" 를 누르면, 그 자리에서 체험이 끝나고 **결제한 날부터** 한 달이 시작됐습니다.

```
체험: 10/1 ~ 10/15
10/5에 결제 → 체험 끝, 이용 기간 10/5 ~ 11/5   (남은 체험 10일이 사라짐)
```

일찍 결제할수록 손해라서, 마음이 정해진 사람도 체험이 끝날 때까지 기다리는 게 나은 구조였습니다. 다른 사이트 빌더는 "결제는 지금 받되 남은 체험은 그대로 두고, 결제한 기간은 체험이 끝나는 때부터" 이어 붙이고 있었습니다.

```
10/5에 결제 → 무료 ~10/15, 결제한 기간 10/15 ~ 11/15, 다음 결제 11/15
```

## 어떻게 풀었나

### 바꾼 건 한 줄, 문제는 그다음

결제가 성공하면 이용 기간의 시작을 "지금" 대신 "체험이 끝나는 시각과 지금 중 늦은 쪽" 으로 바꿨습니다. 그런데 이렇게 하자 **이용 기간이 아직 시작되지 않은 구독** 이 처음으로 생겼고, 기존 계산들이 하나같이 "기간은 이미 시작됐다" 고 가정하고 있었다는 게 드러났습니다.

| 계산 | 기간이 미래에 시작하면 생기던 일 |
|---|---|
| 해지 환불 | 쓴 날을 "최소 1일" 로 세서, 체험 중 해지해도 하루치를 떼고 환불 |
| 요금제 올리기 | 견적 시각이 기간 시작보다 앞이라 "기간 밖" 으로 판단해 견적 자체가 막힘 |
| 애드온 구매 | 지금부터 기간 끝까지(남은 체험 + 한 달)를 한 달 기준으로 나눠 132% 청구 |
| 운영자의 "다음날 하향" | 남은 체험을 없애고 하위 요금제를 바로 시작 |
| 휴점 | 보관료를 내고 무료 체험을 얼려 두는 셈 |

### 기준: 시작 전이면 시작 시각으로

각 계산에서 "지금" 이 기간 시작보다 앞이면 **기간 시작 시각** 을 기준으로 쓰게 맞췄습니다.

- 해지: 기간 시작 전에 해지하면 쓴 날은 0일, 낸 돈 전액 환불
- 요금제 올리기: 아직 안 쓴 기간이 전부 남은 것으로 보고 차액 계산(남은 비율이 100%를 넘지 않게)
- 애드온: 결제한 기간 한 주기만 청구하고, 본 구독과 같은 날 갱신
- 운영자 "다음날 하향" 과 휴점은 이 기간에 막고, 이유를 알려 줌("무료체험이 끝난 뒤에 일시정지할 수 있어요")

### 같이 정리한 것

- 해지를 예약해 둔 채 결제하면, 결제한 한 달이 있어도 예약일(체험 종료)에 닫혀 버렸습니다. 결제 전에 "해지 예약을 먼저 취소" 하도록 안내하고, 예약을 취소하는 버튼도 새로 만들었습니다.
- 결제한 뒤에도 몰 상태가 "체험" 으로 남아 관리 화면에 계속 체험으로 보였습니다. 결제되면 "이용 중" 으로 바꿨습니다.
- 체험 표시는 결제할 때 지웠습니다. 남겨 두면 다른 코드가 "체험 뒤 첫 결제 실패" 로 읽어, 첫 갱신이 한 번 실패했을 때 바로 닫는 잘못된 길로 갔습니다.

## 코드로 보기 (개념 재현)

이름은 예시입니다.

```java
// 결제 성공: 이용 기간은 체험이 끝나는 때부터
void renew(OffsetDateTime paidAt) {
    OffsetDateTime start = (trialEndsAt != null && trialEndsAt.isAfter(paidAt)) ? trialEndsAt : paidAt;
    periodStart = start;
    periodEnd = cycle.nextPeriodEnd(start);
    nextBillingAt = periodEnd;
    trialEndsAt = null;          // 남겨 두면 다른 곳에서 "체험 뒤 첫 결제" 로 잘못 읽힌다
    status = ACTIVE;
}

// 환불: 기간 시작 전 해지는 쓴 날 0
long usedDays(LocalDate cancelDate, LocalDate start, long totalDays) {
    if (cancelDate.isBefore(start)) return 0;                       // 예전엔 최소 1일로 셌다
    long days = ChronoUnit.DAYS.between(start, cancelDate) + 1;
    return Math.max(1, Math.min(days, totalDays));
}

// 요금제 올리기·애드온: "지금" 이 기간 시작보다 앞이면 기간 시작을 기준으로
OffsetDateTime billingFrom(OffsetDateTime now, OffsetDateTime periodStart) {
    return now.isBefore(periodStart) ? periodStart : now;
}
```

## 💡 배운 것

**한 줄을 바꾸면 "새로운 상태" 가 생깁니다.** 기간 시작을 미루는 건 한 줄이었지만, 그 때문에 처음 생긴 "아직 시작 안 한 기간" 을 다른 계산들이 다룰 줄 몰랐습니다. 바꾼 줄보다 그 줄이 만든 상태를 따라가는 데 시간이 더 걸렸습니다.

**경계 조건은 표로 정리합니다.** 환불·업그레이드·애드온·하향·휴점을 한 표에 놓고 "기간 시작 전이면?" 을 하나씩 물어보니 빠뜨린 곳이 보였습니다.

**안 쓰는 표시는 지웁니다.** 남겨 둔 체험 표시가 엉뚱한 분기를 타게 만들 뻔했습니다.

## 소감

사용자 입장에서는 "남은 체험을 지켜 준다" 는 단순한 변화인데, 결제 쪽 코드에서는 기간이 미래에 시작하는 경우를 처음 다루는 일이었습니다. 다른 서비스가 이미 그렇게 하고 있다는 걸 확인하고 시작해서 방향은 흔들리지 않았고, 계산마다 테스트(남은 체험 유지, 체험 중 해지 시 전액 환불, 두 번 눌러도 한 번만 결제)를 붙였습니다.
