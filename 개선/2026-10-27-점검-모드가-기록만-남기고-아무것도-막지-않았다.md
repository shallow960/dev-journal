# 2026-10-27 점검 모드가 기록만 남기고, 아무것도 막지 않았다

> 태그: #개선 #점검모드 #인터셉터 #캐시 #HTTP503

## 무엇을 / 왜

운영자 화면에는 "점검 모드"가 있었습니다. 그런데 켜도 점검 기록 표에 한 줄이 남을 뿐, 손님도 사장님도 평소처럼 주문하고 저장할 수 있었습니다. 켜고 끄는 화면도 따로 없었습니다. 데이터베이스를 옮기거나 큰 배포를 할 때 쓰려고 만든 기능이었는데, 정작 그때 아무것도 막아 주지 않는 상태였습니다.

## 어떻게 풀었나

### 1. "지금 점검 중인가"를 하나로 정했습니다

점검 기록 중 가장 마지막 줄을 지금 상태로 봤습니다. 켜져 있고, 시작 시각이 지났고(비어 있으면 바로), 끝 시각 전이면(비어 있으면 끌 때까지) 점검 중으로 봤습니다. 끝 시각이 지나면 따로 끄지 않아도 저절로 풀리게 했습니다.

### 2. 쓰기만 막고, 막으면 안 되는 길은 열어 뒀습니다

점검 중에는 바꾸는 요청(POST·PUT·PATCH·DELETE)만 503 으로 돌려보내고, 언제 다시 시도하면 되는지 Retry-After 머리글을 붙였습니다. 읽기는 그대로 두어 손님이 상품을 보는 것까지 막지는 않았습니다.

막으면 안 되는 길도 있었습니다.

- 결제 완료 콜백: 손님이 이미 결제한 뒤 돌아오는 길이라, 막으면 돈은 나갔는데 주문은 끝나지 않는 상태가 될 수 있었습니다.
- 결제대행사·메일·영상 처리의 결과 알림: 밖에서 보내는 알림이라, 막으면 다시 보내 주지 않을 수도 있었습니다.
- 운영자 화면과 상태 페이지: 점검 모드를 끄는 곳까지 막으면 안 됐습니다.

### 3. 모든 요청이 묻는 값이라 짧게 기억했습니다

요청마다 데이터베이스에 점검 상태를 물으면 그 자체가 부담이었습니다. 10초 동안 기억하게 하고, 운영자가 켜거나 끄면 그 변경이 커밋된 뒤 바로 잊게 해서 다음 요청부터 새 상태를 보게 했습니다.

### 4. 화면은 상태를 모르면 막지 않았습니다

화면 쪽에서는 미들웨어가 같은 상태를 15초 기억해, 점검 중이면 쇼핑몰·관리 화면을 "서비스 점검 중이에요" 화면으로 보냈습니다. 상태를 물어보지 못했을 때는 막지 않게 했습니다. 상태 확인이 잠깐 실패했다고 모든 화면이 점검 화면으로 바뀌면 그게 더 큰 장애였기 때문입니다.

## 코드로 보기 (개념 재현)

```java
public class MaintenanceGate implements HandlerInterceptor {

    private static final Set<String> WRITES = Set.of("POST", "PUT", "PATCH", "DELETE");

    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object handler) throws IOException {
        if (!WRITES.contains(req.getMethod()) || alwaysOpen(req.getRequestURI())) {
            return true;                       // 읽기와 막으면 안 되는 길은 그대로
        }
        Maintenance now = status.current();    // 10초 기억, 켜고 끄면 커밋 뒤 바로 잊는다
        if (!now.active()) {
            return true;
        }
        res.setStatus(503);
        if (now.endsAt() != null) {
            res.setHeader("Retry-After", String.valueOf(secondsUntil(now.endsAt())));
        }
        res.setContentType("application/json");
        res.getWriter().write("{\"code\":\"MAINTENANCE\"}");
        return false;
    }

    // 결제 완료 콜백·외부 결과 알림·운영자 화면·상태 페이지
    private boolean alwaysOpen(String path) {
        return OPEN_PATHS.stream().anyMatch(path::startsWith);
    }
}
```

## 💡 배운 것

**점검 모드는 "무엇을 막을까"보다 "무엇을 막으면 안 될까"를 먼저 정해야 했습니다.** 이미 돈이 오간 뒤 돌아오는 길과 밖에서 보내는 알림을 막으면, 점검이 끝난 뒤에도 남는 문제가 생길 수 있었습니다.

**모든 요청이 읽는 값은 기억해 두되, 바꾼 순간에는 바로 잊어야 했습니다.** 그래야 부담을 줄이면서도 켜자마자 막혔습니다.

**막는 쪽이 실패했을 때는 열어 두는 게 맞는 경우가 있었습니다.** 상태를 모를 때 막으면, 상태 확인이 흔들리는 것만으로 서비스 전체가 멈췄을 것입니다.

## 소감

기능이 "있다"는 것과 "동작한다"는 것은 다르다는 걸 다시 느꼈습니다. 메뉴와 기록 표가 있으니 당연히 되는 줄 알았는데, 실제로 막는 코드는 없었습니다. 점검 모드처럼 평소에는 쓰지 않는 기능일수록, 쓸 일이 생기기 전에 한 번 켜 보는 것이 필요했습니다.
