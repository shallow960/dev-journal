# 2026-10-26 같은 판의 계약서라도 가게마다 글이 달라, 동의는 채운 글의 해시로 확인했다

> 태그: #개선 #동의기록 #해시 #감사기록 #멀티테넌트

## 무엇을 / 왜

지난번에 약관을 고치지 않고 새 판을 쌓게 바꿨습니다([약관은 고치지 않고, 새 판을 쌓는다](2026-10-15-약관은-고치지-않고-새-판을-쌓는다.md)). 동의 기록에 판 번호를 이어 두니 "그때 무엇에 동의했나"에 답할 수 있었습니다.

이번에 최종 약관을 붙이면서 판 번호만으로는 모자란 문서가 나왔습니다. 개인정보 처리위탁 계약서였습니다. 본문은 하나인데, 가게(테넌트)를 열 때마다 위탁자 상호와 대표자, 가게 이름과 주소, 계약일, 사고 때 연락받을 곳, 쓰는 기능 목록이 빈칸에 채워졌습니다. 판이 같아도 가게마다 글이 달랐습니다.

판 번호만 남기면 두 가지가 비었습니다.

- 나중에 그 가게 주인이 실제로 본 글을 똑같이 다시 만들 수 있다는 보장이 없었습니다. 상호나 연락처가 바뀌면 다시 채운 글도 달라지니까요.
- 주인이 화면을 열어 둔 사이 상호를 바꾸면, 주인이 본 글과 서버가 기록할 글이 달라질 수 있었습니다.

## 어떻게 풀었나

1. 서버가 그 가게의 값으로 빈칸을 채운 글을 만들고, 그 글의 SHA-256 해시를 함께 돌려주는 미리 보기를 만들었습니다. 빈칸(【 】)이 하나라도 남으면 미리 보기부터 거절했습니다.
2. 화면은 그 글을 보여 주고, 동의할 때 받은 해시를 그대로 보내게 했습니다.
3. 서버는 동의 요청을 받으면 지금 값으로 글을 다시 채워 해시를 비교했습니다. 같을 때만 동의를 남기고, 다르면 409 로 돌려보내 다시 보게 했습니다.
4. 동의 기록에는 판 번호와 함께 채운 글 전체, 그 해시, 계약 당사자를 저장했습니다.

화면이 보낸 글을 그대로 저장하지 않은 게 핵심이었습니다. 글은 서버가 다시 만들고, 화면이 보낸 해시는 "이 글을 봤다"는 확인으로만 썼습니다.

같은 날 붙인 다른 문서에도 같은 생각을 썼습니다.

- 입점 계약서: 신청할 때는 브랜드가, 승인할 때는 가게 주인이 각자 본 글의 해시를 보내고, 서버가 다시 만든 글과 같을 때만 기록했습니다
- 결제대행사 약관: 동의한 원문의 해시를 약관마다 남겼습니다
- 주문 확인 문구: 주문을 만든 뒤 그 주문의 실제 금액과 상품으로 서버가 다시 쓴 글을 남겼습니다

## 코드로 보기 (개념 재현)

```java
record Rendered(String body, String sha256) {}

/** 미리 보기: 이 가게의 값으로 채운 글과 해시 */
Rendered preview(ContractInfo info) {
    String body = template.fill(info);                 // 상호·주소·계약일·연락처·기능
    List<String> blanks = Blanks.find(body);           // 【...】 가 남았나
    if (!blanks.isEmpty()) {
        throw new BadRequest("CONTRACT_INFO_REQUIRED", blanks);
    }
    return new Rendered(body, Sha256.hex(body));
}

/** 동의: 화면이 본 글의 해시가 지금 다시 채운 글과 같을 때만 남긴다 */
@Transactional
void agree(ContractInfo info, String seenSha256, Actor actor) {
    Rendered now = preview(info);                      // 화면이 보낸 글은 쓰지 않는다
    if (!now.sha256().equals(seenSha256)) {
        throw new Conflict("CONTRACT_CHANGED");         // 화면을 연 사이 값이 바뀌었다
    }
    consents.save(new ContractConsent(
        documentVersionId, info.party(), now.body(), now.sha256(), actor.id(), clock.instant()));
}
```

```sql
-- 판 번호만이 아니라 '그 가게에 채워진 글'을 남긴다
alter table legal_consents
    add column party         jsonb,  -- 계약 당사자(상호·대표자)
    add column rendered_body text,   -- 동의한 글 그대로
    add column rendered_sha  text;   -- 그 글의 SHA-256
```

시험으로는 이런 경우를 확인했습니다.

- 채운 글에 빈칸이 없고, 미리 보기가 준 해시가 글의 해시와 같은지
- 미리 보기와 다른 해시로 동의하면 "바뀌었다"로 막히는지
- 연락처가 비어 빈칸이 남으면 미리 보기부터 거절되는지
- 동의하면 그 가게 주소가 들어간 글과 그 글의 해시, 계약 당사자가 함께 남는지

## 💡 배운 것

**같은 판이라도 채우는 값이 다르면 다른 글이라는 걸 알게 됐습니다.** 템플릿 문서의 동의는 판 번호보다 "채운 결과"를 남겨야 나중에 그대로 보여 줄 수 있었습니다.

**해시는 화면과 서버가 같은 글을 봤는지 맞춰 보는 데 썼습니다.** 글 전체를 주고받지 않아도 되고, 화면이 보낸 글을 믿을 필요도 없었습니다. 서버는 늘 자기가 다시 만든 글을 저장했습니다.

**빈칸 검사를 미리 보기 단계에 두니 "빈칸에 동의한 기록"이 생길 틈이 없었습니다.**

## 소감

처음에는 판 번호만 남기면 충분하다고 생각했습니다. 그런데 계약서를 실제로 채워 보니 가게마다 글이 달랐고, 그 차이가 바로 법적으로 중요한 부분(누가, 어느 가게를, 언제)이었습니다. 동의 기록은 "동의함" 한 칸이 아니라 "무엇을 보고 동의했나"를 다시 보여 줄 수 있어야 한다는 걸 이번에 더 분명히 느꼈습니다.
