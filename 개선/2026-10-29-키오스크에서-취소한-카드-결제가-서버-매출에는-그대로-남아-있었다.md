# 2026-10-29 키오스크에서 취소한 카드 결제가, 서버 매출에는 그대로 남아 있었다

> 태그: #개선 #매출정합성 #멱등 #재전송 #키오스크

## 무엇을 / 왜
사진 키오스크는 카드 매출을 자기 기록에 남기고 서버로도 올리고 있었습니다. 매장 관리자는 키오스크 관리 메뉴에서 직전 카드 결제를 취소할 수 있었습니다.

- 결제 연결 교차 검토에서, 키오스크에서 취소하면 키오스크 기록에만 '취소'가 남고 서버로 이미 올라간 매출은 그대로라는 것을 찾았습니다.
- 관리자 웹의 환불 기능도 키오스크에서 올라온 매출은 다루지 않아서, 손으로 바로잡을 수도 없었습니다.
- 그대로 두면 관리자 웹의 매출과 정산이 취소한 만큼 부풀어, 매장이 실제로 받은 돈보다 많게 보일 수 있었습니다.

## 어떻게 풀었나
고를 수 있는 길은 셋이었습니다. 키오스크 취소를 서버에 자동으로 반영하기, 관리자 웹에서 직원이 손으로 고치게만 열기, 오픈 때는 매장이 따로 적어 두기. 자동 반영으로 했습니다.

- 키오스크가 매출 취소를 알리면 서버가 그 주문을 환불로 바꾸게 했습니다.
- 그런데 이 길은 키오스크가 서버 매출을 줄일 수 있는 길이기도 했습니다. 그래서 받는 범위를 좁게 정했습니다.
  - 그 키오스크가 올린 주문만 받았습니다. 다른 키오스크의 주문이면 '없다'(404)고 답해서, 그런 주문이 있는지조차 알 수 없게 했습니다.
  - 카드 매출만, 판매 뒤 5일 안만 받았습니다. 5일은 관리자 웹 환불과 같은 기한이고, 넘으면 거절하고 관리자에게 맡겼습니다.
  - 이미 환불된 주문이면 처음과 같은 성공으로 답해서, 같은 취소가 두 번 와도 한 번만 처리되게 했습니다.
  - 환불 기록에 어느 키오스크가 어떤 취소 승인번호로 줄였는지 남겨, 정산 때 카드사 쪽 내역과 맞춰 볼 수 있게 했습니다.
- 키오스크는 취소한 직후 한 번 보내고, 못 보냈으면 몇 분마다 도는 매출 올리기 때 다시 보내게 했습니다.
  - 서버가 '없다'고 하면 매출이 아직 서버에 안 올라갔을 수 있어서 다음에 다시 보냈습니다.
  - 서버가 거절하면 다시 보내도 같은 답이라 멈추고, 오류로 남겨 관리자가 보게 했습니다.

## 코드로 보기 (개념 재현)
서버의 판정과 키오스크의 다시 보내기를 한 파일로 흉내 냈습니다. 이름은 모두 예시입니다.

```js
// 키오스크가 "이 카드 매출을 취소했다"고 알리면 서버 주문을 환불로 바꾼다.
const DAY = 24 * 60 * 60 * 1000;
const CANCEL_WINDOW = 5 * DAY; // 관리자 환불과 같은 기한

// 서버에 올라와 있는 키오스크 매출(예시 데이터)
const orders = new Map([
  ['sale-1', { kioskId: 'K1', method: 'card', refunded: false, soldAt: Date.parse('2026-10-29T10:00:00+09:00') }],
  ['sale-2', { kioskId: 'K2', method: 'card', refunded: false, soldAt: Date.parse('2026-10-29T10:05:00+09:00') }],
  ['sale-3', { kioskId: 'K1', method: 'cash', refunded: false, soldAt: Date.parse('2026-10-29T10:10:00+09:00') }],
  ['sale-4', { kioskId: 'K1', method: 'card', refunded: false, soldAt: Date.parse('2026-10-22T10:00:00+09:00') }],
]);
const refundLog = [];

// 서버: 키오스크가 보낸 취소를 받을지 정한다.
function cancelSale(kioskId, saleId, approvalNo, now) {
  const order = orders.get(saleId);
  // 1) 이 키오스크가 올린 주문이 아니면 "없다"고 답한다. 남의 주문이 있는지조차 알려 주지 않는다.
  if (!order || order.kioskId !== kioskId) return { status: 404 };
  // 2) 카드 매출만 받는다.
  if (order.method !== 'card') return { status: 400, reason: '카드 매출만' };
  // 3) 이미 환불됐으면 같은 성공을 돌려준다. 같은 취소가 두 번 와도 한 번만 처리된다.
  if (order.refunded) return { status: 200, alreadyRefunded: true };
  // 4) 판매 뒤 5일 안만 받는다. 넘으면 관리자에게 맡긴다.
  if (now - order.soldAt > CANCEL_WINDOW) return { status: 400, reason: '5일 지남' };
  order.refunded = true;
  // 5) 어느 키오스크가 어떤 취소 승인번호로 줄였는지 남긴다. 정산 때 카드사 내역과 맞춰 본다.
  refundLog.push({ saleId, kioskId, approvalNo });
  return { status: 200, alreadyRefunded: false };
}

// 키오스크: 응답을 보고 다시 보낼지 정한다.
function nextAction(res) {
  if (res.status >= 200 && res.status < 300) return '반영 끝';
  if (res.status === 404) return '다음에 다시';               // 서버에 아직 매출이 안 올라갔을 수 있다
  if ([400, 403, 409, 422].includes(res.status)) return '멈추고 오류로 남김'; // 다시 보내도 같은 답
  return '다음에 다시';                                        // 서버 오류·네트워크 끊김
}

const now = Date.parse('2026-10-29T15:00:00+09:00');
for (const [label, sale] of [
  ['오늘 판 카드 매출', 'sale-1'],
  ['같은 취소를 한 번 더', 'sale-1'],
  ['다른 키오스크의 매출', 'sale-2'],
  ['현금 매출', 'sale-3'],
  ['7일 전 카드 매출', 'sale-4'],
  ['아직 안 올라온 매출', 'sale-9'],
]) {
  const res = cancelSale('K1', sale, 'A1234567', now);
  console.log(`${label} -> ${JSON.stringify(res)} -> 키오스크: ${nextAction(res)}`);
}
console.log('환불 기록:', JSON.stringify(refundLog));
```

실행 결과입니다.

```
오늘 판 카드 매출 -> {"status":200,"alreadyRefunded":false} -> 키오스크: 반영 끝
같은 취소를 한 번 더 -> {"status":200,"alreadyRefunded":true} -> 키오스크: 반영 끝
다른 키오스크의 매출 -> {"status":404} -> 키오스크: 다음에 다시
현금 매출 -> {"status":400,"reason":"카드 매출만"} -> 키오스크: 멈추고 오류로 남김
7일 전 카드 매출 -> {"status":400,"reason":"5일 지남"} -> 키오스크: 멈추고 오류로 남김
아직 안 올라온 매출 -> {"status":404} -> 키오스크: 다음에 다시
환불 기록: [{"saleId":"sale-1","kioskId":"K1","approvalNo":"A1234567"}]
```

같은 취소를 두 번 보내도 환불 기록은 한 줄이었습니다. 다른 키오스크의 매출과 아직 안 올라온 매출에는 둘 다 404 로 똑같이 답해서, 남의 매출이 있는지 알아낼 수 없었습니다.

## 💡 배운 것
- 돈이 한쪽에서 되돌아가면 연결된 다른 장부에서도 되돌아가야 한다는 걸 다시 배웠습니다(2026-07-24, 환불했는데 판매자 정산은 그대로였던 글). 이번에는 같은 서비스 안의 키오스크 기록과 서버 매출 사이였습니다.
- 매출을 줄일 수 있는 길을 열 때는 되돌리는 방법만큼, 그 길을 누가 어디까지 쓸 수 있는지를 같이 정해야 한다는 걸 배웠습니다.
- 다시 보낼지는 응답의 뜻으로 나눠야 한다는 걸 배웠습니다. '아직 없다'는 기다렸다가 다시 보내고, '안 된다'는 몇 번을 보내도 같은 답이라 멈춰야 했습니다.
