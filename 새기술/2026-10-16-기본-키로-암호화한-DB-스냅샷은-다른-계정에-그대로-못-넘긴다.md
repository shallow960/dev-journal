# 2026-10-16 기본 키로 암호화한 DB 스냅샷은, 다른 계정에 그대로 못 넘긴다

> 태그: #새기술 #AWS #RDS #KMS #서버이전

## 무엇을 / 왜

서비스를 다른 AWS 계정(운영용)으로 옮기면서 DB 를 데이터째 넘겨야 했습니다. DB 는 암호화돼 있었는데, 키가 AWS 가 계정마다 만들어 주는 **기본 키(AWS 관리형 키)** 였어요.

이 키로 암호화한 스냅샷은 **다른 계정과 공유할 수 없습니다.** 기본 키는 키 정책을 바꿀 수 없어서, 다른 계정에 이 키를 쓸 권한을 줄 방법이 없거든요.

## 어떻게 풀었나

1. 원래 계정(A)에 **직접 관리하는 키(고객 관리형 키)** 를 만들고, 키 정책에 운영 계정(B)을 넣었습니다.
2. 운영 중인 DB 에 수동 스냅샷을 찍는 대신, **새벽 자동 백업 스냅샷을 그 키로 복사** 했습니다. 단일 AZ DB 는 스냅샷을 찍을 때 입출력이 잠깐 멈출 수 있어서요. 자동 백업은 바로 공유가 안 되지만, 복사본은 수동 스냅샷이 되어 공유할 수 있어요.
3. 복사본을 B 계정에 공유했습니다.
4. B 계정에서는 공유받은 스냅샷을 **B 계정의 키로 한 번 더 복사** 했습니다. 공유받은 것으로 바로 복원하면 새 DB 가 A 계정의 키에 계속 묶여서, 나중에 A 에서 그 키를 지우면 B 의 DB 를 열 수 없게 돼요.
5. 그 복사본으로 새 DB 를 만들었습니다. 사양, 네트워크, 보안 그룹은 복원할 때 새로 고릅니다.

## 코드로 보기 (개념 재현)

실제로는 콘솔에서 했고, 같은 순서를 CLI 로 적으면 이렇습니다(계정 번호·이름은 예시).

```bash
# A 계정: 자동 백업을 공유용 키로 복사하고, B 계정에 공유한다
aws rds copy-db-snapshot \
  --source-db-snapshot-identifier rds:app-db-2026-10-15-17-35 \
  --target-db-snapshot-identifier app-db-share \
  --kms-key-id alias/snapshot-share        # 기본 키(aws/rds)가 아니라 공유용 키

aws rds modify-db-snapshot-attribute \
  --db-snapshot-identifier app-db-share \
  --attribute-name restore \
  --values-to-add 222222222222             # B 계정

# B 계정: 공유받은 스냅샷을 내 키로 다시 복사한 뒤 복원한다
aws rds copy-db-snapshot \
  --source-db-snapshot-identifier arn:aws:rds:ap-northeast-2:111111111111:snapshot:app-db-share \
  --target-db-snapshot-identifier app-db-copy \
  --kms-key-id alias/aws/rds               # 이제부터 A 계정 키와 상관없다

aws rds restore-db-instance-from-db-snapshot \
  --db-instance-identifier app-db \
  --db-snapshot-identifier app-db-copy \
  --db-instance-class db.t4g.small \
  --no-publicly-accessible \
  --vpc-security-group-ids sg-0123456789abcdef0
```

A 계정 공유용 키의 정책에는 B 계정이 이 키로 복호화하고 복사할 수 있게 하는 문장이 들어갑니다.

```json
{
  "Sid": "AllowAccountB",
  "Effect": "Allow",
  "Principal": { "AWS": "arn:aws:iam::222222222222:root" },
  "Action": ["kms:Decrypt", "kms:DescribeKey", "kms:ReEncrypt*", "kms:GenerateDataKey*", "kms:CreateGrant"],
  "Resource": "*"
}
```

## 💡 배운 것

**AWS 관리형 기본 키로 암호화된 스냅샷은 다른 계정과 공유할 수 없습니다.** 공유하려면 키 정책을 고칠 수 있는 고객 관리형 키로 다시 암호화해야 했어요.

**받은 쪽에서 한 번 더 복사해야 끊어집니다.** 공유받은 스냅샷으로 바로 만든 DB 는 보낸 쪽 키에 기대고 있어요. 받는 계정의 키로 복사해 두면 보낸 쪽과 상관없어집니다.

**운영 중이면 자동 백업을 복사하는 게 부담이 적습니다.** 이미 있는 자동 백업을 복사하면 운영 DB 에 손대지 않아요. 대신 데이터는 그 백업 시각 기준입니다.

**리허설로 시간을 재 둡니다.** 복사 약 4분, 다시 복사 약 11분, 복원 약 13분이 걸렸어요. 실제 이전 때 서비스를 멈출 시간을 이 숫자로 정했습니다.

## 소감

처음엔 "스냅샷 공유" 버튼 하나면 될 줄 알았는데, 암호화 키가 어느 계정에 묶여 있는지가 전체 순서를 정했습니다. 암호화된 데이터를 옮길 때는 데이터보다 키를 먼저 봐야 한다는 걸 배웠어요.
