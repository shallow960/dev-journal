# 2026-10-28 처음 보는 기기에서 로그인하면 알려 주기 - 서버에는 기기 값의 해시만 남겼다

> 태그: #새기술 #보안 #로그인 #쿠키 #해시

## 무엇을 / 왜

쇼핑몰 주인이 쓰는 계정에서 비밀번호나 2단계 인증을 바꾸면 메일로 알리게 만들었습니다. 그런데 정작 누가 다른 곳에서 로그인하는 건 계정 주인이 알 방법이 없었습니다. 비밀번호가 새어 나갔을 때 가장 먼저 알아챌 수 있는 신호가 "내가 아닌 로그인"이라서, 처음 보는 기기에서 로그인하면 메일로 알리기로 했습니다.

문제는 "처음 보는 기기"를 무엇으로 알아보느냐였습니다.

## 어떻게 풀었나

### IP 나 브라우저 정보로는 기기를 가르지 않았습니다

IP 는 와이파이만 바꿔도 달라지고, 브라우저 정보(User-Agent)는 브라우저가 업데이트될 때마다 바뀌었습니다. 이걸로 기기를 가르면 같은 노트북인데도 "새 기기" 메일이 계속 갈 것 같았습니다. 그래서 이 둘은 메일에 적어 보여 주는 데만 쓰고, 기기를 가르는 데는 쓰지 않았습니다.

### 브라우저에 무작위 값을 심고, 서버에는 해시만 남겼습니다

로그인할 때 브라우저에 32바이트짜리 무작위 값을 쿠키로 심었습니다. 자바스크립트가 읽지 못하게(HttpOnly) 하고, 오래 쓰는 기기라 유효 기간을 길게 잡았습니다. 서버에는 이 값 자체가 아니라 해시(SHA-256)만 계정별로 저장했습니다. 저장된 기록이 새어 나가도 그 해시로는 원래 쿠키 값을 만들 수 없게 하려는 것이었습니다.

다음 로그인부터는 이렇게 나눴습니다.

- 쿠키 값의 해시가 그 계정 기록에 있으면 아는 기기로 보고, 마지막으로 본 시각만 고쳤습니다.
- 쿠키가 없거나, 모양이 이상하거나, 기록에 없는 값이면 새 기기로 보고, 새 값을 심고 기록한 뒤 메일을 보냈습니다.

### 알리지 않아야 할 때도 정했습니다

- **계정의 첫 기기:** 기능을 켠 뒤 처음 로그인하면 모든 계정이 "새 기기"가 될 터였습니다. 그때마다 메일이 가면 다들 놀랄 것 같아서, 계정에 기록된 기기가 하나도 없을 때는 기록만 하고 알리지 않았습니다.
- **같은 새 기기로 거의 동시에 두 번 로그인할 때:** 둘 다 "기록에 없음"을 보고 메일을 두 번 보낼 수 있었습니다. 기록을 넣을 때 "이미 있으면 넣지 않기"로 하고, 실제로 넣은 쪽만 메일을 보내게 했습니다.
- **메일은 저장이 끝난 뒤에:** 로그인 처리가 실패해 되돌려졌는데 메일만 나가면 안 되니, 저장이 끝난 뒤에 보냈습니다.

메일에는 "Chrome · Windows (IP 203.0.113.7)"처럼 브라우저·운영체제와 IP 를 적었습니다. 기기를 가르는 데는 쓰지 않았지만, 계정 주인이 "이게 나였나"를 알아보는 데는 도움이 되기 때문이었습니다. 탈퇴하면 기기 기록도 함께 지우고, 보관 기간이 지난 기록은 로그인 기록과 함께 지우게 했습니다.

## 코드로 보기 (개념 재현)

```java
// 로그인할 때마다 부른다 (개념 재현 - 실제 이름과 다름)
@Transactional
public String onLogin(UUID accountId, String cookieValue, String ip, String userAgent) {
    // 모양이 맞는 값만 믿는다. 없거나 이상하면 새 값을 만든다 (32바이트 -> base64url 43자)
    String token = isWellFormed(cookieValue) ? cookieValue : newRandomToken();
    String hash = sha256Hex(token);                  // 서버에는 해시만 둔다

    // 1) 아는 기기면 마지막으로 본 시각만 고치고 끝
    if (devices.touch(accountId, hash) > 0) {
        return token;
    }

    // 2) 계정의 첫 기기인가 - 기능을 켠 뒤 첫 로그인마다 메일이 가지 않게
    boolean firstDevice = !devices.existsAny(accountId);

    // 3) 넣는다. 같은 새 기기로 동시에 들어오면 한쪽만 들어간다 (on conflict do nothing)
    int added = devices.insertIfAbsent(accountId, hash, userAgent, ip);

    // 4) 실제로 넣었고 첫 기기가 아닐 때만, 저장이 끝난 뒤 메일
    if (added > 0 && !firstDevice) {
        notices.afterCommit(accountId, "새 기기에서 로그인했어요", describe(userAgent, ip));
    }
    return token;                                    // 응답에서 쿠키로 다시 심는다
}

private String newRandomToken() {
    byte[] bytes = new byte[32];
    secureRandom.nextBytes(bytes);                   // 추측할 수 없는 값
    return Base64.getUrlEncoder().withoutPadding().encodeToString(bytes);
}
```

```java
// 쿠키로 심기 (개념 재현 - 값은 예시)
ResponseCookie.from("device_id", token)
    .httpOnly(true)                // 자바스크립트가 읽지 못하게
    .secure(true)                  // https 에서만
    .sameSite("Lax")
    .path("/")
    .maxAge(Duration.ofDays(400))  // 오래 쓰는 기기라 길게
    .build();
```

## 💡 배운 것

**기기를 알아보는 데는 자주 바뀌는 정보보다, 내가 심은 무작위 값이 더 믿을 만하다는 걸 알게 됐습니다.** IP 와 브라우저 정보는 기기를 가르는 데가 아니라, 메일에서 계정 주인이 알아보게 돕는 데 쓰는 게 맞았습니다.

**서버에 원래 값 대신 해시만 두면, 기록이 새어도 그 값으로 기기를 흉내 낼 수 없었습니다.** 비밀번호를 해시로 저장하는 것과 같은 생각이었습니다.

**알림은 "언제 보낼지"만큼 "언제 보내지 않을지"를 정하는 게 중요했습니다.** 첫 기기와 동시에 두 번 들어온 로그인을 정하지 않았다면, 기능을 켠 첫날부터 쓸데없는 메일이 쏟아졌을 것 같습니다.

## 소감

메일 한 통 보내는 기능이라 쉽게 생각했는데, 기기를 무엇으로 알아볼지, 무엇을 저장할지, 언제 보내지 않을지를 정하는 데 시간이 더 들었습니다. 해 보니 알림 기능은 보내는 것보다 덜 보내는 쪽을 고민하는 일이었습니다.
