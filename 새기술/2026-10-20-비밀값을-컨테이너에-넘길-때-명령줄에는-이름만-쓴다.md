# 2026-10-20 비밀값을 컨테이너에 넘길 때, 명령줄에는 이름만 쓴다

> 태그: #새기술 #Docker #비밀값 #리눅스 #환경변수

## 무엇을 / 왜

배포 스크립트는 새 서버 컨테이너를 정식으로 바꾸기 전에 후보로 한 번 띄워 봅니다. 이때 서명 개인키 같은 비밀값을 환경변수로 넘겨요. 예전 코드는 값을 명령줄에 그대로 썼습니다.

```bash
docker run -d --name app-candidate -e SIGN_PRIVATE_KEY="$secret_value" app-image
```

리눅스는 기본 설정에서 실행 중인 프로세스의 명령줄을 **다른 사용자도** 볼 수 있어요(/proc 를 hidepid 옵션으로 올린 서버는 예외). 확인해 봤습니다. 시험용 컨테이너 안에서 root 가 `--token=demo-value-123` 이 들어간 명령을 띄우고, 일반 사용자(nobody)로 `ps` 를 돌리니 그 명령줄이 값까지 그대로 보였어요. docker 명령도 똑같이 프로세스라, 위처럼 쓰면 실행되는 동안 개인키가 명령줄에 떠 있습니다.

## 어떻게 풀었나

`docker run -e 이름` 처럼 **값 없이 이름만** 쓰면, docker 가 그 이름의 값을 **docker 명령이 물려받은 환경변수**(셸에서 export 한 값)에서 가져옵니다. export 하지 않은 셸 변수는 넘어가지 않아요. 그래서 값은 하위 셸에서 export 하고, 명령줄에는 이름만 남겼어요(아직 커밋 전이에요).

직접 돌려 보고 세 가지를 확인했습니다.

1. `-e 이름` 만 써도 컨테이너 안에 값이 들어간다.
2. 셸에 그 이름이 없거나 export 하지 않았으면, 오류 없이 **변수가 아예 없는 채로** 컨테이너가 뜬다. 그래서 "값이 있는지" 는 따로 확인해야 해요. compose 에서는 `${이름:?메시지}` 로, 스크립트에서는 배포 전 검사로 막았습니다.
3. `docker inspect` 로 보면 값이 그대로 보인다. 이 방법은 명령줄(ps)에서 숨길 뿐, 도커를 다룰 수 있는 사람(root, docker 그룹)에게는 보여요. inspect 에도 남지 않게 하려면 값을 환경변수가 아니라 파일(마운트)로 넘기거나, 앱이 비밀 저장소에서 직접 읽게 바꿔야 해요. 그래도 서버의 root 는 볼 수 있습니다. 비밀 저장소로 옮기는 일은 남은 일로 적어 뒀어요.

## 코드로 보기 (개념 재현)

```bash
#!/usr/bin/env bash
# 개념 재현: 이름과 경로는 모두 더미다.
set -euo pipefail

# 값은 파일에서 읽어 변수에만 둔다(명령줄 인자로 넘기지 않는다).
secret_value="$(cat /secure/sign-key.b64)"

(
  # 하위 셸에서 export 한다. 이 셸과 그 자식(docker 명령)에게만 보이고,
  # 하위 셸이 끝나면 함께 사라진다.
  export SIGN_PRIVATE_KEY="$secret_value"
  export SIGN_KEY_ID="key-1"

  # -e 뒤에 이름만 쓴다. docker 가 위 환경에서 값을 읽어 컨테이너에 넣는다.
  # 그래서 ps 로 보이는 명령줄에는 이름만 남는다.
  docker run -d --name app-candidate \
    -e SIGN_PRIVATE_KEY \
    -e SIGN_KEY_ID \
    app-image
)
```

확인할 때 쓴 명령과 결과입니다(값은 시험용 더미).

```text
$ export DEMO_SECRET=demo-value-123
$ docker run --rm -e DEMO_SECRET alpine:3.20 sh -c 'echo "$DEMO_SECRET"'
demo-value-123                        <- 이름만 줘도 값이 들어간다

$ docker run --rm -e DEMO_UNSET alpine:3.20 sh -c 'env | grep DEMO_ || echo none'
none                                  <- 셸에 없는 이름은 오류 없이 빠진다

$ SECRET_PLAIN=plain-value-1          <- export 하지 않은 셸 변수
$ docker run --rm -e SECRET_PLAIN alpine:3.20 sh -c 'env | grep SECRET_PLAIN || echo none'
none                                  <- export 하지 않으면 넘어가지 않는다

$ docker run -d --name demo-check -e DEMO_SECRET alpine:3.20 sleep 300
$ docker inspect demo-check --format '{{json .Config.Env}}'
["DEMO_SECRET=demo-value-123", ...]   <- inspect 에는 값이 남는다
$ docker rm -f demo-check
```

## 💡 배운 것

**`docker run -e 이름` 은 셸에서 export 한 환경변수의 값을 가져온다는 걸 배웠습니다.** 값을 명령줄에 쓰지 않아도 컨테이너에는 그대로 들어가요. export 하지 않은 변수는 오류 없이 빠집니다.

**명령줄은 생각보다 공개된 곳이라는 걸 배웠습니다.** 리눅스 기본 설정에서는 같은 서버의 다른 사용자도 `ps` 로 실행 중인 명령의 인자를 볼 수 있어서, 비밀값은 인자로 넘기지 않아야 했어요.

**숨기는 범위를 정확히 알고 써야 한다는 걸 다시 배웠습니다.** `-e 이름` 은 명령줄 노출만 막고, `docker inspect` 에는 남아요. 2026-09-15 에 "막는 장치의 한계(최고 권한이면 끌 수 있다)도 같이 적는다" 를 배웠는데, 이번에도 "안전해졌다" 가 아니라 "명령줄에서는 안 보인다" 가 정확한 설명이었습니다.

**없는 값이 조용히 빠지는 길을 다시 배웠습니다.** 셸에 이름이 없거나 export 하지 않았으면 오류 없이 변수 없는 컨테이너가 떠요. 2026-10-01 에 빈 설정 하나로 백업이 말없이 끝난 일과 같은 모양이라, 값이 있는지는 따로 확인하게 했습니다.

## 소감

한 줄짜리 차이(값을 쓰느냐, 이름만 쓰느냐)인데, 직접 `ps` 로 보기 전에는 실감이 안 났어요. 남은 비밀값(DB 비밀번호 등)도 같은 방식으로 옮길지는 아직 정하지 않았어요.
