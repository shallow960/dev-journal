# 2026-07-30 라이브 방송 영상을 처음 연동해봤다 - 돈 내기 전에 공짜로 검증부터

> 태그: #새기술 #라이브 #외부연동 #영상

## 오늘 한 일 (요약)
- 쇼핑몰에 **라이브 방송(실시간 영상 스트리밍)** 연동을 시작했다. 방송 하나 만들기 → 판매자 송출 주소(OBS용) 발급 → 손님 재생 → 방송이 끝나면 자동 녹화된 **다시보기**까지 흐름을 이었다.
- 결제를 하기 전에, **공짜로 되는 부분만 먼저 찔러서** 연동이 진짜 되는지부터 확인했다.

## 무엇을 / 왜
영상 스트리밍을 직접 붙여본 건 처음이다. 처음엔 "우리 서버가 영상을 받아서 손님한테 뿌리나?" 싶었는데, 알고 보니 그게 아니었다. 라이브는 **① 영상 전용 서비스에 "방송 하나(Live Input)"를 만들고 → ② 그 서비스가 주는 송출 주소·스트림 키를 판매자 OBS에 넣어 방송을 올리면 → ③ 그 서비스가 손님에게 재생 주소(HLS)를 뿌리고 → ④ 방송이 끝나면 자동으로 녹화본을 만들어 다시보기로** 이어지는 구조였다. 즉 무거운 영상 처리는 전부 그 서비스가 하고, 우리는 방송을 "만들고 주소를 넘기는" 역할만 한다.

영상 서비스를 직접 서버로 굴릴 수도 있지만(녹화·화질변환·전송을 다 직접), 8명짜리 팀이 그걸 운영하는 건 부담이라 **관리형 서비스**를 골랐다. 라이브·다시보기·숏폼을 한 곳에서 처리하고, 한국 시청자 전송 비용이 유리한 쪽을 비용까지 비교해서 정했다.

## 어떻게 풀었나 - 기억에 남는 문제 하나
**"월 구독을 결제해야 쓰는 서비스인데, 무작정 결제하기 전에 진짜 되는지 확인하기"**

이 서비스는 무료 요금제가 없어서 최소 월정액이 깔린다. "붙여봤더니 내 코드 가정이 틀렸더라"를 결제한 뒤에 겪으면 아깝다. 그래서 결제 전에 검증할 방법을 찾았다.

핵심은 **"방송 하나를 만드는 것(Live Input 생성)은 공짜"**라는 점이었다. 실제 영상을 송출·저장·전송할 때만 돈이 붙지, 방송 껍데기를 만드는 API 호출 자체는 과금 대상이 아니었다. 그래서 커맨드 한 줄로 그 API를 직접 찔러봤다.

- 토큰·계정이 유효한지 → 응답이 성공으로 왔다
- 구독이 실제로 켜졌는지 → 에러 없이 방송이 만들어졌다
- **내가 문서만 보고 짠 코드가 실제 응답과 맞는지** → 응답에 담긴 필드 이름(송출 주소, 스트림 키, 방송 식별자)이 내 코드가 읽는 자리와 정확히 일치했다

문서를 읽고 "이럴 것이다"라고 짠 코드가, 실물 응답과 한 글자도 안 틀리고 맞는 걸 **돈 한 푼 안 쓰고** 확인한 것이다.

## 💡 배운 것
- **관리형 외부 서비스는 "결제부터 하고 붙이기"가 아니라, 공짜로 되는 부분부터 찔러서 검증할 수 있다.** 리소스를 "만드는" API가 무료인 경우가 많다. 돈은 실제 사용(전송·저장)에 붙지 생성에는 안 붙는 걸 이용하면, 결제 전에 통합을 증명할 수 있다.
- **provider를 갈아끼울 수 있게 경계를 먼저 뒀다.** 영상 provider가 바뀔 수도 있으니, 서비스 코드는 "방송 자격증명을 발급한다"는 인터페이스 하나에만 의존하게 하고, 실제 구현(로컬 가짜 / 실제 서비스)은 설정값 하나로 고르게 했다. **기본값을 "가짜"로 둔 덕에, 토큰을 안 넣고 배포해도 기존 동작이 안 깨진다.** 실제로 켜는 건 준비가 끝난 뒤 설정만 바꾸면 된다.
- **외부 서비스가 우리한테 보내는 콜백(웹훅)은 아무나 못 부르게 서명으로 확인해야 한다.** 녹화가 끝났다고 알려주는 웹훅을, 서비스가 준 공유 비밀로 서명(HMAC)을 계산해 헤더의 서명과 같을 때만 받아들이도록 했다. 안 그러면 남이 "녹화 끝났어"라고 거짓 요청을 보낼 수 있다.

## 코드로 보기 (개념 재현 테스트)
웹훅이 진짜 그 서비스가 보낸 건지 가리는 서명 검증을, 더미 값으로 재현했다. 서명은 **공유 비밀로 "시간.본문"을 해시(HMAC-SHA256)** 한 값이라, 본문이 한 글자만 달라도 서명이 완전히 달라진다.

```java
class WebhookSignatureTest {

    // 서비스와 우리가 같은 규칙으로 계산해야 서명이 일치한다: HMAC-SHA256( 비밀, "시간.본문" )
    private String sign(String secret, String time, String body) {
        return hmacSha256Hex(secret, time + "." + body);
    }

    @Test
    void 같은_비밀과_본문이면_서명이_일치한다() {
        String sig = sign("shared-secret", "1700000000", "{\"uid\":\"abc\"}");
        // 서비스가 보낸 서명(sig)과 우리가 다시 계산한 값이 같아야 "진짜"로 통과
        assertThat(sig).isEqualTo(hmacSha256Hex("shared-secret", "1700000000.{\"uid\":\"abc\"}"));
        assertThat(sig).hasSize(64); // SHA-256 hex = 64자
    }

    @Test
    void 본문이_한_글자라도_바뀌면_서명이_달라진다() {
        String a = sign("shared-secret", "1700000000", "{\"uid\":\"abc\"}");
        String b = sign("shared-secret", "1700000000", "{\"uid\":\"abd\"}"); // 한 글자 차이
        assertThat(a).isNotEqualTo(b); // 위조·변조를 잡아내는 근거
    }
}
```

## 소감
"영상"이라고 하면 막연히 무겁게 느껴졌는데, 막상 흐름을 그려보니 결제 때 배운 것과 비슷했다. 무거운 일은 전문 서비스가 하고 우리는 **만들고 주소를 넘기는** 조립 역할이었다. 특히 이번에 제일 기억에 남는 건 "결제 전에 공짜로 검증하는 법"이다. 예전 같으면 "일단 결제하고 붙여보자" 했을 텐데, 이번엔 돈 쓰기 전에 커맨드 하나로 내 코드가 맞다는 걸 확인하고 들어갔다. 다음엔 실제로 방송을 송출해서 손님 화면에 영상이 뜨는 것까지 눈으로 확인할 예정이다.
