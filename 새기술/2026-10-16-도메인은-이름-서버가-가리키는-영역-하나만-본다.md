# 2026-10-16 도메인은, 이름 서버가 가리키는 영역 하나만 본다

> 태그: #새기술 #DNS #Route53 #이메일 #DKIM

## 무엇을 / 왜

새 AWS 계정에서 메일 발송 서비스를 쓰려면, 도메인 인증용 DKIM 레코드(CNAME 3개)를 DNS 에 넣어야 했습니다. 새 계정에서 작업하다 보니, 새 계정에도 같은 도메인 이름으로 DNS 영역(호스팅 영역)을 만들고 거기에 넣으려고 했어요. 그런데 이 도메인의 DNS 는 원래 계정의 영역이 맡고 있었습니다.

## 어떻게 풀었나

- 도메인에 등록된 **이름 서버(NS)** 4개가 원래 계정 영역의 이름 서버였습니다. 인터넷에서 이 도메인을 찾으면 그 이름 서버에게만 물어요.
- 새 계정에 만든 영역은 같은 이름이어도 **이름 서버가 달라서 아무도 묻지 않습니다.** 거기에 넣은 레코드는 효과가 없어요.
- 그래서 DKIM 레코드는 **원래 계정의 영역에 추가** 했습니다. 원래 계정의 DKIM 3개는 지금 서버가 메일을 보낼 때 쓰고 있어서 지우지 않고, 새것 3개를 더했어요. DKIM 은 키마다 이름(선택자)이 달라서 두 계정이 같은 도메인으로 동시에 보낼 수 있습니다. MAIL FROM(MX·SPF)과 DMARC 레코드는 계정과 상관없는 값이라 그대로 같이 씁니다.
- 레코드를 넣다 "유효한 IPv4 주소가 아니다" 오류가 났는데, 새 줄의 유형이 기본값 **A** 로 남아 있어서였습니다. CNAME 으로 바꾸니 들어갔어요.
- 마지막으로 공개 DNS 에 직접 물어 확인했습니다.

## 코드로 보기 (개념 재현)

```bash
# 1) 이 도메인의 이름 서버는 누구인가 (= 어느 영역이 진짜인가)
dig +short NS example.com
# ns-111.awsdns-11.com.   <- 이 이름 서버를 가진 영역만 인터넷이 본다

# 2) 그 이름 서버에 직접 물어, 레코드가 들어갔는지 확인
dig +short CNAME abc123._domainkey.example.com @ns-111.awsdns-11.com
# abc123.dkim.amazonses.com.

# 3) 공개 DNS 에도 물어, 바깥에서 보이는지 확인
dig +short CNAME abc123._domainkey.example.com @8.8.8.8
```

```powershell
# Windows 에서는 Resolve-DnsName 으로 같은 확인을 한다
Resolve-DnsName -Name abc123._domainkey.example.com -Type CNAME -Server 8.8.8.8 -DnsOnly
```

## 💡 배운 것

**DNS 영역은 만든다고 쓰이는 게 아니라, 위임받아야 쓰입니다.** 같은 이름의 영역이 여러 개 있어도, 도메인의 NS 가 가리키는 하나만 인터넷이 봐요.

**이전 중에는 기존 레코드를 지우지 않고 더합니다.** 메일 인증처럼 지금 서비스가 쓰는 값은, 옮기기가 끝날 때까지 둘 다 살아 있어야 했어요.

**넣은 뒤엔 공개 DNS 에 직접 물어 봅니다.** 콘솔 화면보다 실제 응답이 확실했습니다.

## 소감

"계정을 옮기니 DNS 도 새 계정에"라고 자연스럽게 생각했는데, 도메인은 계정이 아니라 이름 서버를 따라간다는 걸 이번에 분명히 알게 됐어요.
